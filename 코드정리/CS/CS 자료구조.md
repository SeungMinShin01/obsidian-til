# CS 자료구조

> 상위: [[CS]]
> 세부: [[CS 시간 복잡도]] · [[CS 해시와 트리]]

"어떤 그릇에 담느냐"가 속도를 결정한다 — 이미 쓰고 있는 것들의 정체부터.

## 배열 vs 연결 리스트

```
배열(ArrayList)      메모리에 연속 배치. 인덱스 조회 O(1), 중간 삽입·삭제 O(n)
연결 리스트(LinkedList)  노드가 주소로 연결. 조회 O(n), (노드를 아는 상태에서) 삽입·삭제 O(1)
```

- 배열 조회가 O(1)인 이유: 첫 주소 + 타입크기×인덱스 **계산**으로 바로 간다. 연결 리스트는 처음부터 따라가야 한다
- 중간 삽입이 배열에서 O(n)인 이유: 뒤 요소를 전부 한 칸씩 민다. ArrayList가 꽉 차면 1.5배 새 배열로 복사하는 것도 이 구조 때문
- 실전 결론: **거의 항상 ArrayList가 이긴다**(조회가 압도적으로 많아서). LinkedList가 이기는 건 맨 앞 삽입·삭제가 반복될 때 정도

## 스택과 큐

```
스택(LIFO)  나중 것부터 — 뒤로 가기, 실행 취소, 함수 호출 스택, 괄호 검사
큐(FIFO)    먼저 온 순서 — 대기명단, 주문 처리, 프린터 대기열, BFS
```

- "함수 호출 스택"이라는 말 자체가 자료구조 스택이다 — 재귀가 깊으면 StackOverflowError가 나는 이유
- 대기명단 미니프로젝트가 큐의 실물이었다. 자바는 ArrayDeque 하나로 둘 다 쓴다

## 어떤 그릇을 고르나 — 결정표

```
순서 있는 목록, 인덱스로 접근      → 배열 / ArrayList
키로 빠르게 찾기 (번호→객체)      → HashMap
중복 제거, 있냐/없냐만            → HashSet
먼저 온 순서 처리                → Queue(ArrayDeque)
최신 것부터 / 되돌리기            → 스택(ArrayDeque)
항상 정렬 유지, 범위 검색         → TreeMap/TreeSet
우선순위 높은 것 먼저             → PriorityQueue
```

- 면접 질문은 대부분 이 표를 뒤집은 것이다: "회원 번호로 조회가 잦다면 List와 Map 중 무엇을, 왜?"

## 면접 단골 질문

- ArrayList와 LinkedList의 차이는? (내부 구조 → 연산별 복잡도 → 실전 선택까지 이어 말하기)
- ArrayList는 어떻게 크기가 늘어나나? (꽉 차면 1.5배 새 배열 + 복사 — 그래서 초기 용량 지정이 의미 있다)
- HashMap은 왜 빠른가? → 해시와 트리 노트에서
- 스택으로 큐를 만들 수 있나? (스택 2개 — 넣는 통·빼는 통. 사고 과정을 보는 질문)
