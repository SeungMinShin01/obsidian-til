# CS HTTP

> 상위: [[CS 네트워크 기초]]

프론트와 백엔드가 대화하는 규칙 그 자체다. fetch·JDBC 위쪽의 세계는 전부 이 문법으로 돈다.

## 요청과 응답의 생김새

```
GET /boards?page=2 HTTP/1.1          ← 요청줄: 메소드 + 경로
Host: example.com                    ← 헤더들
Content-Type: application/json

{"title": "제목"}                    ← 본문(body)
```

```
HTTP/1.1 200 OK                      ← 상태줄
Content-Type: application/json

[{"no": 1, "title": "..."}]          ← 응답 본문
```

- 요청 = 메소드+경로+헤더+본문, 응답 = 상태코드+헤더+본문. 네트워크 탭에서 요청을 클릭하면 이 원문이 그대로 보인다
- HTTP는 **무상태(stateless)**다 — 서버는 이전 요청을 기억하지 않는다. "로그인 상태"를 따로 만들어야 하는 이유(쿠키·세션·토큰 노트)

## 메소드 — 의도의 표시

```
GET     조회. 본문 없음, 쿼리스트링으로 조건. 몇 번 보내도 같음
POST    생성. 본문에 데이터
PUT     전체 수정   /boards/3 을 통째로 교체
PATCH   부분 수정   제목만 바꾸기
DELETE  삭제
```

- CRUD와의 대응이 REST의 뼈대다: 자원은 URL로(`/boards/3`), 행위는 메소드로. "URL에 동사를 넣지 않는다"(/deleteBoard가 아니라 DELETE /boards/3)
- GET은 몇 번 반복해도 결과가 같아야 한다(멱등) — 조회에 부수효과를 넣지 않는 이유. 브라우저 새로고침 시 "폼 다시 제출" 경고가 뜨는 건 POST가 멱등이 아니라서다

## 상태코드 — 세 자리로 결과 말하기

```
2xx 성공     200 OK / 201 Created(생성됨) / 204 No Content(성공, 본문 없음)
3xx 이동     301 영구 이동 / 302 임시 이동 / 304 캐시 써라
4xx 니 잘못   400 요청이 이상함 / 401 로그인 안 됨 / 403 권한 없음 / 404 없음 / 409 충돌
5xx 내 잘못   500 서버 에러 / 502 게이트웨이 / 503 과부하
```

- 4xx는 **클라이언트 책임**, 5xx는 **서버 책임** — 이 구분이 디버깅의 첫 갈림길이다(400이면 내가 보낸 값부터, 500이면 서버 로그부터)
- 401 vs 403 구분은 단골 질문: 401 "누군지 모름(인증 실패)", 403 "누군지 알지만 권한 없음(인가 실패)"
- API를 직접 만들 때도 이 관례대로 응답해야 프론트가 분기할 수 있다 — 전부 200으로 주고 body에 성공 여부를 넣는 건 안티패턴 취급

## 자주 보는 헤더

```
Content-Type: application/json       본문의 형식 (이거 빼먹으면 서버가 body를 못 읽는 단골 사고)
Authorization: Bearer <토큰>          인증 정보
Cache-Control: max-age=3600          캐시 지시
Access-Control-Allow-Origin: *       CORS 허용
```

- **CORS**: 브라우저가 "다른 출처(도메인·포트)의 API 호출"을 기본 차단하는 보안 정책이다. localhost:5500 프론트에서 localhost:8080 API를 부르면 걸리는 그 에러 — 서버가 허용 헤더를 내려줘야 풀린다. 에러는 브라우저에서 나지만 **수정은 서버에서** 한다는 게 포인트

## 면접 단골 질문

- GET과 POST의 차이는? (용도·본문·멱등성·캐시 — "GET은 조회"에서 멈추지 않기)
- REST API란? (자원=URL, 행위=메소드, 무상태 — 예시 URL 설계까지)
- 401과 403의 차이는? / 상태코드 404·500은 각각 누구 잘못인가?
- CORS 에러를 만난 적 있나, 어떻게 해결하나? (개념 + "서버에서 허용 헤더" 방향)
