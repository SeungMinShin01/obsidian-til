# CS 네트워크 기초

> 상위: [[CS]]
> 세부: [[CS HTTP]] · [[CS 쿠키 세션 토큰]]

"주소창에 URL을 치면 무슨 일이 일어나나" — 면접에서 가장 유명한 질문의 재료들이다.

## URL에서 서버까지

```
https://www.example.com:443/boards?page=2
프로토콜   도메인        포트  경로    쿼리스트링
```

1. **DNS 조회**: 도메인(www.example.com)을 IP 주소로 바꾼다 — 전화번호부 검색
2. **TCP 연결**: 그 IP의 포트로 연결을 만든다(3-way handshake: 요청→응답→확인의 악수 세 번)
3. **HTTP 요청/응답**: 연결 위로 "GET /boards" 요청을 보내고 HTML·JSON 응답을 받는다
4. 브라우저가 응답을 **렌더링**하고, HTML 안의 이미지·CSS·JS를 추가로 요청한다(네트워크 탭에 줄줄이 뜨는 그것)

- localhost:3306, :8080 같은 **포트**는 한 컴퓨터 안의 문 번호다 — MySQL 3306, 웹 8080/443이 관례

## TCP vs UDP

```
TCP  연결·순서·재전송 보장. 느린 대신 정확   → HTTP, DB 연결, 파일 전송
UDP  보장 없음. 그냥 던짐. 빠름              → 영상 통화, 게임, 스트리밍
```

- "택배(TCP) vs 전단지 살포(UDP)"로 기억한다. 잃어버리면 다시 보내주는 게 TCP
- 영상 통화가 UDP인 이유: 0.1초 전 프레임을 재전송받는 것보다 그냥 버리고 다음 프레임이 낫다

## IP · 포트 · 계층 감각

```
애플리케이션   HTTP, DNS          "무엇을" 주고받나
전송          TCP/UDP, 포트       "어느 프로그램에게"
인터넷        IP                  "어느 컴퓨터에게"
물리          이더넷, WiFi        실제 전기 신호
```

- 4계층 이름까진 안 외워도, "IP는 컴퓨터 찾기, 포트는 프로그램 찾기, HTTP는 그 위의 대화 규칙"의 역할 분담은 말할 수 있어야 한다
- 정보처리기사의 서브넷·OSI 7계층이 이 표의 정밀 버전이다

## HTTPS는 뭐가 다른가

- HTTP + 암호화(TLS)다. 중간에서 훔쳐봐도(공용 와이파이) 내용을 읽을 수 없다
- 연결 초기에 서버가 **인증서**를 제시해 "진짜 그 사이트"임을 증명하고, 그 뒤 대칭키로 내용을 암호화한다
- 로그인·결제가 있는 모든 서비스에서 이제 선택이 아니라 기본값이다 — 브라우저가 http를 "주의 요함"으로 표시하는 시대

## 면접 단골 질문

- 주소창에 URL 입력 후 화면이 뜨기까지의 과정은? (DNS → TCP → HTTP → 렌더링, 각 단계 한 문장씩)
- TCP와 UDP의 차이와 각각의 용도는?
- 3-way handshake를 설명하라 (SYN → SYN+ACK → ACK, "서로 들리는지 확인하는 악수")
- HTTP와 HTTPS의 차이는? (암호화 + 인증서 — 왜 필요한지까지)
