# Python day05 — 클래스 정의와 생성자·메소드

> 실습 파일: `day05/c8-1.py`
> 허브: [[Python 정리본 인덱스]] · 이전: [[Python day04 예외 처리 try·except·else·finally]] · 다음: [[Python day05 클래스 변수와 특수 메소드 재정의]]

day05는 **클래스**를 처음 만든 날이다. 지금까지 리스트·딕셔너리·함수로 자료와 동작을 따로 들고 다녔다면, 이번에는 "학생 한 명"처럼 자료(이름·네 과목 점수)와 그 자료로 하는 일(총점·평균·문자열 만들기)을 **한 덩어리로 묶는 설계도**를 그린다. 수업은 절차지향·객체지향·관점지향이라는 큰 그림에서 시작해 추상화·클래스·객체·인스턴스·생성자라는 용어를 정리하고, `class Student: pass`로 빈 클래스를 만들어 인스턴스 여섯 개를 리스트에 담아 본 뒤, `__init__`과 `self`로 멤버변수를 받는 `Student2`를 완성했다. 자바에서 `class`·생성자·`new`·`this`를 썼던 것과 역할은 같고, 괄호 모양(`new`가 없고 `self`를 직접 적는다)만 다르다.

## 1. 배운 내용

### 1-1. 프로그래밍 관점 세 가지와 추상화

```python
# 절차지향 프로그래밍 : 데이터를 순서대로 처리하고 하향식 순차 실행 흐름, C
# 객체지향 프로그래밍 : 객체들의 상호작용으로 프로그래밍 설계 , JAVA/PYTHON/JS
# 관점지향 프로그래밍 : 공통되는 기능(로그/검증/보안 등) 들을 분리하여 프로그래밍 설계, SPRING
# 추상화 : 핵심적인 개념 또는 기능 간추려 내는 것
```

| 관점 | 생각하는 단위 | 대표 |
| --- | --- | --- |
| 절차지향 | 위에서 아래로 흐르는 **명령의 순서** | C |
| 객체지향 | 자료와 동작을 묶은 **객체들끼리의 상호작용** | Java · Python · JS |
| 관점지향 | 여러 객체에 **공통으로 끼어드는 기능**(로그·검증·보안)을 따로 떼어 낸 것 | Spring(AOP) |

지금까지 쓴 파이썬 코드는 사실 절차지향에 가까웠다. 위에서부터 순서대로 실행되고, 자료는 변수에, 동작은 함수에 따로 있었다. 객체지향은 그 둘을 **하나의 단위**로 묶자는 생각이고, 그 첫 단계가 **추상화** — 현실의 학생에게서 "이름과 네 과목 점수"처럼 지금 필요한 핵심만 간추려 내는 일이다. 관점지향은 백엔드 수업에서 만났던 스프링이 쓰는 방식인데, 객체지향 위에 한 겹 더 얹힌 것이라 지금은 이름만 알아 둔다.

### 1-2. 용어 — 클래스·객체·인스턴스·생성자

```python
# [ 리스트 ] , { 딕셔너리 } 객체이다.
# 클래스: 추상화한 데이터들을 구조화 한것( 설계도 )
# 객체: 세상에 존재하는 모든 데이터들을 추상화 ( 실체X )    -> 개념적 객체
# 인스턴스: 추상화한것을 객체로 만든것( 실체O )               -> 물리적 객체
# 인스턴스화: 컴퓨터내 객체 정보 저장 , JAVA : new 생성자() , PY : 생성자()
# 생성자: 클래스 기반으로 인스턴스 만드는 함수              -> 인스턴스 초기화함수
```

| 용어 | 뜻 | 비유 |
| --- | --- | --- |
| 클래스 | 추상화한 자료와 동작을 **구조로 적어 둔 것** | 설계도 |
| 객체 | 추상화의 대상이 되는 모든 것 — 아직 메모리에 없는 **개념** | "학생"이라는 개념 |
| 인스턴스 | 클래스를 바탕으로 **메모리에 실제로 만들어진 것** | 설계도로 지은 집 한 채 |
| 인스턴스화 | 클래스에서 인스턴스를 만드는 행위 | 집을 짓는 일 |
| 생성자 | 인스턴스를 만들 때 **처음 값을 채워 주는 함수** | 입주 전 초기 세팅 |

핵심은 **클래스는 하나, 인스턴스는 여러 개**라는 것이다. 설계도 한 장으로 집을 여러 채 짓듯, `Student` 클래스 하나로 학생 인스턴스를 여섯 개든 백 개든 만든다. 객체와 인스턴스는 실무에서 거의 같은 말로 쓰지만, 수업에서는 "개념(실체 없음)"과 "메모리에 올라간 것(실체 있음)"으로 갈라 두었다. 그리고 첫 줄의 메모가 중요하다 — day02에서 쓴 **리스트와 딕셔너리도 이미 객체**였다. `[1, 2].append(3)`처럼 자료 뒤에 점을 찍고 동작을 불렀던 것이 바로 "자료와 동작이 묶여 있다"는 증거다.

### 1-3. 가장 작은 클래스 — `class 클래스명: pass`

```python
class Student:
    pass

student = Student()      # JAVA: new Student() , PY: Student()
students = [
    Student(),
    Student(),
    Student(),
    Student(),
    Student(),
    Student()
]
```

| 항목 | 설명 |
| --- | --- |
| `class Student:` | 클래스 정의. `def`처럼 콜론 뒤에 들여쓰기 블록이 온다. 이름은 관례상 **대문자로 시작**(함수·변수는 소문자) |
| `pass` | 아직 내용이 없을 때 블록을 채우는 자리 — day01의 `if`, day03의 함수, day04의 `except`와 같은 자리 채움 |
| `Student()` | 인스턴스화. 클래스 이름 뒤에 괄호를 붙여 **함수처럼 호출**하면 인스턴스가 하나 나온다 |
| `students = [Student(), …]` | 인스턴스도 값이므로 리스트에 담을 수 있다. 여섯 번 호출하면 서로 다른 인스턴스 여섯 개 |

자바와 비교하면 `new`가 없다. 자바는 `new Student()`로 "새로 만든다"를 따로 적지만, 파이썬은 **클래스 이름을 그냥 호출**하면 그것이 곧 인스턴스화다. `Student()`를 여섯 번 쓴 리스트는 모양이 `[Student(), Student(), …]`라서 같은 것 하나를 여섯 번 넣은 것처럼 보이지만, 호출할 때마다 새 인스턴스가 만들어지므로 여섯 개는 전부 다른 존재다.

### 1-4. 생성자 `__init__`과 `self` — 멤버변수 채우기

```python
class Student2:
    # def __init__(self , 멤버변수1 ) :
    #     self.멤버변수1 = 멤버변수1;
    def __init__(self, name, korean, math, engligh, science):
        self.name = name
        self.korean = korean
        self.math = math
        self.engligh = engligh
        self.science = science
```

| 항목 | 설명 |
| --- | --- |
| `__init__` | 생성자. 이름이 고정이고 앞뒤로 밑줄 두 개씩(**던더**, double underscore). `Student2(...)`를 호출하면 파이썬이 자동으로 이 함수를 부른다 |
| `self` | 첫 번째 매개변수. **지금 만들어지고 있는 그 인스턴스 자신**을 가리킨다. 호출할 때는 적지 않고 파이썬이 채워 넣는다 |
| `self.name = name` | 매개변수로 받은 값을 인스턴스의 **멤버변수**(인스턴스 변수)에 저장. 왼쪽은 "이 인스턴스의 name 칸", 오른쪽은 방금 받은 인수 |
| `Student2("윤인성", 87, 98, 88, 85)` | 호출 쪽은 `self`를 빼고 나머지 다섯 개만 순서대로 넘긴다 |

`self`가 처음에는 낯선데, 자바의 `this`와 같은 역할이다. 다만 자바는 `this`를 생략할 수 있고 매개변수 목록에도 쓰지 않지만, 파이썬은 **메소드의 첫 매개변수에 반드시 적고, 멤버변수에 접근할 때마다 `self.`를 붙인다**. `self.name`과 `name`은 다른 변수다 — 앞쪽은 인스턴스에 저장되어 함수가 끝나도 남고, 뒤쪽은 매개변수라 `__init__`이 끝나면 사라진다. 주석의 `self.멤버변수1 = 멤버변수1` 꼴이 생성자의 가장 흔한 형태다.

### 1-5. 메소드 — 클래스 안의 함수

```python
    # def 메소드명( self , 매개변수1 ) :
    def get_sum(self):
        return self.korean + self.math + self.engligh + self.science

    def get_average(self):
        return self.get_sum() / 4

    def to_string(self):
        return "{} \t {} \t {}".format(self.name, self.get_sum(), self.get_average())
```

| 메소드 | 하는 일 | 눈여겨볼 점 |
| --- | --- | --- |
| `get_sum` | 네 과목 점수 합 | 매개변수는 `self`뿐 — 필요한 값이 이미 `self.korean` 등에 들어 있어서 따로 받을 게 없다 |
| `get_average` | 총점 ÷ 4 | 같은 클래스의 다른 메소드를 부를 때도 `self.get_sum()`처럼 **`self.`를 붙인다** |
| `to_string` | 이름·총점·평균을 탭으로 이어 문자열로 | day01의 `format()`을 그대로 쓴다. 출력은 하지 않고 **문자열을 돌려주기만** 한다 |

메소드는 `def`로 정의하는 함수인데 **클래스 안에 들어 있고 첫 매개변수가 `self`**라는 두 가지가 다르다. 그 덕에 메소드 안에서는 "이 인스턴스의 점수"를 인수로 받지 않아도 `self.`로 꺼내 쓸 수 있다. `get_average`가 `get_sum`을 다시 쓰는 것처럼, 계산을 작은 메소드로 나누고 서로 부르게 하면 총점 계산식이 한 곳에만 있게 된다 — day03에서 "한 곳만 고치면 전부 반영"이라고 적었던 함수의 장점이 클래스 안에서도 똑같이 적용된다.

### 1-6. 일반 함수와 메소드의 차이

```python
# 일반함수 와 메소드 차이? 일반함수는 클래스밖에서 독립선언 / 메소드는 클래스안에서 내부선언
# 일반함수에서는 self 없고 메소드는 self 있다.
def get_sum2():
    pass
```

| | 일반 함수 | 메소드 |
| --- | --- | --- |
| 선언 위치 | 클래스 **밖**, 독립적으로 | 클래스 **안**, 들여쓰기 블록 속 |
| 첫 매개변수 | 없음(필요한 값은 전부 인수로) | `self`(인스턴스 자신) |
| 호출 | `get_sum2()` | `students[0].get_sum()` — 인스턴스 뒤에 점을 찍고 |
| 자료 접근 | 인수로 받거나 전역 변수 | `self.korean`처럼 인스턴스의 멤버변수를 바로 |

같은 `def`인데 어디에 적혔느냐로 성격이 갈린다. 일반 함수 `get_sum2`가 총점을 내려면 점수 네 개를 전부 인수로 받아야 하지만, 메소드 `get_sum`은 **어느 학생의 것인지가 `self`로 이미 정해져 있어** 인수가 필요 없다. day02에서 `list.append(값)`은 되고 `append(list, 값)`은 안 됐던 이유도 `append`가 리스트 클래스의 메소드이기 때문이었다.

### 1-7. 인스턴스 만들고 멤버변수 꺼내기

```python
# 생성자 이용한 인스턴스 생성 , py: 클래스명( 인수, 인수 , 인수 )
# JAVA: Student2 s = new Student( "유재석" , 10 , 20 , 30 , 40 )
students = [
    Student2("윤인성", 87, 98, 88, 85),
    Student2("윤인성", 87, 98, 88, 85),
    # ... 여섯 개
]

# 인스턴스내 멤버변수 호출
print(students[0].korean)   # 87
```

`students[0]`으로 리스트에서 첫 인스턴스를 꺼내고, 점을 찍어 `.korean` 멤버변수를 읽는다. 딕셔너리라면 `students[0]["korean"]`이라고 적었을 자리가 `.korean`으로 바뀐 셈이다. 같은 인수로 여섯 번 만들었어도 각 인스턴스는 **자기만의 `name`·`korean` 칸**을 따로 가진다 — `students[0].korean = 100`으로 바꿔도 `students[1].korean`은 87 그대로다. 메소드를 부를 때는 `students[0].get_sum()`처럼 괄호까지 붙인다. 괄호 없이 `students[0].get_sum`이라고 쓰면 day03 콜백에서 본 것처럼 함수 자체가 나올 뿐 실행되지 않는다.

## 2. 추가로 알면 좋은 활용법

### 2-1. 딕셔너리에서 클래스로 — 무엇이 달라지나

```python
# day02 방식 — 딕셔너리
student = {"name": "윤인성", "korean": 87, "math": 98, "engligh": 88, "science": 85}
total = student["korean"] + student["math"] + student["engligh"] + student["science"]

# day05 방식 — 클래스
student = Student2("윤인성", 87, 98, 88, 85)
total = student.get_sum()
```

| | 딕셔너리 | 클래스 |
| --- | --- | --- |
| 자료 | 키로 접근, 키 이름이 틀려도 실행 전에는 모른다 | `__init__`이 받을 값을 정해 두므로 개수·순서가 어긋나면 바로 `TypeError` |
| 동작 | 밖에 함수를 따로 두고 딕셔너리를 넘긴다 | 자료 옆에 메소드로 붙어 있어 `student.get_sum()` 한 줄 |
| 여러 개 | `[{...}, {...}]` | `[Student2(...), Student2(...)]` |

API 응답을 받을 때처럼 **구조를 내가 정하지 않는 자료**는 딕셔너리가 편하고, "학생 목록을 받아 성적표를 만든다"처럼 **같은 모양이 반복되고 거기 딸린 계산이 있는 자료**는 클래스가 깔끔하다. 둘은 서로 바꿔 쓸 수도 있어서, 딕셔너리를 `Student2(**d)`로 풀어 넣거나 인스턴스를 `vars(student)`로 딕셔너리로 되돌릴 수 있다.

### 2-2. 메소드를 반복문에서 쓰기

```python
print("이름", "총점", "평균", sep="\t")
for student in students:
    print(student.to_string())
```

리스트에 담긴 인스턴스를 `for`로 돌리며 메소드를 부르는 것이 클래스를 쓰는 가장 흔한 모양이다. 출력 형식을 바꾸고 싶으면 `to_string` 한 곳만 고치면 된다. 총점 순으로 줄 세우고 싶으면 day03 콜백 노트의 `key=`를 그대로 써서 `sorted(students, key=lambda s: s.get_sum(), reverse=True)`로 정렬할 수 있다 — 메소드도 람다 안에서 부를 수 있다.

### 2-3. 인스턴스 안을 들여다보기

```python
print(type(student))            # <class '__main__.Student2'>
print(vars(student))            # {'name': '윤인성', 'korean': 87, ...}
print(hasattr(student, "math")) # True
```

day01에서 `type()`으로 자료형을 확인했듯, 인스턴스에 `type()`을 쓰면 어느 클래스로 만들어졌는지가 나온다. `vars()`는 멤버변수를 딕셔너리로 보여 주어 `__init__`이 제대로 채웠는지 확인할 때 쓸 만하다.

### 2-4. 자바와 나란히 — 대응표

| 파이썬 | 자바 | 메모 |
| --- | --- | --- |
| `class Student:` | `class Student {` | 파이썬은 콜론과 들여쓰기 |
| `def __init__(self, name):` | `Student(String name) {` | 자바는 클래스 이름이 곧 생성자 이름 |
| `self.name = name` | `this.name = name;` | 파이썬은 필드 선언 없이 대입만으로 멤버변수가 생긴다 |
| `Student("윤인성")` | `new Student("윤인성")` | `new` 없음 |
| `def get_sum(self):` | `int getSum() {` | `self`를 명시, 반환 타입 없음 |
| `student.get_sum()` | `student.getSum();` | 호출은 같다 |
| (없음) | `private`·`public` 접근 제어자 | 파이썬은 다음 노트의 `__변수` 관례로 흉내 |

## 3. 더 나아가 알면 좋은 것

- **`__str__`·`__repr__`** — `to_string`처럼 이름을 직접 지은 메소드 대신 `__str__`을 정의하면 `print(student)`·`str(student)`가 그 문자열을 쓴다. 다음 노트에서 바로 이어진다
- **클래스 변수와 `@classmethod`** — 모든 인스턴스가 공유하는 값(학생 수 세기 등)은 `self.`가 아니라 클래스에 둔다. 역시 다음 노트
- **`dataclass`** — `@dataclass`를 붙이면 `__init__`·`__repr__`·`__eq__`를 필드 선언만으로 자동 생성해 준다. 생성자가 대입문의 나열뿐인 클래스에 어울린다
- **타입 힌트** — `def __init__(self, name: str, korean: int)`처럼 적어 두면 편집기가 인수 실수를 잡아 준다
- **`__slots__`** — 멤버변수 이름을 고정해 오타로 새 변수가 생기는 것을 막고 메모리를 아낀다
- **객체지향 4대 특성** — 추상화(오늘), 캡슐화·상속(다음 노트), 다형성. 스프링의 AOP는 그 위에 관점을 얹은 것
