# Python day09 — 따릉이 대여이력 EDA 실습

> 실습 파일: `practice/practice6.py` (문제 2), `practice/서울특별시 공공자전거 대여이력 정보_2501.csv`, `…_2502.csv`
> 허브: [[Python 정리본 인덱스]] · 이전: [[Python day09 타이타닉 생존 데이터 EDA 실습]] · 다음: (아직 없음)

타이타닉과 같은 파일의 두 번째 문제로, 이번에는 **서울 열린데이터 광장의 공공자전거 대여이력** 2025년 1월·2월 CSV 두 장(합쳐 약 333만 행 × 17열, 600MB)을 다룬다. day07에 넘파이로 본 따릉이 데이터가 "대여소 × 월 합계표"였다면, 이번 것은 **대여 한 건이 한 행**인 원천 로그라 규모가 200배다. 가설은 셋 — ① 출퇴근 시간대(08시·18시 전후)의 대여량이 압도적이다, ② 지하철역 인근·유동인구 많은 대여소가 상위권이다, ③ 이용시간과 이용거리는 강한 양의 상관이다. 흐름은 타이타닉과 같은 가설 → 수집 → 전처리 → 시각화인데, 전처리 쪽 비중이 훨씬 크다. `encoding='cp949'`로 읽고 `concat`으로 두 달을 잇고, 결측의 문자열 표현 `'\N'`을 진짜 결측으로 바꾸고, 성별 표기(`m`/`M`/`f`/`F`/결측)를 통일하고, 문자열로 읽힌 수치를 `to_numeric`·날짜를 `to_datetime`으로 바꾼 뒤 시간대 파생열을 만든다. 그다음 카운트플롯·시간대 막대·가로 막대(상위 10 대여소)·히트맵 네 장으로 가설을 확인한다. **실제 공공데이터는 읽는 순간부터 손이 간다**는 것, 그리고 `value_counts()`가 수백만 행을 한 번에 세는 집계 도구라는 것이 이번 실습의 요점이다.

## 1. 배운 내용

### 1-1. 읽기 — `encoding='cp949'`와 열 지도

```python
data1 = pd.read_csv('./practice/서울특별시 공공자전거 대여이력 정보_2501.csv', encoding='cp949')
data2 = pd.read_csv('./practice/서울특별시 공공자전거 대여이력 정보_2502.csv', encoding='cp949')
```

| 열(17개 중 이번에 쓰는 것) | 내용 | 읽힌 자료형 | 처리 |
| --- | --- | --- | --- |
| `대여일시` | `2025-01-01 00:01:39` | object | `to_datetime` → 시간대 추출 |
| `대여 대여소명` | 마곡나루역 2번 출구 … | object | `value_counts().head(10)` |
| `이용시간(분)` | 1, 3, … | object(`'\N'` 섞임) | `to_numeric` |
| `이용거리(M)` | 290.00 … | object(`'\N'` 섞임) | `to_numeric` |
| `성별` | M / F / m / f / `\N` / 빈칸 | object | 대문자 통일 + `'U'` |
| 그 외 | 자전거번호·대여소번호·반납 정보·생년·이용자종류·자전거구분 | — | 이번엔 안 씀 |

이커머스 CSV가 `utf-8-sig`였다면 서울시 공공데이터는 **`cp949`(한국어 윈도우 인코딩)**다. 잘못 고르면 `UnicodeDecodeError`가 나거나 한글이 깨져 열 이름부터 읽을 수 없으므로, 한글 CSV는 `utf-8-sig` → `cp949` 순서로 시도해 보는 것이 관례다. 한 달치가 160~170만 행이라 읽는 데만 십수 초가 걸리는데, 실제로 필요한 열이 다섯 개뿐이면 `usecols=[…]`로 **그 열만 읽어** 시간과 메모리를 크게 줄일 수 있다(2-1).

### 1-2. 두 달 잇기 — `concat(ignore_index=True)`

```python
df = pd.concat([data1, data2], axis=0, ignore_index=True)
print(df.shape)   # (3333662, 17)
```

1월 1,704,188행 + 2월 1,629,474행 = **3,333,662행**이다. 연습문제 9번의 상·하반기 실적과 같은 세로 연결이고, 열 이름이 두 파일에서 같으니 그대로 맞춰진다. `ignore_index=True`가 없으면 인덱스가 1월 0~170만, 2월 0~163만으로 겹쳐 `loc`로 행을 집을 때 두 행이 나오는 사고가 생긴다. day07 넘파이 실습에서는 같은 일을 `np.vstack`으로 했는데, 그때는 열 이름이 없어 "열 순서가 같다"를 사람이 보장해야 했던 차이를 떠올려 둘 만하다.

### 1-3. 결측의 문자열 표현 `'\N'`과 성별 표기 통일

```python
df = df.replace('\\N', None)
df['성별'] = df['성별'].replace('m', 'M').replace('f', 'F').fillna('U')
print(df['성별'].value_counts())   # M 1,689,062 · U 864,699 · F 779,901
```

| 성별 원래 값 | 건수 | 처리 후 |
| --- | --- | --- |
| `M` | 1,688,674 | `M` |
| `F` | 779,619 | `F` |
| `'\N'` (문자열) | 777,614 | → `None` → `U` |
| 진짜 결측(빈칸) | 87,085 | → `U` |
| `m` | 388 | → `M` |
| `f` | 282 | → `F` |

`'\N'`은 DB(MySQL)에서 내보낼 때 **NULL을 글자로 적어 둔 것**이라, 판다스는 이걸 결측이 아니라 역슬래시와 N 두 글자짜리 문자열로 읽는다. 파이썬 코드에서 `'\\N'`으로 역슬래시를 두 번 쓴 것은 이스케이프 때문이다 — 문자열 리터럴 `'\N'`은 유니코드 이름 이스케이프로 해석되어 오류가 나므로 `'\\N'`이라야 글자 그대로의 `\N`이 된다. `df.replace('\\N', None)`은 **표 전체**에서 이 값을 찾아 결측으로 바꾼다. 이커머스 실습의 `replace(r'^\s*$', None, regex=True)`가 "공백 문자열 → 결측"이었다면 이번엔 "특정 표기 → 결측"이고, 둘 다 전처리 노트 ③의 "결측 표기 통일" 단계다.

성별은 **대소문자 혼용**이 숨어 있었다. `m`·`f`가 각각 수백 건이라 `value_counts()`를 찍어 보지 않으면 모르고 지나갈 양인데, 그대로 두면 카운트플롯에 막대가 다섯 개 서서 그림이 거짓말을 한다. `.replace('m', 'M').replace('f', 'F')`로 대문자로 모으고, 결측(원래 빈칸 8.7만 + `\N`에서 온 77.8만)은 `fillna('U')`로 **"모름(Unknown)" 범주**를 따로 만들었다. 결측을 최빈값 `M`으로 채우지 않은 것이 중요하다 — 성별 미기입이 26%나 되는데 전부 남성으로 채우면 분포가 왜곡되고, "모름"도 하나의 정보(비회원·QR 대여 등)이기 때문이다. 전처리 노트에서 "범주 결측은 최빈값"이라고 했지만, 비율이 크면 **별도 범주로 남기는 선택**이 더 정직하다.

### 1-4. 형변환 — `to_numeric`·`to_datetime`과 시간대 파생열

```python
df['이용시간(분)'] = pd.to_numeric(df['이용시간(분)'])
df['이용거리(M)'] = pd.to_numeric(df['이용거리(M)'])
df['대여일시'] = pd.to_datetime(df['대여일시'])
df['대여 시간대'] = df['대여일시'].dt.hour
```

| 변환 | 전 | 후 | 왜 필요한가 |
| --- | --- | --- | --- |
| `to_numeric` | object(`'\N'`이 섞여 숫자로 못 읽힘) | float64 | `corr()`·`describe()`가 숫자 열만 받음 |
| `to_datetime` | object `'2025-01-01 00:01:39'` | datetime64 | `.dt.hour`를 쓰려면 날짜형이어야 함 |
| `.dt.hour` | — | int 0~23 | 가설 1의 **시간대 축** |

수치 열이 문자열로 읽힌 이유가 1-3의 `'\N'`이다 — 한 칸이라도 글자가 섞이면 판다스는 열 전체를 object로 둔다. 그래서 **`'\N'`을 먼저 결측으로 바꾼 뒤** `to_numeric`을 불러야 오류 없이 변환된다(순서가 바뀌면 `Unable to parse string "\N"` 오류). 이커머스 실습에서 `Order_Date`를 바꿔 `.dt.year`·`.dt.month`를 뽑았듯, 여기서는 `.dt.hour`로 **0~23시**를 뽑아 `대여 시간대` 열을 만든다. 날짜 변환은 333만 행이라 시간이 꽤 걸리는데, 형식이 일정할 때 `format='%Y-%m-%d %H:%M:%S'`를 주면 추론 없이 바로 파싱해 몇 배 빨라진다(2-2).

### 1-9. 타이타닉과 나란히 — 같은 틀, 다른 무게

| 단계 | 타이타닉 (891행) | 따릉이 (333만 행) |
| --- | --- | --- |
| 읽기 | `read_csv` 기본 | `encoding='cp949'` · 두 파일 `concat` |
| 결측 | `NaN`을 `median`·`mode`로 채움 | `'\N'` 문자열을 먼저 결측으로 · 성별은 `'U'` 범주로 보존 |
| 자료형 | 처음부터 숫자 | `to_numeric`·`to_datetime` 직접 변환 |
| 파생열 | (없음) | `.dt.hour` 시간대 |
| 집계 | `groupby().mean()` 비율 | `value_counts()` 건수 |
| 그림 | 카운트플롯 ×3 + KDE | 카운트플롯 + 시간대 막대 + 가로 막대 + 히트맵 |

작은 데이터에서는 전처리가 두 줄이고 해석이 길었지만, 큰 원천 로그에서는 **전처리가 본문**이고 그림은 집계 결과를 보여 주는 끝단이다. 두 실습을 붙여 보면 EDA의 틀은 같되 데이터가 더러울수록 4단계에 시간이 쏠린다는 것이 드러난다.

## 2. 추가로 알면 좋은 활용법

### 2-1. 큰 CSV를 가볍게 읽기 — `usecols`·`dtype`·`na_values`

```python
cols = ['대여일시', '대여 대여소명', '이용시간(분)', '이용거리(M)', '성별']
df = pd.read_csv(path, encoding='cp949', usecols=cols,
                 na_values=['\\N'],                          # 읽으면서 바로 결측 처리
                 dtype={'대여 대여소명': 'category', '성별': 'category'})
```

필요한 다섯 열만 읽으면 메모리가 1/3로 줄고, `na_values=['\\N']`을 주면 1-3의 `replace` 단계가 사라지며 수치 열이 **처음부터 float**로 읽힌다. 범주 열을 `category`로 지정하면 수천 개 대여소 이름을 문자열 333만 개가 아니라 번호로 저장해 집계가 빨라진다.

### 2-2. 날짜 파싱 빠르게 — `format=`과 `parse_dates`

```python
df['대여일시'] = pd.to_datetime(df['대여일시'], format='%Y-%m-%d %H:%M:%S')
df = pd.read_csv(path, encoding='cp949', parse_dates=['대여일시'])   # 읽을 때 변환
df['요일'] = df['대여일시'].dt.dayofweek    # 0=월 … 6=일
```

형식을 알려 주면 판다스가 행마다 형식을 추론하지 않아 수 배 빨라진다. `dayofweek`를 뽑아 `groupby(['요일', '대여 시간대']).size().unstack()`을 히트맵으로 그리면 **요일 × 시간대 수요 지도**가 되어, 평일 출퇴근 봉우리와 주말 오후 봉우리가 갈라져 보인다.

### 2-3. 시간대 막대를 평균으로 — 하루 평균 대여량

```python
days = df['대여일시'].dt.date.nunique()            # 59일
(hour_counts / days).round(0)                       # 시간대별 하루 평균 건수
sns.lineplot(x=hour_counts.index, y=hour_counts.values / days, marker='o')
```

두 달 합계는 기간이 바뀌면 비교가 안 되므로 **하루 평균**으로 나누어 두면 다른 달과 나란히 놓을 수 있다. 시간대처럼 **순서가 있는 x**는 막대보다 선 차트가 봉우리 모양을 더 잘 보여 준다.

### 2-4. 이상치를 걷어낸 상관 — IQR과 스피어만

```python
q1, q3 = df['이용시간(분)'].quantile([0.25, 0.75]);  iqr = q3 - q1
clean = df[(df['이용시간(분)'] <= q3 + 1.5 * iqr) & (df['이용거리(M)'] > 0)]
clean[['이용시간(분)', '이용거리(M)']].corr()                     # 피어슨 — 꼬리 제거 후
df[['이용시간(분)', '이용거리(M)']].corr(method='spearman')     # 순위 상관 — 극단값에 둔감
```

1-8의 0.53이 극단값 때문에 눌린 것인지 확인하는 두 길이다. 거리 0인 기록(대여 직후 반납)을 빼고 42분(≈ Q3 + 1.5·IQR) 넘는 장시간 대여를 걷어낸 뒤 다시 재면 평소 이용의 시간–거리 관계가 더 또렷해진다.

### 2-5. 대여소 상위 N을 비율·누적으로

```python
station = df['대여 대여소명'].value_counts()
(station.head(10) / len(df) * 100).round(2)          # 상위 10곳이 전체의 몇 %인가
station.cumsum().div(len(df)).lt(0.5).sum()           # 전체 대여의 절반을 차지하는 대여소 수
```

"상위 10곳이 전체의 3%"처럼 분모를 붙여야 집중도가 읽힌다. 누적 비율로 "상위 몇 곳이 절반을 차지하나"를 세면 재배치 우선순위(day07의 주제)로 바로 이어진다.

### 2-6. 성별 비중을 비율로 — `normalize`와 `U` 제외

```python
df['성별'].value_counts(normalize=True).round(3)                          # U 포함 비율
df.loc[df['성별'] != 'U', '성별'].value_counts(normalize=True).round(3)   # 기록된 승객 중 비율
```

`U`를 넣고 뺀 두 비율을 같이 적어야 "남성 51%"(전체)와 "남성 68%"(기록된 사람 중)의 차이가 숨지 않는다.

## 3. 더 나아가 알면 좋은 것

### 3-1. 메모리와 속도 — 333만 행이 가르쳐 주는 것

이 데이터는 `read_csv`만 수십 초, `to_datetime`도 수십 초가 걸린다. 판다스는 열을 통째로 메모리에 올리므로 **열을 줄이고(`usecols`), 자료형을 줄이고(`category`·`float32`), 날짜는 형식을 알려 주는** 세 가지가 기본 처방이다. 더 커지면 `chunksize=`로 나눠 읽어 집계만 누적하거나, Parquet 형식으로 한 번 변환해 두거나, Polars·DuckDB 같은 도구로 옮기는 것이 다음 단계다. day07 넘파이 실습의 `genfromtxt`로는 이 크기를 다루기 어렵다는 것도 판다스를 쓰는 이유다.

### 3-2. 시간대 데이터의 특수성 — 순환 변수

`대여 시간대`는 23시 다음이 0시인 **순환 변수**라, 히트맵의 피어슨 상관이나 평균 시간대 같은 계산이 뜻을 잃는다. 머신러닝 입력으로 쓸 때는 `sin(2π·h/24)`·`cos(2π·h/24)` 두 열로 바꾸거나, 출근·낮·퇴근·심야 **범주로 구간화(`pd.cut`)**해 `get_dummies`로 넣는다. 시간대 막대(1-6)가 상관계수보다 훨씬 많은 것을 말해 주는 이유다.

### 3-3. 대여소 분석에서 공간 분석으로

상위 대여소가 전부 역 근처라는 결론은 **위도·경도**를 붙이면 지도가 된다. 서울시는 대여소 마스터(번호·이름·좌표)를 따로 제공하므로 `merge(on='대여 대여소번호')`로 좌표를 붙이고 `folium`이나 `plotly`로 점 지도를 그리면 마곡·잠실·여의도 군집이 보인다. day07의 `argmax`로 찾던 재배치 대상 대여소를 지도 위에서 고르는 것이 자연스러운 다음 과제다.
