# Python day06 — 넘파이 시작과 배열 생성

> 실습 파일: `day06/n-01.py`
> 허브: [[Python 정리본 인덱스]] · 이전: [[Python day05 프라이빗 변수·property와 상속]] · 다음: (아직 없음)

여기부터는 파이썬 문법이 아니라 **라이브러리**를 쓰는 단계다. 첫 번째로 만난 것이 넘파이(NumPy) — 숫자 계산, 특히 **배열(행렬) 계산을 빠르게 하는 라이브러리**다. 이 시간에 한 일은 세 가지다. `import numpy as np`로 불러와 버전을 찍어 설치를 확인하고, 왜 넘파이를 배우는지(데이터 분석·머신러닝/딥러닝의 바닥 재료) 적어 두고, `np.array()`에 리스트를 넣어 1차원·2차원 배열을 만들어 봤다. 분량은 적지만 "리스트와 배열이 어떻게 다른가"가 이 수업 전체의 출발점이라 따로 정리한다.

## 1. 배운 내용

### 1-1. 라이브러리 불러오기 — `import … as 별칭`

```python
import numpy as np
print(np.__version__)

# import 라이브러리이름
# import 라이브러리이름 as 별칭
```

| 문법 | 뜻 | 쓰는 모양 |
| --- | --- | --- |
| `import numpy` | 넘파이를 그 이름 그대로 불러온다 | `numpy.array([...])` |
| `import numpy as np` | 불러오되 **`np`라는 짧은 이름**으로 쓴다 | `np.array([...])` |
| `np.__version__` | 설치된 버전 문자열 | `print(np.__version__)` |

day01에 `import keyword`로 예약어 목록을 꺼내 봤던 것과 같은 `import`다. 차이는 `keyword`가 파이썬에 처음부터 들어 있는 **표준 모듈**이고 넘파이는 **따로 설치한 외부 라이브러리**라는 점 — 그래서 첫 줄에서 `__version__`을 찍어 "설치가 됐고 불러와진다"를 먼저 확인했다. `as np`는 관례다. 넘파이 코드는 어디서 봐도 `np.`로 시작하므로 다른 별칭을 붙이면 오히려 읽기 어려워진다. 나중에 만날 판다스도 같은 식으로 `import pandas as pd`로 쓴다.

### 1-2. 넘파이를 배우는 이유

```python
# 3. 넘파이 학습하는 이유: 1) 데이터분석(수치계산) 2) ML/DL 라이브러리들이 사용
```

| 이유 | 풀어 쓰면 |
| --- | --- |
| 데이터 분석(수치 계산) | 수천·수만 개 숫자를 반복문 없이 한 번에 더하고 곱하고 평균 낸다. 리스트로 하면 `for`를 돌려야 하는 일이 식 하나로 끝난다 |
| ML/DL 라이브러리들이 사용 | 판다스·사이킷런·텐서플로·파이토치가 전부 안쪽에서 넘파이 배열을 주고받는다. 넘파이를 모르면 그 라이브러리들의 입력·출력을 읽을 수 없다 |

정리하면 넘파이는 **그 자체가 목적이 아니라 뒤에 올 것들의 공용 자료형**이다. 리스트가 파이썬 문법의 기본 그릇이었듯, 넘파이 배열은 데이터 분석 세계의 기본 그릇이다.

### 1-3. 1차원 배열 만들기 — `np.array(리스트)`

```python
# 1] 배열 생성
x = np.array( [1, 2, 3, 4] ) # 1차원 배열
print( x ) # [ 1 2 3 4 ]
```

`np.array()`에 **리스트를 넣으면 배열이 된다.** 출력 모양을 보면 리스트와 다른 점이 바로 드러난다.

| | 리스트 `[1, 2, 3, 4]` | 배열 `np.array([1, 2, 3, 4])` |
| --- | --- | --- |
| 출력 | `[1, 2, 3, 4]` — 쉼표로 구분 | `[1 2 3 4]` — **공백으로 구분** |
| 안에 담는 것 | 자료형 섞어도 됨 | **한 가지 자료형**(전부 정수, 전부 실수 …) |
| `+` | 연결 (`[1, 2] + [3, 4]` → `[1, 2, 3, 4]`) | **요소끼리 덧셈** (`[1 2] + [3 4]` → `[4 6]`) |
| 용도 | 무엇이든 순서대로 담는 범용 그릇 | 숫자 계산 전용 |

day02 리스트 노트에 "`[1, 2] + [3, 4]`가 `[4, 6]`이 되지는 않는다, 요소끼리 더하려면 나중에 배울 넘파이 배열을 써야 한다"고 적어 둔 그 자리가 여기다. 리스트의 `+`는 연결이고 배열의 `+`는 수학 연산이다. 출력에서 쉼표가 사라진 것은 "이건 리스트가 아니라 넘파이 배열이다"라는 표식이라 눈에 익혀 두는 편이 좋다.

### 1-4. 2차원 배열 — 리스트 안의 리스트

```python
x = np.array(
    [ [1, 2, 3],
      [4, 5, 6] ]
)
# [[1 2 3]
#  [4 5 6]]
```

리스트 안에 리스트를 넣으면 **2차원 배열(행렬)**이 된다. day02에서 2차원 리스트를 `[행][열]`로 읽었던 것과 같은 모양인데, 넘파이는 이걸 "2행 3열의 행렬"로 다룬다. 안쪽 리스트 하나가 **행(row)** 한 줄이고, 안쪽 리스트의 길이가 **열(column)** 개수다.

| 차원 | 만드는 재료 | 모양(shape) | 비유 |
| --- | --- | --- | --- |
| 1차원 | `[1, 2, 3, 4]` | `(4,)` | 숫자 한 줄 |
| 2차원 | `[[1, 2, 3], [4, 5, 6]]` | `(2, 3)` | 표 — 2행 3열 |

2차원 배열을 만들 때 **바깥 대괄호 하나, 안쪽 대괄호가 행마다 하나**이고 행과 행 사이에는 쉼표가 들어간다. 안쪽 리스트들의 길이는 모두 같아야 네모난 표가 된다 — 길이가 다르면 행렬이 아니라 "리스트를 담은 1차원 배열"로 취급되어 뒤의 계산이 꼬이므로, 2차원 배열을 손으로 적을 때는 행 길이를 맞추는 것을 먼저 확인한다. 여러 줄로 나눠 쓰는 것은 그냥 보기 좋게 하려는 것이고, 한 줄에 `np.array([[1, 2, 3], [4, 5, 6]])`로 적어도 같다.

## 2. 추가로 알면 좋은 활용법

### 2-1. 배열의 속성 세 가지 — `ndim`·`shape`·`dtype`

```python
x = np.array([[1, 2, 3], [4, 5, 6]])
print(x.ndim)   # 2       — 차원 수
print(x.shape)  # (2, 3)  — 각 차원의 길이 (행, 열)
print(x.dtype)  # int64   — 요소의 자료형 (환경에 따라 int32)
```

배열을 받으면 가장 먼저 이 셋을 찍어 보는 습관이 유용하다. 리스트는 `len()`밖에 없어서 2차원이면 `len(x)`, `len(x[0])`을 따로 봐야 했지만, 배열은 `shape` 한 번으로 전체 모양이 나온다. `dtype`은 리스트와 가장 다른 지점 — 배열은 **모든 요소가 같은 자료형**이라 정수와 실수를 섞어 넣으면 전부 실수로 올라간다(`np.array([1, 2.5])` → `[1.  2.5]`).

### 2-2. 리스트 → 배열 → 리스트

```python
lst = [1, 2, 3]
arr = np.array(lst)      # 리스트 → 배열
back = arr.tolist()      # 배열 → 리스트
print(type(arr), type(back))  # <class 'numpy.ndarray'> <class 'list'>
```

`type()`으로 찍으면 넘파이 배열의 정식 이름이 `ndarray`(n-dimensional array)라는 것을 알 수 있다. 계산은 배열로 하고, 결과를 JSON으로 보내거나 다른 파이썬 코드에 넘길 때는 `tolist()`로 다시 리스트로 바꾸는 식으로 오간다.

### 2-3. 리스트 없이 바로 만드는 배열

```python
np.zeros(3)          # [0. 0. 0.]
np.ones((2, 3))      # 1로 채운 2행 3열
np.arange(1, 5)      # [1 2 3 4]  — range의 배열판
np.linspace(0, 1, 5) # 0~1을 5등분 [0.   0.25 0.5  0.75 1.  ]
```

`np.arange`는 day02의 `range`와 인자 규칙(시작·끝·단계, 끝 미포함)이 같다. 차이는 `range`가 반복문용 범위 객체를 주는 데 비해 `arange`는 **바로 계산할 수 있는 배열**을 준다는 것. 자리만 먼저 만들어 두고 값을 나중에 채울 때는 `zeros`·`ones`를 쓴다.

### 2-4. 요소끼리 계산 — 반복문이 사라지는 자리

```python
scores = np.array([80, 90, 70])
print(scores + 5)        # [85 95 75]  — 모든 요소에 5
print(scores * 1.1)      # [88. 99. 77.]
print(scores.mean())     # 80.0
print(scores.max())      # 90
```

리스트였다면 `[s + 5 for s in scores]`나 `for`가 필요했던 일이 **배열에서는 식 하나**다. 이것을 벡터화(vectorization)라고 부른다. day05에서 학생 점수를 클래스로 묶어 `get_sum`·`get_average`를 만들었는데, 점수 묶음을 배열로 두면 `sum()`·`mean()`이 이미 있다 — 자료가 "같은 종류의 숫자 여러 개"라면 클래스보다 배열이 어울리는 경우가 많다.

## 3. 더 나아가 알면 좋은 것

### 3-1. 왜 넘파이가 빠른가

리스트는 요소 하나하나가 따로 떨어진 파이썬 객체를 가리키는 **주소 모음**이라 더할 때마다 하나씩 꺼내 자료형을 확인한다. 넘파이 배열은 **같은 자료형의 값이 메모리에 연속으로** 놓여 있고, 계산 자체는 C로 짜인 코드가 한 번에 돈다. `dtype`이 하나로 고정되는 것은 제약이 아니라 이 속도를 얻기 위한 조건이다. 자바에서 `int[]`가 `ArrayList<Integer>`보다 가벼운 것과 같은 이유다.

### 3-2. 인덱싱·슬라이싱·불리언 마스크

리스트의 `[2]`·`[1:3]`은 배열에서도 그대로 되고, 2차원에서는 `x[0, 1]`처럼 **쉼표 하나로 행·열을 동시에** 고른다(리스트는 `x[0][1]`). 거기에 `scores[scores >= 80]`처럼 **조건식을 대괄호 안에 넣어** 참인 요소만 골라내는 불리언 마스크가 더해진다 — day03의 `filter(lambda s: s >= 80, scores)`가 식 하나로 줄어드는 자리다.

### 3-3. 브로드캐스팅과 축(axis)

모양이 다른 배열끼리 계산할 때 작은 쪽을 자동으로 늘려 맞추는 규칙이 브로드캐스팅이다(`scores + 5`에서 숫자 5가 세 칸으로 늘어난 것이 가장 단순한 예). 2차원에서 `sum(axis=0)`은 열 방향(세로), `axis=1`은 행 방향(가로) 합 — 이 둘은 판다스 `DataFrame`까지 그대로 이어지는 개념이라 다음 수업에서 가장 헷갈리는 지점이 될 것이다.
