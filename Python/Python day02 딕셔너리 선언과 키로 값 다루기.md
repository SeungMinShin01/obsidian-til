# Python day02 — 딕셔너리 선언과 키로 값 다루기

> 실습 파일: `day02/c4-2.py`
> 허브: [[Python 정리본 인덱스]] · 이전: [[Python day02 리스트 선언과 인덱싱·슬라이싱]] · 다음: (아직 없음)

리스트 다음은 **딕셔너리**다. 리스트가 "순서 번호로 찾는 통"이었다면 딕셔너리는 "**이름(키)으로 찾는 통**"이다. 중괄호 안에 `키: 값` 쌍을 쉼표로 늘어놓고, 대괄호에 인덱스 대신 키를 넣어 값을 꺼낸다. 수업 주석에 적힌 대로 자바스크립트의 JSON 객체, 자바의 `Map`(또는 필드 이름이 있는 DTO), 데이터베이스의 레코드 한 줄과 같은 자리를 차지하는 자료형이라, 앞으로 API 응답이나 판다스 행을 다룰 때 가장 자주 만나게 될 모양이다. 이 파일은 선언 → 값 호출 → 추가 → 수정 → 삭제 → `in` 확인 → `get` → `for` 순회까지, 리스트에서 했던 작업을 딕셔너리에서 **똑같은 순서로 한 번씩** 해 본 것이라 리스트 노트와 나란히 놓고 읽으면 차이가 또렷해진다.

## 1. 배운 내용

### 1-1. 딕셔너리란 — 중괄호 안의 `키: 값` 쌍

```python
# 딕셔너리란? { } 중괄호로 선언하고 키:값 형태를 쉼표로 연결
# { key:value , key:value , key:value }
# key 중복 X / value 중복 O
# JS: JSON , Java: Map / DTO , DB: RECORD
dict_a = { 'name' : '어벤저스 엔드게임' , 'type' : '히어로 무비' }
```

| 용어 | 뜻 |
| --- | --- |
| 딕셔너리(dict) | 중괄호 `{ }` 안에 `키: 값` 쌍을 쉼표로 나열한 모음. `type()`으로 찍으면 `<class 'dict'>` |
| 키(key) | 값을 찾는 이름표. **중복될 수 없다** — 같은 키를 두 번 적으면 뒤에 적은 값이 남는다 |
| 값(value) | 키에 매달린 데이터. 중복되어도 상관없고 자료형도 자유다 |

리스트가 `[ ]`에 값만 늘어놓고 자리 번호가 자동으로 붙는 구조라면, 딕셔너리는 `{ }`에 **값마다 이름을 직접 붙여** 넣는 구조다. 그래서 "두 번째 값"이 아니라 "`name`에 해당하는 값"을 묻게 된다. 키로는 보통 문자열을 쓰지만 정수나 튜플처럼 **바꿀 수 없는 값**이면 무엇이든 되고, 리스트처럼 바뀌는 값은 키로 쓸 수 없다(`TypeError: unhashable type`). 다른 언어와 짝을 지어 보면 자바스크립트의 `{ name: "...", type: "..." }` 객체와 모양이 거의 같고, 자바로는 `Map<String, Object>`에 `put("name", "...")`을 한 것, 데이터베이스로는 열 이름이 붙은 한 행(레코드)에 해당한다. 자바 `Map`과 다른 점은 선언할 때 키·값의 자료형을 정하지 않아서 한 딕셔너리에 문자열 값과 정수 값이 섞여도 된다는 것이다.

### 1-2. 값 호출 — `딕셔너리명['키']`

```python
print( dict_a['name'] )   # 어벤저스 엔드게임
print( dict_a['type'] )   # 히어로 무비
```

| 식 | 결과 | 설명 |
| --- | --- | --- |
| `dict_a['name']` | `'어벤저스 엔드게임'` | 키 `'name'`에 매달린 값 |
| `dict_a['price']` | `KeyError: 'price'` | 없는 키를 대괄호로 부르면 오류 |
| `dict_a[0]` | `KeyError: 0` | 딕셔너리에는 **순서 번호가 없다**. `0`도 그냥 "없는 키"다 |

리스트의 `list_a[2]`와 같은 대괄호 문법인데, 괄호 안에 들어가는 것이 인덱스가 아니라 **키**다. 그래서 리스트에서 `IndexError`가 나던 자리에 딕셔너리는 `KeyError`가 난다. 키가 문자열이면 따옴표를 빼먹지 않도록 주의해야 한다 — `dict_a[name]`으로 쓰면 `name`이라는 변수를 찾으러 가서 `NameError`가 난다. 자바 `map.get("name")`에 해당하지만, 자바는 없는 키에 `null`을 돌려주고 파이썬의 대괄호는 예외를 던진다는 차이가 있다. 그 차이를 메우는 것이 아래 1-7의 `get`이다.

### 1-3. 값 추가 — 새 키에 대입

```python
dict_a[ 'price' ] = 5000    # 없는 키에 대입 → 쌍이 새로 생긴다
print( dict_a )             # {'name': '어벤저스 엔드게임', 'type': '히어로 무비', 'price': 5000}
```

리스트는 요소를 더할 때 `append`라는 메소드를 불러야 했지만, 딕셔너리는 **없는 키에 그냥 대입**하면 쌍이 추가된다. 따로 "추가" 메소드가 없는 셈이다. 자바에서 `map.put("price", 5000)`을 하는 것과 같고, 자바스크립트에서 `obj.price = 5000`으로 속성을 붙이는 것과 같다. 출력해 보면 **넣은 순서대로** 찍힌다 — 파이썬 3.7부터 딕셔너리는 삽입 순서를 보존하므로, 순서가 없다기보다 "순서로 찾지는 않는다"고 적어 두는 편이 정확하다.

### 1-4. 값 수정 — 있는 키에 대입

```python
dict_a['type'] = '호러 무비'   # 이미 존재하는 키는 값 수정
print( dict_a )                # {'name': '어벤저스 엔드게임', 'type': '호러 무비', 'price': 5000}
```

1-3과 **문법이 완전히 같다**. 대입하는 키가 이미 있으면 수정, 없으면 추가다. 그래서 키를 한 글자라도 잘못 적으면 수정이 아니라 새 쌍이 하나 생겨 버린다 — `dict_a['tpye'] = ...`처럼 쓰면 오류 없이 `tpye`라는 키가 늘어나는 식이라, 오타가 조용히 묻히는 자리로 기억해 두는 편이 안전하다. 1-1에서 "키는 중복될 수 없다"고 적은 것이 바로 이 동작의 근거다. 키가 하나뿐이니 같은 키에 다시 대입하면 덮어쓸 수밖에 없다.

### 1-5. 쌍 삭제 — `del 딕셔너리명['키']`

```python
del dict_a['price']   # 키 'price' 와 그 값을 함께 지운다
print( dict_a )       # {'name': '어벤저스 엔드게임', 'type': '호러 무비'}
```

리스트에서 `del list_a[1]`로 인덱스 자리를 지웠던 것과 같은 키워드다. 대괄호 안이 인덱스에서 키로 바뀐 것뿐이다. 없는 키를 지우려 하면 호출할 때와 마찬가지로 `KeyError`가 난다. 리스트의 `pop`에 해당하는 `dict_a.pop('price')`도 있어서 지우면서 값을 돌려받고 싶을 때는 그쪽을 쓴다.

### 1-6. 키가 있는지 확인 — `'키' in 딕셔너리명`

```python
print( 'price' in dict_a )   # False — 방금 지웠다
print( 'name' in dict_a )    # True
```

리스트의 `52 in list_a`가 **값**이 있는지를 물었다면, 딕셔너리의 `in`은 **키**가 있는지를 묻는다. 값이 있는지를 물으려면 `'호러 무비' in dict_a.values()`처럼 `values()`를 거쳐야 한다. 1-2의 `KeyError`를 피하는 가장 기본적인 방법이 이것이라, `if 'price' in dict_a:`로 먼저 확인한 뒤 대괄호로 꺼내는 모양을 자주 쓴다. 자바의 `map.containsKey("price")`에 해당한다.

### 1-7. 값 호출 두 가지 — 대괄호 vs `get`

```python
# 방법1: 딕셔너리명['key']  → 없으면 KeyError
# 방법2: 딕셔너리명.get(key) → 없으면 None
print( dict_a.get('name') )    # 어벤저스 엔드게임
print( dict_a.get('price') )   # None
```

| 방법 | 키가 있을 때 | 키가 없을 때 | 쓰는 자리 |
| --- | --- | --- | --- |
| `dict_a['key']` | 값 | `KeyError` | 키가 **반드시 있어야** 하는 자리. 없으면 오류로 알고 싶을 때 |
| `dict_a.get('key')` | 값 | `None` | 키가 없을 수도 있는 자리. 오류 대신 빈 값으로 받고 싶을 때 |
| `dict_a.get('key', 기본값)` | 값 | 기본값 | 없을 때 쓸 값을 정해 두고 싶을 때 |

둘의 차이는 **없는 키를 어떻게 다루느냐** 하나다. 대괄호는 프로그램을 멈추고, `get`은 `None`을 돌려주고 계속 간다. 외부에서 받은 JSON처럼 어떤 키가 들어 있을지 확실하지 않은 데이터는 `get`으로 읽는 편이 안전하고, 반대로 내가 직접 만든 설정값처럼 키가 꼭 있어야 하는 데이터는 대괄호로 읽어 빠진 것을 바로 알아채는 편이 낫다. 자바 `Map.get`이 `null`을 돌려주는 동작과 같은 것이 파이썬에서는 `get`이고, `getOrDefault`에 해당하는 것이 두 번째 인수를 넣은 `get(key, 기본값)`이다.

### 1-8. `for` 반복문과 딕셔너리 — 키가 하나씩 나온다

```python
# for key반복변수 in 딕셔너리명:
#       실행코드
for key in dict_a :
    print( dict_a.get(key) )   # 방법1 — get 으로 값 꺼내기
    print( dict_a[key] )       # 방법2 — 대괄호로 값 꺼내기
```

| 반복 대상 | 반복 변수에 들어오는 것 |
| --- | --- |
| `for x in 리스트:` | 요소 하나씩 |
| `for x in "문자열":` | 글자 하나씩 |
| `for x in 딕셔너리:` | **키** 하나씩 (값이 아니다) |

리스트와 문자열을 `for`에 넣으면 요소·글자가 나왔듯 딕셔너리를 넣으면 **키**가 나온다. 값은 나오지 않으므로 몸체에서 `dict_a[key]`나 `dict_a.get(key)`로 한 번 더 꺼내야 한다. 그래서 수업 파일처럼 반복 변수 이름을 `key`로 두면 읽을 때 헷갈리지 않는다. 반복 순서는 1-3에서 적은 대로 넣은 순서다. 자바에서 `for (String key : map.keySet())`을 돌리는 것과 같은 모양인데, 파이썬은 `keySet()` 없이 딕셔너리 자체를 넣으면 키가 나온다.

## 2. 추가로 알면 좋은 활용법

### 2-1. `keys()`·`values()`·`items()` — 키·값·쌍을 골라 돌리기

```python
for key in dict_a.keys():            # 1-8 과 같다 — 키만
    print(key)
for value in dict_a.values():        # 값만
    print(value)
for key, value in dict_a.items():    # 키와 값을 한 번에 — 가장 많이 쓰는 모양
    print(key, ':', value)
```

1-8에서 키를 받아 다시 `dict_a[key]`를 부르던 두 줄은 `items()`로 한 줄이 된다. `items()`는 `(키, 값)` 튜플을 하나씩 돌려주고, `for key, value in ...`처럼 변수 두 개를 적으면 튜플이 풀려서 들어온다. 값만 필요하면 `values()`를 돈다. 자바의 `map.entrySet()`에 해당하지만 `getKey()`·`getValue()`를 부를 필요가 없어 짧다.

### 2-2. 리스트 안의 딕셔너리 — API 응답의 기본 모양

```python
movies = [
    { 'name': '어벤저스 엔드게임', 'type': '히어로 무비', 'price': 5000 },
    { 'name': '컨저링',          'type': '호러 무비',   'price': 4000 },
]
print( movies[1]['name'] )          # 컨저링 — 리스트 인덱스 → 딕셔너리 키 순서로 대괄호를 붙인다
for movie in movies:
    print( movie['name'], movie.get('price') )
```

리스트 노트의 2차원 리스트가 `[행][열]`이었다면, 실제 데이터는 대부분 **행은 리스트, 열은 딕셔너리**인 이 모양으로 온다. 스프링 쪽에서 `List<BoardDto>`를 JSON으로 내주면 파이썬에서 받는 것이 정확히 이 구조다. 대괄호를 왼쪽부터 차례로 적용한다는 규칙은 그대로이고, 바깥은 숫자 인덱스·안쪽은 문자열 키라는 점만 다르다. 판다스의 `DataFrame`이 이 리스트를 통째로 받아 표로 만들어 준다.

### 2-3. `setdefault`·`update`·`pop` — 자주 쓰는 변경 메소드

```python
dict_a.setdefault('price', 0)         # 없으면 넣고, 있으면 그대로 두고 값을 돌려준다
dict_a.update({ 'price': 6000, 'rating': 8.5 })   # 여러 쌍을 한 번에 추가·수정
price = dict_a.pop('price')           # 지우면서 값 받기 (없으면 KeyError, pop('price', None) 으로 피한다)
```

`update`는 다른 딕셔너리의 쌍을 통째로 덮어쓰는 것이라 1-3·1-4의 대입을 여러 번 한 것과 같다. 이 폴더의 Python 코드 해석 문제(이관) 노트에서 본 dict 병합이 이 `update`와 `{**a, **b}` 이야기다. 셀레니움 크롤러에서 수집한 레코드를 합칠 때도 결국 이 메소드들이다.

### 2-4. 값으로 횟수 세기 — 딕셔너리의 단골 패턴

```python
words = ['a', 'b', 'a', 'c', 'a']
count = {}
for w in words:
    count[w] = count.get(w, 0) + 1    # 없으면 0 에서, 있으면 기존 값에서 1 더하기
print(count)                          # {'a': 3, 'b': 1, 'c': 1}
```

1-7의 `get(key, 기본값)`과 1-3·1-4의 "대입 하나로 추가·수정"이 합쳐진 모양이다. 대괄호로 `count[w] + 1`을 쓰면 첫 등장 때 `KeyError`가 나므로 `get`에 기본값 `0`을 주는 것이 핵심이다. 이런 집계는 자바에서 `map.merge(w, 1, Integer::sum)`으로 쓰던 일인데, 파이썬에서는 `collections.Counter(words)` 한 줄로도 된다.

## 3. 더 나아가 알면 좋은 것

### 3-1. 왜 키로 찾는 것이 빠른가 — 해시

리스트에서 `52 in list_a`는 앞에서부터 하나씩 비교하므로 요소가 백만 개면 최악의 경우 백만 번 본다. 딕셔너리의 `'name' in dict_a`는 키를 **해시 함수**에 넣어 저장 위치를 바로 계산하기 때문에 크기와 상관없이 거의 한 번에 찾는다. 1-1에서 "키는 바꿀 수 없는 값이어야 한다"고 적은 이유가 이것이다 — 키가 바뀌면 계산된 위치도 바뀌어 다시 못 찾게 되므로, 파이썬은 리스트처럼 바뀌는 값을 키로 받지 않는다. 자바 `HashMap`과 같은 원리고, 자바에서 `hashCode`·`equals`를 함께 재정의하라는 규칙도 같은 사정에서 나온다.

### 3-2. 딕셔너리 컴프리헨션과 `zip`

```python
names  = ['name', 'type', 'price']
values = ['컨저링', '호러 무비', 4000]
movie = { k: v for k, v in zip(names, values) }     # 두 리스트를 키·값으로 묶어 딕셔너리 만들기
prices = { m['name']: m['price'] for m in movies }  # 리스트 안의 딕셔너리에서 필요한 열만 뽑기
```

리스트 컴프리헨션의 중괄호 버전이다. 두 리스트를 짝지어 딕셔너리를 만들거나, 2-2의 레코드 목록에서 두 열만 골라 "이름 → 가격" 표를 만드는 데 쓴다. `zip`은 같은 자리의 요소를 튜플로 묶어 주는 함수라 `items()`의 역방향쯤으로 기억해 두면 된다.

### 3-3. 집합(set)과 JSON

중괄호를 쓰되 `값: 값` 없이 값만 늘어놓으면(`{1, 2, 3}`) 딕셔너리가 아니라 **집합**이다. 중복이 자동으로 제거되고 `in`이 딕셔너리처럼 빠르며, 합집합·교집합 연산이 된다 — 딕셔너리에서 값을 떼고 키만 남긴 것이라고 보면 된다. 빈 중괄호 `{}`는 집합이 아니라 빈 딕셔너리이니 빈 집합은 `set()`으로 만든다. 그리고 1-1 주석에 적힌 "JS: JSON"은 `json` 모듈로 실제 왕복이 된다 — `json.dumps(dict_a)`가 딕셔너리를 JSON 문자열로, `json.loads(문자열)`이 JSON을 딕셔너리로 바꿔 준다. 스프링 서버의 응답을 `requests`로 받으면 `.json()` 한 번에 2-2의 모양이 손에 들어온다.
