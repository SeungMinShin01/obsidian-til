## 1. 배운 내용

### 1-1. 가장 기본적인 함수 — `def`로 정의하고 이름으로 호출

```python
# def 함수명( 매개변수명 ) :
#   실행문

def print_3_time():
    print("안녕하세요")
    print("안녕하세요")
    print("안녕하세요")

print_3_time()      # 함수 사용/호출
```

| 항목 | 설명 |
| --- | --- |
| `def` | "함수를 정의한다"는 키워드. day01에서 `keyword.kwlist`로 본 예약어 목록에 들어 있다 |
| `print_3_time` | 함수 이름(식별자). 변수 이름과 같은 규칙으로 짓는다 |
| `()` | 매개변수 자리. 받을 값이 없어도 괄호는 꼭 쓴다 |
| `:` + 들여쓰기 | `if`·`for`·`while`과 같은 블록 규칙. 들여쓴 줄까지가 함수의 몸체다 |
| `print_3_time()` | 호출. 이름 뒤에 괄호를 붙여야 실행된다. 괄호가 없으면 함수 객체를 가리킬 뿐 실행되지 않는다 |

`def` 줄부터 들여쓴 몸체까지는 **정의**일 뿐 실행되지 않는다. 파이썬이 그 줄을 읽으면 "이 이름에 이 코드 덩어리를 매어 둔다"는 일만 하고, 실제로 `안녕하세요`가 찍히는 건 아래에서 `print_3_time()`을 만났을 때다. 그래서 정의가 호출보다 **먼저** 나와야 한다 — 자바는 클래스 안에 메소드를 어디에 적든 상관없지만, 파이썬 스크립트는 위에서 아래로 읽으면서 이름을 등록하므로 정의 전에 부르면 `NameError`가 난다.

### 1-2. 반복문과의 차이 — 같은 결과, 다른 재사용

```python
for i in range(0, 3, 1):
    print("안녕하세요")
```

| | `for`로 세 번 | 함수로 세 번 |
| --- | --- | --- |
| 출력 | 같다 | 같다 |
| 재사용 | 그 자리에서만 돈다. 다른 곳에서 또 찍으려면 `for`를 다시 쓴다 | 이름이 있어서 어디서든 `print_3_time()` 한 줄로 부른다 |
| 바꿀 때 | 복사해 둔 `for`를 전부 찾아 고친다 | 정의 한 곳만 고치면 호출한 모든 곳에 반영된다 |

결과만 보면 `for i in range(3)`과 `print_3_time()`은 똑같이 세 줄을 찍는다. 차이는 **식별자가 있느냐**다. 반복문은 패턴을 그 자리에서 펼치는 도구이고, 함수는 패턴에 이름을 주어 떼어 두는 도구라서 둘은 경쟁 관계가 아니라 겹쳐 쓰는 관계다 — 실제로 바로 다음 함수는 몸체 안에 `for`를 품는다.

### 1-3. 매개변수 — 호출할 때 값을 넘겨 받는 자리

```python
def print_n_times(value, n):
    for i in range(n):
        print(value)

print_n_times("안녕하세요", 5)      # 5번
print_n_times("안녕하세요", 3)      # 3번
# print_n_times("안녕하세요")      # 매개변수는 약속이라 어기면 실행되지 않는다
```

| 용어 | 어디에 | 예 |
| --- | --- | --- |
| **매개변수**(parameter) | 정의 쪽 괄호 안 — 받을 값의 이름 | `value`, `n` |
| **인수·인자값**(argument) | 호출 쪽 괄호 안 — 실제로 넘기는 값 | `"안녕하세요"`, `5` |

`print_3_time`은 늘 같은 말을 같은 횟수로만 찍지만, `print_n_times`는 **무엇을 몇 번** 찍을지를 호출하는 쪽이 정한다. 호출 `print_n_times("안녕하세요", 5)`가 실행되면 `"안녕하세요"`가 `value`에, `5`가 `n`에 **순서대로** 들어가고, 몸체의 `for i in range(n)`은 `range(5)`가 되어 다섯 번 돈다. "매개(媒介)"라는 말 그대로 호출하는 쪽과 함수 몸체 사이를 이어 주는 변수다. 이름이 두 가지인 것이 처음에는 헷갈리는데, **정의할 때 쓴 이름이 매개변수, 부를 때 넣은 값이 인수**라고 자리로 기억하면 된다.

매개변수는 **약속**이다. 두 개를 받기로 정의했으면 두 개를 넘겨야 하고, 하나만 넘기면 `TypeError: print_n_times() missing 1 required positional argument: 'n'`으로 멈춘다. 파이썬은 자료형을 검사하지 않지만 **개수는 검사한다**는 뜻이다. 자바 메소드에서 인자 개수가 다르면 컴파일이 안 되던 것과 같은 규칙이 실행 시점에 적용된다.

### 1-4. 가변 매개변수 — 몇 개가 올지 모를 때 `*`

```python
# def 함수명( 매개변수, 매개변수, *가변매개변수 ) :
def print_n_times2(n, *values):
    for i in range(n):
        for value in values:
            print(value)
        print()

print_n_times2(3, "안녕하세요", "즐거운", "파이썬")
print_n_times2(2, "안녕하세요", "즐거운")
```

```
안녕하세요
즐거운
파이썬

안녕하세요
즐거운
파이썬

안녕하세요
즐거운
파이썬

안녕하세요
즐거운

안녕하세요
즐거운

```

| 호출 | `n` | `values` |
| --- | --- | --- |
| `print_n_times2(3, "안녕하세요", "즐거운", "파이썬")` | `3` | `('안녕하세요', '즐거운', '파이썬')` |
| `print_n_times2(2, "안녕하세요", "즐거운")` | `2` | `('안녕하세요', '즐거운')` |

찍을 말이 세 개일 수도, 두 개일 수도 있다면 매개변수를 `value1, value2, value3`처럼 고정할 수 없다. 이럴 때 이름 앞에 `*`를 붙여 **가변 매개변수**로 선언하면, 호출 시 그 자리부터 넘어온 값이 **전부 하나의 튜플로 묶여** `values`에 들어간다. 첫 인수 `3`은 앞의 일반 매개변수 `n`이 받고, 나머지가 `values`로 간다. 몸체에서는 `values`가 튜플이므로 리스트처럼 `for value in values`로 돌면 되고, 바깥 `for`가 `n`번 감싸서 "묶음 전체를 `n`번 찍고 매 묶음 뒤에 빈 줄"이 된다. 두 번째 호출은 묶음이 두 개이고 횟수가 2라 출력이 짧아진다.

가변 매개변수는 **일반 매개변수 뒤에, 하나만** 둔다. `*values`가 "남는 건 전부 내가 받는다"는 뜻이라 앞에 두면 뒤의 매개변수가 아무것도 못 받기 때문이다(뒤에 두면 1-7처럼 이름으로만 받게 된다). 자바의 `String... values` 가변 인자와 같은 개념이고, 자바가 배열로 받는 자리에 파이썬은 튜플로 받는다. `print()`가 `print("a", "b", "c")`처럼 몇 개를 넣어도 받아 주는 것이 바로 이 문법으로 만들어진 함수이기 때문이다.

### 1-5. 기본 매개변수 — 인수를 생략하면 대신 쓰는 값

```python
# 기본 매개변수: 매개변수에 기본값을 대입해 두는 형태. 인수를 생략하면 그 값이 적용된다
def print_n_times3(value, n=2):
    for i in range(n):
        print(value)

print_n_times3("안녕하세요")        # 2번 — n을 안 넘겼으니 기본값 2
print_n_times3("안녕하세요", 3)     # 3번 — 넘기면 넘긴 값
```

| 호출 | `value` | `n` |
| --- | --- | --- |
| `print_n_times3("안녕하세요")` | `"안녕하세요"` | `2` (기본값) |
| `print_n_times3("안녕하세요", 3)` | `"안녕하세요"` | `3` |

1-3에서는 인수를 하나만 넘기면 약속을 어긴 것이라 `TypeError`가 났다. 정의 쪽에 `n=2`처럼 **기본값을 미리 대입**해 두면 그 약속이 느슨해져서, 호출할 때 그 자리를 비워도 기본값으로 채워진다. 넘기면 넘긴 값이 이기고 안 넘기면 기본값이 쓰이므로, "대부분은 2번이지만 가끔 다르게"처럼 **자주 쓰는 값은 정의에 적어 두고 예외만 호출에서 바꾸는** 용도다. 매개변수 자리는 그대로 있고 `=`로 값만 뒤에 붙는 모양이라, 정의 괄호 안에 `=`가 보이면 기본 매개변수라고 읽으면 된다. 기본 매개변수는 일반 매개변수 **뒤에** 둔다 — 앞에서부터 순서대로 채우기 때문에 생략 가능한 것이 앞에 있으면 무엇을 건너뛴 것인지 알 수 없어서다.

### 1-6. 기본 매개변수와 가변 매개변수의 순서

```python
# 기본 매개변수가 가변 매개변수보다 앞에 오면  → 쓰지 않는 조합
# 가변 매개변수가 기본 매개변수보다 앞에 오면  → 기본 매개변수는 위치 인수로 값을 받지 못한다
```

| 순서 | 무슨 일이 생기나 |
| --- | --- |
| 기본 → 가변 (`def f(n=2, *values)`) | 첫 위치 인수가 늘 `n` 자리를 차지해 기본값이 쓰일 일이 없다. 뜻이 어긋나는 조합이라 쓰지 않는다 |
| 가변 → 기본 (`def f(*values, n=2)`) | `*values`가 위치 인수를 전부 삼키므로 `n`에는 위치로 닿을 수 없다. 넘기려면 `n=3`처럼 **이름을 지정**해야 하고, 지정하지 않으면 기본값이다 |

1-4에서 "가변 매개변수는 뒤에, 하나만"이라고 정리했는데, 기본 매개변수가 섞이면 둘의 순서가 새 문제가 된다. 핵심은 `*values`가 **남는 위치 인수를 전부 가져간다**는 성질 하나다. 그 앞에 둔 매개변수는 위치로 채워지고, 그 뒤에 둔 매개변수는 위치로는 영영 채워지지 않는다. 그래서 가변 뒤의 매개변수에는 기본값을 주고 이름으로 넘기는 방식이 짝이 된다 — 바로 다음 1-7의 모양이다.

### 1-7. 키워드 매개변수 — 이름을 지정해서 넘기기, `print`의 `end`

```python
print("안녕하세요")              # 안녕하세요 — 끝에 줄바꿈
print("안녕하세요", end="\n")    # 위와 같다. end의 기본값이 "\n"이기 때문
print("안녕하세요", end="")      # 줄바꿈 없이 끝난다

# 가변 매개변수 뒤의 기본 매개변수 — 값은 이름으로만 넘긴다
def print_n_times4(*values, n=2):
    # *매개변수 → 가변 매개변수 / 매개변수명=기본값 → 기본 매개변수
    for i in range(n):
        for value in values:
            print(value)
        print()

print_n_times4("안녕하세요", "즐거운", "파이썬", n=3)   # 묶음을 3번
print_n_times4("안녕하세요", "즐거운", 3)             # 3도 values에 들어간다 → 묶음을 2번
```

| 호출 | `values` | `n` |
| --- | --- | --- |
| `print_n_times4("안녕하세요", "즐거운", "파이썬", n=3)` | `('안녕하세요', '즐거운', '파이썬')` | `3` |
| `print_n_times4("안녕하세요", "즐거운", 3)` | `('안녕하세요', '즐거운', 3)` | `2` (기본값) |

**키워드 매개변수**는 호출할 때 `n=3`처럼 **매개변수 이름을 지정해서** 값을 넘기는 방식이다. 지금까지 아무 생각 없이 쓰던 `print()`가 이미 그 예다. `print("안녕하세요")`가 끝에 줄을 바꾸는 것은 `end`라는 기본 매개변수의 기본값이 `"\n"`이어서이고, `end=""`로 지정하면 줄을 바꾸지 않는다. `print`는 `*values`로 찍을 값을 몇 개든 받고 `end`·`sep`를 기본 매개변수로 뒤에 둔 함수라서, `print_n_times4`는 그 구조를 손으로 흉내 낸 셈이다.

두 번째 호출이 함정이다. `3`을 횟수로 넘길 생각이었어도 이름 없이 넘기면 위치 인수이고, 위치 인수는 `*values`가 전부 가져가므로 `3`은 찍을 값이 되고 `n`은 기본값 2로 남는다. 가변 매개변수 뒤의 값은 **반드시 이름을 붙여** 넘긴다고 정리해 둔다. 반대로 1-4의 `print_n_times2(n, *values)`처럼 횟수를 앞에 두면 위치만으로 부를 수 있다 — 어느 쪽에 둘지는 "호출할 때 이름을 쓰게 할 것인가"로 정한다.

### 1-8. `return` — 함수를 끝내며 값을 돌려주기

```python
# 리턴이란? 함수가 종료되면서 반환되는 값
x = 3
y = 2
z = x + y               # 5 — 식을 그 자리에서 계산

def myFunc(x, y):
    return x + y        # 식에 이름을 붙이고, 결과를 돌려준다
z = myFunc(x, y)        # 5

# 자료 없는 리턴 — 자바의 void처럼 함수를 끝내기만 한다
def return_test():
    print("A 위치 입니다.")
    return                      # 리턴 = 함수 종료 = 함수 끝
    print("B 위치 입니다.")      # 실행되지 않는다
return_test()                   # A 위치 입니다.

# 자료와 함께 리턴
def return_test2():
    return 100
value = return_test2()
print(value)                    # 100
print(return_test())            # A 위치 입니다. / None — 값 없는 return은 None을 돌려준다
```

| 모양 | 하는 일 | 호출 식의 값 |
| --- | --- | --- |
| `return 값` | 함수를 끝내고 값을 돌려준다 | 그 값 |
| `return` | 함수를 끝내기만 한다 | `None` |
| `return` 없음 | 몸체가 끝까지 돌고 끝난다 | `None` |

수업 머리에 적힌 "리턴값 = 함수를 호출해서 최종적으로 나오는 결과"가 이것이다. `z = x + y`처럼 식을 직접 적는 것과 `myFunc`의 차이는 **공식에 이름을 붙여 두었느냐**다. 한 번 정의해 두면 `myFunc(10, 20)`처럼 다른 값으로도 같은 공식을 돌릴 수 있다. `return`은 두 가지 일을 **동시에** 한다 — 함수를 그 자리에서 끝내는 것과 값을 호출한 쪽으로 돌려보내는 것. `return_test`에서 B 위치가 찍히지 않는 것이 "끝내기" 쪽이고, `return_test2`의 100이 `value`에 담기는 것이 "돌려주기" 쪽이다. 값 없이 `return`만 쓰면 자바의 `void` 메소드에서 `return;`을 쓰는 것과 같고, 호출 식의 값은 `None`이 된다. 지금까지 만든 `print_n_times` 계열은 전부 화면에 찍기만 하고 돌려주는 값이 없어서 호출 식 자체는 `None`이다 — 리스트 노트에서 `append`가 원본만 바꾸고 `None`을 돌려주던 것과 같은 성질이다.

### 1-9. 예제 — 범위의 합 `sum_all`로 기본값·키워드 인수 써 보기

```python
# 예제 1 — 시작과 끝을 받아 그 사이의 정수를 모두 더한다
def sum_all(start, end):
    output = 0
    for i in range(start, end + 1):
        output += i
    return output

print("0 to 100:", sum_all(0, 100))        # 0 to 100: 5050
print("50 to 100:", sum_all(50, 100))      # 50 to 100: 3825
print("500 to 1000:", sum_all(500, 1000))  # 500 to 1000: 375750

# 예제 2 — 세 매개변수 모두 기본값을 주고, 필요한 것만 이름으로 바꾼다
def sum_all(start=0, end=100, step=1):
    output = 0
    for i in range(start, end + 1, step):
        output += i
    return output

print("A.", sum_all(0, 100, 10))       # A. 550   — 0, 10, …, 100
print("B.", sum_all(end=100))          # B. 5050  — start·step은 기본값
print("C.", sum_all(end=100, step=2))  # C. 2550  — 0, 2, …, 100
```

| 호출 | `start` | `end` | `step` | 결과 |
| --- | --- | --- | --- | --- |
| `sum_all(0, 100, 10)` | `0` | `100` | `10` | `550` |
| `sum_all(end=100)` | `0` (기본) | `100` | `1` (기본) | `5050` |
| `sum_all(end=100, step=2)` | `0` (기본) | `100` | `2` | `2550` |

예제 1은 지금까지의 조각을 한 함수에 모은 것이다. `range(start, end + 1)`의 `+ 1`은 `range`가 끝 값을 포함하지 않기 때문이고(range 노트), `output`에 더해 나가는 모양은 연습문제에서 쓰던 누적 변수 패턴이며, 결과를 `print`하지 않고 `return`으로 돌려주므로 호출한 쪽에서 `print("0 to 100:", sum_all(0, 100))`처럼 문자열 옆에 바로 넣을 수 있다.

예제 2는 같은 이름 `sum_all`을 **다시 정의**한다. 함수도 이름에 매인 값이라 나중 `def`가 앞의 것을 덮어쓴다 — 그래서 아래의 A·B·C는 전부 세 매개변수짜리 새 버전으로 돈다. 세 매개변수 모두 기본값이 있으니 `sum_all()`만 써도 0부터 100까지의 합이 나오고, 바꾸고 싶은 것만 고른다. B의 `sum_all(end=100)`은 `start`를 건너뛰고 `end`만 넘기는데, 위치 인수로는 첫 자리가 무조건 `start`라 이렇게 중간만 고를 수 없다. **앞의 것은 기본값으로 두고 뒤의 것만 바꾸려면 키워드 인수가 필요하다**는 것이 이 예제의 요지다. C의 `step=2`는 `range`의 세 번째 인수로 그대로 흘러가 짝수만 더한다.

## 2. 추가로 알면 좋은 활용법

### 2-1. 여러 값을 한 번에 돌려주기 — `return a, b`

```python
def min_max(numbers):
    return min(numbers), max(numbers)   # 튜플 하나로 묶여 돌아간다

low, high = min_max([3, 1, 7])          # low = 1, high = 7
```

`return` 뒤에 쉼표로 여러 값을 나열하면 튜플 하나로 묶여 돌아가고, 받는 쪽에서 변수 여러 개로 풀어 받는다. 연습문제의 "합이 100인 두 수의 최대 곱"에서 최대 곱과 두 수를 함께 돌려주려면 이 모양이다. 자바는 반환값이 하나뿐이라 값 두 개를 돌려주려면 DTO 클래스를 만들어야 했는데, 파이썬은 튜플이 그 자리를 대신한다.

### 2-2. 조건이 안 맞으면 먼저 `return` — 이른 반환

```python
def sum_all(start=0, end=100, step=1):
    if step <= 0:
        return None          # 잘못된 입력이면 더 가지 않는다
    output = 0
    for i in range(start, end + 1, step):
        output += i
    return output
```

1-8의 "`return`은 함수를 그 자리에서 끝낸다"는 성질을 쓰는 관용구다. 처리할 수 없는 입력을 앞에서 걸러 내고 돌려보내면, 본문을 `if`로 겹겹이 감싸지 않아도 된다. `return`이 여러 개 있어도 실제로 실행되는 것은 처음 만나는 하나뿐이다.

### 2-3. 기본값에 리스트·딕셔너리를 두지 않기

```python
def add_item(item, items=[]):    # 기본값 리스트는 한 번만 만들어져 호출마다 공유된다
    items.append(item)
    return items

add_item(1)      # [1]
add_item(2)      # [1, 2] — 새 리스트가 아니다

def add_item(item, items=None):  # 안전한 모양
    if items is None:
        items = []
    items.append(item)
    return items
```

기본값은 `def` 줄을 읽을 때 **한 번만** 만들어지고, 이후 호출은 같은 객체를 돌려 쓴다. 숫자·문자열·`None`처럼 바뀌지 않는 값은 상관없지만, 리스트 노트에서 본 "`append`는 원본을 바꾼다"는 성질과 만나면 앞 호출의 흔적이 다음 호출에 남는다. 그래서 바뀔 수 있는 값은 기본값을 `None`으로 두고 몸체에서 새로 만드는 것이 관용구다.

### 2-4. 튜플을 풀어서 넘기기 — 호출 쪽의 `*`

```python
words = ["안녕하세요", "즐거운", "파이썬"]
print_n_times2(2, *words)       # print_n_times2(2, "안녕하세요", "즐거운", "파이썬")과 같다
```

정의 쪽 `*values`가 "여러 개를 하나로 묶기"라면, 호출 쪽 `*words`는 반대로 "하나를 여러 개로 풀기"다. 리스트를 가변 매개변수 함수에 넘길 때 요소를 하나씩 적지 않아도 된다. 같은 기호가 자리에 따라 묶고 푸는 양방향으로 쓰이는 것인데, 둘을 나란히 두면 `*`의 뜻이 "여러 값과 하나의 묶음 사이를 오간다"로 정리된다.

### 2-5. 함수 머리에 설명 달기 — 독스트링

```python
def print_n_times(value, n):
    """value를 n번 출력한다."""
    for i in range(n):
        print(value)

help(print_n_times)     # 설명이 찍힌다
```

몸체 첫 줄에 따옴표 세 개로 적은 문자열은 함수의 설명(docstring)으로 저장되어 `help()`나 편집기 툴팁에 나온다. day01에서 본 "따옴표 세 종류" 중 세 겹 따옴표가 여러 줄 문자열 외에 이렇게도 쓰인다. 주석(`#`)은 코드를 읽는 사람만 보지만 독스트링은 프로그램이 들고 다니는 정보라, 남이 쓸 함수에는 한 줄이라도 적어 두는 편이 안전하다.

## 3. 더 나아가 알면 좋은 것

### 3-1. 키워드 가변 매개변수 `**kwargs`

```python
def show(**options):
    for key, value in options.items():
        print(key, value)

show(color="red", size=3)   # color red / size 3
```

`*values`가 위치 인수를 튜플로 모은다면, `**options`는 `이름=값` 인수를 **딕셔너리**로 모은다. 딕셔너리 노트의 `items()`로 풀어 받는 모양이 그대로 쓰인다. 라이브러리 함수가 `def f(*args, **kwargs)`로 선언되어 있으면 "무엇이든 받아서 다른 함수에 그대로 넘긴다"는 뜻이라, 뒤에 판다스·웹 프레임워크 코드를 읽을 때 이 서명이 자주 보인다.

### 3-2. 변수가 보이는 범위 — 지역과 전역

```python
count = 0
def increase():
    global count    # 이 줄이 없으면 함수 안의 count는 새 지역 변수다
    count += 1
```

함수 안에서 만든 변수(매개변수 포함)는 함수가 끝나면 사라지는 **지역 변수**이고, 바깥에서 만든 변수는 **전역 변수**다. 함수 안에서 전역 변수를 읽는 건 되지만 **대입**하면 같은 이름의 지역 변수가 새로 생기므로, 바깥 값을 바꾸려면 `global` 선언이 필요하다. 1-4의 `for value in values`에서 `value`가 함수 밖의 변수와 이름이 겹쳐도 서로 간섭하지 않는 이유가 이것이다. 다만 `global`에 기대기보다 `return`으로 결과를 돌려주고 바깥에서 받는 쪽이 함수를 독립적으로 유지하는 길이다.

### 3-3. 자바 메소드와 견주기

| | 자바 메소드 | 파이썬 함수 |
| --- | --- | --- |
| 정의 | `static void f(String v, int n)` — 반환형·자료형 명시 | `def f(v, n):` — 자료형 없음 |
| 인자 개수 | 컴파일 때 검사 | 실행 때 검사 (`TypeError`) |
| 같은 이름 여러 버전 | 오버로딩 | 없음 — 기본값·가변 매개변수로 대신한다 |
| 가변 인자 | `String... v` (배열) | `*v` (튜플) |
| 소속 | 반드시 클래스 안 | 클래스 밖에 단독으로 둘 수 있다 |
| 기본값 | 없음 (오버로딩으로 흉내) | `n=2` |

자바에서 `f(String)`·`f(String, int)` 두 버전을 오버로딩으로 두던 일을, 파이썬은 `def f(v, n=2)` 하나로 해결한다. 반대로 자료형이 없으므로 "문자열을 넣어야 하는 자리에 숫자를 넣었다"는 실수는 호출 시점이 아니라 몸체가 돌다가 드러난다. 그래서 `def f(v: str, n: int = 2) -> None:`처럼 **타입 힌트**를 적어 편집기가 미리 잡게 하는 관행이 있다.

### 3-4. 함수도 값이다 — 람다와 `key=`

연습문제 노트에서 `max(pairs, key=lambda p: p[0] * p[1])`로 기준 함수를 넘긴 적이 있다. 파이썬에서 함수는 변수에 담고 인수로 넘길 수 있는 **값**이고, `lambda`는 이름 없이 한 줄짜리 함수를 그 자리에서 만드는 문법이다. `def`로 만든 함수와 본질은 같아서 `sorted(…, key=함수이름)`처럼 `def`로 만든 것도 넘길 수 있다. 이 성질이 뒤에 나올 `map`·`filter`·데코레이터·콜백의 바탕이다.

### 3-5. 다음에 볼 키워드

- 키워드 전용 인수 — 매개변수 목록 중간에 `*` 하나만 두어 그 뒤를 이름 전용으로 만들기 (`def f(value, *, n=2)`)
- 위치 전용 인수 `/`와 함수 서명 읽는 법 (`help(print)`에 나오는 `print(*args, sep=' ', end='\n', …)`)
- `*args`·`**kwargs` — 위치·키워드 가변 매개변수와 호출 쪽 언패킹
- 지역 변수·전역 변수·`global`·`nonlocal`
- 독스트링과 `help()`, 타입 힌트(`: str`, `-> int`)
- `lambda`·`map`·`filter`·`sorted(key=…)` — 함수를 값으로 넘기기
- 재귀 함수 — 자기 자신을 부르는 함수(딕셔너리 연습문제에서 미리 본 `show`)
- 모듈 — 함수를 파일로 묶어 `import`로 가져오기
