# Python day03 — 튜플 선언과 구조분해·스왑

> 실습 파일: `day03/C5-3.PY` (앞부분 — 튜플)
> 허브: [[Python 정리본 인덱스]] · 이전: [[Python day03 재귀 함수로 푸는 팩토리얼과 구구단]] · 다음: [[Python day03 콜백 함수와 map·filter·람다]]

day02 리스트 노트의 "더 나아가기"에서 이름만 적어 두었던 **튜플**을 정식으로 다룬다. 수업의 한 줄 정의는 *여러 자료를 저장하는, 리스트와 비슷한 자료형 — 단 초기화 이후 수정 불가능*. 대괄호 대신 소괄호를 쓰고, 한 번 만들면 요소를 바꿀 수 없다는 것이 리스트와의 전부다. 그런데 이 파일이 튜플을 함수 노트 사이에 끼워 넣은 이유는 자료형 하나를 더 배우기 위해서가 아니다. `a, b = 10, 20`처럼 **소괄호를 생략한 튜플이 여러 변수에 한 번에 값을 나눠 담는 문법**이 되고, 그 문법이 `a, b = b, a` 스왑과 리액트의 `const [count, setCount] = useState(0)` 구조분해로 이어지며, 마지막으로 **함수가 `return 10, 20`으로 값을 여러 개 돌려주는 것처럼 보이는 것도 사실은 튜플 하나**라는 데까지 닿기 때문이다. 가변 매개변수 `*values`가 튜플로 들어오던 것까지 포함하면, 함수 주변에서 "여러 값을 하나로 묶는" 일은 전부 튜플이 맡고 있다.

## 1. 배운 내용

### 1-1. 튜플 선언과 요소 호출 — 소괄호, 인덱스는 리스트와 같다

```python
# ( 요소, 요소, 요소 )
tuple_test = (10, 20, 30)
print(tuple_test[0], tuple_test[2])    # 10 30
```

| 항목 | 리스트 | 튜플 |
| --- | --- | --- |
| 선언 | `[10, 20, 30]` | `(10, 20, 30)` |
| 요소 읽기 | `[0]`·`[-1]`·슬라이싱 | 같다 |
| `for`로 돌기·`len`·`in` | 된다 | 된다 |
| 요소 수정·추가·삭제 | `[0] = 40`·`append`·`del` | **안 된다** |

읽는 쪽은 리스트와 완전히 같다. 인덱싱·슬라이싱·`len`·`in`·`for` 전부 그대로 쓰면 된다. day02 이터레이터 노트에서 `for`에 쓸 수 있는 자료 목록에 튜플이 들어 있던 것이 이것이다. 차이는 오직 **쓰는 쪽**에 있다.

### 1-2. 수정 불가 — 튜플은 만든 뒤 바꿀 수 없다

```python
# tuple_test[0] = 40   # TypeError: 'tuple' object does not support item assignment
```

리스트 노트에서 "문자열은 불변, 리스트는 가변"으로 정리했는데, 튜플은 **불변 쪽**이다. 요소를 대입하면 `TypeError`가 나고, `append`·`remove` 같은 메소드 자체가 없다. 처음엔 "바꿀 수 없는 리스트가 왜 필요한가" 싶은데, 바꿀 수 없다는 것이 곧 장점이 되는 자리가 있다. 좌표 `(x, y)`, 날짜 `(년, 월, 일)`, DB 한 행처럼 **묶음 자체가 하나의 값**이고 중간에 요소가 바뀌면 안 되는 자료, 그리고 바뀌지 않기 때문에 딕셔너리의 **키로 쓸 수 있다**는 점이다(리스트는 키가 될 수 없다). 함수가 돌려주는 여러 값도 받는 쪽이 고칠 일이 없으니 튜플이 어울린다.

### 1-3. 요소가 하나인 튜플 — 쉼표가 튜플을 만든다

```python
tuple_test2 = (273)
print(tuple_test2)          # 273
```

| 식 | 자료형 | 이유 |
| --- | --- | --- |
| `(273)` | `int` | 소괄호는 연산 우선순위용 괄호로 읽힌다 — `(1 + 2)`의 괄호와 같다 |
| `(273,)` | `tuple` | 뒤의 **쉼표**가 튜플임을 알린다 |
| `273,` | `tuple` | 소괄호 없이 쉼표만 있어도 튜플이다 |

튜플을 만드는 것은 소괄호가 아니라 **쉼표**다. 요소가 둘 이상이면 쉼표가 자연히 들어가서 신경 쓸 일이 없지만, 하나짜리는 쉼표를 붙여야 튜플이 된다. `type()`으로 찍어 보면 바로 확인된다. 이 성질을 알아야 다음 절의 "소괄호 생략"이 이해된다 — 괄호는 보조일 뿐이고, 쉼표로 나열된 값들이 튜플이다.

### 1-4. 소괄호 생략과 구조분해 — 여러 변수에 한 번에 나눠 담기

```python
(a, b) = (10, 20)
print(a, b)         # 10 20

a, b = 10, 20       # 소괄호를 양쪽 다 생략해도 같다
print(a, b)         # 10 20

c, d = [30, 40]     # 오른쪽이 리스트여도 된다
print(c, d)         # 30 40
```

| 왼쪽 | 오른쪽 | 일어나는 일 |
| --- | --- | --- |
| `a, b` (변수 묶음) | `10, 20` (튜플) | 오른쪽 요소가 **자리 순서대로** 왼쪽 변수에 하나씩 들어간다 |
| `c, d` | `[30, 40]` (리스트) | 리스트도 순서가 있으니 같은 방식으로 풀린다 |
| `a, b` | 요소 3개 | `ValueError: too many values to unpack` — 개수가 맞아야 한다 |

`a, b = 10, 20`은 사실 두 단계다. 오른쪽 `10, 20`이 먼저 **튜플 하나로 묶이고**, 그 튜플이 왼쪽 변수 개수만큼 **풀려서** 들어간다. 이렇게 묶음을 변수 여러 개로 푸는 것을 언패킹(구조분해)이라 한다. 이미 여러 번 만났다 — `for index, value in enumerate(…)`와 `for key, value in d.items()`에서 `(인덱스, 값)`·`(키, 값)` 튜플을 변수 두 개로 받던 것이 바로 이 문법이다. 왼쪽이 변수 묶음이고 오른쪽이 순서 있는 자료이기만 하면 리스트든 튜플이든 풀린다.

### 1-5. 스왑 — 임시 변수 없이 두 값 바꾸기

```python
a, b = b, a         # a에 b 값 대입, b에 a 값 대입
```

| 언어 | 두 변수 값 바꾸기 |
| --- | --- |
| 자바 | `int tmp = a; a = b; b = tmp;` — 임시 변수 세 줄 |
| 파이썬 | `a, b = b, a` — 한 줄 |

1-4의 두 단계를 알면 왜 되는지 보인다. 오른쪽 `b, a`가 **먼저** 현재 값으로 튜플 `(20, 10)`이 되고, 그다음에 왼쪽 `a, b`에 풀려 들어간다. 오른쪽이 전부 계산된 뒤에 대입이 일어나므로, 중간에 `a`가 덮어써져 값을 잃는 일이 없다. 자바에서 `tmp`를 두던 이유가 "대입하는 순간 원래 값이 사라지기 때문"이었는데, 파이썬은 오른쪽을 튜플로 먼저 굳혀 두므로 그 문제가 생기지 않는다. 정렬 알고리즘에서 요소를 맞바꿀 때 `nums[i], nums[j] = nums[j], nums[i]`로 그대로 쓰인다.

### 1-6. 리액트의 구조분해와 같은 발상

```python
# JS에서 비슷한 문법 → 구조분해 (useState, props)
# const [count, setCount] = useState(0)
# const { name, age } = props
```

| | 파이썬 | JS / 리액트 |
| --- | --- | --- |
| 순서로 풀기 | `a, b = [10, 20]` | `const [a, b] = [10, 20]` — `useState`가 돌려주는 `[값, 설정함수]`를 받는 모양 |
| 이름으로 풀기 | 없음 — 딕셔너리는 `d["name"]`으로 꺼낸다 | `const { name, age } = props` |

수업 주석에 적힌 대로 리액트 수업에서 매일 쓰던 `const [count, setCount] = useState(0)`이 같은 생각이다. 함수가 배열 하나를 돌려주고, 받는 쪽이 자리 순서대로 변수 두 개에 나눠 담는다. 파이썬은 순서 기반 언패킹만 있고, JS처럼 객체의 **이름**으로 꺼내는 `{ name, age } = …`는 없다. 파이썬에서 딕셔너리를 `name, age = {"name": "유재석", "age": 10}`처럼 풀면 값이 아니라 **키**가 순서대로 들어온다(딕셔너리를 `for`로 돌리면 키가 나오던 것과 같은 이유). 딕셔너리 값을 변수로 받으려면 `name, age = d["name"], d["age"]`처럼 적거나 `d.values()`를 푼다.

### 1-7. 함수의 결과는 항상 하나 — `return 10, 20`은 튜플 하나

```python
def test():
    # return (10, 20)
    return 10, 20       # 결과는 1개 — 10과 20을 묶은 튜플 1개

result = test()         # (10, 20)
x, y = test()           # x = 10, y = 20
```

| 받는 모양 | 결과 |
| --- | --- |
| `result = test()` | `result`는 튜플 `(10, 20)` 하나 |
| `x, y = test()` | 튜플이 풀려서 `x = 10`, `y = 20` |

함수 노트 2-1에서 "여러 값을 돌려주려면 `return a, b`"라고 적어 두었는데, 정확히는 **여러 값을 돌려주는 것이 아니라 튜플 하나를 돌려주는 것**이다. 수업 주석의 "함수/연산 결과는 항상 1개"가 그 뜻이다. `return 10, 20`과 `return (10, 20)`은 1-4에서 본 소괄호 생략 때문에 완전히 같은 문장이고, 받는 쪽에서 `x, y = test()`로 풀어 받는 것은 구조분해다. 즉 "여러 값 반환"은 새 기능이 아니라 **튜플 + 언패킹 두 가지의 조합**이다. 자바는 반환값이 하나뿐이라 값 두 개를 돌려주려면 DTO 클래스를 만들었는데, 파이썬도 반환값은 하나뿐이지만 그 하나가 튜플일 수 있어 클래스 없이 끝난다. 가변 매개변수 `*values`가 **들어올 때** 튜플로 묶이던 것과 짝을 이뤄, 함수의 입구와 출구 양쪽에서 튜플이 "여러 값을 하나로" 묶는 역할을 한다.

## 2. 추가로 알면 좋은 활용법

### 2-1. 나머지를 한 번에 받기 — 언패킹의 `*`

```python
first, *rest = [1, 2, 3, 4]       # first = 1, rest = [2, 3, 4]
*init, last = [1, 2, 3, 4]        # init = [1, 2, 3], last = 4
head, *_, tail = "python"         # head = 'p', tail = 'n'
```

왼쪽 변수 개수와 오른쪽 요소 개수가 맞지 않으면 `ValueError`였다. 변수 하나에 `*`를 붙이면 그 변수가 **남는 요소를 전부 리스트로** 받아 개수가 안 맞아도 풀린다. 함수 정의의 `*values`가 남는 인수를 모으던 것과 같은 기호, 같은 뜻이다. 관심 없는 자리는 관례상 `_`로 받는다.

### 2-2. 튜플 → 리스트, 리스트 → 튜플

```python
t = (1, 2, 3)
lst = list(t)       # [1, 2, 3] — 고쳐야 하면 리스트로 바꿔서
lst.append(4)
t2 = tuple(lst)     # (1, 2, 3, 4) — 다시 굳히기
```

튜플은 못 고치지만 `list()`로 복사본을 만들어 고친 뒤 `tuple()`로 되돌릴 수는 있다. day02 이터레이터 노트의 `int()`·`str()`·`list()` 변환 함수 목록에 `tuple()`이 하나 더 추가되는 셈이다. 원본 튜플은 그대로이고 새 튜플이 만들어진다는 점이 "불변"의 뜻이다.

### 2-3. 튜플을 딕셔너리 키로 — 좌표·쌍을 키로 쓰기

```python
visited = {}
visited[(0, 0)] = True          # 리스트 [0, 0]은 키가 될 수 없다
distance = {("서울", "부산"): 325, ("서울", "대전"): 140}
```

딕셔너리 키는 바뀌지 않는 값이어야 해서 리스트는 안 되고 튜플은 된다. 격자 좌표, 출발-도착 쌍, (년, 월) 같은 복합 키가 필요할 때 튜플이 그 자리를 맡는다. 딕셔너리 노트에서 "키는 해시 가능한 값"이라고 적어 둔 조건을 튜플이 만족한다.

### 2-4. `zip`으로 두 리스트를 튜플 쌍으로 묶어 풀기

```python
keys = ["name", "hp", "mp"]
values = ["기사", 200, 30]
for key, value in zip(keys, values):      # ("name", "기사"), ("hp", 200), …
    print(key, value)
character = dict(zip(keys, values))
```

연습문제 노트에서 `range(4)`의 인덱스로 두 리스트를 같이 읽던 일을 `zip`은 튜플 쌍으로 묶어 준다. `for key, value in …`에서 받는 모양이 바로 1-4의 언패킹이고, `dict()`는 `(키, 값)` 튜플의 나열을 그대로 딕셔너리로 만든다.

## 3. 더 나아가 알면 좋은 것

### 3-1. 불변의 쓸모 — 왜 바꿀 수 없는 자료형이 따로 있나

튜플이 불변이라서 얻는 것은 **안전**과 **해시**다. 함수에 튜플을 넘기면 함수 안에서 요소가 바뀔 걱정이 없고(리스트는 `append` 한 번이면 바깥까지 바뀐다 — 함수 노트의 가변 기본값 함정이 그 예), 바뀌지 않으니 해시값을 미리 계산해 딕셔너리 키·집합 요소가 될 수 있다. 자바의 `String`이 불변인 이유, 리액트에서 상태를 직접 고치지 않고 새 배열을 만들어 `setState`에 넘기는 이유가 같은 줄기다 — **바뀌지 않는 값은 비교와 공유가 쉽다.** 다만 튜플 안에 리스트가 들어 있으면 그 리스트의 내용은 여전히 바뀔 수 있다(튜플이 보장하는 건 "어떤 객체를 가리키는가"뿐이다).

### 3-2. 이름 있는 튜플 — `namedtuple`과 `dataclass`

```python
from collections import namedtuple
Point = namedtuple("Point", ["x", "y"])
p = Point(3, 4)
p.x, p[0]           # 3, 3 — 이름으로도 자리로도 접근
```

`(3, 4)`만 보면 무엇이 x이고 y인지 코드에 드러나지 않는다. `namedtuple`은 각 자리에 이름을 붙인 튜플이라 `p.x`처럼 읽히면서도 여전히 불변이고 언패킹도 된다. 함수가 돌려주는 값이 셋 이상이 되면 튜플보다 이쪽이 읽기 좋고, 더 나아가면 `@dataclass`로 클래스를 만든다 — 자바의 DTO에 가까워지는 길이다.

### 3-3. 시퀀스라는 공통 분모

문자열·리스트·튜플·`range`는 전부 **순서가 있고 인덱스로 접근하는 자료형(시퀀스)**이라 인덱싱·슬라이싱·`len`·`in`·`for`·언패킹이 똑같이 동작한다. 그중 리스트만 가변이고 나머지는 불변이다. 자료형마다 문법을 따로 외우는 게 아니라 "시퀀스면 다 된다"로 묶어 두면, 뒤에 `bytes`나 넘파이 배열을 만나도 같은 눈으로 읽을 수 있다.
