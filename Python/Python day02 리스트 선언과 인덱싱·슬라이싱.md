# Python day02 — 리스트 선언과 인덱싱·슬라이싱

> 실습 파일: `day02/c4-1.py`
> 허브: [[Python 정리본 인덱스]] · 이전: [[Python day01 비교·논리 연산자와 if 조건문]] · 다음: [[Python day02 딕셔너리 선언과 키로 값 다루기]]

파이썬 수업 둘째 날은 교재 4장, **리스트**로 시작했다. 첫날 문자열에 썼던 대괄호 인덱싱과 슬라이싱이 리스트에도 **똑같은 모양으로** 적용된다는 것이 이 파일의 핵심이다. 리스트 하나를 선언해서 인덱스로 요소를 꺼내고, 구간을 잘라 내고, 요소 값을 바꾸고, 음수 인덱스로 뒤에서 세고, 리스트 안의 문자열에 다시 대괄호를 붙여 글자 하나를 꺼내는 데까지 갔다. 이어서 리스트 안에 리스트를 넣은 2차원·3차원 리스트를 `[행][열]`로 읽고, `+`·`*`·`len`이 문자열과 똑같이 리스트에도 통한다는 것과 `append`로 요소를 뒤에 붙이는 것까지 봤다. 파일 뒷부분에서는 `insert`로 끼워 넣기, `del`·`pop`·`remove`·`clear`로 지우기, 슬라이싱의 세 번째 칸, `sort()`, `in`·`not in`, 그리고 리스트를 도는 `for` 반복문까지 이어졌다 — 리스트를 만들고, 읽고, 바꾸고, 지우고, 돌리는 한 바퀴가 이 파일 하나에 들어 있다. 자바 배열과 가장 다른 점은 **자료형이 섞여도 되고 길이가 고정되지 않는다**는 것이라, 그 차이를 중심으로 적어 둔다.

## 1. 배운 내용

### 1-1. 리스트란 — 대괄호에 쉼표로 나열한 요소의 모음

```python
# 리스트란? 대괄호 [ ] 에 자료를 쉼표로 구분하여 여러 자료들을 저장
# [ 요소, 요소, 요소 ] , 요소 = element
# 인덱스란? 리스트 내 요소들이 저장된 순서 번호, 0번 시작 ~
list_a = [ 273, 32, 103, "문자열", True, False ]   # 리스트 선언
```

| 용어 | 뜻 |
| --- | --- |
| 리스트(list) | 대괄호 `[ ]` 안에 값을 쉼표로 나열한 **순서 있는 모음**. `type()`으로 찍으면 `<class 'list'>` |
| 요소(element) | 리스트 안에 들어 있는 값 하나하나 |
| 인덱스(index) | 요소가 저장된 순서 번호. **0부터** 시작한다 |

자바의 배열(`int[] arr = {273, 32, 103};`)과 비교하면 모양은 비슷하지만 성격이 다르다. 자바 배열은 선언할 때 자료형을 하나로 정하고 길이도 고정되지만, 파이썬 리스트는 위처럼 **정수·문자열·불리언을 한 리스트에 섞어** 넣을 수 있고, 뒤에서 요소를 더하거나 빼서 길이가 변한다. 자바로 치면 `ArrayList<Object>`에 가깝다. 변수명을 `list_a`처럼 쓴 이유도 적어 둘 만하다 — `list`는 파이썬의 내장 함수 이름이라 변수명으로 덮어쓰면 그 뒤로 `list()`를 못 쓰게 되므로 피하는 편이 안전하다.

### 1-2. 인덱싱 — 요소 하나 꺼내기

```python
print( list_a[ 2 ] )    # 103
```

| 식 | 결과 | 설명 |
| --- | --- | --- |
| `list_a[0]` | `273` | 첫 번째 요소 |
| `list_a[2]` | `103` | 세 번째 요소 — 인덱스는 0부터이므로 2 |
| `list_a[6]` | `IndexError` | 요소가 6개라 마지막 인덱스는 5. 범위를 넘으면 오류 |

문자열에서 `s[2]`로 글자 하나를 꺼냈던 것과 같은 문법이다. 자바의 `arr[2]`와도 똑같고, 범위를 넘으면 자바의 `ArrayIndexOutOfBoundsException`처럼 `IndexError: list index out of range`가 난다. 인덱스 자리에는 정수만 올 수 있다 — `list_a[1.0]`처럼 실수를 넣으면 `TypeError`다.

### 1-3. 슬라이싱 — 구간 잘라 내기

```python
print( list_a[ 1:3 ] )  # [32, 103]  — 인덱스 1부터 3 앞까지
```

| 식               | 결과                              | 설명                                   |
| --------------- | ------------------------------- | ------------------------------------ |
| `list_a[1:3]`   | `[32, 103]`                     | 1번부터 **3번 앞(2번)까지**. 끝 인덱스는 포함하지 않는다 |
| `list_a[:2]`    | `[273, 32]`                     | 시작을 비우면 처음부터                         |
| `list_a[3:]`    | `["문자열", True, False]`          | 끝을 비우면 마지막까지                         |
| `list_a[1:100]` | `[32, 103, "문자열", True, False]` | 범위를 넘겨도 오류 없이 있는 만큼만                 |

문자열 슬라이싱의 규칙이 그대로다. "끝 − 시작 = 요소 개수"라서 `[1:3]`은 두 개다. 결과가 **새 리스트**로 돌아온다는 점이 중요하다. 원본 `list_a`는 그대로이고, 잘라 낸 복사본이 하나 더 생긴다. 자바에서는 `Arrays.copyOfRange(arr, 1, 3)`이나 `list.subList(1, 3)`을 불러야 하던 일이 대괄호 하나로 끝난다.

### 1-4. 요소 값 바꾸기

```python
list_a[2] = 7          # 요소 값 수정 / 변경
print( list_a[2] )     # 7
```

인덱스로 자리를 지목하고 `=`로 새 값을 넣으면 그 자리가 바뀐다. 리스트 전체를 다시 만드는 것이 아니라 **그 자리 하나만** 교체된다. 첫날 노트에서 문자열은 `s[0] = "하"`가 `TypeError`를 냈는데(문자열은 불변), 리스트는 이것이 된다. 같은 대괄호 문법을 쓰면서도 **문자열은 불변, 리스트는 가변**이라는 차이가 여기서 처음 드러난다. 바꾸는 값의 자료형이 원래 값과 달라도 상관없다 — `103`이 있던 자리에 `"칠"`을 넣어도 오류가 없다.

### 1-5. 음수 인덱스 — 뒤에서 세기

```python
print( list_a[-2] )    # True  — 뒤에서 두 번째
```

| 앞에서 | 0 | 1 | 2 | 3 | 4 | 5 |
| --- | --- | --- | --- | --- | --- | --- |
| 요소 | `273` | `32` | `7` | `"문자열"` | `True` | `False` |
| 뒤에서 | -6 | -5 | -4 | -3 | -2 | -1 |

`-1`이 마지막 요소, `-2`가 그 앞이다. 자바에는 없는 기능이라 자바라면 `arr[arr.length - 2]`로 써야 하던 것이 `[-2]`로 줄어든다. 슬라이싱에도 그대로 써서 `list_a[-2:]`는 마지막 두 개, `list_a[:-1]`은 마지막 하나를 뺀 나머지다. 앞 표의 `-0`은 없다 — `list_a[-0]`은 그냥 `list_a[0]`이다.

### 1-6. 요소가 문자열이면 한 번 더 인덱싱할 수 있다

```python
print( list_a[3][1] )   # "자"  — 3번 요소 "문자열"의 1번 글자
# print( list_a[1][1] ) # 오류 — 1번 요소 32 는 정수라 인덱싱이 안 된다
```

`list_a[3]`은 `"문자열"`이고, 문자열은 첫날 배운 대로 인덱싱이 되므로 뒤에 `[1]`을 하나 더 붙이면 두 번째 글자 `"자"`가 나온다. 대괄호를 **왼쪽부터 차례로** 적용한다고 읽으면 된다. 반면 정수 요소에 대괄호를 붙이면 `TypeError: 'int' object is not subscriptable`이 난다 — 대괄호 인덱싱은 문자열·리스트처럼 **순서가 있는 값**에만 된다는 뜻이다. 리스트 안에 리스트를 넣으면(`[ [1, 2], [3, 4] ]`처럼) 같은 방식으로 `[0][1]`처럼 꺼내게 되는데, 이것이 자바 2차원 배열에 해당한다.

### 1-7. 리스트 안의 리스트 — 1차원·2차원·3차원

```python
list_1 = [ 1, 2, 3 ]                              # 1차원
list_2 = [ [1, 2] , [3, 4] , [ 5, 6 ] ]           # 2차원
list_3 = [ [ [ 1, 2] , [3, 4] ] , [5, 6] ]        # 3차원
print( list_2[1][0] )   # 3  — [행][열] => 판다스/데이터
```

| 식 | 결과 | 읽는 법 |
| --- | --- | --- |
| `list_2[1]` | `[3, 4]` | 바깥 리스트의 1번 요소 = 두 번째 행 |
| `list_2[1][0]` | `3` | 그 행의 0번 요소 = 첫 번째 열 |
| `list_3[0][1][0]` | `3` | 대괄호가 세 개면 세 번 들어간다 |

1-6에서 `list_a[3][1]`로 문자열 요소의 글자를 꺼냈던 것과 같은 원리다. 요소 자리에 리스트가 들어 있으면 대괄호를 하나 더 붙여 그 안으로 한 단계 들어간다. 대괄호를 **왼쪽부터 차례로** 적용한다는 규칙은 그대로이고, 안쪽에 들어 있는 것이 문자열이냐 리스트냐만 다르다. 2차원 리스트는 자바의 `int[][]`에 해당하고, `[행][열]`로 읽으면 표 한 장과 모양이 같다. 수업에서 "판다스/데이터"라고 적어 둔 이유가 이것인데, 뒤에 배울 판다스의 `DataFrame`이 결국 이 2차원 구조에 행·열 이름을 붙인 것이라서 여기서 익힌 `[행][열]` 감각이 그대로 이어진다. 자바와 다른 점은 안쪽 리스트의 길이가 서로 달라도 된다는 것이다 — `list_3`처럼 첫 요소는 2차원이고 둘째 요소는 1차원인 들쭉날쭉한 모양도 허용된다. 그래서 `list_3[1][0][0]`처럼 없는 깊이까지 파고들면 `TypeError`가 나므로, 몇 겹인지 세어 가며 대괄호를 붙이는 편이 안전하다.

### 1-8. 리스트끼리의 연산 — `+`·`*`·`len`·`append`

```python
list_b = [ 1,2,3 ]
list_c = [ 4,5,6 ]
print( list_b + list_c )   # [1, 2, 3, 4, 5, 6]  — 리스트 + 리스트 => 연결
print( list_b * 3 )        # [1, 2, 3, 1, 2, 3, 1, 2, 3]  — 반복
print( len(list_b) )       # 3
# 파이썬의 특징 = 정형화된 데이터들의 연산이 가능하다
list_bb = [ [1], [2], [3] ]
print( list_b + list_bb )  # [1, 2, 3, [1], [2], [3]]
list_b.append( 4 )         # 요소 추가
print( list_b )            # [1, 2, 3, 4]
```

| 식 | 결과 | 설명 |
| --- | --- | --- |
| `list_b + list_c` | `[1, 2, 3, 4, 5, 6]` | 두 리스트를 이어 붙인 **새 리스트**. 원본 둘은 그대로 |
| `list_b * 3` | `[1, 2, 3, 1, 2, 3, 1, 2, 3]` | 같은 요소를 세 번 반복 |
| `len(list_b)` | `3` | 요소 개수 |
| `list_b + list_bb` | `[1, 2, 3, [1], [2], [3]]` | 요소가 리스트인 리스트를 붙여도 **펴지지 않고** 리스트 그대로 요소가 된다 |
| `list_b.append(4)` | `None` (원본이 `[1, 2, 3, 4]`로 변함) | 맨 뒤에 요소 하나 추가 |

첫날 문자열에서 `"안녕" + "하세요"`, `"=" * 10`, `len("안녕")`을 봤는데, 리스트에서도 **같은 기호가 같은 뜻**이다. 파이썬은 문자열·리스트·튜플을 모두 "순서 있는 값의 나열(시퀀스)"로 보기 때문에 한 번 익힌 연산이 자료형을 바꿔도 그대로 통한다 — 수업에서 "정형화된 데이터들의 연산이 가능하다"고 적은 것이 이 뜻이다. 자바라면 배열 두 개를 잇기 위해 새 배열을 만들고 `System.arraycopy`나 반복문을 써야 했던 일이 `+` 하나로 끝난다. 다만 `+`는 덧셈이 아니라 **연결**이라서 `[1, 2] + [3, 4]`가 `[4, 6]`이 되지는 않는다. 요소끼리 더하려면 반복문을 돌리거나 나중에 배울 넘파이 배열을 써야 한다.

`list_b + list_bb`의 결과가 `[1, 2, 3, [1], [2], [3]]`이 되는 것은 눈여겨 둘 만하다. `+`는 오른쪽 리스트의 **요소를 그대로** 뒤에 붙일 뿐, 요소가 리스트라고 해서 안을 풀어 주지 않는다. 그래서 결과는 앞 세 개가 정수, 뒤 세 개가 길이 1짜리 리스트인 섞인 모양이 된다. 1-1에서 본 "자료형이 섞여도 된다"가 여기서 다시 나온다.

`append`는 앞의 연산들과 성격이 다르다. `+`·`*`·슬라이싱은 **새 리스트를 돌려주고 원본은 그대로**인데, `append`는 **원본 리스트 자체를 바꾸고** 돌려주는 값은 없다(`None`). 그래서 `list_b = list_b.append(4)`처럼 쓰면 `list_b`가 `None`이 되어 버리는 실수를 하기 쉽다 — 메소드 호출만 하고 대입은 하지 않는 편이 안전하다. 1-4에서 "리스트는 가변"이라고 적은 것이 요소 수정에 이어 요소 추가에서도 확인되는 자리다. `list_b + [4]`로 쓰면 새 리스트가 생기고, `list_b.append(4)`로 쓰면 그 자리에서 늘어난다는 짝으로 기억해 두면 된다.

### 1-9. 요소 끼워 넣기와 `+`·`append`의 차이

```python
list_b.insert( 0 , 5 )     # 특정 인덱스에 요소 추가 — .insert( 위치, 값 )
print( list_b )            # [5, 1, 2, 3, 4]

list_d = [ 1, 2 ]
list_d + [3]               # 방법1] 새 리스트 [1, 2, 3] 을 만들어 돌려준다 — list_d 는 그대로
list_d.append(3)           # 방법2] list_d 자체가 [1, 2, 3] 으로 바뀐다
```

| 식 | 결과 | 원본 `list_d` |
| --- | --- | --- |
| `list_d + [3]` | 새 리스트 `[1, 2, 3]` 반환 | 변하지 않음 |
| `list_d.append(3)` | `None` 반환 | `[1, 2, 3]`으로 변함 |
| `list_d.insert(0, 5)` | `None` 반환 | `[5, 1, 2]`로 변함 |

`append`가 맨 뒤에만 붙인다면 `insert(위치, 값)`은 **원하는 자리에 끼워 넣고** 뒤의 요소들을 한 칸씩 밀어낸다. 자바 `ArrayList`의 `add(0, 5)`와 같다. 두 번째 코드가 이 파일에서 눈여겨 둘 자리인데, 결과 모양은 둘 다 `[1, 2, 3]`이지만 `+`는 **새 리스트를 만들어 돌려주고 원본은 손대지 않는** 연산이고 `append`는 **원본 리스트 자체를 바꾸는** 메소드라는 점이 다르다. 그래서 `list_d + [3]`은 결과를 변수에 받지 않으면 그냥 사라지고, `list_d.append(3)`은 받을 것 없이 `list_d`가 바뀌어 있다. 1-8 끝에서 적은 "`+`는 새 리스트, `append`는 그 자리에서 늘어남"의 짝이 여기서 한 번 더 확인된다. 어느 쪽을 쓸지는 "원본을 남겨 둘 필요가 있는가"로 가르면 된다.

### 1-10. 요소 삭제 — `del`·`pop`·`remove`·`clear`

```python
list_a = [1, 2, 3, 4, 5]
del list_a[1]          # 1번 인덱스 삭제        → [1, 3, 4, 5]
list_a.pop( 2 )        # 2번 인덱스 삭제(값 반환) → [1, 3, 5]
del list_a[ 0:2 ]      # 슬라이싱으로 구간 삭제  → [5]
list_a.remove( 5 )     # 값 5 를 찾아 삭제       → []
list_a.clear()         # 전부 비우기            → []
```

| 방법 | 무엇으로 지정하나 | 돌려주는 값 | 자바 `ArrayList` |
| --- | --- | --- | --- |
| `del lst[i]` | 인덱스 | 없음 | — |
| `del lst[a:b]` | 슬라이스 구간 | 없음 | `subList(a, b).clear()` |
| `lst.pop(i)` | 인덱스 (비우면 마지막) | **지운 요소** | `remove(int)` |
| `lst.remove(x)` | **값** (첫 번째 하나만) | 없음 | `remove(Object)` |
| `lst.clear()` | 전부 | 없음 | `clear()` |

지우는 방법이 넷인데 기준은 둘이다. **인덱스로 지우면 `del`·`pop`, 값으로 지우면 `remove`.** `pop`은 지운 값을 돌려주므로 `last = list_a.pop()`처럼 꺼내 쓰고 지우는 두 일을 한 번에 할 때 쓴다. `del`은 메소드가 아니라 **키워드**라서 `del list_a[1]`처럼 앞에 붙여 쓰고, 슬라이스에도 그대로 되어 구간을 한 번에 지울 수 있다. `remove`는 같은 값이 여럿이면 앞의 하나만 지우고, 없는 값을 지우려 하면 `ValueError`가 난다. 자바 배열은 요소를 지울 수 없어 새 배열로 복사해야 했지만, 파이썬 리스트는 1-8의 `append`로 늘어나듯 여기서 줄어든다 — 길이가 변하는 자료형이라는 점이 양쪽에서 확인되는 셈이다.

### 1-11. 슬라이싱의 세 번째 칸 — `[시작:끝:단계]`

```python
numbers = [1, 2, 3, 4, 5, 6, 7, 8]
print( numbers[1:5:2] )    # [2, 4] — 1번부터 5번 앞까지 2칸씩
print( numbers[ : : -1] )  # [8, 7, 6, 5, 4, 3, 2, 1] — 시작·끝 생략, 단계 -1 이면 역순
```

| 식 | 결과 | 설명 |
| --- | --- | --- |
| `numbers[1:5:2]` | `[2, 4]` | 인덱스 1·3 — 1에서 시작해 2칸씩, 5 앞에서 멈춤 |
| `numbers[::2]` | `[1, 3, 5, 7]` | 처음부터 끝까지 2칸씩 |
| `numbers[::-1]` | `[8, 7, …, 1]` | 단계가 음수면 **뒤에서 앞으로** |
| `numbers[5:1:-1]` | `[6, 5, 4, 3]` | 음수 단계일 때는 시작이 끝보다 커야 한다 |

1-3의 `[시작:끝]`에 칸이 하나 더 붙은 것이다. 시작을 생략하면 0, 끝을 생략하면 마지막까지라는 규칙은 그대로이고, 단계만 새로 들어온다. 가장 자주 쓰는 모양은 `[::-1]`로 리스트를 **뒤집은 새 리스트**를 얻는 관용구다. 문자열에도 같은 문법이 통해서 `"안녕하세요"[::-1]`로 글자를 뒤집을 수 있다. 자바에서 배열을 뒤집으려면 반복문이나 `Collections.reverse`를 써야 했던 일이 콜론 두 개로 끝난다. 결과는 1-3과 같이 새 리스트이고 원본은 그대로라는 것도 같다.

### 1-12. 정렬 — `sort()`와 `reverse=True`

```python
list_e = [ 52, 273, 103, 32, 275, 1, 7 ]
list_e.sort()                 # 오름차순 — 원본이 바뀐다
print( list_e )               # [1, 7, 32, 52, 103, 273, 275]
list_e.sort( reverse=True )   # 내림차순
print( list_e )               # [275, 273, 103, 52, 32, 7, 1]
```

`sort()`는 `append`·`insert`처럼 **원본을 그 자리에서 정렬하고 `None`을 돌려주는** 메소드다. 그래서 `list_e = list_e.sort()`로 받으면 `None`이 되어 버린다 — 1-8에서 `append`에 적은 것과 같은 함정이다. `reverse=True`는 이름을 적어 넘기는 **키워드 인수**로, 이렇게 적으면 어떤 뜻인지 호출하는 쪽에서 바로 읽힌다. 자바로는 `Collections.sort(list)`와 `list.sort(Comparator.reverseOrder())`에 해당한다. 요소가 문자열이면 사전순, 숫자면 크기순으로 정렬되고, 숫자와 문자열이 섞여 있으면 비교할 수 없어 `TypeError`가 나므로 1-1처럼 자료형이 섞인 리스트는 정렬하기 전에 한 종류로 맞춰 두는 편이 안전하다.

### 1-13. 포함 여부 — `in`·`not in`

```python
print( 52 in list_e )       # True  — 52 가 들어 있다
print( 51 in list_e )       # False
print( 52 not in list_e )   # False
print( 51 not in list_e )   # True
```

첫날 문자열에서 `"안" in "안녕"`으로 썼던 `in`이 리스트에도 그대로 된다. 결과는 `bool`이라 조건문 노트의 `if` 뒤에 바로 놓을 수 있고, `not in`은 `not (52 in list_e)`를 한 단어처럼 붙여 쓴 것이다. 자바 `list.contains(52)`에 해당하지만 자바 배열에는 대응하는 메소드가 없어 반복문을 돌려야 했다. 안쪽에서는 앞에서부터 하나씩 비교하므로 리스트가 아주 길면 그만큼 시간이 걸린다는 점만 기억해 두면 된다.

### 1-14. 리스트와 `for` 반복문 — 요소를 하나씩

```python
# for 반복변수 in 반복가능한자료 :
#       실행코드
for i in list_e :            # vs 자바  for( int i=0; i<list.size(); i++ ){ }
    print( i )
for char in "안녕하세요" :   # 문자열도 리스트처럼 돌아간다
    print( char )
```

| 자리 | 설명 |
| --- | --- |
| `for 변수 in 자료:` | 자료의 요소를 **처음부터 끝까지 하나씩** 변수에 넣어 가며 몸체를 실행한다 |
| 반복 변수 | 인덱스가 아니라 **요소 그 자체**가 들어온다. 위 코드의 `i`에는 `275`, `273`, … 값이 온다 |
| 반복 가능한 자료 | 리스트, 문자열, 튜플, 딕셔너리, `range()` 등 순서대로 꺼낼 수 있는 것 전부 |
| 몸체 | 조건문과 같이 콜론 뒤 들여쓰기 블록 |

자바 `for (int i = 0; i < list.size(); i++)`처럼 인덱스를 세는 `for`가 파이썬에는 없다. 파이썬의 `for`는 자바의 **향상된 for**(`for (int x : list)`)에 해당해서, 처음부터 "요소 하나씩"만 꺼낸다. 그래서 반복 변수 이름은 `i`보다 `num`·`item`처럼 요소를 가리키는 이름이 읽기 좋고, 인덱스가 필요하면 아래 2-3의 `enumerate`를 쓴다. 두 번째 코드가 보여 주듯 문자열도 글자 하나씩 꺼내지는 반복 가능한 자료라서, 첫날부터 리스트와 문자열에 같은 문법이 통했던 것이 반복문에서도 이어진다. 몸체가 콜론 뒤 들여쓰기 블록인 것은 조건문 노트에서 본 규칙 그대로다.

## 2. 추가로 알면 좋은 활용법

### 2-1. `extend`·`[0] * n` — 1-8·1-9의 연산을 조금 더 넓히기

```python
print( [0] * 3 )              # [0, 0, 0] — 같은 값으로 채운 리스트
list_b.extend( [5, 6] )       # 다른 리스트의 요소를 하나씩 뒤에 붙이기 (원본 변경)
list_b += [7, 8]              # extend 와 같다
list_b.append( [5, 6] )       # 리스트 하나가 요소 하나로 들어간다 → [..., [5, 6]]
```

`[0] * 3`은 같은 값으로 채운 리스트를 빠르게 만들 때 쓰는 관용구다. `extend`는 1-9의 `+`를 원본에 적용하는 버전이라 `list_b += [5, 6]`과 같고, `append`에 리스트를 넘기면 1-8의 `list_b + list_bb`처럼 리스트 통째로 요소 하나가 된다는 차이가 있다 — "요소를 여럿 붙이려면 `extend`, 하나 붙이려면 `append`"로 갈라 두면 된다.

### 2-2. `sorted`·`reversed` — 원본을 남기고 새로 받기

```python
nums = [52, 273, 103]
new = sorted(nums)                  # 정렬된 새 리스트, nums 는 그대로
new = sorted(nums, reverse=True)
new = sorted(["banana", "kiwi", "apple"], key=len)   # 정렬 기준을 함수로 — 길이순
nums.reverse()                      # 원본을 그 자리에서 뒤집기 (sort 와 같은 성격)
```

1-12의 `sort()`는 원본을 바꾸고, `sorted()`는 **새 리스트를 돌려주고 원본을 남긴다**. `+` vs `append`, `[::-1]` vs `reverse()`와 같은 짝이다. `sorted`는 리스트뿐 아니라 문자열·딕셔너리 등 반복 가능한 자료 어디에나 쓸 수 있고, `key=`에 함수를 넘기면 "무엇을 기준으로 비교할지"를 바꿀 수 있다. 1-12에서 자료형이 섞이면 정렬이 안 된다고 적었는데, `key=str`로 전부 문자열로 바꿔 비교하게 하면 그 문제도 피해 갈 수 있다.

### 2-3. 인덱스가 같이 필요하면 `enumerate`, 번호만 돌리려면 `range`

```python
for i, item in enumerate(list_e):   # 인덱스와 요소를 같이
    print(i, item)
for i in range(len(list_e)):        # 자바식 — 인덱스만 돌고 몸체에서 list_e[i]
    print(list_e[i])
for n in range(1, 11):              # 1부터 10까지 숫자만
    print(n)
```

1-14의 `for`는 요소만 주기 때문에 "몇 번째인지"가 필요하면 `enumerate`로 감싼다. `(인덱스, 요소)` 튜플이 하나씩 나오고 변수 두 개를 적으면 풀려서 들어온다. 자바식으로 인덱스를 돌리고 싶으면 `range(len(...))`을 쓰는데, 요소 수정이 목적이 아니면 `enumerate`가 관용구다. `range(a, b)`는 슬라이싱과 같이 **끝을 포함하지 않는다**.

### 2-4. 슬라이스에 대입하기

```python
nums = [0, 1, 2, 3, 4]
nums[1:3] = [10, 20, 30]    # [0, 10, 20, 30, 3, 4] — 구간을 통째로 교체, 길이도 바뀐다
```

1-4의 "한 자리 바꾸기"를 구간으로 넓힌 것이다. 왼쪽 슬라이스 길이와 오른쪽 리스트 길이가 달라도 되고, 그만큼 리스트가 늘거나 준다. 1-10의 `del lst[a:b]`가 구간 삭제라면 이것은 구간 교체다. 자바에는 대응하는 문법이 없고 반복문을 돌려야 하던 일이다.

## 3. 더 나아가 알면 좋은 것

### 3-1. 리스트는 참조로 다뤄진다 — 복사와 별명

```python
a = [1, 2, 3]
b = a            # 별명 — 같은 리스트를 가리킨다
b[0] = 99
print(a)         # [99, 2, 3]  — a 도 바뀐다

c = a[:]         # 슬라이싱으로 복사 — 새 리스트
c[0] = 0
print(a)         # [99, 2, 3]  — a 는 그대로
```

`b = a`는 리스트를 복사하는 것이 아니라 **같은 객체에 이름을 하나 더 붙이는** 것이다. 자바에서 배열 변수를 다른 변수에 대입하면 같은 배열을 가리키는 것과 같은 원리다. 복사본이 필요하면 `a[:]`·`a.copy()`·`list(a)` 중 하나를 쓴다. 리스트가 가변이라서 생기는 문제이고, 문자열은 불변이라 이런 걱정이 없다 — 1-4에서 본 "문자열은 불변, 리스트는 가변"이 실제로 영향을 주는 자리가 여기다. 1-9·1-10·1-12에서 원본을 바꾸는 메소드(`append`·`insert`·`del`·`sort`)를 별명 `b`에 적용하면 `a`도 함께 바뀐다는 뜻이기도 하다. 리스트 안에 리스트가 들어 있으면 `[:]`도 바깥 껍데기만 복사하므로(얕은 복사), 안쪽까지 떼어 내려면 `copy.deepcopy`가 필요하다 — 이 폴더의 Python 코드 해석 문제(이관) 노트에 있는 얕은 복사 문제가 바로 이 이야기다.

### 3-2. 튜플 — 바꿀 수 없는 리스트

`(273, 32, 103)`처럼 소괄호로 만들면 **튜플**이고, 인덱싱·슬라이싱·`len`·`in`·`for`는 리스트와 똑같이 되지만 `t[0] = 1`처럼 요소를 바꾸는 것은 `TypeError`다. 당연히 `append`·`sort`·`del`도 없다. 바뀌면 안 되는 값 묶음(좌표, 설정값, 함수가 여러 값을 돌려줄 때)에 쓴다. 리스트가 "문자열처럼 인덱싱되는데 바꿀 수 있는 것"이라면, 튜플은 "리스트처럼 생겼는데 문자열처럼 못 바꾸는 것"으로 묶어 두면 정리가 된다. 2-3의 `enumerate`가 돌려주는 `(인덱스, 요소)`가 바로 튜플이다.

### 3-3. 리스트 컴프리헨션 — `for`를 한 줄로 접기

```python
squares = [ n * n for n in range(1, 6) ]           # [1, 4, 9, 16, 25]
evens   = [ n for n in list_e if n % 2 == 0 ]      # 조건으로 거르기
```

1-14의 `for`로 빈 리스트에 `append`를 반복하던 일을 대괄호 안에 한 줄로 적는 문법이다. "결과식 `for` 변수 `in` 자료 `if` 조건" 순서이고, 읽을 때는 뒤의 `for`부터 읽으면 된다. 자바 스트림의 `map`·`filter`·`collect`에 해당하는데 훨씬 짧다. 이 폴더의 Python 코드 해석 문제(이관) 노트에 리스트 컴프리헨션 문제가 있어서, 1-14와 2-3이 익숙해진 뒤 그쪽으로 넘어가면 바로 읽힌다.
