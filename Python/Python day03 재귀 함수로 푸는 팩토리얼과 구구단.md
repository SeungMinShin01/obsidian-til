# Python day03 — 재귀 함수로 푸는 팩토리얼과 구구단

> 실습 파일: `day03/c5-2.py`
> 허브: [[Python 정리본 인덱스]] · 이전: [[Python day03 함수 정의와 매개변수·가변 매개변수]] · 다음: [[Python day03 튜플 선언과 구조분해·스왑]]

함수 정의를 배운 바로 다음 파일은 **함수가 자기 자신을 부르는** 재귀다. 수업 머리의 한 줄 정의가 전부다 — *재귀란 자기 자신을 호출하는 것*. 같은 문제를 두 번씩 푼다. 팩토리얼을 먼저 `for`로 풀고 다시 재귀로, 구구단을 이중 `for`로 풀고 다시 재귀로. 반복문으로 이미 풀 수 있는 문제를 굳이 재귀로 다시 쓰는 이유는 **반복문의 "다음 바퀴"가 재귀에서는 "다시 호출"로 바뀐다**는 대응을 눈으로 보기 위해서다. 그리고 두 재귀 함수 모두 몸체 첫 줄이 "무한 재귀 방지"라는 점이 이 파일의 진짜 요지다. 반복문은 조건식이 거짓이 되면 멈추지만, 재귀는 **멈추는 조건을 함수 안에 직접 적어 두지 않으면 영원히 자기를 부른다.**

## 1. 배운 내용

### 1-1. 팩토리얼을 반복문으로 — 누적 변수 패턴

```python
# 1] 팩토리얼 반복문
def factorial1(n):
    output = 1
    for i in range(1, n + 1):
        output *= i
    return output

factorial1(2)   # 2! → 1 × 2 = 2
factorial1(3)   # 3! → 1 × 2 × 3 = 6
```

| 항목 | 설명 |
| --- | --- |
| `output = 1` | 곱을 쌓을 누적 변수. 합이면 0에서, 곱이면 1에서 시작한다 |
| `range(1, n + 1)` | 1부터 `n`까지. `range`는 끝을 포함하지 않으므로 `+ 1` |
| `output *= i` | 바퀴마다 `i`를 곱해 나간다 — `output = output * i` |
| `return output` | 다 곱한 값을 돌려준다. `print`가 아니라 `return`이라 호출한 쪽이 값을 받는다 |

n!(팩토리얼)은 1부터 n까지의 정수를 전부 곱한 값이다. 연습문제 노트에서 합을 구할 때 `sum_value = 0`으로 시작해 `+=`로 쌓았다면, 곱은 `output = 1`로 시작해 `*=`로 쌓는다는 것만 다르다. 0으로 시작하면 무엇을 곱해도 0이라 곱의 출발점은 1이어야 한다. 이 함수는 `return`으로 값을 돌려주므로 `print(factorial1(3))`처럼 써야 화면에 보인다 — 호출만 하면 값은 계산되지만 아무것도 찍히지 않는다.

### 1-2. 팩토리얼을 재귀로 — 자기 자신을 부르되 멈추는 조건부터

```python
# 2] 팩토리얼 재귀
def factorial2(n):
    # 무한 재귀 방지
    if n == 0:
        return 1
    else:                            # 재귀함수
        return n * factorial2(n - 1)

factorial2(2)
factorial2(3)
```

| 줄 | 역할 | 부르는 이름 |
| --- | --- | --- |
| `if n == 0: return 1` | 더 이상 자기를 부르지 않고 값을 돌려주는 출구 | **종료 조건**(base case) |
| `return n * factorial2(n - 1)` | `n`을 하나 줄여 자기 자신을 다시 부른다 | **재귀 호출**(recursive case) |

재귀는 "n! = n × (n−1)!"이라는 **정의 자체를 코드로 옮긴 것**이다. 3!을 알려면 2!을 알면 되고, 2!을 알려면 1!을 알면 되고, 1!은 0!에 1을 곱한 것이며, 0!은 1이다. `factorial2(3)`이 실제로 어떻게 풀리는지 따라가면 이렇다.

```
factorial2(3)
= 3 * factorial2(2)
= 3 * (2 * factorial2(1))
= 3 * (2 * (1 * factorial2(0)))
= 3 * (2 * (1 * 1))        ← n == 0에서 멈추고 1을 돌려준다
= 3 * (2 * 1)
= 3 * 2
= 6
```

호출이 안으로 들어갈 때는 아직 아무것도 곱해지지 않는다. `factorial2(3)`은 `factorial2(2)`의 답을 **기다리고**, 그것은 다시 `factorial2(1)`을 기다린다. 가장 안쪽 `factorial2(0)`이 1을 돌려주는 순간부터 바깥으로 되돌아 나오며 곱셈이 차례로 실행된다. 즉 재귀는 **들어갈 때 쌓이고 나올 때 계산된다.** 반복문 버전이 `i = 1, 2, 3` 순서로 곱해 나간 것과 달리, 재귀 버전은 `1 × 1`, `2 × 1`, `3 × 2` 순서로 안에서 바깥으로 곱해진다.

`if n == 0: return 1`이 없으면 어떻게 될까. `factorial2(0)`이 `0 * factorial2(-1)`을 부르고, 그것이 `factorial2(-2)`를 부르고… 영원히 멈추지 않는다. 파이썬은 호출이 일정 깊이(기본 1000)를 넘으면 `RecursionError: maximum recursion depth exceeded`로 끊어 준다. 그래서 수업 코드가 두 재귀 함수 모두 **몸체 첫 줄에 종료 조건**을 둔 것이다 — 재귀 함수를 쓸 때는 "어디서 멈추나"를 먼저 적고 "어떻게 자기를 부르나"를 그다음에 적는다.

### 1-3. 구구단을 이중 반복문으로

```python
# 구구단 반복문
for 단 in range(2, 10, 1):       # 단 : 2부터 9까지 1씩 증가
    for 곱 in range(1, 10, 1):   # 곱 : 1부터 9까지 1씩 증가
        print(단 * 곱)
```

| 반복문 | 범위 | 역할 |
| --- | --- | --- |
| 바깥 `for 단` | 2 ~ 9 | 단을 고른다. 바깥이 한 바퀴 돌 때 안쪽이 끝까지 돈다 |
| 안쪽 `for 곱` | 1 ~ 9 | 고른 단에 1부터 9까지 곱한다 |

변수 이름에 한글 `단`·`곱`을 그대로 썼다. 파이썬 식별자는 유니코드를 허용해서 한글 변수명이 문법상 문제없이 돈다 — 수업에서 흐름을 설명하려고 쓴 것이고, 실제 코드에서는 영문을 쓰는 것이 관례다. 흐름은 2단이 1~9까지 끝나야 3단으로 넘어가는 **바깥 1바퀴 = 안쪽 9바퀴** 구조다. 수업 과제로 "3단까지의 순서도"가 붙어 있는데, 순서도로 그리면 안쪽 `for`가 끝나는 지점에서 바깥 `for`의 다음 값으로 올라가는 화살표가 그려진다. 재귀 버전은 바로 이 화살표를 함수 호출로 바꾼다.

### 1-4. 구구단을 재귀로 — 두 개의 멈춤 조건과 두 종류의 재귀 호출

```python
# 구구단 재귀
def 구구단(단=2, 곱=1):
    # 무한재귀 방지
    if 단 > 9:               # 재귀 끝
        return
    if 곱 > 9:               # 곱하기 9까지 했으면 단 올리기
        구구단(단 + 1, 1)
        return
    print(단 * 곱)
    구구단(단, 곱 + 1)       # 곱올리기

구구단()
```

| 조건 | 반복문에서의 대응 | 하는 일 |
| --- | --- | --- |
| `단 > 9` → `return` | 바깥 `for`의 끝 | 전체 종료. 값 없는 `return`으로 함수를 끝낸다 |
| `곱 > 9` → `구구단(단 + 1, 1)` 후 `return` | 안쪽 `for`가 끝나 바깥이 다음 바퀴로 | 다음 단으로, 곱은 1부터 다시 |
| `print` 후 `구구단(단, 곱 + 1)` | 안쪽 `for`의 다음 바퀴 | 같은 단에서 곱만 하나 올린다 |

팩토리얼 재귀가 매개변수 하나를 줄여 가며 한 방향으로만 들어갔다면, 구구단 재귀는 **매개변수가 둘이고 재귀 호출도 두 갈래**다. 곱이 9를 넘지 않았으면 `구구단(단, 곱 + 1)`로 곱을 올리고, 넘었으면 `구구단(단 + 1, 1)`로 단을 올리며 곱을 1로 되돌린다. 이중 `for`의 안쪽 바퀴와 바깥 바퀴가 각각 재귀 호출 하나로 바뀐 셈이다. 호출 순서를 따라가면 `구구단(2, 1) → 구구단(2, 2) → … → 구구단(2, 9) → 구구단(2, 10)`에서 `곱 > 9`에 걸려 `구구단(3, 1)`로 넘어가고, 마지막에 `구구단(10, 1)`이 `단 > 9`에 걸려 전체가 끝난다.

두 가지를 더 짚어 둔다. 첫째, `단=2, 곱=1`은 앞 노트의 **기본 매개변수**라서 `구구단()`처럼 빈 괄호로 부르면 2단 1곱부터 시작한다. 바깥에서 부를 때는 인수를 생략하고, 재귀 호출에서만 값을 넘기는 모양이다. 둘째, `곱 > 9` 분기에서 다음 단을 부른 뒤 **반드시 `return`**을 둔다. 이 `return`이 없으면 다음 단이 전부 끝난 뒤 돌아와서 아래의 `print(단 * 곱)`을 `곱 = 10`인 채로 찍고 `구구단(단, 11)`을 또 부르게 된다. 재귀에서 `return`은 "값을 돌려준다"보다 **"여기서 이 호출을 끝낸다"**는 뜻으로 더 자주 쓰인다. 팩토리얼처럼 결과를 돌려주는 재귀와, 구구단처럼 `print`만 하고 돌려주는 값이 없는 재귀가 모양이 다른 것도 이 때문이다.

### 1-5. 반복문과 재귀 — 같은 문제를 두 가지로 푸는 이유

| | 반복문 | 재귀 |
| --- | --- | --- |
| 멈추는 조건 | `for`의 범위 / `while`의 조건식 | 함수 안의 `if … return` (직접 적어야 한다) |
| 다음 단계로 가기 | 다음 바퀴 | 자기 자신을 다시 호출 |
| 상태를 어디에 두나 | 바깥 변수(`output`, `단`, `곱`) | 매개변수(`n`, `단`, `곱`) — 호출마다 새 값 |
| 읽기 | 절차가 보인다 | 정의가 보인다 (n! = n × (n−1)!) |
| 깊이 제한 | 없음 | 있다 — 약 1000단계를 넘으면 `RecursionError` |
| 잘 맞는 문제 | 횟수가 정해진 단순 반복 | 문제가 같은 꼴의 더 작은 문제로 쪼개지는 경우(트리·중첩 구조·분할 정복) |

이 파일의 예제는 전부 반복문으로도 풀리는 문제다. 재귀가 꼭 필요한 건 **깊이를 미리 알 수 없는 구조**를 다룰 때다. 딕셔너리 연습문제 노트의 "더 나아가기"에서 적어 둔, 딕셔너리 안에 딕셔너리가 몇 겹인지 모를 때 안쪽을 훑는 `show` 함수가 그 예이고, 폴더 안의 폴더를 전부 도는 일, 댓글의 대댓글을 그리는 일도 같은 꼴이다. 반복문으로는 "몇 겹인지"를 먼저 알아야 `for`를 그만큼 겹칠 수 있지만, 재귀는 "안에 또 있으면 같은 함수를 부른다"로 깊이에 상관없이 처리된다. 그래서 수업은 반복문으로 충분한 쉬운 문제에서 재귀의 **모양과 종료 조건**을 먼저 익히게 한 것이다.

## 2. 추가로 알면 좋은 활용법

### 2-1. 종료 조건을 넓게 잡기 — `n <= 1`

```python
def factorial(n):
    if n <= 1:          # 0!과 1!을 한 번에, 음수가 들어와도 멈춘다
        return 1
    return n * factorial(n - 1)
```

`n == 0`만 종료 조건으로 두면 실수로 음수가 들어왔을 때 영원히 내려간다. `<=`로 잡아 두면 0·1·음수 모두에서 멈추고, 1!을 구할 때 한 단계 덜 들어간다. 재귀의 종료 조건은 "정확히 이 값일 때"보다 **"이 범위면 멈춘다"**로 적는 편이 안전하다. `else` 없이 `return`으로 바로 끝내는 모양은 앞 노트의 이른 반환 관용구다.

### 2-2. 재귀 깊이 확인과 반복문으로의 전환

```python
import sys
sys.getrecursionlimit()      # 1000 — 기본 한계
# sys.setrecursionlimit(5000) — 늘릴 수는 있지만 근본 해결은 아니다
```

`factorial2(2000)`은 `RecursionError`로 끊긴다. 한계를 늘릴 수도 있지만, 깊이가 입력 크기에 비례해 커지는 재귀(팩토리얼·합·리스트 순회)는 **반복문으로 바꾸는 것이 정답**이다. 재귀가 어울리는 건 깊이가 로그로 자라거나(이진 탐색·분할 정복) 구조의 깊이 자체가 얕은 경우(중첩 딕셔너리·폴더 트리)다. 파이썬은 꼬리 호출 최적화를 하지 않으므로, `return factorial2(n - 1)`처럼 마지막에 호출만 남겨도 깊이가 줄지 않는다.

### 2-3. 같은 값을 다시 계산하지 않기 — 메모이제이션

```python
from functools import lru_cache

@lru_cache
def fib(n):
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)

fib(50)     # 캐시 없이는 수십 초, 캐시가 있으면 즉시
```

피보나치처럼 재귀 호출이 **두 갈래로 갈라지는** 함수는 같은 `fib(10)`을 수만 번 다시 계산한다. `functools.lru_cache`를 함수 위에 붙이면 한 번 계산한 인수의 결과를 딕셔너리에 저장해 두었다가 재사용한다. `@` 한 줄로 붙이는 이 문법이 데코레이터이고, 안쪽은 "인수 → 결과" 딕셔너리라서 딕셔너리 노트의 횟수 세기 패턴과 같은 원리다. 재귀를 쓸 때 "같은 입력으로 또 부르는 일이 있나"를 한 번 따져 보는 습관이 여기서 나온다.

### 2-4. 구구단 재귀를 다른 모양으로 — 한 단을 재귀, 단 넘김은 반복으로

```python
def 한단(단, 곱=1):
    if 곱 > 9:
        return
    print(f"{단} x {곱} = {단 * 곱}")
    한단(단, 곱 + 1)

for 단 in range(2, 10):
    한단(단)
```

1-4처럼 두 매개변수를 한 함수에서 전부 재귀로 다루면 분기가 둘이라 따라가기 어렵다. 안쪽 바퀴만 재귀로 두고 바깥은 `for`로 돌리면 함수 하나가 "한 단을 끝까지 찍는다"로 역할이 좁아져 읽기 쉽다. 재귀와 반복문은 양자택일이 아니라 **층마다 어울리는 쪽을 고르는** 도구다.

## 3. 더 나아가 알면 좋은 것

### 3-1. 호출 스택 — 재귀가 "쌓인다"는 말의 실체

함수를 부를 때마다 파이썬은 그 호출의 매개변수와 지역 변수를 담은 틀(프레임)을 **스택**에 하나 쌓고, `return`되면 걷어 낸다. `factorial2(3)`이 안으로 들어갈 때 프레임이 4개(n=3, 2, 1, 0) 쌓였다가 바깥으로 나오며 하나씩 사라지는 것이고, `RecursionError`는 이 스택이 한계까지 찬 것이다. 1-2에서 "들어갈 때 쌓이고 나올 때 계산된다"고 적은 이유가 이 구조다. 자바에서 `StackOverflowError`가 나는 것과 같은 현상이고, 스택이라는 자료구조 자체는 CS 이론에서 따로 다룬다.

### 3-2. 분할 정복 — 재귀가 본업인 알고리즘

```python
def binary_search(nums, target, lo, hi):
    if lo > hi:
        return -1                       # 종료: 범위가 비었다
    mid = (lo + hi) // 2
    if nums[mid] == target:
        return mid                      # 종료: 찾았다
    if nums[mid] < target:
        return binary_search(nums, target, mid + 1, hi)
    return binary_search(nums, target, lo, mid - 1)
```

정렬된 리스트에서 절반씩 버리며 찾는 이진 탐색은 "같은 문제를 절반 크기로 다시 푼다"는 재귀의 전형이다. 깊이가 log n이라 2-2의 깊이 걱정이 없다. 병합 정렬·퀵 정렬·하노이의 탑도 같은 꼴이며, 알고리즘 수업에서 재귀를 만나는 자리는 대부분 여기다.

### 3-3. 트리 구조 순회 — 깊이를 모르는 데이터

```python
def show(data, depth=0):
    for key, value in data.items():
        print("  " * depth + str(key))
        if isinstance(value, dict):
            show(value, depth + 1)      # 안에 또 딕셔너리가 있으면 같은 함수로
```

딕셔너리 연습문제 노트에서 예고했던 모양이다. 중첩 딕셔너리, JSON 응답, 폴더 트리(`os.walk`가 안에서 하는 일), 리액트의 댓글-대댓글 컴포넌트가 전부 이 패턴이다. `depth`를 매개변수로 넘겨 들여쓰기를 만드는 것처럼, 재귀에서 "지금 몇 번째 층인가"는 바깥 변수가 아니라 **인수로 들고 내려간다**.
