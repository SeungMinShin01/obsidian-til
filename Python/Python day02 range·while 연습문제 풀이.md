# Python day02 — range·while 연습문제 풀이

> 실습 파일: `practice/p247-249.py`
> 허브: [[Python 정리본 인덱스]] · 이전: [[Python day02 딕셔너리 연습문제 풀이]] · 다음: [[Python day03 함수 정의와 매개변수·가변 매개변수]]

`range`와 `for`·`while`을 배운 뒤 교재 247~249쪽 확인문제를 푼 파일이다. 앞의 두 연습문제가 리스트와 딕셔너리라는 **자료의 모양**을 다뤘다면, 이번 세 문제는 **반복문을 어떤 기준으로 고르고 어떻게 끝내느냐**에 초점이 있다. 1번은 두 리스트를 인덱스로 나란히 읽어 딕셔너리로 합치는 `for`+`range`, 2번은 몇 번 돌지 미리 알 수 없어서 조건으로 멈추는 `while`, 3번은 두 수의 곱이 가장 커지는 순간을 `for`를 돌며 기록해 두는 최댓값 갱신이다. 셋 다 반복문 노트에서 문법으로 본 것인데, 문제로 만나니 "반복 횟수를 아는가 모르는가"가 `for`와 `while`을 가르는 첫 기준이고, "돌면서 무엇을 남길 것인가"가 누적 변수의 자리를 정한다는 점이 보인다.

## 1. 배운 내용

### 1-1. 두 리스트를 인덱스로 짝지어 딕셔너리 만들기

```python
key_list = ["name", "hp", "mp", "level"]
value_list = ["기사", 200, 30, 5]
character = {}

for i in range(4):
    character[key_list[i]] = value_list[i]

print(character)
# {'name': '기사', 'hp': 200, 'mp': 30, 'level': 5}
```

| `i` | `key_list[i]` | `value_list[i]` | 실행된 대입 | `character` |
| --- | --- | --- | --- | --- |
| 0 | `'name'` | `'기사'` | `character['name'] = '기사'` | `{'name': '기사'}` |
| 1 | `'hp'` | `200` | `character['hp'] = 200` | `{'name': '기사', 'hp': 200}` |
| 2 | `'mp'` | `30` | `character['mp'] = 30` | `{…, 'mp': 30}` |
| 3 | `'level'` | `5` | `character['level'] = 5` | `{…, 'level': 5}` |

키 목록과 값 목록이 **같은 길이에 같은 순서**로 놓여 있다는 것이 이 문제의 전제다. 그래서 요소를 직접 도는 `for key in key_list`가 아니라 `range(4)`로 **인덱스 숫자**를 돌리고, 같은 `i`로 두 리스트를 동시에 읽는다. 리스트 노트에서 `for`는 요소를 넘겨 주지만 "몇 번째인지"는 모른다고 적어 둔 것이 여기서 문제가 된다 — 두 리스트를 나란히 읽으려면 자리 번호가 필요하고, 자리 번호는 `range`가 만든다. 몸체는 딕셔너리 연습문제 1번에서 본 "없는 키에 대입하면 추가"가 그대로다. `character[key_list[i]]`처럼 **대괄호 안에 다시 대괄호 식**이 들어가는데, 안쪽 `key_list[i]`가 먼저 계산되어 문자열 키가 되고 그 키로 바깥 딕셔너리에 쓴다고 읽으면 된다. 결과는 넣은 순서대로 쌓인 딕셔너리이고, 자바로 치면 두 배열을 `for (int i …)`로 돌며 `map.put(keys[i], values[i])`를 하는 일이다.

### 1-2. 몇 번 돌지 모를 때 — `while`로 한도를 넘는 순간 찾기

```python
limit = 10000
i = 0
sum_value = 0

while sum_value <= limit:
    i += 1
    sum_value += i

print("{}를 더할 때 {}을 넘으며 그때의 값은 {}입니다".format(i, limit, sum_value))
# 141를 더할 때 10000을 넘으며 그때의 값은 10011입니다
```

| 회차 | 검사 `sum_value <= limit` | `i` | `sum_value` |
| --- | --- | --- | --- |
| 시작 | — | 0 | 0 |
| 1 | `0 <= 10000` 참 | 1 | 1 |
| 2 | `1 <= 10000` 참 | 2 | 3 |
| 3 | `3 <= 10000` 참 | 3 | 6 |
| … | … | … | … |
| 140 | `9730 <= 10000` 참 | 140 | 9870 |
| 141 | `9870 <= 10000` 참 | 141 | **10011** |
| 종료 | `10011 <= 10000` 거짓 | — | — |

"1부터 차례로 더해 가다가 처음으로 10000을 넘는 순간"은 몇 번 돌아야 하는지 미리 모른다. 반복문 노트에서 정리한 기준대로, 횟수를 알면 `for`+`range`, **끝나는 조건만 알면 `while`**이다. 구조는 셋으로 나뉜다 — 반복 전에 `i`와 `sum_value`를 0으로 준비하고, 매 회차 시작에 `sum_value <= limit`를 검사하고, 몸체에서 `i`를 하나 올린 뒤 그 `i`를 합에 더한다. 조건이 `<=`라서 합이 정확히 10000이어도 한 번 더 돌고, 넘는 순간 검사가 거짓이 되어 빠져나온다. 빠져나온 직후의 `i`·`sum_value`가 "넘긴 수"와 "넘긴 합"이므로 그 값을 그대로 출력하면 된다.

`i += 1`을 `sum_value += i`보다 **먼저** 둔 순서도 짚어 둘 만하다. 더한 뒤에 올리면 `sum_value`에는 0부터 더해져 마지막 회차의 `i`가 실제로 더한 수보다 하나 앞서 버린다. `while` 몸체에서 변수 갱신 순서를 바꾸면 결과가 달라지므로, 처음 쓸 때는 1~3회차를 표처럼 손으로 따라가 보고 순서를 확정하는 편이 안전하다. 출력은 day01에서 본 `format()`에 값 세 개를 차례로 끼워 넣는 모양이다.

### 1-3. 돌면서 최댓값 기억하기 — 합이 100인 두 수의 최대 곱

```python
max_value = 0
a = 0
b = 0

for i in range(1, 100, 1):
    j = 100 - i

    if (i * j > max_value):
        max_value = i * j
        a = i
        b = j

print("최대가 되는 경우: {} * {} = {}".format(a, b, max_value))
# 최대가 되는 경우: 50 * 50 = 2500
```

| `i` | `j = 100 - i` | `i * j` | `> max_value`? | `max_value`·`a`·`b` |
| --- | --- | --- | --- | --- |
| 1 | 99 | 99 | 참 | 99 · 1 · 99 |
| 2 | 98 | 196 | 참 | 196 · 2 · 98 |
| … | … | … | 참 (계속 커짐) | … |
| 50 | 50 | 2500 | 참 | **2500 · 50 · 50** |
| 51 | 49 | 2499 | 거짓 | 그대로 |
| … | … | … | 거짓 (계속 작아짐) | 그대로 |

이번에는 후보가 1~99로 정해져 있으니 `for`+`range(1, 100, 1)`이다. `range`의 끝 미포함 규칙 때문에 `i`는 99까지 나오고, 짝이 되는 `j`는 `100 - i`로 바로 구해지므로 변수 하나만 돌면 된다. 핵심은 **최댓값을 담아 둘 변수를 반복 바깥에 미리 두고**, 매 회차 지금 곱이 그보다 크면 갈아 끼우는 패턴이다. `max_value`만 갱신하면 "얼마"는 알아도 "어떤 두 수"였는지 잃어버리므로, 같은 `if` 블록 안에서 `a`·`b`도 함께 바꿔 둔다. 집계 함수 노트의 `max()`가 리스트를 통째로 받아 가장 큰 값을 돌려주는 것과 달리, 이 방식은 리스트를 만들지 않고 **지나가는 값을 하나씩 비교해 최고 기록만 남긴다** — 값이 수백만 개라도 변수 세 개면 되는 이유다.

`max_value`의 시작값을 0으로 둔 것도 전제가 있다. 모든 곱이 양수라 0은 반드시 첫 회차에 갱신된다. 음수가 섞일 수 있는 자료라면 0이 아니라 "첫 번째 값"이나 아주 작은 수로 시작해야 하므로, 초기값은 자료의 범위를 보고 정하는 편이 안전하다. 또 비교가 `>`라서 곱이 같은 경우에는 먼저 나온 짝이 남는데, 이 문제는 50에서 한 번 최고점을 찍고 내려오는 대칭 구조라 결과에 영향이 없다.

## 2. 추가로 알면 좋은 활용법

### 2-1. 1번 문제를 짧게 — `zip`·`enumerate`·딕셔너리 컴프리헨션

```python
# 방법1: zip으로 두 리스트를 쌍으로 묶어 돌기
for key, value in zip(key_list, value_list):
    character[key] = value

# 방법2: dict()에 zip을 바로 넣기
character = dict(zip(key_list, value_list))

# 방법3: 딕셔너리 컴프리헨션
character = {key: value for key, value in zip(key_list, value_list)}

# 방법4: 길이를 직접 쓰지 않기
for i in range(len(key_list)):
    character[key_list[i]] = value_list[i]
```

| 방법 | 인덱스 사용 | 특징 |
| --- | --- | --- |
| `range(4)` | 있음 | 길이 4가 코드에 박혀 있어 리스트가 늘면 같이 고쳐야 한다 |
| `range(len(key_list))` | 있음 | 길이를 리스트에서 읽어 와 요소 수가 바뀌어도 그대로 |
| `zip` | 없음 | 두 리스트를 같은 자리끼리 `(키, 값)` 튜플로 묶어 넘긴다. 짧은 쪽 길이에서 멈춘다 |
| `dict(zip(…))` | 없음 | 한 줄. "두 리스트 → 딕셔너리"의 관용구 |

`zip`은 집계 함수 노트에서 `enumerate`와 나란히 본 짝 짓기 도구인데, 1번 문제가 바로 그 쓰임새다. 두 리스트를 같은 자리끼리 묶어 주므로 인덱스가 사라지고, `for key, value in …`로 풀어 받는 모양은 `items()`·`enumerate`와 같다. 처음에는 `range`로 인덱스 흐름을 눈에 익히고, 손에 붙으면 `dict(zip(…))`으로 줄이는 순서가 자연스럽다.

### 2-2. 2번 문제를 다른 모양으로 — `while True`+`break`, `for`+`break`

```python
# while True로 쓰고 안에서 빠져나오기
i = 0
sum_value = 0
while True:
    i += 1
    sum_value += i
    if sum_value > limit:
        break

# 상한을 넉넉히 잡고 for로 돌다가 끊기
sum_value = 0
for i in range(1, 1000):
    sum_value += i
    if sum_value > limit:
        break
```

`while 조건:`은 "계속할 조건"을 머리에 적고, `while True`+`break`는 "그만둘 조건"을 몸체에 적는다. 결과는 같지만 읽는 사람 입장에서 멈추는 지점이 몸체 안에 보이는 쪽이 이해하기 쉬울 때가 있다. `for`+`break`는 상한을 넉넉히 잡을 수 있을 때만 쓸 수 있고, 상한을 잘못 잡으면 못 찾은 채 끝나므로 이 문제처럼 "언젠가는 반드시 넘는다"가 보장될 때는 `while` 쪽이 뜻에 맞는다. 어느 쪽이든 `i`와 `sum_value`를 **반복 밖에서 선언**해야 반복이 끝난 뒤에도 값을 꺼내 쓸 수 있다 — 파이썬은 반복 변수가 블록 밖에서도 살아 있지만, 처음부터 바깥에 두는 습관이 자바로 돌아갔을 때도 헷갈리지 않는다.

### 2-3. 3번 문제를 다른 모양으로 — `max()`에 `key=` 주기

```python
pairs = [(i, 100 - i) for i in range(1, 100)]
a, b = max(pairs, key=lambda p: p[0] * p[1])
print(a, b, a * b)      # 50 50 2500

# 곱만 필요하면
print(max(i * (100 - i) for i in range(1, 100)))   # 2500
```

1-3의 "비교하며 기록" 패턴을 `max()`에 맡기는 방법이다. `key=`에 "무엇을 기준으로 클지"를 함수로 주면 `max`가 그 기준으로 가장 큰 **원래 요소**(여기서는 `(50, 50)` 튜플)를 돌려주므로, `a`·`b`를 따로 기억할 필요가 없다. 다만 후보 쌍을 리스트로 먼저 만든다는 점이 1-3과 다르다 — 후보가 적을 때는 이 쪽이 짧고, 후보가 아주 많거나 끝없이 생성될 때는 1-3처럼 하나씩 비교하는 쪽이 메모리를 아낀다. 두 방법의 자리가 서로 다르다는 것을 알아 두면 된다.

### 2-4. 최댓값 갱신 패턴의 일반형

```python
best = None
for item in candidates:
    score = 기준(item)
    if best is None or score > best_score:
        best, best_score = item, score
```

3번 문제의 뼈대를 일반화하면 이 모양이다. 초기값을 0이 아니라 `None`으로 두고 `best is None or …`로 첫 회차를 통과시키면, 자료에 음수가 섞여도 안전하다(1-3에서 짚은 초기값 문제의 해결책). 가장 긴 문자열 찾기, 가장 싼 상품 찾기, 가장 가까운 좌표 찾기 모두 `기준()`만 바뀌고 틀은 같다.

## 3. 더 나아가 알면 좋은 것

### 3-1. 2번 문제는 수식으로도 풀린다 — 반복 vs 계산

1부터 `n`까지의 합은 `n(n+1)/2`이므로, 2번은 "이 식이 10000을 처음 넘는 `n`"을 찾는 문제다. `n² ≈ 20000` 근처에서 `n ≈ 141`이 바로 나온다. 반복문으로 141번 도는 대신 식 한 줄로 끝낼 수 있다는 뜻인데, 그렇다고 반복이 쓸모없는 것은 아니다 — 합이 아니라 "조건을 만족하는 첫 항목"을 찾는 일반 문제에서는 공식이 없고, 반복으로 하나씩 검사하는 것이 유일한 길이다. 반복으로 먼저 풀어 답을 확인하고, 공식이 보이면 그걸로 바꾸는 순서가 실무에서도 통한다.

### 3-2. 3번 문제의 탐색 범위 줄이기 — 대칭과 조기 종료

`i * (100 - i)`는 `i = 50`을 중심으로 좌우 대칭이라 1~50만 돌아도 답이 같고, 50을 넘으면서 곱이 줄기 시작하는 순간 `break`로 끝낼 수도 있다. 후보가 99개일 때는 차이가 없지만, 후보가 수백만 개가 되면 "어디까지만 보면 되는가"를 생각하는 것이 성능의 출발점이다. 수학적으로는 합이 일정할 때 곱이 최대가 되는 것은 두 수가 같을 때(산술·기하 평균 부등식)라 애초에 50·50이 답임을 알 수 있지만, 모르는 상태에서 전부 돌려 확인하는 것이 완전 탐색(brute force)이고, 범위를 줄이는 것이 그 다음 단계다.

### 3-3. 누적 변수 패턴이 가는 곳 — `sum`·`itertools.accumulate`·판다스

2번의 `sum_value += i`는 "지나가며 쌓기"의 최소 단위다. 전부 더하기만 할 거면 `sum(range(1, 142))`로 끝나고, 중간 합을 전부 남겨 두고 싶으면 `itertools.accumulate(range(1, 142))`가 `1, 3, 6, 10, …`을 차례로 돌려준다. 판다스에서는 `Series.cumsum()`이 같은 일을 열 단위로 하고, "처음으로 10000을 넘는 자리"는 `(s.cumsum() > 10000).idxmax()` 한 줄이 된다. 지금 `while`로 손으로 쌓는 흐름이 그 함수들이 안에서 하는 일이라, 이름만 알아 두면 나중에 바로 연결된다.

### 3-4. 다음에 볼 키워드

- `zip`·`dict(zip(keys, values))` — 두 리스트를 딕셔너리로 합치는 관용구
- `while True` + `break`·`continue` — 멈출 조건을 몸체에 적는 반복
- `max(iterable, key=…)`·`min(…, key=…)` — 기준 함수로 원래 요소 고르기
- `None`으로 시작하는 최댓값·최솟값 갱신 패턴
- `itertools.accumulate`·`sum`·판다스 `cumsum` — 누적 합
- 완전 탐색(brute force)과 탐색 범위 줄이기(대칭·조기 종료)
- 함수 정의(`def`) — 2번·3번의 반복 블록을 이름 붙여 재사용하는 자리
