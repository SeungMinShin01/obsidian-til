# Python day08 — 판다스 데이터 전처리 중복 제거와 타입 변환

> 허브: [[Python 정리본 인덱스]] · 이전: [[Python day08 판다스 데이터프레임 생성과 인덱싱·필터링]] · 다음: [[Python day09 맷플롯립 시작과 선 차트]]

앞 노트까지는 깨끗한 샘플 표로 데이터프레임의 생김새와 인덱싱·필터링·병합·정렬을 익혔다. 이번 파일은 출발점부터 다르다. **일부러 더럽힌 사원 명부**를 딕셔너리 리스트로 만들어 두고, 그걸 쓸 만한 표로 고쳐 가는 **전처리(preprocessing)** 단계에 들어간다. 실제 데이터는 넘파이 실습의 따릉이 CSV처럼 "읽자마자 분석"이 되는 경우가 드물고, 중복·결측·공백·자료형 불일치를 먼저 걷어 내야 집계 숫자를 믿을 수 있다. 처음에는 `drop_duplicates()`로 완전 중복 행을 지우고 `astype()`으로 사번을 문자열로 바꾸는 두 단계까지만 다뤘는데, 수업이 이어지면서 파일이 **번호 1~10의 전처리 파이프라인**으로 자랐다 — 공백·빈 문자열을 결측으로 통일하고, 결측을 세고 지우고 채우고, 범위를 `clip`으로 누르고, 연속값을 `cut`으로 구간화하고, 날짜 문자열을 `to_datetime`으로 바꿔 `.dt`로 연도를 뽑고, 마지막에 `groupby`·`agg`로 부서별 집계를 낸 뒤 정규화 공식과 원-핫 인코딩(`get_dummies`)까지 닿는다. `df.info()`를 단계마다 찍어 **행 수·non-null 수·dtype이 어떻게 바뀌는지** 눈으로 확인하는 것이 이번 시간의 읽는 법이고, 번호 순서 자체가 "전처리는 이 순서로 한다"는 체크리스트다.

## 1. 배운 내용

### 1-1. 샘플 데이터 — 일부러 심어 둔 다섯 가지 함정

```python
import pandas as pd
raw_data = [
    {'사번': 25001, '이름': ' 김철수 ', '나이': 20.0, '부서': '정보보호부', '입사일': '2022-03-02'},
    {'사번': 25001, '이름': ' 김철수 ', '나이': 20.0, '부서': '정보보호부', '입사일': '2022-03-02'},  # 완전 중복 행
    {'사번': 25002, '이름': '이영희', '부서': '기술부', '입사일': '2021-03-02'},                # 나이 키 누락
    {'사번': 25003, '이름': '박민수', '나이': 22.0, '부서': '', '입사일': '2020-03-02'},        # 부서 빈 문자열
    {'사번': 25008, '이름': '조현우', '나이': 21.0, '부서': '   ', '입사일': '2021-08-20'},     # 부서 스페이스만
    ...
]
df = pd.DataFrame(raw_data)
```

딕셔너리 리스트로 만드는 방식은 앞 노트의 "딕셔너리 → 열" 방식과 방향이 다르다. 여기서는 **딕셔너리 하나가 행 하나**이고 키가 열 이름이 된다. 리스트 안의 딕셔너리들이 가진 키를 전부 모아 열을 만들기 때문에, 어떤 행에 `'나이'` 키가 없으면 그 칸은 비워진 채(`NaN`) 들어간다.

20줄 안에 섞어 둔 문제는 다섯 종류다.

| 함정 | 예 | 걸리는 이유 | 처리 (번호) |
| --- | --- | --- | --- |
| 완전 중복 행 | 25001·25005·25013이 두 번 | 집계하면 인원·합계가 부풀려진다 | ① `drop_duplicates` |
| 자료형이 어긋난 열 | `사번`이 숫자(`int64`) | 사번은 계산할 값이 아니라 식별자 | ② `astype(str)` |
| 공백 | `이름: ' 김철수 '`, `부서: '   '` | 같은 이름이 다른 값으로 취급된다 | ③ `.str.strip()` |
| 빈 문자열 | `부서: ''` | `info()`에서는 non-null로 잡혀 결측처럼 안 보인다 | ③ `.replace('', None)` |
| 키 누락(결측) | `나이` 키가 없는 행 4개 → `NaN` | 평균·합계가 그 행을 어떻게 다룰지 정해야 한다 | ④~⑥ `isnull`·`dropna`·`fillna` |

핵심은 **`NaN`과 `''`와 `'   '`는 판다스 입장에서 전부 다른 값**이라는 점이다. `info()`의 non-null 개수에 잡히는 것은 `NaN`뿐이라, 빈 문자열과 공백은 따로 찾아내야 한다. 그래서 ③에서 공백과 빈 문자열을 **먼저 `NaN`으로 통일**해 두고, ④부터는 결측 하나의 규칙으로 다룬다.

### 1-2. 진단 — `df.info()`로 출발점 찍기

```python

```

```
RangeIndex: 20 entries, 0 to 19
 #   Column  Non-Null Count  Dtype
 0   사번      20 non-null     int64
 1   이름      20 non-null     object
 2   나이      16 non-null     float64
 3   부서      20 non-null     object
 4   입사일     20 non-null     object
```

`info()` 한 줄에서 읽어 낼 것이 세 가지다.

| 읽을 곳 | 이번 데이터 | 뜻 |
| --- | --- | --- |
| `RangeIndex: 20 entries` | 20행 | 중복 3줄이 섞인 채의 행 수 |
| `나이 16 non-null` | 4칸이 `NaN` | 키 누락이 결측치로 들어왔다 |
| `나이 float64` | 정수를 넣었는데 실수 | `NaN`이 섞이면 정수 열도 `float64`로 승격된다 |

`부서`가 `20 non-null`로 나오는 것도 눈여겨볼 자리다. 빈 문자열과 공백은 "값이 있다"로 세기 때문에, `info()`만 믿으면 부서 결측이 없는 것처럼 보인다.

### 1-3. ① 중복 행 제거 — `drop_duplicates()`와 `reset_index(drop=True)`

```python
# df = df.drop_duplicates()                    # 인덱스 유지 — 0, 2, 3, 4, 6, ...
df = df.drop_duplicates().reset_index(drop=True)  # 인덱스 초기화 — 0, 1, 2, 3, ...
```

`drop_duplicates()`는 **모든 열의 값이 똑같은 행**을 찾아 첫 번째만 남기고 나머지를 지운 **새 표를 돌려준다**. 원본은 그대로이므로 `df = …`로 다시 받아야 한다(`rename`과 같은 규칙). 지운 뒤에는 인덱스에 구멍이 생긴다 — 1번·6번·15번이 빠져 `0, 2, 3, 4, 5, 7, …`이 된다.

| 표기 | 인덱스 | 쓰는 상황 |
| --- | --- | --- |
| `df.drop_duplicates()` | 원래 번호 유지 (`0, 2, 3, …`) | 어느 행이 지워졌는지 추적할 때 |
| `….reset_index(drop=True)` | `0, 1, 2, …`로 다시 매김 | `iloc`로 순번 접근하거나 다른 표와 나란히 둘 때 |

`reset_index()`만 쓰면 옛 인덱스가 `index`라는 **새 열로 살아남는다**. 그것까지 버리려면 `drop=True`가 필요하다. 앞 노트의 `concat(ignore_index=True)`가 하는 일과 결과는 같다.

처리 뒤 `info()`를 다시 찍으면 `17 entries`, `나이 13 non-null`로 바뀐다. 중복 3줄이 빠지면서 결측도 4 → 4 그대로지만 분모가 줄어 non-null이 13이 된 것이다 — 중복을 먼저 걷어 내야 결측 비율 같은 숫자가 정확해진다.

### 1-4. ② 타입 변환 — `astype()`

```python
df['사번'] = df['사번'].astype(str)
df.info()      # 사번  17 non-null  object
```

`astype(변환할타입)`은 열(`Series`) 하나를 받아 **자료형을 바꾼 새 열**을 돌려준다. 넘파이 실습에서 `data.astype(np.int32)`로 배열 전체를 바꿨던 것과 같은 메소드다. 여기서는 열 하나만 골라 바꾸고 같은 이름으로 다시 대입한다.

사번을 굳이 문자열로 바꾸는 이유는 두 가지다.

| 이유 | 설명 |
| --- | --- |
| 식별자는 계산하지 않는다 | `describe()`나 `mean()`이 사번의 평균을 내 버리면 의미 없는 숫자가 집계에 섞인다 |
| 앞자리 0·결합 키 | `'00123'` 같은 번호는 숫자로 두면 `123`이 되고, 문자열 키와 `merge`할 때 자료형이 달라 짝이 안 맞는다 |

변환 뒤 `Dtype`이 `int64` → `object`로 바뀐다. 판다스에서 문자열 열은 `object`로 표시된다(최근 버전은 `string`이 따로 있지만 기본은 여전히 `object`).

### 1-5. 전처리 순서 — 왜 중복부터인가

코드의 번호 순서(진단 → 중복 제거 → 타입 변환 → 값 정리 → 결측 → 범위·구간 → 날짜 → 집계)에는 이유가 있다.

1. **`info()`로 먼저 본다** — 행 수와 결측, dtype을 모르고 손대면 무엇이 바뀌었는지 알 수 없다.
2. **중복을 먼저 지운다** — 중복이 남은 채 결측을 채우거나 집계하면 같은 줄이 두 번 영향을 준다.
3. **자료형을 맞춘다** — 이후 문자열 처리(`str.strip` 등)는 열이 문자열이어야 통하고, 숫자 집계는 숫자 열이어야 한다.
4. **값을 정리해 결측을 한 종류로 모은다** — 공백·빈 문자열을 `NaN`으로 통일해야 `isnull`·`fillna`가 전부를 잡는다.
5. **결측을 처리한 뒤에야 집계한다** — `fillna`로 채운 값이 `groupby` 평균에 그대로 들어가므로, 어떤 대표값으로 채웠는지가 집계 결과를 정한다.

자료형이 정해진 뒤에야 "빈 문자열을 `NaN`으로 통일"처럼 값 기준의 정리가 가능하고, 결측이 정리된 뒤에야 `clip`·`cut`·`groupby` 같은 숫자 연산이 의미를 갖는다. 아래 1-6부터가 그 ③~⑩이다.

### 1-6. ③ 공백·빈 문자열을 결측으로 — `.str.strip()`과 `replace('', None)`

```python
# 문자열.strip()   앞뒤 여백/공백 제거
# 문자열.replace('기존문자', '새로운문자')   문자열 안에 기존문자가 있으면 치환
df['이름'] = df['이름'].str.strip()
df['부서'] = df['부서'].str.strip().replace('', None)
```

문자열 열에는 `.str` 접근자가 붙어 파이썬 문자열 메소드를 **열 전체에 한 번에** 건다 — 넘파이의 벡터 연산과 같은 발상이다. `' 김철수 '`는 `'김철수'`가 되어 같은 이름끼리 같은 값으로 묶인다.

`부서`는 두 단계를 이어 붙였다. `'   '`(스페이스만)은 `strip()`을 거치면 `''`가 되므로, **공백 처리와 빈 문자열 처리가 한 줄로 합쳐진다.** 그 뒤 `.replace('', None)`이 빈 문자열을 결측으로 바꾼다. 여기서 두 `replace`를 구분해 둘 자리다.

| 표기 | 대상 | 하는 일 |
| --- | --- | --- |
| `df['부서'].str.replace('a', 'b')` | 문자열 **안의** 글자 | 부분 문자열 치환 (파이썬 `str.replace`와 같음) |
| `df['부서'].replace('', None)` | 칸의 **값 전체** | 값이 정확히 `''`인 칸을 `None`(→ `NaN`)으로 바꿈 |

`.str` 없이 부른 `Series.replace`는 값 단위 치환이라 `''` 전체가 결측으로 바뀐다. 이 한 줄로 `부서` 열의 non-null이 17에서 14로 줄어, `info()`만으로는 안 보이던 결측 3개가 드러난다.

### 1-7. ④·⑤ 결측 확인과 제거 — `isnull().sum()`·`dropna()`

```python
print(df.isnull().sum())      # 열마다 결측 개수
new_df = df.dropna(axis=0)    # 결측이 하나라도 있는 행을 통째로 제거
new_df.info()                 # 10 entries
```

```
사번     0
이름     0
나이     4
부서     3
입사일    0
```

`isnull()`은 표 전체를 같은 모양의 참·거짓 표로 바꾸고, `.sum()`은 열 방향으로 `True`를 센다 — 넘파이에서 `np.sum(마스크)`로 조건에 맞는 개수를 세던 것과 같은 꼴이다. ③을 거쳤기 때문에 `부서 3`이 잡힌다. `isnull()`과 `isna()`는 같은 메소드의 두 이름이다.

`dropna(axis=0)`은 **결측이 한 칸이라도 있는 행**을 버린 새 표를 돌려준다. `나이` 결측 4행과 `부서` 결측 3행이 겹치지 않아 17행에서 10행으로 줄었다. `axis=1`이면 결측이 있는 **열**을 버린다 — `나이`·`부서` 열이 통째로 사라지는 식이라, 어느 축으로 버릴지는 "그 행이 쓸모없는가, 그 열이 쓸모없는가"로 정한다.

여기서는 결과를 `new_df`라는 **다른 변수**에 받았다. `df`는 그대로 두고 "버리면 몇 줄 남는지"만 확인한 것이고, 실제 전처리는 다음 ⑥에서 채우는 쪽으로 간다. 표본이 17줄밖에 없는데 7줄을 버리면 분석할 것이 남지 않기 때문이다.

### 1-8. ⑥ 결측 채우기 — `fillna()`에 중앙값·최빈값

```python
# 표본이 부족하거나 손실을 막기 위해 대표값으로 채운다 — 수치는 중앙값, 범주는 최빈값
df['나이'] = df['나이'].fillna(df['나이'].median())    # 22.0
df['부서'] = df['부서'].fillna(df['부서'].mode()[0])   # '개발부'
```

`fillna(값)`은 결측 칸을 그 값으로 채운 새 열을 돌려준다. 무엇으로 채우느냐가 이 단계의 전부이고, 수업에서 잡은 기준은 **열의 성격**이다.

| 열 | 성격 | 대표값 | 이유 |
| --- | --- | --- | --- |
| `나이` | 수치(연속) | `median()` 중앙값 22.0 | 평균은 극단값 하나에 끌려가지만 중앙값은 그렇지 않다 — "이상치 최소화" |
| `부서` | 범주 | `mode()[0]` 최빈값 `'개발부'` | 범주는 평균을 낼 수 없으니 가장 많이 나온 값으로 |

`mode()`가 **`Series`를 돌려준다**는 점이 작은 함정이다. 최빈값은 여러 개가 동률일 수 있어서 판다스는 항상 리스트 꼴로 주고, 그중 첫 번째를 쓰려면 `[0]`을 붙여야 한다. 중앙값·최빈값 모두 따릉이 실습에서 `np.median`으로 "치우친 분포에는 평균보다 중앙값"이라고 정리했던 판단이 그대로 이어진다.

채운 뒤 `print(df)`를 찍으면 17행 전부가 값으로 차 있고, 이영희·최유리·백지은·문채원의 나이가 22.0, 박민수·조현우·신아름의 부서가 개발부로 들어가 있다. **채운 값은 이후 집계에 진짜 값처럼 섞인다** — ⑩의 부서별 인원수에서 개발부가 7명으로 가장 많은 것은 최빈값으로 채운 3명이 더해진 결과다. 채우기는 공짜가 아니라는 뜻이고, 그래서 어떤 규칙으로 채웠는지를 주석으로 남겨 두는 편이 안전하다.

### 1-9. ⑦ 범위 밖 값 누르기 — `clip(lower, upper)`

```python
# 지정된 임계 범위 기준으로 강제 조정 — 벗어나면 최솟값(18)/최댓값(60)으로
df['나이'] = df['나이'].clip(lower=18, upper=60)
```

`clip`은 넘파이의 `np.clip`과 같은 함수다. 하한보다 작은 값은 하한으로, 상한보다 큰 값은 상한으로 **바꿔 넣고**, 범위 안의 값은 그대로 둔다. 이번 데이터는 20~26세라 바뀌는 칸이 없지만, 입력 실수로 `200`이나 `-1`이 들어온 경우를 상상하면 역할이 분명하다 — 그런 값은 지우지 않고 **경계값으로 끌어당긴다**.

이상값 처리에는 세 갈래가 있고 `clip`은 그중 하나다.

| 방법 | 하는 일 | 쓰는 때 |
| --- | --- | --- |
| 조건 필터로 행 제거 | `df[df['나이'] <= 60]` | 그 줄 자체가 믿을 수 없을 때 |
| `NaN`으로 바꾼 뒤 ⑥으로 | `df.loc[df['나이'] > 60, '나이'] = None` → `fillna` | 값만 틀렸고 나머지 열은 쓸 만할 때 |
| `clip` | 경계값으로 치환 | 범위를 벗어난 정도는 중요하지 않고 행 수를 유지해야 할 때 |

### 1-10. ⑧ 연속값을 구간으로 — `pd.cut(bins, labels)`

```python
bins   = [0, 20, 30, 40]              # 구간 경계
labels = ['청년기', '도약기', '성숙기']  # 구간마다 붙일 이름 (경계 개수 - 1)
# 0 ~ 20 청년기 / 21 ~ 30 도약기 / 31 ~ 40 성숙기
df['연령그룹'] = pd.cut(df['나이'], bins=bins, labels=labels)
```

`pd.cut`은 숫자 열을 받아 **각 값이 어느 구간에 들어가는지**를 범주로 돌려준다. `bins`가 경계 4개이면 구간은 3개이고 `labels`도 3개여야 한다. 결과 열의 dtype은 `category`로, 문자열처럼 보이지만 "정해진 값 중 하나"라는 정보를 품은 자료형이다.

경계가 어느 쪽에 붙는지는 확인해 둘 자리다. 기본값 `right=True`는 **오른쪽 경계를 포함**하는 `(0, 20]`, `(20, 30]`, `(30, 40]`이다. 그래서 20세는 청년기, 21세부터 도약기가 되어 주석의 "0~20 / 21~30"과 맞아떨어진다. 이번 데이터에서는 20세 3명이 청년기, 나머지 14명이 도약기, 성숙기는 0명이다.

연속값을 굳이 범주로 바꾸는 이유는 다음 단계인 ⑩에 있다 — "나이별 평균"은 값이 제각각이라 묶이지 않지만 "연령그룹별 평균"은 세 줄로 요약된다. 넘파이 실습에서 `np.percentile`·분위 기준선으로 "상위 10%"를 자르던 것이 손으로 한 구간화였다면, `cut`은 경계만 주면 그 일을 열 전체에 한 번에 한다.

### 1-11. ⑨ 날짜 문자열을 날짜형으로 — `pd.to_datetime`과 `.dt`

```python
# yyyy-mm-dd, yyyy/mm/dd, yyyy.mm.dd 등 다양한 표기를 표준 날짜로
df['입사일'] = pd.to_datetime(df['입사일'])
print(df['입사일'].dt.year)        # 2022, 2021, 2020, ...
# .dt.year 연도 / .dt.month 월 / .dt.day 일 / .dt.dayofweek 요일(0=월 ~ 6=일)
# .dt.hour 시 / .dt.minute 분 / .dt.second 초
```

`'2022-03-02'`는 지금까지 그냥 문자열(`object`)이었다. 문자열인 채로는 "2020년 이전 입사자"를 거르거나 근속 연수를 빼는 계산이 안 된다. `pd.to_datetime`은 여러 표기의 날짜 문자열을 알아서 해석해 `datetime64` 자료형으로 바꾸고, 그 뒤부터 **`.dt` 접근자**로 연·월·일·요일을 열 단위로 꺼낼 수 있다. `.str`이 문자열 열의 메소드 묶음이었듯 `.dt`는 날짜 열의 속성 묶음이다.

| 접근자 | 돌려주는 것 |
| --- | --- |
| `.dt.year` · `.dt.month` · `.dt.day` | 연·월·일 (정수 열) |
| `.dt.dayofweek` | 요일, 월요일 0 ~ 일요일 6 |
| `.dt.hour` · `.dt.minute` · `.dt.second` | 시·분·초 (날짜만 있으면 전부 0) |

`astype(str)`이 "숫자를 문자열로"였다면 `to_datetime`은 "문자열을 날짜로"다. 둘 다 ②의 타입 변환 범주이지만, 날짜는 `astype`으로는 안 되고 전용 함수를 써야 한다는 점만 다르다.

### 1-12. ⑩ 그룹화 집계 — `groupby`와 `agg`

```python
# df.groupby(['그룹컬럼'])['집계컬럼'].집계함수()
new_df = df.groupby('부서')['나이'].mean()               # 부서별 나이 평균
new_df = df.groupby(['부서', '연령그룹'])['나이'].mean()   # 다중 그룹 — 부서 × 연령그룹
```

```
부서
개발부      22.857143
기술부      22.666667
기획부      21.000000
...
```

`groupby('부서')`는 표를 부서 값이 같은 행끼리 묶는다. 그 묶음에서 `['나이']` 열만 고르고 `.mean()`을 부르면 **부서마다 하나씩** 평균이 나온다. 결과는 부서가 인덱스인 `Series`다. 따릉이 실습에서 `for i in ids: m = data[:, 0] == i; np.sum(data[m, 2])`로 대여소별 합계를 손으로 돌렸던 것이 바로 이 한 줄이다 — 마스크 반복이 `groupby`로 접힌다.

그룹 열을 리스트로 두 개 주면 **조합마다** 묶인다. `['부서', '연령그룹']`이면 "개발부의 도약기", "기획부의 청년기"처럼 인덱스가 두 겹(`MultiIndex`)인 결과가 된다. ⑧에서 연령그룹을 만들어 둔 것이 여기서 쓰인다.

집계 함수를 **여러 개, 열마다 다르게** 걸고 결과 열 이름까지 정하려면 `agg`다.

```python
# .agg( 새이름 = ('기준컬럼', '집계함수') )
new_df = df.groupby('부서').agg(
    인원수   = ('사번', 'count'),
    평균나이 = ('나이', 'mean'),
    최고령나이 = ('나이', 'max')
)
```

```
       인원수       평균나이  최고령나이
부서
개발부      7  22.857143   26.0
기술부      3  22.666667   24.0
기획부      2  21.000000   22.0
인사부      1  24.000000   24.0
전략본부     2  21.000000   22.0
정보보호부    2  21.500000   23.0
```

| 표기 | 뜻 |
| --- | --- |
| `인원수=('사번', 'count')` | `사번` 열을 `count`로 집계해 `인원수`라는 열에 담는다 |
| `('나이', 'mean')` · `('나이', 'max')` | 같은 열에 다른 함수를 두 번 걸어도 된다 |
| 결과 | 부서가 인덱스, 지정한 이름이 열인 `DataFrame` |

`(열, 함수명)` 튜플을 키워드 인수 이름에 붙이는 이 꼴을 **named aggregation**이라고 부른다. 함수 이름은 문자열(`'count'`·`'mean'`·`'max'`·`'min'`·`'sum'`·`'median'`·`'std'`)로 주거나 `np.mean`처럼 함수 자체를 줘도 된다. 앞 노트 3단에서 "`groupby`/`agg`가 마스크 반복 group by를 대체한다"고 키워드만 적어 두었던 것이 여기서 실제 코드가 되었다.

### 1-13. 정규화 공식과 원-핫 인코딩 — `get_dummies`

파일 끝에는 집계가 아니라 **다음 단계(모델링)를 위한 변환** 두 가지가 적혀 있다.

```python
# 정규화: (x - 최솟값) / (최댓값 - 최솟값)
# 이유: 0~1 범위로 만들기 — 서로 다른 속성 간의 이상치/왜곡 방지
# 예] 나이: 0 ~ 150  /  연봉: 0 ~ 3,000,000,000,000
```

Min-Max 정규화 공식은 따릉이 실습 Step 5에서 순유출 대수를 0~1로 눌렀던 바로 그 식이다. 여기서는 **왜 하는가**가 한 줄 더 붙었다 — 나이는 두 자리, 연봉은 열 자리인 두 열을 그대로 거리나 가중치 계산에 넣으면 연봉이 결과를 독점한다. 단위가 다른 열을 같은 0~1 자로 재는 것이 목적이다. 판다스에서는 `(df['나이'] - df['나이'].min()) / (df['나이'].max() - df['나이'].min())`으로 열 하나에 그대로 적을 수 있다.

```python
# 원-핫 인코딩: pd.get_dummies(df, columns=[컬럼명], dtype=int)
# 이유: 범주(문자)를 계산할 수 있는 이진(0/1)으로 변환
# 예] 개발부=0, 정보보호부=1, 기술부=0
new_df = pd.get_dummies(df, columns=['부서'], dtype=int)
```

```
      사번   이름    나이        입사일 연령그룹  부서_개발부  부서_기술부  부서_기획부  부서_인사부  부서_전략본부  부서_정보보호부
0  25001  김철수  20.0 2022-03-02  청년기         0         0         0         0          0           1
1  25002  이영희  22.0 2021-03-02  도약기         0         1         0         0          0           0
```

`get_dummies`는 범주 열 하나를 **범주 개수만큼의 0/1 열**로 펼친다. `부서` 열이 사라지고 `부서_개발부`·`부서_기술부`… 여섯 열이 생기며, 각 행은 자기 부서 열에만 1이 찍힌다. `dtype=int`를 주지 않으면 `True`/`False`로 나오므로 숫자 계산에 쓰려면 붙여 두는 편이 낫다.

굳이 펼치는 이유는 **문자열에는 순서가 없다**는 데 있다. `개발부=1, 기술부=2, 기획부=3`처럼 번호를 매기면 "기획부가 개발부의 세 배"라는 있지도 않은 크기 관계가 생긴다. 열을 쪼개 각각 0/1로 두면 그런 왜곡 없이 "이 부서인가 아닌가"만 남는다. ⑧의 `cut`이 숫자 → 범주였다면 `get_dummies`는 범주 → 숫자로, 방향이 반대인 변환이다.

### 1-14. 파이프라인 한눈에 — 번호가 곧 순서

| 번호 | 메소드 | 하는 일 | 확인 |
| --- | --- | --- | --- |
| — | `info()` | 행 수·non-null·dtype 출발점 | 20행, 나이 16 non-null |
| ① | `drop_duplicates().reset_index(drop=True)` | 완전 중복 제거·인덱스 재정렬 | 17행 |
| ② | `astype(str)` | 식별자를 문자열로 | 사번 `object` |
| ③ | `.str.strip()`·`.replace('', None)` | 공백·빈 문자열을 `NaN`으로 통일 | 부서 non-null 14 |
| ④ | `isnull().sum()` | 열별 결측 개수 | 나이 4, 부서 3 |
| ⑤ | `dropna(axis=0)` | 결측 행 제거 (확인용, 다른 변수에) | 10행 |
| ⑥ | `fillna(median())`·`fillna(mode()[0])` | 수치는 중앙값, 범주는 최빈값 | 결측 0 |
| ⑦ | `clip(lower=18, upper=60)` | 범위 밖 값을 경계값으로 | 변동 없음 |
| ⑧ | `pd.cut(bins, labels)` | 연속값 → 구간 범주 | `연령그룹` `category` |
| ⑨ | `pd.to_datetime` + `.dt.year` | 문자열 → 날짜형 → 연도 | `datetime64` |
| ⑩ | `groupby().mean()`·`agg(이름=(열, 함수))` | 그룹별 집계 | 부서별 인원수·평균·최고령 |
| + | 정규화 공식·`get_dummies` | 모델에 넣기 위한 숫자화 | 0~1 / 0·1 열 |

①~⑥이 "틀린 것을 바로잡는" 정제(cleaning)이고, ⑦~⑨가 "쓰기 좋은 꼴로 바꾸는" 변환(transformation), ⑩이 집계, 마지막이 모델 입력 준비다. 다음 데이터를 만나면 이 표의 번호를 위에서부터 훑는 것이 출발점이 된다.

## 2. 추가로 알면 좋은 활용법

### 2-1. 중복 확인부터 — `duplicated()`

```python
df.duplicated()                 # 행마다 True/False (두 번째 등장부터 True)
df.duplicated().sum()           # 중복 행 개수 — 3
df[df.duplicated(keep=False)]   # 중복에 걸린 행 전부 보기 (첫 번째 포함)
```

지우기 전에 **무엇이 지워질지** 보는 습관이다. `duplicated()`는 불리언 `Series`를 돌려주므로 앞 노트의 필터링 문법 그대로 `df[…]`에 넣으면 된다. `keep=False`는 "첫 번째도 남기지 말고 전부 표시"다.

### 2-2. 일부 열 기준 중복 — `subset=`과 `keep=`

```python
df.drop_duplicates(subset=['사번'])                 # 사번이 같으면 중복으로 본다
df.drop_duplicates(subset=['사번'], keep='last')    # 마지막 것을 남긴다
```

완전 중복만이 아니라 **키가 같으면 중복**으로 보는 경우가 실무에서는 더 흔하다. 같은 사번인데 부서만 다르게 들어온 줄이 있다면 `subset=['사번']`으로 잡힌다. `keep='first'`(기본)·`'last'`·`False` 세 가지로 어느 줄을 남길지 정한다.

### 2-3. 결측 표시를 명시적으로 — `pd.NA`·`np.nan`과 정규식 공백

```python
import numpy as np
df['부서'] = df['부서'].str.strip().replace('', np.nan)      # None 대신 결측값을 직접
df['부서'] = df['부서'].replace(r'^\s*$', np.nan, regex=True)  # 공백만 있는 칸을 한 번에
```

③에서 `None`을 넘겨 결측으로 만들었는데, `replace`의 두 번째 인수를 `np.nan`이나 `pd.NA`로 적으면 "결측으로 바꾼다"는 의도가 코드에 그대로 드러난다. 판다스 버전에 따라 `value=None`을 다른 뜻으로 읽는 경우가 있었으므로, 결측을 만들 때는 결측값을 직접 적는 편이 안전하다. `regex=True`를 켜면 `^\s*$`(공백만 있거나 빈 문자열)을 한 번에 잡아 `strip()`과 `replace`를 한 줄로 합칠 수도 있다.

### 2-4. 결측 처리 옵션 — `dropna(subset=, thresh=)`와 그룹별 `fillna`

```python
df.dropna(subset=['부서'])                 # 부서가 빈 행만 버린다 (나이 결측은 둔다)
df.dropna(thresh=4)                       # 값이 4개 이상 있는 행만 남긴다
df['나이'] = df['나이'].fillna(df.groupby('부서')['나이'].transform('median'))   # 부서별 중앙값으로
```

⑤의 `dropna()`는 결측이 하나라도 있으면 버리는 가장 센 옵션이다. `subset=`으로 **어느 열의 결측만 볼지** 좁히거나, `thresh=`로 "값이 몇 개 이상이면 살린다"는 기준을 둘 수 있다. 채우기도 전체 중앙값 하나보다 **그룹별 대표값**이 더 자연스러울 때가 많다 — `groupby().transform('median')`은 그룹별 중앙값을 **원래 행 수 그대로** 펼쳐 주므로 `fillna`에 바로 넣을 수 있다. 어느 쪽이든 결정의 근거를 주석으로 남기는 편이 안전하다. 채운 값은 집계에 그대로 섞이기 때문이다.

### 2-5. 자료형 한 번에 보기와 여러 열 변환

```python
df.dtypes                                              # info()보다 짧게 dtype만
df = df.astype({'사번': str, '나이': 'Int64'})           # 딕셔너리로 여러 열 동시에
df['입사일'] = pd.to_datetime(df['입사일'], format='%Y-%m-%d', errors='coerce')
```

`astype`에 딕셔너리를 넘기면 열마다 다른 타입으로 한 번에 바꾼다. `'Int64'`(대문자 I)는 **결측을 품을 수 있는 정수형**이라 `NaN` 때문에 `float64`로 승격된 나이 열을 정수로 되돌릴 때 쓴다. `to_datetime`에 `format=`을 주면 표기를 추측하지 않아 빠르고, `errors='coerce'`는 해석이 안 되는 문자열을 오류 대신 `NaT`(날짜의 결측)로 바꿔 ④~⑥의 결측 처리로 넘길 수 있게 한다.

### 2-6. 구간화 옵션 — `right=False`·`pd.qcut`

```python
pd.cut(df['나이'], bins=[0, 20, 30, 40], labels=labels, right=False)   # [0,20), [20,30), [30,40)
pd.cut(df['나이'], bins=3)                                             # 경계를 세 등분으로 자동
pd.qcut(df['나이'], q=4, labels=['Q1', 'Q2', 'Q3', 'Q4'])              # 분위수로 — 구간마다 행 수가 비슷
```

`right=False`로 바꾸면 왼쪽 경계가 포함되어 20세가 도약기로 넘어간다. 경계를 어디에 붙일지는 데이터의 정의에 따라 다르므로, `cut`을 쓸 때 가장 먼저 정할 것이 이 옵션이다. `bins`에 정수를 주면 최솟값~최댓값을 등분하고, **`qcut`은 값이 아니라 개수 기준**으로 잘라 각 구간에 비슷한 수의 행이 들어간다 — 따릉이 실습의 "상위 10%"처럼 분위 기준이 필요할 때는 `cut`보다 `qcut`이 맞다.

### 2-7. 집계 결과 다루기 — `reset_index`·`observed`·`transform`

```python
g = df.groupby('부서').agg(인원수=('사번', 'count')).reset_index()   # 부서를 인덱스에서 열로
df.groupby(['부서', '연령그룹'], observed=True)['나이'].mean()     # 실제로 있는 조합만
df['부서평균'] = df.groupby('부서')['나이'].transform('mean')       # 그룹 값을 각 행 옆에 붙이기
```

`groupby` 결과는 그룹 열이 **인덱스**로 가 있어서, 다시 `merge`하거나 CSV로 내보내려면 `reset_index()`로 열로 되돌리는 편이 편하다. 그룹 열이 `category`(⑧의 `연령그룹`)이면 데이터에 없는 조합(성숙기)까지 빈 줄로 나오는데, `observed=True`를 주면 실제 등장한 조합만 남는다. `agg`가 그룹당 한 줄로 **줄이는** 것이라면 `transform`은 그룹 값을 **원래 행 수로 펼쳐서** 돌려주므로 "자기 부서 평균과의 차이" 같은 열을 만들 때 쓴다.

### 2-8. 원-핫 인코딩 옵션 — `drop_first`·여러 열

```python
pd.get_dummies(df, columns=['부서', '연령그룹'], dtype=int)      # 여러 범주 열을 한 번에
pd.get_dummies(df, columns=['부서'], drop_first=True, dtype=int)  # 열 하나를 빼서 중복 정보 제거
```

범주 열이 여럿이면 `columns`에 전부 적으면 된다. `drop_first=True`는 첫 범주 열을 빼는 옵션이다 — 여섯 부서 중 다섯 열이 전부 0이면 나머지 하나임이 정해지므로 여섯 번째 열은 정보가 겹친다. 회귀 모델처럼 열 간 종속이 문제가 되는 자리에서 쓰는 관용구다.

## 3. 더 나아가 알면 좋은 것

### 3-1. 메소드 체이닝으로 전처리 파이프라인 쓰기

```python
df = (
    pd.DataFrame(raw_data)
      .drop_duplicates()
      .reset_index(drop=True)
      .astype({'사번': str})
      .assign(이름=lambda d: d['이름'].str.strip(),
              부서=lambda d: d['부서'].str.strip().replace('', np.nan))
      .assign(나이=lambda d: d['나이'].fillna(d['나이'].median()).clip(18, 60))
)
```

전처리 메소드는 대부분 **새 표를 돌려주므로** 점으로 이어 붙일 수 있다. `assign`은 열을 추가·수정한 새 표를 돌려주는 메소드형 표기다. 단계가 많아질수록 `df = df.…`를 반복하는 것보다 흐름이 한눈에 들어오고, 중간 변수가 남지 않는다. 반대로 단계별 `info()` 확인이 필요할 때는 풀어 쓰는 편이 낫다 — 수업 코드가 번호마다 끊어 쓴 것은 그 확인을 위해서다.

### 3-2. `inplace=True`는 쓰지 않는 쪽으로

`drop_duplicates(inplace=True)`처럼 원본을 직접 바꾸는 옵션이 있지만, 반환값이 `None`이 되어 체이닝이 끊기고 판다스 쪽에서도 권장하지 않는 흐름이다. "새 표를 받아 다시 대입"을 기본 습관으로 두는 편이 안전하다.

### 3-3. 자료형이 집계를 바꾼다

| 열의 dtype | `describe()` | `mean()` | `merge` 키로 쓸 때 |
| --- | --- | --- | --- |
| `int64` 사번 | 평균·표준편차가 계산된다(무의미) | 계산됨 | 숫자 키끼리만 짝 |
| `object` 사번 | 숫자 통계에서 빠진다 | 오류 | 문자열 키끼리만 짝 |

사번·우편번호·전화번호처럼 **숫자로 생겼지만 숫자가 아닌 열**을 처음부터 문자열로 고정하는 것이 전처리의 첫 판단이다. `read_csv(dtype={'사번': str})`처럼 읽는 시점에 정해 두면 앞자리 0도 보존된다.

### 3-4. 정규화와 표준화 — 모델 입력 준비의 두 갈래

```python
norm = (df['나이'] - df['나이'].min()) / (df['나이'].max() - df['나이'].min())   # Min-Max → 0~1
std  = (df['나이'] - df['나이'].mean()) / df['나이'].std()                       # Z-score → 평균 0·표준편차 1
```

수업 주석의 Min-Max 정규화 옆에 **표준화(Z-score)**가 나란히 있다. 정규화는 범위를 0~1로 고정하지만 극단값 하나가 있으면 나머지가 0 근처로 눌리고, 표준화는 범위가 고정되지 않는 대신 극단값에 덜 흔들린다. 머신러닝 쪽에서는 `sklearn.preprocessing`의 `MinMaxScaler`·`StandardScaler`가 같은 식을 "학습 데이터에서 기준을 외워 두고 새 데이터에 같은 기준을 적용"하는 꼴로 포장해 둔 것이라, 이 공식을 손으로 한 번 써 본 뒤에 그쪽으로 넘어가면 무엇을 외우는지가 보인다.

### 3-5. `category` dtype과 순서 있는 범주

`cut`이 만든 `연령그룹`은 `category` 자료형이고 청년기 < 도약기 < 성숙기 순서를 안다. `df['연령그룹'].cat.codes`로 0·1·2 정수를 꺼낼 수 있고, `astype('category')`로 일반 문자열 열도 범주로 바꿀 수 있다. 범주형은 같은 문자열을 반복 저장하지 않아 메모리가 줄고 `groupby`가 빨라지며, 순서가 있는 범주(`ordered=True`)는 `<` 비교와 정렬이 의미대로 된다 — 원-핫 인코딩이 순서를 **지우는** 변환이라면 순서형 범주는 순서를 **살리는** 변환이다.

### 3-6. 전처리 체크리스트

실습 데이터의 함정과 번호 순서를 일반화하면 이런 순서가 된다.

1. 모양 보기 — `shape`·`info()`·`head()`
2. 중복 — `duplicated().sum()` → `drop_duplicates()`
3. 자료형 — `dtypes` → `astype`·`to_datetime`
4. 문자열 정리 — `str.strip()`·`str.lower()`·`replace`
5. 결측 — `isna().sum()` → `fillna`/`dropna`
6. 이상값 — `describe()`로 범위 확인 → `clip`·조건 필터
7. 파생 변수 — `cut`/`qcut`·`.dt`·사칙연산
8. 집계 — `groupby`·`agg`·`transform`
9. 모델 입력 — 정규화/표준화·`get_dummies`
10. 다시 `info()`로 끝 상태 기록
