# Python day08 — 판다스 데이터 전처리 중복 제거와 타입 변환

> 실습 파일: `day08/p-02.py`
> 허브: [[Python 정리본 인덱스]] · 이전: [[Python day08 판다스 데이터프레임 생성과 인덱싱·필터링]] · 다음: (아직 없음)

앞 노트까지는 깨끗한 샘플 표로 데이터프레임의 생김새와 인덱싱·필터링·병합·정렬을 익혔다. 이번 파일은 출발점부터 다르다. **일부러 더럽힌 사원 명부**를 딕셔너리 리스트로 만들어 두고, 그걸 쓸 만한 표로 고쳐 가는 **전처리(preprocessing)** 단계에 들어간다. 실제 데이터는 넘파이 실습의 따릉이 CSV처럼 "읽자마자 분석"이 되는 경우가 드물고, 중복·결측·공백·자료형 불일치를 먼저 걷어 내야 집계 숫자를 믿을 수 있다. 오늘 코드가 실제로 한 일은 두 가지 — `drop_duplicates()`로 완전 중복 행을 지우고 인덱스를 다시 매기는 것, `astype()`으로 사번을 문자열로 바꾸는 것 — 이고, 샘플 데이터의 주석에 적힌 나머지 함정(결측치·빈 문자열·앞뒤 공백)은 다음 순서를 예고하는 자리다. `df.info()`를 단계마다 찍어 **행 수·non-null 수·dtype이 어떻게 바뀌는지** 눈으로 확인하는 것이 이번 시간의 읽는 법이다.

## 1. 배운 내용

### 1-1. 샘플 데이터 — 일부러 심어 둔 다섯 가지 함정

```python
import pandas as pd
raw_data = [
    {'사번': 25001, '이름': ' 김철수 ', '나이': 20.0, '부서': '정보보호부', '입사일': '2022-03-02'},
    {'사번': 25001, '이름': ' 김철수 ', '나이': 20.0, '부서': '정보보호부', '입사일': '2022-03-02'},  # 완전 중복 행
    {'사번': 25002, '이름': '이영희', '부서': '기술부', '입사일': '2021-03-02'},                # 나이 키 누락
    {'사번': 25003, '이름': '박민수', '나이': 22.0, '부서': '', '입사일': '2020-03-02'},        # 부서 빈 문자열
    {'사번': 25008, '이름': '조현우', '나이': 21.0, '부서': '   ', '입사일': '2021-08-20'},     # 부서 스페이스만
    ...
]
df = pd.DataFrame(raw_data)
```

딕셔너리 리스트로 만드는 방식은 앞 노트의 "딕셔너리 → 열" 방식과 방향이 다르다. 여기서는 **딕셔너리 하나가 행 하나**이고 키가 열 이름이 된다. 리스트 안의 딕셔너리들이 가진 키를 전부 모아 열을 만들기 때문에, 어떤 행에 `'나이'` 키가 없으면 그 칸은 비워진 채(`NaN`) 들어간다.

20줄 안에 섞어 둔 문제는 다섯 종류다.

| 함정 | 예 | 걸리는 이유 | 오늘 처리했나 |
| --- | --- | --- | --- |
| 완전 중복 행 | 25001·25005·25013이 두 번 | 집계하면 인원·합계가 부풀려진다 | O — `drop_duplicates` |
| 자료형이 어긋난 열 | `사번`이 숫자(`int64`) | 사번은 계산할 값이 아니라 식별자 | O — `astype(str)` |
| 키 누락(결측) | `나이` 키가 없는 행 4개 → `NaN` | 평균·합계가 그 행을 어떻게 다룰지 정해야 한다 | 다음 순서 |
| 빈 문자열 | `부서: ''` | `info()`에서는 non-null로 잡혀 결측처럼 안 보인다 | 다음 순서 |
| 공백 | `이름: ' 김철수 '`, `부서: '   '` | 같은 이름이 다른 값으로 취급된다 | 다음 순서 |

핵심은 **`NaN`과 `''`와 `'   '`는 판다스 입장에서 전부 다른 값**이라는 점이다. `info()`의 non-null 개수에 잡히는 것은 `NaN`뿐이라, 빈 문자열과 공백은 따로 찾아내야 한다.

### 1-2. 진단 — `df.info()`로 출발점 찍기

```python
df.info()
```

```
RangeIndex: 20 entries, 0 to 19
 #   Column  Non-Null Count  Dtype
 0   사번      20 non-null     int64
 1   이름      20 non-null     object
 2   나이      16 non-null     float64
 3   부서      20 non-null     object
 4   입사일     20 non-null     object
```

`info()` 한 줄에서 읽어 낼 것이 세 가지다.

| 읽을 곳 | 이번 데이터 | 뜻 |
| --- | --- | --- |
| `RangeIndex: 20 entries` | 20행 | 중복 3줄이 섞인 채의 행 수 |
| `나이 16 non-null` | 4칸이 `NaN` | 키 누락이 결측치로 들어왔다 |
| `나이 float64` | 정수를 넣었는데 실수 | `NaN`이 섞이면 정수 열도 `float64`로 승격된다 |

`부서`가 `20 non-null`로 나오는 것도 눈여겨볼 자리다. 빈 문자열과 공백은 "값이 있다"로 세기 때문에, `info()`만 믿으면 부서 결측이 없는 것처럼 보인다.

### 1-3. 중복 행 제거 — `drop_duplicates()`와 `reset_index(drop=True)`

```python
# df = df.drop_duplicates()                    # 인덱스 유지 — 0, 2, 3, 4, 6, ...
df = df.drop_duplicates().reset_index(drop=True)  # 인덱스 초기화 — 0, 1, 2, 3, ...
```

`drop_duplicates()`는 **모든 열의 값이 똑같은 행**을 찾아 첫 번째만 남기고 나머지를 지운 **새 표를 돌려준다**. 원본은 그대로이므로 `df = …`로 다시 받아야 한다(`rename`과 같은 규칙). 지운 뒤에는 인덱스에 구멍이 생긴다 — 1번·6번·15번이 빠져 `0, 2, 3, 4, 5, 7, …`이 된다.

| 표기 | 인덱스 | 쓰는 상황 |
| --- | --- | --- |
| `df.drop_duplicates()` | 원래 번호 유지 (`0, 2, 3, …`) | 어느 행이 지워졌는지 추적할 때 |
| `….reset_index(drop=True)` | `0, 1, 2, …`로 다시 매김 | `iloc`로 순번 접근하거나 다른 표와 나란히 둘 때 |

`reset_index()`만 쓰면 옛 인덱스가 `index`라는 **새 열로 살아남는다**. 그것까지 버리려면 `drop=True`가 필요하다. 앞 노트의 `concat(ignore_index=True)`가 하는 일과 결과는 같다.

처리 뒤 `info()`를 다시 찍으면 `17 entries`, `나이 13 non-null`로 바뀐다. 중복 3줄이 빠지면서 결측도 4 → 4 그대로지만 분모가 줄어 non-null이 13이 된 것이다 — 중복을 먼저 걷어 내야 결측 비율 같은 숫자가 정확해진다.

### 1-4. 타입 변환 — `astype()`

```python
df['사번'] = df['사번'].astype(str)
df.info()      # 사번  17 non-null  object
```

`astype(변환할타입)`은 열(`Series`) 하나를 받아 **자료형을 바꾼 새 열**을 돌려준다. 넘파이 실습에서 `data.astype(np.int32)`로 배열 전체를 바꿨던 것과 같은 메소드다. 여기서는 열 하나만 골라 바꾸고 같은 이름으로 다시 대입한다.

사번을 굳이 문자열로 바꾸는 이유는 두 가지다.

| 이유 | 설명 |
| --- | --- |
| 식별자는 계산하지 않는다 | `describe()`나 `mean()`이 사번의 평균을 내 버리면 의미 없는 숫자가 집계에 섞인다 |
| 앞자리 0·결합 키 | `'00123'` 같은 번호는 숫자로 두면 `123`이 되고, 문자열 키와 `merge`할 때 자료형이 달라 짝이 안 맞는다 |

변환 뒤 `Dtype`이 `int64` → `object`로 바뀐다. 판다스에서 문자열 열은 `object`로 표시된다(최근 버전은 `string`이 따로 있지만 기본은 여전히 `object`).

### 1-5. 전처리 순서 — 왜 중복부터인가

오늘 코드의 순서(진단 → 중복 제거 → 타입 변환)에는 이유가 있다.

1. **`info()`로 먼저 본다** — 행 수와 결측, dtype을 모르고 손대면 무엇이 바뀌었는지 알 수 없다.
2. **중복을 먼저 지운다** — 중복이 남은 채 결측을 채우거나 집계하면 같은 줄이 두 번 영향을 준다.
3. **자료형을 맞춘다** — 이후 문자열 처리(`str.strip` 등)는 열이 문자열이어야 통하고, 숫자 집계는 숫자 열이어야 한다.

이 뒤에 결측·공백 처리가 오는 것이 자연스럽다. 자료형이 정해진 뒤에야 "빈 문자열을 `NaN`으로 통일"처럼 값 기준의 정리가 가능하다.

## 2. 추가로 알면 좋은 활용법

### 2-1. 중복 확인부터 — `duplicated()`

```python
df.duplicated()                 # 행마다 True/False (두 번째 등장부터 True)
df.duplicated().sum()           # 중복 행 개수 — 3
df[df.duplicated(keep=False)]   # 중복에 걸린 행 전부 보기 (첫 번째 포함)
```

지우기 전에 **무엇이 지워질지** 보는 습관이다. `duplicated()`는 불리언 `Series`를 돌려주므로 앞 노트의 필터링 문법 그대로 `df[…]`에 넣으면 된다. `keep=False`는 "첫 번째도 남기지 말고 전부 표시"다.

### 2-2. 일부 열 기준 중복 — `subset=`과 `keep=`

```python
df.drop_duplicates(subset=['사번'])                 # 사번이 같으면 중복으로 본다
df.drop_duplicates(subset=['사번'], keep='last')    # 마지막 것을 남긴다
```

완전 중복만이 아니라 **키가 같으면 중복**으로 보는 경우가 실무에서는 더 흔하다. 같은 사번인데 부서만 다르게 들어온 줄이 있다면 `subset=['사번']`으로 잡힌다. `keep='first'`(기본)·`'last'`·`False` 세 가지로 어느 줄을 남길지 정한다.

### 2-3. 빈 문자열·공백을 결측으로 통일

```python
df['이름'] = df['이름'].str.strip()                      # 앞뒤 공백 제거
df['부서'] = df['부서'].str.strip().replace('', pd.NA)   # 공백만 있는 값도 ''가 된 뒤 NA로
df.info()                                                # 이제 부서의 non-null이 줄어든다
```

문자열 열에는 `.str` 접근자가 붙어 파이썬 문자열 메소드를 **열 전체에 한 번에** 건다 — 넘파이의 벡터 연산과 같은 발상이다. `'   '`은 `strip()`을 거치면 `''`가 되므로, 공백 처리와 빈 문자열 처리를 한 줄로 묶을 수 있다. `pd.NA`(또는 `np.nan`)로 바꿔 두면 이후 `isna()`·`fillna()`·`dropna()`가 한 가지 규칙으로 동작한다.

### 2-4. 결측치 다루기 — `isna`·`fillna`·`dropna`

```python
df.isna().sum()                              # 열마다 결측 개수
df['나이'] = df['나이'].fillna(df['나이'].mean())   # 평균으로 채우기
df = df.dropna(subset=['부서'])               # 부서 없는 행은 버리기
```

결측은 **채울지 버릴지**를 열마다 따로 정한다. 나이처럼 대략의 값으로 메워도 되는 열은 평균·중앙값으로 채우고, 부서처럼 추정이 불가능한 열은 행을 버리거나 `'미배정'` 같은 표시값으로 둔다. 어느 쪽이든 결정의 근거를 주석으로 남기는 편이 안전하다 — 채운 값은 집계에 그대로 섞이기 때문이다.

### 2-5. 자료형 한 번에 보기와 여러 열 변환

```python
df.dtypes                                              # info()보다 짧게 dtype만
df = df.astype({'사번': str, '나이': 'Int64'})           # 딕셔너리로 여러 열 동시에
df['입사일'] = pd.to_datetime(df['입사일'])              # 문자열 날짜 → datetime64
```

`astype`에 딕셔너리를 넘기면 열마다 다른 타입으로 한 번에 바꾼다. `'Int64'`(대문자 I)는 **결측을 품을 수 있는 정수형**이라 `NaN` 때문에 `float64`로 승격된 나이 열을 정수로 되돌릴 때 쓴다. 날짜 문자열은 `astype`이 아니라 `pd.to_datetime`으로 바꿔야 `dt.year` 같은 날짜 연산이 열린다.

## 3. 더 나아가 알면 좋은 것

### 3-1. 메소드 체이닝으로 전처리 파이프라인 쓰기

```python
df = (
    pd.DataFrame(raw_data)
      .drop_duplicates()
      .reset_index(drop=True)
      .astype({'사번': str})
      .assign(이름=lambda d: d['이름'].str.strip())
)
```

전처리 메소드는 대부분 **새 표를 돌려주므로** 점으로 이어 붙일 수 있다. `assign`은 열을 추가·수정한 새 표를 돌려주는 메소드형 표기다. 단계가 많아질수록 `df = df.…`를 반복하는 것보다 흐름이 한눈에 들어오고, 중간 변수가 남지 않는다. 반대로 단계별 `info()` 확인이 필요할 때는 풀어 쓰는 편이 낫다.

### 3-2. `inplace=True`는 쓰지 않는 쪽으로

`drop_duplicates(inplace=True)`처럼 원본을 직접 바꾸는 옵션이 있지만, 반환값이 `None`이 되어 체이닝이 끊기고 판다스 쪽에서도 권장하지 않는 흐름이다. "새 표를 받아 다시 대입"을 기본 습관으로 두는 편이 안전하다.

### 3-3. 자료형이 집계를 바꾼다

| 열의 dtype | `describe()` | `mean()` | `merge` 키로 쓸 때 |
| --- | --- | --- | --- |
| `int64` 사번 | 평균·표준편차가 계산된다(무의미) | 계산됨 | 숫자 키끼리만 짝 |
| `object` 사번 | 숫자 통계에서 빠진다 | 오류 | 문자열 키끼리만 짝 |

사번·우편번호·전화번호처럼 **숫자로 생겼지만 숫자가 아닌 열**을 처음부터 문자열로 고정하는 것이 전처리의 첫 판단이다. `read_csv(dtype={'사번': str})`처럼 읽는 시점에 정해 두면 앞자리 0도 보존된다.

### 3-4. 전처리 체크리스트

실습 데이터의 다섯 함정을 일반화하면 이런 순서가 된다.

1. 모양 보기 — `shape`·`info()`·`head()`
2. 중복 — `duplicated().sum()` → `drop_duplicates()`
3. 자료형 — `dtypes` → `astype`·`to_datetime`
4. 문자열 정리 — `str.strip()`·`str.lower()`·`replace`
5. 결측 — `isna().sum()` → `fillna`/`dropna`
6. 이상값 — `describe()`로 범위 확인 → 조건 필터
7. 다시 `info()`로 끝 상태 기록

### 다음에 볼 키워드

- `duplicated(keep=False)`·`drop_duplicates(subset=, keep=)`·`reset_index(drop=True)`
- `.str` 접근자(`strip`·`replace`·`contains`)·`pd.NA` vs `np.nan`
- `isna`·`fillna`·`dropna(subset=)`·`'Int64'` 결측 허용 정수형
- `astype({…})`·`pd.to_datetime`·`read_csv(dtype=)`
