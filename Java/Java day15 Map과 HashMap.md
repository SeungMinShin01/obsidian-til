# Java day15 — Map과 HashMap

> 실습 파일: `day15/exam/exam1.java`(제네릭 타입 복습·컬렉션 세 갈래 정리·Map 인터페이스와 HashMap·엔트리 조작 메소드·keySet 순회)
> 허브: [[Java MOC]] · 이전: [[Java day14 제네릭]]

day14에서 컬렉션 프레임워크의 세 갈래를 늘어놓고 `List` 와 `Set` 을 실습으로 확인했다. 남은 하나가 `Map` 이다. 앞의 둘이 "값을 죽 늘어놓는" 구조였다면 `Map` 은 **값에 이름표를 붙여 담는** 구조라, 꺼내는 방식부터 달라진다.

시작은 제네릭 복습이다. `List<BoardDto> list = new ArrayList<>();` 에서 꺾쇠 안을 채우는 시점이 **인터페이스를 만들 때가 아니라 쓸 때**라는 것 — [[Java day14 제네릭]] 에서 정리한 "타입을 정하는 시점을 미룬다"가 컬렉션에서 어떻게 나타나는지 다시 짚고 들어간다.

## 1. 배운 내용

### 1-1. 컬렉션 세 갈래를 다시 세워 두기

`Map` 을 보기 전에 세 인터페이스가 무엇으로 갈리는지 정리한다.

| 인터페이스 | 중복 | 순서(인덱스) | 구현체 |
| --- | --- | --- | --- |
| `List` | 허용 | 있다 | `ArrayList`, `LinkedList`, `Vector` |
| `Set` | 불가 | 없다 | `HashSet`, `TreeSet` |
| `Map` | 키는 불가 / 값은 허용 | 없다 | `HashMap`, `HashTable`, `TreeMap` |

`Map` 의 줄을 눈여겨볼 필요가 있다. **키 쪽은 `Set` 의 성질을, 값 쪽은 `List` 의 성질을 갖는다.** 키는 중복될 수 없고 값은 몇 번이든 겹칠 수 있다. 그래서 `Map` 은 별개의 자료구조라기보다 **`Set` 하나와 `List` 하나를 짝지어 붙인 형태**로 읽는 편이 이해가 빠르다.

`Map` 인터페이스는 `Collection` 을 상속하지 않는다는 점도 여기서 갈린다. `List`·`Set` 은 "값 하나"를 담지만 `Map` 은 "쌍"을 담기 때문에, `add(값)` 같은 공통 메소드가 성립하지 않는다.

### 1-2. Map — 키와 값 한 쌍을 담는 구조

`Map` 에 들어가는 한 쌍을 **엔트리(entry)** 라고 부른다. 키 하나와 값 하나가 묶인 것이 엔트리 하나이고, `Map` 은 그 엔트리를 여러 개 담는다.

```java
Map<String, Integer> map = new HashMap<>();
```

읽는 순서를 나눠 두면 이렇다.

| 자리 | 뜻 |
| --- | --- |
| `Map<K, V>` | 인터페이스 타입 — 왼쪽에 둔다 |
| `<String, Integer>` | 키는 문자열, 값은 정수 |
| `new HashMap<>()` | 구현체 — 오른쪽에 둔다 |

타입 파라미터가 두 개인 것이 `List`·`Set` 과 다른 유일한 문법 차이다. [[Java day14 제네릭]] 에서 `Box4<T, E>` 로 타입 자리를 두 개 두었던 그 형태가 표준 라이브러리에서 실제로 쓰이는 대표 사례다. 선언을 인터페이스 타입으로 두고 구현체를 갈아끼울 수 있게 하는 관용구도 그대로 적용된다.

**모양이 JSON과 같다**는 것이 실무에서 이 구조를 계속 만나게 되는 이유다.

```
JSON      { "유재석": 95, "강호동": 30 }
Map       {유재석=95, 강호동=30}
```

중괄호 안에 `이름: 값` 쌍이 나열된 구조가 그대로 대응된다. 자바스크립트에서 객체 리터럴로 만들던 데이터가 자바로 넘어오면 `Map` 이나 DTO가 되는 셈이라, 통신 구간을 다룰 때 이 대응을 잡아 두면 편하다 — [[JS day07 객체]] 의 `{ }` 가 여기에 짝지어진다.

### 1-3. 엔트리 추가 — put, 그리고 키 중복

```java
map.put("유재석", 95);
map.put("강호동", 30);
map.put("신동엽", 10);
map.put("유재석", 80);
System.out.println(map);   // {신동엽=10, 유재석=80, 강호동=30}
```

앞의 셋은 그대로 들어간다. 눈여겨볼 곳은 네 번째 줄이다. `"유재석"` 은 이미 있는 키라 **새 엔트리가 추가되지 않고 기존 값이 덮어써진다.** 95가 80으로 바뀌고 엔트리 수는 그대로 셋이다.

`List` 의 `add` 와 성격이 갈리는 자리다.

| | 같은 것을 다시 넣으면 |
| --- | --- |
| `List.add` | 그냥 하나 더 쌓인다 |
| `Set.add` | 무시된다 — 원래 값이 남는다 |
| `Map.put` | 값이 교체된다 — 나중 것이 남는다 |

`Set` 과 `Map` 둘 다 중복을 막지만 **처리 방향이 반대**다. `Set` 은 새 값을 버리고 `Map` 은 옛 값을 버린다. `put` 이 "추가"가 아니라 "설정"에 가까운 동작이라고 잡아 두면 헷갈리지 않는다.

키가 같은지 판단하는 기준은 `Set` 과 동일하다. 주소 비교(`==`)가 아니라 `hashCode()` 로 자리를 잡고 `equals()` 로 내용을 비교한다 — [[Java day13 Object 클래스와 리플렉션]] 에서 정리한 두 메소드가 여기서도 그대로 일한다. 직접 만든 클래스를 키로 쓸 때 중복이 안 걸러지는 이유도 같은 자리에서 나온다.

출력된 순서가 넣은 순서와 다르다는 점도 확인해 둔다. `HashMap` 은 **순서를 보장하지 않는다.** 해시값으로 자리를 정해 담기 때문에, 넣은 차례와 무관한 순서로 나온다.

### 1-4. 값 꺼내기 — get

```java
System.out.println(map.get("강호동"));   // 30
```

`List` 가 `get(인덱스)` 로 몇 번째인지를 물었다면, `Map` 은 `get(키)` 로 **이름을 대고 값을 받는다.** 인덱스가 없으니 "몇 번째"라는 질문 자체가 성립하지 않는다.

| | 꺼내는 기준 |
| --- | --- |
| `List` | 인덱스 — `get(0)` |
| `Set` | 꺼내는 메소드가 없다 — 순회로만 |
| `Map` | 키 — `get("강호동")` |

없는 키를 넣으면 예외가 아니라 **`null` 이 돌아온다.** `List` 에서 범위를 벗어난 인덱스를 부르면 `IndexOutOfBoundsException` 이 났던 것과 다른 처리다. 조용히 `null` 이 나오는 쪽이 편할 때도 있지만, 그 값을 바로 계산에 쓰면 `NullPointerException` 으로 한 박자 늦게 터진다. 꺼낸 뒤 확인하는 습관이 필요한 자리다.

### 1-5. 크기·포함 여부 확인

```java
System.out.println(map.size());              // 3 — 엔트리 개수
System.out.println(map.containsKey("강호동"));  // true
System.out.println(map.containsValue(10));    // true
```

| 메소드 | 하는 일 |
| --- | --- |
| `size()` | 담긴 엔트리 수. 쌍 하나가 1이다 |
| `containsKey(키)` | 그 키가 있는지 `true`/`false` |
| `containsValue(값)` | 그 값을 가진 엔트리가 있는지 |

키를 넷 넣었는데 `size()` 가 3인 것이 1-3에서 본 덮어쓰기의 결과다.

찾는 비용은 두 메소드가 크게 다르다. `containsKey` 는 해시로 자리를 바로 계산해 확인하지만, `containsValue` 는 **값을 전부 훑어야 한다.** `Map` 이 빠른 것은 어디까지나 키로 찾을 때이고, 값으로 거꾸로 찾는 일이 잦다면 자료구조를 잘못 고른 신호로 보는 편이 낫다.

### 1-6. 키 전체·값 전체 꺼내기 — keySet, values

```java
System.out.println(map.keySet());   // [신동엽, 유재석, 강호동]
System.out.println(map.values());   // [10, 80, 30]
```

돌아오는 타입이 서로 다른 것이 1-1에서 정리한 성질 그대로다.

| 메소드 | 반환 | 이유 |
| --- | --- | --- |
| `keySet()` | `Set<K>` | 키는 중복되지 않으니 집합 |
| `values()` | `Collection<V>` | 값은 중복될 수 있으니 목록 |

출력이 `[ ]` 대괄호로 나오는 것도 이 둘이 `Map` 이 아니라 `Set`·`Collection` 이기 때문이다. 엔트리 전체(`{ }`)와 구분되는 지점이다.

`keySet()` 이 중요한 이유는 따로 있다. **`Map` 을 순회할 열쇠 꾸러미**가 되기 때문이다(1-8).

### 1-7. 삭제와 비우기

```java
map.remove("강호동");        // 키로 엔트리 하나 삭제
System.out.println(map);    // {신동엽=10, 유재석=80}

map.clear();                // 전부 삭제
System.out.println(map.isEmpty());   // true
```

| 메소드 | 하는 일 |
| --- | --- |
| `remove(키)` | 그 키의 엔트리(키·값 한 쌍)를 통째로 지운다 |
| `clear()` | 모든 엔트리를 지운다 |
| `isEmpty()` | 엔트리가 하나도 없으면 `true` |

지우는 단위가 **값이 아니라 엔트리**라는 점을 잡아 둔다. 키를 지우면 짝지어진 값도 함께 사라진다. `remove` 는 지워진 값을 반환하므로, 없는 키를 지우려 하면 `null` 이 돌아올 뿐 오류가 나지는 않는다.

`isEmpty()` 는 `size() == 0` 과 같은 뜻이지만, 의도가 문장에 드러나서 더 자주 쓰인다. `List`·`Set` 에서 쓰던 것과 이름·동작이 같은 메소드라 셋을 함께 외워 두면 편하다.

### 1-8. Map 순회 — 인덱스가 없으니 키로 돈다

`Map` 에는 인덱스가 없다. [[Java day14 제네릭]] 에서 정리한 순회 세 가지 중 **일반 for문은 쓸 수 없다.** `get(0)` 을 부를 수 없기 때문이다. `Set` 에서 막혔던 자리와 같다.

대신 `keySet()` 으로 키를 먼저 꺼내고, **그 키를 돌면서 값을 조회**한다.

**① 향상된 for문 + keySet**

```java
for (String key : map.keySet()) {
    System.out.println(key + ":" + map.get(key));
}
```

두 단계로 읽는다. `map.keySet()` 이 키만 모인 `Set` 을 돌려주고, 향상된 for문이 그 집합을 하나씩 훑는다. 각 회차에서 `map.get(key)` 로 짝이 되는 값을 꺼낸다. **키를 순회하고 값은 조회로 얻는다**는 구조다.

**② forEach + keySet**

```java
map.keySet().forEach((key) -> {
    System.out.println(key + ":" + map.get(key));
});
```

`keySet()` 이 돌려준 `Set` 의 `forEach` 를 부르는 형태다. 도는 일은 컬렉션에 맡기고 처리 내용만 람다로 넘기는 것도 앞에서 본 그대로다.

정리하면 이렇다.

| 방법 | `List` | `Set` | `Map` |
| --- | --- | --- | --- |
| 일반 for | O | X | X |
| 향상된 for | O | O | `keySet()` 을 거쳐서 |
| `forEach` | O | O | `keySet()`·`values()` 를 거쳐서 |

`Map` 만 한 단계를 더 거치는 이유는 **꺼낼 대상이 하나가 아니라 쌍**이라서다. 향상된 for문의 콜론 오른쪽에는 값이 하나씩 나오는 목록이 와야 하는데, 엔트리는 키와 값 둘이라 그대로 놓일 수 없다. 그래서 키만 뽑아 목록으로 만든 뒤 도는 우회를 쓴다.

값만 필요하다면 `map.values()` 를 직접 돌아도 된다. 키와 값을 함께 쓸 때 `keySet()` 을 쓴다.

### 1-9. 어디에 쓰이는가

`Map` 이 실제로 놓이는 자리를 두 갈래로 정리해 둔다.

**① 통신 구간 — JSON ↔ DTO/Map**

서버와 브라우저가 주고받는 데이터가 JSON이고, 그 모양이 1-2에서 본 대로 `Map` 과 같다. 자바 쪽에서 받을 때 **필드가 고정이면 DTO 클래스**로, **키가 유동적이면 `Map`** 으로 받는다.

```java
Map<String, Object> 응답 = new HashMap<>();
응답.put("성공여부", true);
응답.put("데이터", 목록);
```

DTO는 필드가 정해져 있어 오타가 컴파일에서 잡히고, `Map` 은 키를 자유롭게 넣을 수 있는 대신 오타가 실행 중에야 `null` 로 드러난다 — [[Java day14 제네릭]] 에서 본 "컴파일에서 잡는가, 실행에서 잡는가"의 대비가 여기에도 그대로 있다. 구조가 정해진 데이터는 DTO, 그때그때 달라지는 데이터는 `Map` 으로 나누는 편이 무난하다.

**② 이름으로 찾는 자료구조**

번호나 아이디로 데이터를 찾는 자리에 쓴다. 조회 결과를 `List` 로 쌓으면 원하는 항목을 찾을 때마다 처음부터 훑어야 하지만, `Map` 에 담아 두면 키로 바로 집을 수 있다.

```java
Map<Integer, BoardDto> 게시글모음 = new HashMap<>();
게시글모음.put(dto.getNo(), dto);
BoardDto 찾은글 = 게시글모음.get(3);
```

DAO에서 조회 결과를 `List` 로 반환할지 `Map` 으로 반환할지가 갈리는 지점이라 [[Java day12 종합예제 JDBC DAO]] 와 이어서 보면 쓰임이 잡힌다. 순서대로 화면에 뿌릴 것이면 `List`, 특정 번호를 반복해서 찾을 것이면 `Map` 쪽이다.

## 2. 추가로 알면 좋은 활용법

### 2-1. entrySet — 키와 값을 한 번에 꺼내기

`keySet()` 으로 돌면 회차마다 `map.get(key)` 를 한 번씩 더 부른다. 엔트리 자체를 꺼내면 그 조회가 사라진다.

```java
for (Map.Entry<String, Integer> entry : map.entrySet()) {
    System.out.println(entry.getKey() + ":" + entry.getValue());
}
```

`Map.Entry` 는 키와 값을 한 쌍으로 묶어 둔 타입이고, `getKey()`·`getValue()` 로 각각 꺼낸다. `Map` 자체에도 두 값을 함께 받는 `forEach` 가 있다.

```java
map.forEach((key, value) -> {
    System.out.println(key + ":" + value);
});
```

람다의 매개변수가 둘인 것이 `List`·`Set` 의 `forEach` 와 다른 점이다. 키와 값을 모두 쓰는 순회에서는 이 두 형태가 가장 짧다.

### 2-2. null을 피하는 조회 메소드들

`get()` 이 `null` 을 돌려주는 성질 때문에 확인 코드가 늘어나기 쉽다. 자주 쓰는 형태가 메소드로 준비돼 있다.

| 메소드 | 하는 일 |
| --- | --- |
| `getOrDefault(키, 기본값)` | 키가 없으면 기본값을 돌려준다 |
| `putIfAbsent(키, 값)` | 키가 없을 때만 넣는다 — 기존 값을 덮지 않는다 |
| `computeIfAbsent(키, 함수)` | 키가 없으면 함수로 값을 만들어 넣고 돌려준다 |
| `merge(키, 값, 병합함수)` | 있으면 병합, 없으면 그대로 넣는다 |

개수를 세는 코드가 대표적인 활용이다.

```java
Map<String, Integer> 개수 = new HashMap<>();
for (String 단어 : 단어들) {
    개수.put(단어, 개수.getOrDefault(단어, 0) + 1);
}
```

`Map` 이 "세기·묶기"에 강한 이유가 이 한 줄에 들어 있다. 처음 나온 단어면 0에서 시작하고, 이미 있으면 이전 값에 1을 더한다.

### 2-3. 구현체 고르기 — HashMap·LinkedHashMap·TreeMap

`Set` 이 `HashSet`·`LinkedHashSet`·`TreeSet` 으로 갈렸던 것과 같은 구도가 `Map` 에도 있다.

| 구현체 | 순서 |
| --- | --- |
| `HashMap` | 보장 없음 — 기본 선택 |
| `LinkedHashMap` | 넣은 순서 유지 |
| `TreeMap` | 키 기준 오름차순 정렬 |

`HashTable` 은 `HashMap` 과 구조가 같고 동기화가 붙은 옛 클래스다. `Vector` 가 `ArrayList` 에 밀린 것과 같은 이유로, 지금은 `HashMap` 을 기본으로 두고 필요할 때 `ConcurrentHashMap` 을 쓰는 쪽이 관례다.

`TreeMap` 은 키를 정렬해 담으므로 키 타입이 크기 비교가 가능해야 한다 — `Comparable` 구현이나 `Comparator` 가 필요한 것도 `TreeSet` 과 같다.

### 2-4. 키에 쓰기 좋은 타입

키는 `hashCode()`·`equals()` 로 판정되므로, **값이 변하지 않는 타입**이 안전하다. `String`·`Integer` 같은 불변 타입이 키로 자주 쓰이는 이유다.

직접 만든 클래스를 키로 쓰려면 두 메소드를 함께 재정의한다. 담은 뒤에 그 객체의 필드를 바꾸면 해시값이 달라져 **자기가 넣은 값을 못 찾는 상태**가 되므로, 키로 쓸 객체는 넣은 뒤 건드리지 않는 편이 안전하다.

### 2-5. Set과 Map은 사실 같은 구조다

`HashSet` 은 내부에 `HashMap` 을 두고 **키만 쓰는** 구조로 만들어져 있다. 값 자리에는 의미 없는 상수 객체가 들어간다. 그래서 두 컬렉션의 중복 판정이 똑같이 동작하고, `keySet()` 이 `Set` 을 돌려주는 것도 자연스럽다.

`Map` 하나를 이해하면 `Set` 은 그 절반이라고 보면 [[Java day14 제네릭]] 에서 본 두 컬렉션이 한 줄에 꿰인다.

### 2-6. 두 값을 묶는 다른 방법들

키·값 쌍을 담을 자리에 항상 `Map` 이 답은 아니다.

- 필드가 고정이면 **DTO 클래스** — 이름이 컴파일에서 검사된다
- 쌍이 하나뿐이면 `Map.entry(k, v)` 로 엔트리 하나만 만들 수도 있다
- 읽기 전용이면 `Map.of("a", 1, "b", 2)` 로 바로 만든다 — 수정하려 하면 예외가 난다

`Map` 은 키가 유동적이거나 개수가 정해지지 않을 때 쓰는 도구라고 잡아 두면 선택이 쉬워진다.

## 3. 더 나아가 알면 좋은 것

### 3-1. 해시 테이블이 빠른 이유

`HashMap` 이 키로 값을 즉시 찾는 것은 **키를 계산해서 저장 위치를 정하기** 때문이다. 순서를 훑는 것이 아니라 `hashCode()` 결과로 배열의 몇 번 칸에 넣을지를 계산한다. 꺼낼 때도 같은 계산을 하니 한 번에 자리를 찾는다.

서로 다른 키가 같은 칸을 계산해 내는 일(해시 충돌)이 생기면 그 칸에 여러 엔트리를 이어 두고 `equals()` 로 구분한다. 1-3에서 두 메소드가 짝으로 필요했던 이유가 여기 있다 — `hashCode()` 는 칸을 정하고 `equals()` 는 칸 안에서 고른다.

- 충돌이 심해지면 그 칸이 목록처럼 길어져 조회가 느려진다. 자바 8부터는 일정 길이를 넘으면 트리 구조로 바꿔 완만하게 만든다
- 담긴 개수가 늘면 배열을 키우고 전부 다시 배치한다(리사이즈). 담을 양을 대충 알면 생성자에 초기 크기를 주는 편이 낫다

### 3-2. 순서를 기억하는 방법의 차이

`LinkedHashMap` 은 해시 테이블에 **연결 리스트를 겹쳐** 순서를 기억한다. [[Java day14 제네릭]] 에서 본 `LinkedList` 의 노드 연결이 해시 구조 위에 얹힌 형태다. 조회는 해시로, 순회는 연결을 따라간다.

접근 순서로 정렬하는 모드를 켜면 오래 안 쓴 항목이 뒤로 밀리는데, 이 성질을 이용해 캐시(LRU)를 만드는 것이 알려진 활용이다.

### 3-3. 컬렉션 다음에 볼 것

`List`·`Set`·`Map` 을 다 훑었으니 그 위에 얹히는 것들이 남는다. 특히 **스트림**은 컬렉션을 "돌면서 처리"하는 코드를 통째로 바꾸는 도구라, 지금까지 for문으로 쓰던 것들이 한 줄로 줄어드는 지점이다.

### 3-4. 다음에 볼 키워드

- `Map.Entry`·`entrySet()` 순회와 두 인자 `forEach`
- `getOrDefault`·`putIfAbsent`·`computeIfAbsent`·`merge` 로 null 처리 줄이기
- `LinkedHashMap`·`TreeMap` 과 정렬 기준(`Comparable`·`Comparator`)
- 해시 충돌·리사이즈·`hashCode()` 규약
- `Collections.unmodifiableMap`·`Map.of` 로 읽기 전용 만들기
- `ConcurrentHashMap` 과 동시성 컬렉션
- `Queue`·`Deque`·`Stack` — 컬렉션의 나머지 갈래
- 스트림 API — `filter`·`map`·`collect`·`groupingBy`
