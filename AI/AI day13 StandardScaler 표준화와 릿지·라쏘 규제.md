# AI day13 — StandardScaler 표준화와 릿지·라쏘 규제

> 실습 파일: `day13/s-03.py`
> 허브: [[AI 정리본 인덱스]] · 이전: [[AI day13 다항 회귀 제곱항 추가와 PolynomialFeatures]] · 다음: [[AI day13 다항 규제 회귀 연습문제 풀이]]

앞 노트에서 특성을 9개로 펼친 다항 회귀가 0.97을 찍었고, 285개로 펼치자 0.07로 무너졌다. 이 노트는 그 뒷부분 — 특성이 많아졌을 때 두 가지를 해 주는 이야기다. 하나는 **표준화**(`StandardScaler`): 길이 16 cm와 길이² 262처럼 단위와 크기가 제각각인 특성을 평균 0·표준편차 1로 맞춘다. 다른 하나는 **규제**(`Ridge`·`Lasso`): 기울기가 멋대로 커지지 못하게 벌점을 매겨 과대적합을 누른다. 규제는 기울기 크기를 보고 벌점을 매기므로 특성 크기가 들쭉날쭉하면 공정하지 않다 — 그래서 **표준화가 규제의 전제 조건**이다. `alpha` 여섯 개를 돌려 학습 점수와 테스트 점수의 격차가 가장 작은 값을 찾고, 라쏘가 기울기 몇 개를 0으로 만들어 특성을 아예 지워 버리는 것까지 확인한다.

## 1. 배운 내용

### 1-1. 왜 표준화인가 — 항을 더하면 단위가 흩어진다

```python
print(X_train_poly[0])    # [ 16.2   4.59   2.63   262.44   74.40   42.63   21.09   12.09   6.93 ]
```

앞 노트 1-8에서 만든 다항 특성 한 행이다. 길이 16.2, 높이 4.6, 너비 2.6까지는 비슷한 크기인데, 길이² 262, 길이×높이 74처럼 **제곱·곱셈항은 한 자릿수 이상 크다**. 수업 주석의 표현대로 "특성이 많아짐에 따라 특성 간의 단위 표준화"가 필요해지는 지점이다. 선형 회귀 자체는 특성 크기에 비교적 둔감하지만, 다음 절의 규제는 기울기의 **크기**에 벌점을 매기므로 262짜리 특성과 2.6짜리 특성의 기울기를 같은 잣대로 재면 안 된다 — 큰 특성은 작은 기울기로도 충분해서 벌점을 덜 받고, 작은 특성은 큰 기울기가 필요해 벌점을 더 받는 불공정이 생긴다.

### 1-2. `StandardScaler` — 평균 0, 표준편차 1로

```python
from sklearn.preprocessing import StandardScaler
ss = StandardScaler()           # 객체 생성
ss.fit(X_train_poly)            # 항이 추가된 학습용 특성으로 열마다 평균·표준편차 계산
X_train_scaled = ss.transform(X_train_poly)
X_test_scaled = ss.transform(X_test_poly)     # 테스트용은 transform만

print(X_train_poly[0])     # [ 16.2    4.5924  ~~ ]
print(X_train_scaled[0])   # [-1.149  -1.063   ~~ ]
```

`PolynomialFeatures`와 똑같은 `fit` → `transform` 변환기다. `fit`이 하는 일은 **열마다** 평균과 표준편차를 구해 저장하는 것이고(`ss.mean_`·`ss.scale_`), `transform`은 각 값에서 그 열의 평균을 빼고 표준편차로 나눈다. day07에서 손으로 하던 z-score가 바로 이것이다.

```text
z = (x − 열 평균) / 열 표준편차
```

| 원본 값 | 열 평균 | 열 표준편차 | 표준화 값 |
| --- | --- | --- | --- |
| 길이 16.2 | 28.4 | 10.6 | (16.2 − 28.4) / 10.6 = **−1.15** |
| 높이 4.59 | 8.8 | 4.0 | **−1.06** |

수업 주석이 "평균보다 작으면 음수, 평균 + 1표준편차보다 크면 1 이상"이라고 적은 그대로다. 첫 행의 물고기는 모든 특성이 음수이므로 평균보다 작은 — 작은 물고기다. 표준화 뒤에는 모든 열이 대략 −3 ~ +3 사이에 놓여 262와 2.6의 차이가 사라지고, 어느 열의 기울기가 크든 "그 특성이 1표준편차 움직일 때 무게가 얼마나 변하나"라는 **같은 뜻**이 된다.

### 1-3. `fit`은 학습용에만 — 순서가 결과를 바꾸는 첫 변환기

```python
ss.fit(X_train_poly)                   # ① 학습용으로만 통계 계산
X_train_scaled = ss.transform(X_train_poly)
X_test_scaled  = ss.transform(X_test_poly)   # ② 같은 평균·표준편차로 테스트용 변환
```

앞 노트의 `PolynomialFeatures`는 어느 쪽에 `fit`하든 결과가 같았지만, `StandardScaler`는 다르다. 테스트용으로 `fit`하면 테스트 자료의 평균·표준편차가 모델에 스며들어 **테스트 점수가 부풀려진다**(데이터 누수). 실전에서 새 물고기 한 마리가 들어올 때 "그 한 마리의 평균"이라는 건 없으므로, 학습 때 저장해 둔 평균·표준편차로 변환하는 것이 유일하게 말이 되는 방식이다. `fit_transform(X_train)` 한 줄로 ①②를 합칠 수 있지만 테스트용에는 절대 `fit_transform`을 쓰지 않는다.

| 자료 | 호출 | 이유 |
| --- | --- | --- |
| 학습용 | `fit` → `transform` (또는 `fit_transform`) | 통계를 배우고 적용 |
| 테스트용 | `transform`만 | 학습용 통계를 그대로 적용 |
| 새 입력(예측) | `transform`만 | 위와 같음 |

### 1-4. 규제란 — 기울기 크기에 벌점

수업 주석의 정의: "기울기(가중치) 크기에 페널티를 부여하여 … 특성 완만/제외". 앞 노트 1-9에서 `degree=10`의 모델이 학습 점수 0.96·테스트 점수 0.07로 무너진 이유는 285개 기울기가 **제멋대로 커지며** 학습 자료의 잡음까지 맞췄기 때문이다. 규제는 손실 함수에 "기울기가 크면 벌점"을 더해, 오차를 줄이는 것과 기울기를 작게 유지하는 것 사이에서 타협하게 만든다.

```text
보통 선형 회귀:   오차² 합                     을 최소화
릿지(L2):        오차² 합 + alpha × Σ(기울기²)  을 최소화  → 기울기를 고르게 줄임
라쏘(L1):        오차² 합 + alpha × Σ|기울기|   을 최소화  → 일부 기울기를 정확히 0으로
```

| 모델 | 벌점 | 효과 | 사이킷런 |
| --- | --- | --- | --- |
| 릿지 | 기울기의 **제곱** 합 (L2) | 모든 기울기를 조금씩 0 쪽으로 — 완만하게 | `Ridge(alpha=)` |
| 라쏘 | 기울기의 **절댓값** 합 (L1) | 중요하지 않은 기울기를 **정확히 0**으로 — 특성 제외 | `Lasso(alpha=)` |

`alpha`가 규제 강도다. 수업 주석대로 "값이 커질수록 가중치/기울기를 0에 가깝게 규제"하고, 0이면 보통 선형 회귀와 같다.

### 1-5. 릿지 — `alpha`를 바꿔 가며 격차 보기

```python
from sklearn.linear_model import Ridge
alpha_list = [0.001, 0.01, 0.1, 1, 10, 100]
for alpha in alpha_list:
    model = Ridge(alpha=alpha)
    model.fit(X_train_scaled, Y_train)
    print(alpha, " :  --- 훈련용 학습 데이터 점수 vs 테스트용 학습 데이터 점수 --- ")
    print("Train R2: ", model.score(X_train_scaled, Y_train))
    print("Test R2: ", model.score(X_test_scaled, Y_test))
```

`LinearRegression` 자리에 `Ridge(alpha=…)`를 넣는 것 외엔 코드가 같다. `alpha` 후보 여섯 개를 **10배씩** 띄워 두고(0.001부터 100까지 — 규제 강도는 로그 눈금으로 훑는 것이 관례) 반복문으로 학습 점수와 테스트 점수를 나란히 찍는다.

| alpha | 학습 R² | 테스트 R² | 격차 |
| --- | --- | --- | --- |
| 0.001 | 0.983 | 0.972 | 0.011 |
| 0.01 | 0.983 | 0.972 | 0.011 |
| 0.1 | 0.982 | 0.972 | 0.010 |
| 1 | 0.978 | 0.975 | 0.003 |
| **10** | 0.963 | 0.970 | **−0.007** (테스트가 더 높음) |
| 100 | 0.926 | 0.949 | −0.023 |

`alpha`가 커질수록 학습 점수는 꾸준히 내려가고(기울기를 누르니 학습 자료를 덜 외운다), 테스트 점수는 1 근처에서 살짝 올랐다가 100에서 함께 내려간다. 수업 주석이 고른 답은 **`alpha=10`** — "훈련 점수와 테스트 점수 격차가 가장 적은" 지점이다. 학습 점수가 테스트 점수보다 높은 것은 당연하고, 그 격차가 작을수록 외운 것이 아니라 일반화된 것이라는 day12 2-1의 기준을 여기서 **고르는 도구**로 쓴다. 격차만 보면 10이지만 테스트 점수 자체는 1이 가장 높으므로, 어느 쪽을 택할지는 "안정성"과 "성능" 중 무엇을 우선하느냐의 문제다 — 수업은 안정성(격차)을 기준으로 삼았다.

9개 특성에서는 규제 없이도 0.972였기 때문에 효과가 크지 않다. 규제가 진짜 빛나는 자리는 앞 노트의 **차수 10·285개 특성**이다 — 그 특성을 표준화한 뒤 `Ridge(alpha=10)`을 씌우면 테스트 R²가 0.07에서 **0.97**로 돌아온다. 특성은 그대로 두고 기울기만 눌러서 과대적합을 치료한 것이다.

### 1-6. 라쏘 — 기울기를 0으로 만들어 특성 제거

```python
from sklearn.linear_model import Lasso
lasso = Lasso(alpha=10)
lasso.fit(X_train_scaled, Y_train)
print(lasso.score(X_train_scaled, Y_train))   # 0.959
print(lasso.score(X_test_scaled, Y_test))     # 0.961

import numpy as np
zero_features = np.sum(lasso.coef_ == 0)
print('기울기 0으로 제거된 특성 수 : ', zero_features)   # 6
```

클래스 이름만 `Lasso`로 바꿨다. 점수는 릿지와 비슷한데, 마지막 두 줄이 라쏘만의 특징을 보여 준다. `lasso.coef_ == 0`은 기울기 9개 각각이 0인지 묻는 참·거짓 배열이고, `np.sum`이 `True`를 1로 세어 **0이 된 기울기 개수**를 돌려준다(day06의 `(cond).sum()` 패턴). 결과는 **6개** — 9개 특성 중 6개가 모델에서 완전히 빠지고 3개만 남았다.

```python
print(np.round(lasso.coef_, 1))
# [  0.    0.    0.   70.2  83.1  191.7   0.    0.    0. ]
#  길이  높이  너비  길이²  길이·높이  길이·너비  높이²  높이·너비  너비²
```

남은 셋은 `길이²`·`길이×높이`·`길이×너비` — 전부 길이가 들어간 2차항이다. 물고기 무게가 "길이 × 단면"에 비례한다는 걸 라쏘가 자료만 보고 골라낸 셈이다. 릿지는 9개 기울기를 모두 작게 **줄이기만** 하고 0으로 만들지는 않는 데 비해, 라쏘는 절댓값 벌점의 성질 때문에 기울기가 정확히 0에 닿는다. 그래서 라쏘를 **특성 선택** 도구로도 쓴다.

| | 릿지 (L2) | 라쏘 (L1) |
| --- | --- | --- |
| 기울기 0이 되나 | 안 됨 — 작아질 뿐 | 됨 — 특성이 빠짐 |
| 특성끼리 비슷할 때 | 비슷한 기울기를 나눠 가짐 | 하나만 남기고 나머지 0 |
| 어울리는 상황 | 특성 대부분이 조금씩 유용 | 소수의 특성만 중요, 나머지는 잡음 |
| `alpha` 키우면 | 전체가 완만해짐 | 0인 특성이 늘어남 |

### 1-7. 이 날의 흐름 한 장

```text
특성 3개 ─PolynomialFeatures(fit: 학습용)─▶ 9개 ─StandardScaler(fit: 학습용)─▶ 평균 0·편차 1
                                                                │
                                        ┌───────────────────────┼───────────────────────┐
                                   LinearRegression         Ridge(alpha)            Lasso(alpha)
                                   0.983 / 0.972            10: 0.963 / 0.970       10: 0.959 / 0.961
                                                            격차 최소               특성 6개 → 0
```

수업 끝 주석의 세 줄이 결론이다. "다항에서 `StandardScaler()` 표준화 필수", "특성이 적으면(과소적합) 항 추가 / `degree`", "특성이 많으면(과대적합) 규제(L1 라쏘, L2 릿지) / `alpha`". 변환기 둘(`PolynomialFeatures`·`StandardScaler`)은 모두 학습용에 `fit`하고 테스트용엔 `transform`만, 모델 셋은 `fit`·`score` 사용법이 같다.

### 1-8. 수업 슬라이드 — 표준화 스케일링이란

스케일링(표준화)은 서로 다른 특성들의 **단위가 다를 때 공정하게 일정한 크기 단위로 맞추는 전처리**다. 왜 필요한가 — 어떤 특성의 수치 단위가 지나치게 크면 컴퓨터가 **숫자가 큰 특성을 더 중요하다고 착각**해 모델 결과를 통째로 지배해 버리기 때문이다.

슬라이드의 예시는 두 가지다. 물고기의 길이(수십 cm)와 무게(수백 g), 사람의 달리기 점수(70~90점)와 몸무게(40~1,100 kg). 단위와 범위가 다르니 그대로 넣으면 일관된 비교가 안 되고, 스케일링을 거치면 일정한 비율의 수치로 취급되어 모든 특성이 공정하게 학습에 반영된다. 그림의 저울이 그것이다 — 왼쪽 "단위 불균형"에서는 몸무게 쪽 추가 무거워 달리기 점수·물고기 길이가 소외되고, 오른쪽 "공정한 비교"에서는 네 특성이 전부 0~1 크기의 동그라미가 되어 저울이 수평이다.

| 자료 종류 | 방법 | 식 |
| --- | --- | --- |
| 일반 수치형 데이터 | `StandardScaler` — 평균 0, 표준편차 1로 표준화 | (원본 값 − 평균) / 표준편차 |
| 자연어(텍스트) 데이터 | 문장을 수치 벡터로 바꾼 뒤 **벡터 길이를 1로 고정**(normalize) | 값들의 제곱합의 루트로 나눔 — 예: `[0.2, 0.7, 0.5]` → 길이 1 |

첫째 줄이 이 노트의 1-2이고, 둘째 줄은 나중에 텍스트·임베딩을 다룰 때 다시 만나게 될 L2 정규화다. 같은 "크기 맞추기"인데 수치형은 **열(특성)마다**, 텍스트는 **행(문장)마다** 맞춘다는 방향 차이를 기억해 둔다.

### 1-9. 수업 슬라이드 — `StandardScaler` 네 줄의 뜻

| 코드 | 슬라이드 설명 |
| --- | --- |
| `StandardScaler()` | 각 특성의 평균을 0, 표준편차를 1로 맞추는 **Z-score 표준화** 변환기. 규제(`Ridge`·`Lasso`) 모델은 가중치의 절댓값·제곱 크기에 직접 페널티를 매기므로, 특성마다 자릿수가 다르면 큰 단위의 변수에만 규제가 불공평하게 집중되는 왜곡이 생긴다 — 그래서 규제 앞에 **필수** |
| `ss.fit(train_poly)` | 고차원으로 확장된 훈련 세트의 **열별 평균(`mean_`)과 표준편차(`scale_`)** 를 계산해 객체 안에 저장. 오직 훈련 세트만 기준으로 삼아야 평가 데이터 정보가 미리 새는 평가 왜곡을 막는다 |
| `ss.transform(train_poly)` | `fit`에서 구한 평균·표준편차로 `(x − mean) / std`를 각 샘플에 일괄 적용 — 모든 특성의 분포 중심을 0, 분산을 1로 |
| `ss.transform(test_poly)` | 테스트 데이터의 자체 평균·표준편차를 **새로 구하지 않고** 훈련 세트에서 학습한 기준을 그대로 적용. 배포된 모델에 새 샘플이 들어올 때도 학습 당시의 잣대를 일관되게 쓰는 원리 |

1-3에서 "순서가 결과를 바꾸는 첫 변환기"라고 적은 이유가 여기 네 줄에 다 들어 있다.

### 1-10. 수업 슬라이드 — 규제를 손으로 계산해 보기

슬라이드의 세 표현부터.

| 코드 | 슬라이드 설명 |
| --- | --- |
| `Ridge()` | 손실 함수에 **가중치들의 제곱합(L2 Norm)** 을 페널티로 더하는 L2 규제 선형 회귀. 특정 특성의 가중치가 비정상적으로 비대해지는 것을 억제해 회귀선을 완만하게 — 과적합 방지 |
| `for alpth in alpha_list:` | 모델이 스스로 배울 수 없어 사람이 지정해야 하는 **하이퍼파라미터** `alpha`를 지수적 간격(0.001~100)으로 바꿔 가며 거동을 관찰. 너무 작으면 규제가 안 걸려 과적합, 너무 크면 가중치를 과하게 눌러 과소적합 — **훈련 점수와 테스트 점수의 격차가 최소가 되는 균형점**을 경험적으로 찾는 과정 |
| `Lasso(alpha=10)` | 손실 함수에 **가중치들의 절댓값 합(L1 Norm)** 을 페널티로 부과하는 L1 규제. 릿지와 달리 덜 중요한 특성의 가중치를 **완전히 0으로 수렴**시켜 연산에서 배제하므로, 수백 개로 폭발한 다항 특성 중 유의미한 것만 남기는 **자동 특성 선택(Feature Selection)** 효과 |

슬라이드 아래의 손계산 예시가 "릿지는 0에 가깝게, 라쏘는 정확히 0"의 이유를 숫자로 보여 준다. 가정은 실제값 y = 10, 예측값 ŷ = w × x, x = 1 — 그러니 규제가 없으면 w = 10이 오차 0으로 최소다.

```text
릿지 (L2)  손실 = (10 − w)² + α·w²          → 최소점 w = 10 / (1 + α)
  ① α = 0  : 손실 = (10 − w)²            → w = 10     (오차 최소)
  ② α = 2  : 손실 = (10 − w)² + 2w²      → w ≒ 3.33   (크게 감소)
  ③ α = 8  : 손실 = (10 − w)² + 8w²      → w ≒ 1.11   (0에 아주 가깝게 억제, 0은 아님)

라쏘 (L1)  손실 = (10 − w)² + α·|w|         → 최소점 w = 10 − α/2  (음수가 되면 0에서 멈춤)
  ① α = 0  : 손실 = (10 − w)²            → w = 10     (오차 최소)
  ② α = 4  : 손실 = (10 − w)² + 4w       → w = 8      (절댓값 크기만큼 깎임)
  ③ α = 24 : 손실 = (10 − w)² + 24w      → w = 0      (페널티가 오차를 압도하여 완전히 제거)
```

릿지는 `α`를 아무리 키워도 w가 `10 / (1 + α)`라 **0에 가까워질 뿐 0이 되지 않는다** — 제곱 벌점은 w가 작아질수록 벌점의 기울기도 함께 작아져 마지막 한 조각을 밀어내지 못하기 때문이다. 라쏘는 벌점의 기울기가 `α`로 **일정**해서, 오차 쪽 기울기(`2(10 − w)`)가 `α`보다 작아지는 순간 w가 0에 닿고 거기서 멈춘다. 1-6에서 라쏘가 9개 중 6개 기울기를 정확히 0으로 만든 것이 이 산수의 결과이고, 3-1의 "원 vs 마름모" 그림은 같은 사실을 2차원에서 본 것이다.

## 2. 추가로 알면 좋은 활용법

### 2-1. 파이프라인으로 세 단계 묶기

```python
from sklearn.pipeline import make_pipeline
ridge_pipe = make_pipeline(
    PolynomialFeatures(include_bias=False),
    StandardScaler(),
    Ridge(alpha=10)
)
ridge_pipe.fit(X_train, Y_train)          # 원본 특성 3개만 넣는다
print(ridge_pipe.score(X_test, Y_test))   # 0.970
ridge_pipe.predict([[30, 10, 4]])         # 변환 두 번이 안에서 자동
```

1-2·1-3에서 `transform`을 여섯 번 호출했던 것이 전부 사라진다. 파이프라인은 `fit` 때 각 변환기를 순서대로 `fit_transform`하고 마지막 모델을 `fit`하며, `predict`·`score` 때는 변환기들을 `transform`만 거치게 한다 — **데이터 누수를 구조적으로 막아 주는** 도구다. 저장(`joblib.dump`)도 파이프라인 통째로 하면 전처리 규칙과 모델이 한 파일에 담긴다.

### 2-2. `alpha` 자동 선택 — `RidgeCV`·`LassoCV`

```python
from sklearn.linear_model import RidgeCV, LassoCV
ridge_cv = RidgeCV(alphas=[0.001, 0.01, 0.1, 1, 10, 100]).fit(X_train_scaled, Y_train)
print(ridge_cv.alpha_)        # 교차 검증으로 고른 alpha
lasso_cv = LassoCV(cv=5).fit(X_train_scaled, Y_train)
print(lasso_cv.alpha_)
```

1-5의 반복문은 테스트 세트를 보고 `alpha`를 골랐는데, 그러면 테스트 세트가 더 이상 "처음 보는 자료"가 아니다. `RidgeCV`·`LassoCV`는 **학습 자료 안에서 교차 검증**으로 `alpha`를 고르고, 테스트 세트는 마지막 평가에만 남겨 둔다. 반복문 패턴을 한 번 손으로 써 본 뒤에는 이쪽을 쓰는 편이 안전하다.

### 2-3. `alpha` 후보는 로그 눈금으로

```python
alphas = np.logspace(-3, 2, 6)    # [0.001, 0.01, 0.1, 1, 10, 100]
```

수업의 `alpha_list`를 `np.logspace`로 만들면 같은 값이 나온다. 0.001과 0.01의 차이가 10과 100의 차이만큼 중요하기 때문에 **등간격이 아니라 등비**로 후보를 두는 것이고, 그래프를 그릴 때도 `plt.xscale('log')`로 x축을 로그로 두어야 여섯 점이 고르게 보인다.

```python
train_scores, test_scores = [], []
for a in alphas:
    m = Ridge(alpha=a).fit(X_train_scaled, Y_train)
    train_scores.append(m.score(X_train_scaled, Y_train))
    test_scores.append(m.score(X_test_scaled, Y_test))
plt.plot(alphas, train_scores, label='train'); plt.plot(alphas, test_scores, label='test')
plt.xscale('log'); plt.legend(); plt.show()
```

1-5의 표를 선 두 개로 그린 것이다. 두 선이 가장 가까워지는 지점이 수업이 고른 `alpha=10`이다.

### 2-4. 남은 특성 이름 확인 — 라쏘를 특성 선택기로

```python
names = poly.get_feature_names_out()
print(names[lasso.coef_ != 0])     # ['Length2^2' 'Length2 Height' 'Length2 Width']
```

앞 노트 2-1의 `get_feature_names_out`과 1-6의 불리언 배열을 합치면 라쏘가 **살려 둔 특성 이름**이 바로 나온다. 특성이 수십 개일 때 "무엇이 중요한가"를 빠르게 훑는 용도로 라쏘를 먼저 돌려 보는 일이 흔하다. `SelectFromModel(Lasso(alpha=…))`로 이 선택을 변환기처럼 파이프라인에 끼울 수도 있다.

### 2-5. 라쏘 수렴 경고와 `max_iter`

라쏘는 공식이 아니라 반복 계산으로 기울기를 찾기 때문에 `alpha`가 아주 작거나 특성이 많으면 `ConvergenceWarning`(수렴하지 않았다)이 뜰 수 있다. `Lasso(alpha=…, max_iter=10000)`처럼 반복 횟수를 늘리거나 `alpha`를 조금 키우면 사라진다. 표준화를 안 했을 때도 자주 나는 경고라, 경고가 보이면 먼저 `StandardScaler`를 거쳤는지 확인한다.

### 2-6. 둘을 섞은 `ElasticNet`

```python
from sklearn.linear_model import ElasticNet
ElasticNet(alpha=1.0, l1_ratio=0.5)    # L1·L2 벌점을 절반씩
```

릿지의 안정성과 라쏘의 특성 선택을 함께 원할 때 쓴다. `l1_ratio`가 1이면 라쏘, 0이면 릿지다. 특성끼리 상관이 강할 때(길이1·길이2·길이3처럼) 라쏘가 하나만 남기고 나머지를 임의로 지워 버리는 것이 불안하면 엘라스틱넷이 중간 답이다.

### 2-7. 표준화 vs 정규화 — 무엇을 언제

| 변환기 | 식 | 결과 범위 | 어울리는 때 |
| --- | --- | --- | --- |
| `StandardScaler` | (x − 평균) / 표준편차 | 대략 −3 ~ 3, 평균 0 | 규제 선형 모델·SVM·PCA, 이상치가 적당할 때 |
| `MinMaxScaler` | (x − 최소) / (최대 − 최소) | 0 ~ 1 | 신경망 입력, 범위가 정해진 값 |
| `RobustScaler` | (x − 중앙값) / IQR | 중앙값 0 | 이상치가 많을 때 |

day07·08에서 손으로 하던 Min-Max 정규화와 z-score 표준화가 각각 `MinMaxScaler`·`StandardScaler`다. 둘 다 "열마다 크기를 맞춘다"는 목적은 같고, 규제 선형 모델엔 표준화가 관례다. 트리 계열 모델(결정 트리·랜덤 포레스트)은 특성 크기를 비교하지 않으므로 둘 다 필요 없다.

## 3. 더 나아가 알면 좋은 것

### 3-1. 규제가 기하학적으로 하는 일

릿지는 기울기 벡터를 **원(구)** 안에, 라쏘는 **마름모(다면체)** 안에 가두고 그 안에서 오차가 가장 작은 점을 고른다. 마름모는 꼭짓점이 축 위에 있어 최적점이 꼭짓점에 닿기 쉽고, 축 위의 점은 다른 좌표가 0이다 — 라쏘가 기울기를 정확히 0으로 만드는 이유가 이 그림 하나로 설명된다. 원은 꼭짓점이 없어 기울기가 작아질 뿐 0에 닿지 않는다.

### 3-2. 베이즈 관점 — 규제는 사전 믿음

릿지는 "기울기는 0 근처에 정규분포로 퍼져 있을 것"이라는 사전 믿음을, 라쏘는 "대부분 0이고 몇 개만 클 것"이라는 라플라스 분포 믿음을 수식에 넣은 것과 같다. `alpha`는 그 믿음의 강도다. 자료가 많아질수록 사전 믿음의 영향은 줄어들어 규제의 효과도 작아진다 — 127마리에서는 규제가 중요하지만 1만 마리면 덜 중요한 이유다.

### 3-3. 다중공선성과 릿지

길이1·길이2·길이3처럼 거의 같은 정보를 담은 특성이 함께 들어가면 보통 선형 회귀는 기울기가 한쪽은 +1000, 다른 쪽은 −990처럼 요동친다(day12 3-3의 다중공선성). 릿지는 제곱 벌점으로 이런 극단을 막아 두 기울기를 비슷한 크기로 나눠 갖게 한다 — 규제가 처음 고안된 동기가 바로 이 문제였다. 상관 히트맵(day09)에서 0.9 이상이 보이면 릿지를 떠올리는 것이 자연스럽다.

### 3-4. 조기 종료·드롭아웃 — 다른 얼굴의 규제

벌점항을 더하는 것만 규제가 아니다. day09의 `val_loss` 그래프에서 검증 손실이 다시 오르기 전에 학습을 멈추는 **조기 종료**, 신경망에서 뉴런을 무작위로 끄는 **드롭아웃**, 트리의 깊이 제한도 모두 "모델이 학습 자료를 외우지 못하게 제약한다"는 뜻에서 규제다. 과대적합이 보이면 "어떤 규제를 걸까"가 공통 질문이 된다.

### 3-5. 경사 하강법과 특성 스케일

`LinearRegression`은 공식으로 한 번에 풀지만 `SGDRegressor`·신경망은 경사 하강법으로 조금씩 내려간다. 특성 크기가 들쭉날쭉하면 손실 함수의 등고선이 길쭉한 타원이 되어 지그재그로 느리게 수렴하고, 표준화하면 원에 가까워져 빠르게 내려간다. 표준화가 규제의 공정성뿐 아니라 **학습 속도**에도 관여하는 이유다.

### 3-6. 다음에 볼 키워드

- `StandardScaler` · `mean_`/`scale_` · z-score · `fit`은 학습용에만·`transform`만 테스트용 · `fit_transform` · 데이터 누수
- 규제·L1/L2 벌점 · `Ridge(alpha)`/`Lasso(alpha)` · `alpha` 로그 눈금 `np.logspace` · 학습 vs 테스트 격차로 고르기
- `coef_ == 0` 개수 세기 · 특성 선택 · `get_feature_names_out()[coef_ != 0]` · `SelectFromModel`
- `make_pipeline(Poly, Scaler, Ridge)` · `RidgeCV`/`LassoCV` · `ElasticNet(l1_ratio)` · `ConvergenceWarning`/`max_iter`
- `MinMaxScaler`/`RobustScaler` · 트리 모델은 스케일 무관 · 다중공선성 · 조기 종료·드롭아웃 · `SGDRegressor`
