# AI day20 — NSMC 영화 리뷰 감성 분석 연습문제 풀이

> 실습 파일: `ML_practice/practice8.py`
> 허브: [[AI 정리본 인덱스]] · 이전: [[AI day20 Kiwi 형태소 분석과 TF-IDF로 네이버 쇼핑 리뷰 감성 분류]] · 다음: [[AI day21 구글 코랩 시작과 드라이브 마운트·런타임]]

`s-14.ipynb`에서 쇼핑 리뷰로 밟은 "정규표현식 정제 → Kiwi 토크나이저 → TF-IDF → 로지스틱 회귀 → 새 문장 예측"을 **네이버 영화 리뷰(NSMC)**로 처음부터 다시 쓰는 연습이다. 지시문은 다섯 단계이고 코드는 수업 파일과 거의 글자 단위로 같다 — 달라지는 것은 **자료**(쇼핑 → 영화, 라벨이 이미 0/1로 들어 있다), **사전 등록 단어와 추가 불용어**(도메인이 바뀌니 목록이 바뀐다), 그리고 **결과 숫자**다. 그래서 이 노트는 코드를 다시 설명하기보다 "같은 코드가 다른 자료에서 왜 다른 숫자를 내는가"에 무게를 둔다 — 테스트 정확도가 0.816에서 **0.728**로 9 %p 떨어지고, 셋째 리뷰가 중립이 아니라 **부정**으로 판정되는 이유다. 숫자는 파일 주석의 값과 이 노트에서 다시 돌린 값(kiwipiepy 0.24 · scikit-learn 1.9)이고, `random_state=42`가 고정돼 있어 같다.

## 1. 배운 내용

### 1-1. 자료 준비 — NSMC `ratings_train.txt`, `dropna(subset=['document'])`, 라벨은 이미 0/1

```python
url = 'https://raw.githubusercontent.com/e9t/nsmc/master/ratings_train.txt'
df = pd.read_table(url)            # id: 리뷰ID, document: 리뷰내용, label: 감성라벨(0: 부정, 1: 긍정)
df = df.dropna(subset=['document'])
df_sample = df.sample(n=5000, random_state=42).reset_index(drop=True)
```

**NSMC(Naver Sentiment Movie Corpus)**는 한국어 감성 분석의 표준 벤치마크다 — 네이버 영화 평점 1~10점에서 1~4점을 부정(0), 9~10점을 긍정(1)으로 둔 20만 건 중 훈련용 15만 건이 `ratings_train.txt`에 있다. 수업 자료와 같은 **탭 구분 텍스트**라 `read_table`로 읽는데, 세 가지가 다르다.

| | 쇼핑 리뷰(`s-14.ipynb`) | 영화 리뷰(이 연습) |
| --- | --- | --- |
| 헤더 | 없음 → `names=['rating', 'review']` | **있음**(`id`·`document`·`label`) → `names=` 불필요 |
| 타깃 | `rating` 1~5 → `!= 3` 제외 → `>= 4` 로 0/1 생성 | `label` **0/1이 이미 들어 있다** — 중립(5~8점)은 자료 만들 때 이미 빠짐 |
| 결측 | 없음 | `document`에 `NaN` **5건** → `dropna(subset=['document'])` |

`dropna(subset=['document'])`는 day19 연습의 `dropna(subset=['TotalCharges'])`와 같은 꼴로, 리뷰 본문이 비어 있는 5행만 지워 149,995건이 남는다 — `subset=`을 안 주면 `id`·`label`의 결측까지 보지만 여기서는 결과가 같다. 결측을 미리 지우니 1단계의 `str(text)`가 `'nan'`이라는 가짜 단어를 만들 일이 없다. 5,000건을 뽑으면 부정 2,540 · 긍정 2,460으로 쇼핑 자료처럼 **거의 반반**이고, 리뷰 한 건 평균 34글자로 쇼핑 리뷰(39글자)보다 조금 짧다.

### 1-2. 단계 1 — 같은 정규표현식, 다른 결과: 빈 문자열 23건

```python
cleaned_list = []

```

수업 1단계와 **글자 하나 다르지 않다** — 열 이름만 `review`에서 `document`로 바뀌었다. 그런데 결과에 차이가 하나 생긴다. 쇼핑 리뷰에서는 정제 뒤 빈 문자열이 0건이었는데 영화 리뷰에서는 **23건**이다 — `ㅋㅋㅋㅋ`, `ㅠㅠ`, `...`, `!!!`처럼 **자모·기호만으로 된 리뷰**가 영화 댓글에는 흔해서, `가-힣` 범위(완성형 음절)에 들지 않는 `ㅋ`·`ㅠ`가 전부 공백으로 바뀌고 나면 아무것도 남지 않는다. 빈 문장은 7단계에서 **모든 열이 0인 행**이 되어 모델에 아무 정보도 주지 않고, 라벨만 남아 평가 점수를 깎는다. 쇼핑 리뷰는 "상품 설명"이 섞인 글이고 영화 리뷰는 "감정 표출"이 많은 댓글이라는 **자료의 성격 차이**가 정규표현식 한 줄의 결과를 바꾼 첫 자리다.

### 1-3. 단계 2 — 사전 등록 단어와 추가 불용어를 **영화 도메인**으로

```python
kiwi = Kiwi()
for word in ['노잼', '꿀잼', '갓작', '발연기', '인생영화']:
    kiwi.add_user_word(word, 'NNG')

kiwi_stopwords = Stopwords()
custom_stopwords = {'영화', '진짜', '정말', '그냥', '너무', '완전'}

def tokenize_kiwi(text):                 # 수업과 동일
    tokens = kiwi.tokenize(text, stopwords=kiwi_stopwords)
    target_tags = {'NNG', 'NNP', 'VV', 'VA', 'MAG'}
    result = []
    for t in tokens:
        if t.tag in target_tags and t.form not in custom_stopwords:
            if len(t.form) > 1 or t.form in {'못', '잘'}:
                word = t.form + '다' if t.tag in {'VV', 'VA'} else t.form
                result.append(word)
    return result

print(tokenize_kiwi(df_sample['cleaned_review'].iloc[0]))   # 원본이 최고 → ['원본', '최고']
```

함수 몸통은 수업과 같고 **두 목록만** 바뀌었다. 이 연습이 묻는 것은 "도메인이 바뀌면 전처리의 어디를 고치는가"이고, 답이 이 두 줄이다.

**사전 등록 단어** — 등록하지 않으면 Kiwi가 어떻게 쪼개는지 이 노트에서 확인하면 이유가 보인다.

| 등록 단어 | 등록 안 했을 때 | 문제 |
| --- | --- | --- |
| `노잼` | `노/NNG + 잼/NNG` | "노"라는 뜻 없는 명사가 생기고 `잼`은 `꿀잼`과 **같은 열**이 된다 — 반대 감정이 한 단어로 |
| `꿀잼` | `꿀/NNG + 잼/NNG` | `꿀`은 식품, `잼`은 위와 충돌 |
| `갓작` | 사전 밖 조각 | 갈라지면 뜻이 사라진다 |
| `발연기` | `발/NNG + 연기/NNG` | **`연기`가 긍정 리뷰의 "연기 좋다"와 같은 열**이 된다 — 부정 신호가 긍정 단어로 흡수 |
| `인생영화` | `인생/NNG + 영화/NNG` | `영화`는 추가 불용어라 사라지고 `인생`만 남는다 |

`발연기`가 가장 좋은 예다 — 등록이 없으면 "발연기"라는 **강한 부정** 표현이 "연기"라는 **중립~긍정** 열에 섞여 들어가 모델이 혼동한다. 1-5의 가중치 표에서 `노잼`이 −1.50으로 부정 상위 15위 안에 든 것이 등록의 효과다.

**추가 불용어** — `영화`가 핵심이다. 영화 리뷰에서 "영화"는 거의 모든 문장에 나오니 IDF가 바닥이고 감정 방향도 없다 — 쇼핑 리뷰에서 "상품"·"제품"이 그런 자리인데 수업은 그것을 빼지 않았고, 이 연습은 뺐다. `진짜`·`정말`·`너무`·`완전`은 **강조 부사**다 — "진짜 재밌다"와 "진짜 최악" 양쪽에 똑같이 붙어 방향이 없다. 수업의 `그냥`은 그대로 남기고 `그저`·`모른다`는 빠졌다 — 영화 댓글에서 "모른다"는 유보가 아니라 "뭘 말하는지 모르겠다"는 부정일 때가 많아서다. 불용어 목록은 **자료마다 다시 정하는 것**이라는 점이 이 단계의 교훈이다.

### 1-4. 단계 3 — 같은 TF-IDF, 어휘 4,106 → **5,175**

```python
X_train, X_test, Y_train, Y_test = train_test_split(
    df_sample['cleaned_review'], df_sample['label'],
    test_size=0.2, random_state=42, stratify=df_sample['label'])

tfidf = TfidfVectorizer(tokenizer=tokenize_kiwi, token_pattern=None)
X_train_tfidf = tfidf.fit_transform(X_train)
X_test_tfidf = tfidf.transform(X_test)
print(X_train_tfidf.shape)   # (4000, 5175)
print(X_test_tfidf.shape)    # (1000, 5175)
print(tfidf.get_feature_names_out()[:10])
# ['007 나를 사랑한 스파이' '007 문레이커' '13구역' '7광구' '가게' '가관' '가까이' '가끔' '가능' '가득']
```

코드는 수업 6~7단계와 같고 결과만 다르다. 같은 4,000문장인데 어휘가 **5,175개**로 쇼핑(4,106)보다 26 % 많다 — 영화 리뷰는 영화 제목·배우 이름·장르·감독 등 **고유 어휘**가 쇼핑 리뷰보다 훨씬 다양해서다. 어휘 앞머리에 `'007 나를 사랑한 스파이'`·`'007 문레이커'`·`'7광구'`가 띄어쓰기를 품은 **한 토큰**으로 들어 있는 것이 그 증거다 — Kiwi가 영화 제목을 고유명사(`NNP`) 하나로 묶어 낸 것이고, 토크나이저가 `NNP`를 남기도록 돼 있으니 그대로 열이 된다. 쇼핑 어휘의 `'가게'·'가격'·'가격대'`와 나란히 두면 두 도메인의 성격이 첫 열 열 개에서 이미 갈린다.

| | 쇼핑 | 영화 |
| --- | --- | --- |
| 어휘(열) | 4,106 | **5,175** |
| 0 아닌 칸 | 21,415 (리뷰당 5.4단어) | 17,755 (리뷰당 **4.4단어**) |
| 밀도 | 0.13 % | 0.086 % |
| 한 번만 나온 단어 | 2,357 (57 %) | **3,315 (64 %)** |
| 테스트 중 어휘와 겹치는 단어가 하나도 없는 행 | 32 | **103** |

열은 늘고 행마다 남는 단어는 줄었다 — **더 희소하고 더 흩어진** 행렬이다. 어휘의 64 %가 한 번만 나온 단어이고(영화 제목·이름이 대부분 이쪽이다), 테스트 1,000건 중 **103건(10 %)**은 훈련 어휘와 단어가 하나도 겹치지 않아 모두 0인 행으로 들어간다 — 1-2의 빈 문자열 23건에 "훈련에 없던 단어로만 쓴 리뷰" 80건이 더해진 것이다. 모델은 그 103건을 절편 부호 하나로 찍을 수밖에 없다. 뒤에 나오는 정확도 차이의 절반은 여기서 이미 결정된다.

### 1-5. 단계 4 — 같은 로지스틱 회귀, 0.816 → **0.728**

```python
model = LogisticRegression(C=1.0, max_iter=1000, random_state=42)
model.fit(X_train_tfidf, Y_train)
print(model.score(X_train_tfidf, Y_train))   # 0.88175
print(model.score(X_test_tfidf, Y_test))     # 0.728
Y_pred = model.predict(X_test_tfidf)
print('f1 : ', f1_score(Y_test, Y_pred))     # 0.7068965517241379
```

| 지표 | 쇼핑 | 영화 | 차이 |
| --- | --- | --- | --- |
| 훈련 정확도 | 0.890 | 0.882 | −0.8 %p |
| 테스트 정확도 | 0.816 | **0.728** | **−8.8 %p** |
| F1(긍정) | 0.809 | 0.707 | −10.2 %p |
| 훈련 − 테스트 | 7.4 %p | **15.4 %p** | 과대적합 두 배 |

훈련 정확도는 거의 같은데 테스트가 9 %p 떨어졌다 — **외운 것은 같은 만큼인데 새 문장에 통하는 정도가 다르다**는 뜻이다. 이유를 1-2·1-4에서 모아 보면 이렇다. ① 전부 0인 행 103건은 맞혀도 우연이다. ② 어휘의 64 %가 한 번 나온 단어라 가중치 대부분이 훈련 문장 한 건의 라벨을 외우는 데 쓰였고, 테스트에는 그 단어가 없다. ③ 영화 리뷰는 "연기는 좋은데 스토리가 별로"처럼 **한 문장에 긍·부정이 섞인** 글과 반어("돈 아깝지 않은 영화… 라고 말하고 싶었다")가 쇼핑 리뷰보다 많아, 단어 봉지만으로는 방향을 잡기 어렵다. 혼동행렬은 부정 508건 중 400 맞춤, 긍정 492건 중 328 맞춤 — **긍정을 부정으로** 보는 실수(164건)가 반대(108건)보다 1.5배 많고, 그래서 F1(긍정 재현율 0.667)이 정확도보다 더 떨어진다.

가중치 상위를 보면 모델이 배운 것 자체는 그럴듯하다(이 노트).

| 부정 쪽 | 긍정 쪽 |
| --- | --- |
| `재미없다` −2.81 · `쓰레기` −2.67 · `짜증` −2.59 · `최악` −2.58 · `수준` −1.90 · `별로` · `지루하다` · `실망` · `알바` · `전혀` · `졸작` · `허접` · `어이없다` · **`노잼`** −1.50 | `최고` +4.40 · `재미있다` +3.49 · `재밌다` +2.94 · `감동` +2.53 · `사랑` · `다시` +2.25 · `마음` · `눈물` · `멋지다` · `재밋` · `여운` · `추천` · `완벽` |

두 가지가 눈에 띈다. `재미있다`·`재밌다`·`재밋`이 **세 열로 갈라져** 있다 — `재밌다`는 `재미있다`의 줄임이고 `재밋`은 오타인데 BoW는 셋을 다른 단어로 본다(수업 7단계 주석의 "오타 → 다른 단어" 문제가 쇼핑 자료보다 영화 댓글에서 훨씬 심하다). 그리고 `다시`가 쇼핑에서는 **부정**(−1.95, "다시는 안 산다")이었는데 영화에서는 **긍정**(+2.25, "다시 보고 싶다")이다 — 같은 단어의 감정 방향이 도메인에 따라 뒤집히니, 쇼핑으로 학습한 모델을 영화에 그대로 쓸 수 없다는 뜻이다.

### 1-6. 단계 5 — 새 영화 리뷰 3건, 임계값 경계가 `>`/`<`로, 셋째가 **부정**

```python
new_reviews = [
    "배우들 연기력이 미쳤고 스토리 몰입감이 최고입니다! 무조건 극장에서 보세요.",
    "시간 아깝고 연출도 엉망이라 중간에 나올 뻔했네요. 최악의 영화입니다.",
    "킬링타임용으로 나쁘지 않지만 그렇다고 특별히 기억에 남지도 않네요."
]
cleaned_new = []
for text in new_reviews:
    text = re.sub(r'[^가-힣a-zA-Z0-9\s]', ' ', str(text))
    cleaned_new.append(' '.join(text.split()))
new_tfidf = tfidf.transform(cleaned_new)
probs = model.predict_proba(new_tfidf)
for i in range(len(new_reviews)):
    pos = probs[i][1]
    if pos > 0.6:     contents = '긍정(1)'
    elif pos < 0.4:   contents = '부정(0)'
    else:             contents = '중립(애매함)'
    print(f'리뷰: {new_reviews[i]}')
    print(f'감성분석: {contents} , 긍정확률:{pos}, 부정확률:{probs[i][0]}')
```

```
배우들 연기력이 미쳤고 스토리 몰입감이 최고입니다! 무조건 극장에서 보세요.  → 긍정(1)   긍정확률 0.7789  부정확률 0.2211
시간 아깝고 연출도 엉망이라 중간에 나올 뻔했네요. 최악의 영화입니다.        → 부정(0)   긍정확률 0.0821  부정확률 0.9179
킬링타임용으로 나쁘지 않지만 그렇다고 특별히 기억에 남지도 않네요.          → 부정(0)   긍정확률 0.3502  부정확률 0.6497
```

흐름은 수업 9단계와 같다 — 같은 `re.sub`, `fit` 없이 `tfidf.transform`, `predict_proba`, 임계값 둘. 지시문이 "0.4 이상 0.6 **이하**이면 중립, 0.6 **초과** 긍정, 0.4 **미만** 부정"이라 수업의 `>=`/`<=`가 `>`/`<`로 바뀌었다 — 경계값 0.4·0.6 자체가 어느 쪽에 속하는지만 다르고, 세 리뷰 모두 경계에 걸리지 않아 결과는 같다. 라벨 문자열에 `(1)`·`(0)`·`(애매함)`을 붙인 것은 지시문 표기 그대로다.

결과를 수업과 견주면 둘이 다르다. 첫 리뷰의 긍정 확률이 쇼핑의 0.92보다 낮은 **0.78**이다 — `배우`·`연기력`·`미치다`·`스토리`·`몰입`·`최고`·`무조건`·`극장` 여덟 단어 중 강한 긍정은 `최고` 하나고, `미치다`는 "연기력이 미쳤다"(긍정)와 "미친 영화"(욕) 양쪽에 쓰여 방향이 약하다. 더 중요한 것은 **셋째 리뷰가 중립이 아니라 부정**이라는 점이다. 토큰은 `['킬링', '타임', '나쁘다', '특별히', '기억']` 다섯 개로(`않`·`지만`·`그렇다고`는 불용어, `남`은 1글자), 각 단어의 기여를 더해 보면 `기억` +0.59에 `나쁘다` −0.37 · `타임` −0.37 · `킬링` −0.28이 맞서 긍정 확률 0.35 → 부정이다. 쇼핑에서는 `나쁘다`가 +0.17로 **약한 긍정**("나쁘지 않아요"가 긍정 리뷰에 흔함)이었는데 영화에서는 **부정**이다 — 영화 댓글의 "나쁘다"는 "나쁘지 않다"보다 "연기 나쁘다"로 더 자주 쓰여서다. `킬링타임`도 `킬링`·`타임`으로 갈라져 둘 다 부정 가중치를 받았다 — "킬링타임용"은 영화 리뷰에서 "그 정도 가치밖에 없다"는 미지근한 평이고, 모델은 그것을 부정으로 배웠다. 사람이 읽으면 중립인 글을 모델이 부정으로 보는 것은 틀린 판정이라기보다 **"어디까지를 중립으로 둘 것인가"가 임계값 두 개로는 안 잡히는 경우**다 — 0.35는 0.4 바로 아래라 중립 구간을 0.3~0.7로 넓히면 중립이 된다(수업 노트 3-3의 임계값 조정이 이 자리다).

## 2. 추가로 알면 좋은 활용법

### 2-1. 빈 문장과 어휘 밖 문장을 먼저 세어 보기

```python
empty = (df_sample['cleaned_review'] == '').sum()                   # 23
zero_rows = int((X_test_tfidf.getnnz(axis=1) == 0).sum())          # 103
```

1-2·1-4의 두 숫자는 모델을 돌리기 **전에** 알 수 있는 것이다. 정제 뒤 빈 문자열은 `df_sample[df_sample['cleaned_review'] != '']`로 빼고(라벨만 있는 행은 학습에 해롭다), 어휘 밖 문장이 10 %면 `min_df`를 올리는 것이 아니라 **자료를 늘려야** 한다는 신호다 — 15만 건 중 5,000건만 쓴 것이 이 연습의 가장 큰 제약이다. 자모만 남은 리뷰(`ㅋㅋ`·`ㅠㅠ`)는 실제로는 감정 정보가 있으니, 정규표현식에 `ㄱ-ㅎㅏ-ㅣ`를 더해 자모를 살리고 `kiwi.tokenize(..., normalize_coda=True)`로 처리하는 길도 있다.

### 2-2. `C`를 움직여 과대적합 재기 — 이 자료에서는 거의 안 변한다

| `C` | 쇼핑 훈련 / 테스트 | 영화 훈련 / 테스트 |
| --- | --- | --- |
| 0.1 | 0.796 / 0.789 | 0.755 / 0.713 |
| **1.0** | 0.890 / 0.816 | 0.882 / 0.728 |
| 10 | 0.942 / 0.798 | 0.935 / 0.729 |

규제를 열 배 세게 해도(`C=0.1`) 영화 테스트는 0.713으로 떨어지고, 열 배 약하게 해도(`C=10`) 0.729로 그대로다 — **규제로 고칠 수 있는 과대적합이 아니다.** 1-4의 희소함(어휘 밖 문장·한 번 나온 단어)은 모델 인자가 아니라 자료와 표현의 문제라서다. day13 릿지에서 `alpha`가 점수를 크게 움직이던 것과 대비되는 결과이고, "어느 손잡이를 돌려야 하는가"를 가르쳐 준다. 기본 공백 토크나이저로 바꿔 돌리면 어휘 16,593개에 테스트 **0.746**으로 Kiwi 쪽(0.728)보다 오히려 조금 높은데, 어미까지 열로 남아 "재밌어요"·"재밌네요"가 따로 세어지는 것이 짧은 댓글에서는 손해가 아니었다는 뜻이다 — 형태소 분석이 늘 이기는 것은 아니고, 벡터라이저 인자와 함께 **교차 검증으로 골라야 할 선택지**다.

### 2-3. `Pipeline(tfidf, logreg)` + `GridSearchCV`로 전처리 인자까지 한 번에

```python
from sklearn.pipeline import Pipeline
from sklearn.model_selection import GridSearchCV
pipe = Pipeline([('tfidf', TfidfVectorizer(tokenizer=tokenize_kiwi, token_pattern=None)),
                 ('lr', LogisticRegression(max_iter=1000, random_state=42))])
params = {'tfidf__min_df': [1, 2, 3], 'tfidf__ngram_range': [(1, 1), (1, 2)], 'lr__C': [0.3, 1, 3]}
grid = GridSearchCV(pipe, params, cv=5, scoring='f1', n_jobs=-1).fit(X_train, Y_train)
```

day14의 `Pipeline`·`GridSearchCV`를 텍스트에 그대로 쓴 꼴이다. 벡터라이저가 파이프라인 안에 있으니 교차 검증의 폴드마다 **훈련 폴드로만 어휘를 `fit`**해 누수가 없고, `joblib.dump(grid.best_estimator_)` 하나로 토크나이저 설정·어휘·가중치가 함께 저장돼 1-6의 "같은 정제 → 같은 transform"을 사람이 반복하지 않아도 된다. 단, `tokenize_kiwi`는 모듈 수준 함수여야 `joblib`이 직렬화한다(람다·중첩 함수는 안 된다)는 점과, `Kiwi()` 객체는 저장 파일에 들어가지 않으니 불러 쓰는 쪽에서 같은 사전 등록을 다시 해야 한다는 점을 적어 둔다.

### 2-4. 도메인마다 모델을 — 쇼핑 모델로 영화를 예측하면

1-5에서 `다시`·`나쁘다`의 부호가 도메인에 따라 뒤집히는 것을 봤다. 쇼핑 리뷰로 학습한 `tfidf`·`model`에 영화 리뷰 테스트 1,000건을 넣으면 정확도가 0.6 근처로 내려간다 — 어휘가 다르고(`배송`·`가성비` vs `연기`·`스토리`), 같은 단어의 방향도 다르기 때문이다. 감성 분석 모델은 **학습한 도메인 안에서만** 신뢰할 수 있고, 새 도메인에는 그 도메인 자료로 다시 학습하거나 최소한 1-3의 두 목록을 다시 정해야 한다. 이것이 "전처리 코드는 같고 사전·불용어만 바꾼다"는 이 연습의 구성이 가르치는 것이다.

## 3. 더 나아가 알면 좋은 것

### 3-1. NSMC 벤치마크의 숫자들 — 이 연습이 서 있는 자리

NSMC 15만 건 전체로 TF-IDF + 선형 모델을 돌리면 정확도 **0.83~0.85**, KoBERT·KcELECTRA 같은 사전학습 모델을 미세조정하면 **0.90~0.91**이 알려진 수준이다. 5,000건으로 0.728이 나온 이 연습은 그 사다리의 맨 아래 칸이고, 자료 30배(→ 0.84 근처)와 모델 교체(→ 0.90)가 각각 어느 정도의 몫인지 감을 주는 기준점으로 삼을 만하다. 벤치마크 자료의 좋은 점은 **남이 낸 숫자와 비교할 수 있다**는 것이다 — 자기 자료에서는 0.728이 좋은지 나쁜지 알 길이 없다.

### 3-2. 반어·혼합 감정·문맥 — 단어 봉지가 못 보는 것

"돈 아깝지 않은 영화… 라고 말하고 싶었다", "연기는 좋은데 스토리가 별로"는 단어만 세면 긍·부정이 반반이다. 순서와 문맥을 보는 모델 — RNN/LSTM(순서), 그리고 **어텐션** 기반의 BERT(문장 안 모든 단어가 서로를 본다) — 이 이것을 어느 정도 읽는다. 더 나가면 **속성 기반 감성 분석(ABSA)**이 "연기 → 긍정, 스토리 → 부정"처럼 대상별로 감정을 나눠 매긴다. 한국어 공개 모델은 Hugging Face에서 `beomi/KcELECTRA-base`(댓글로 학습)가 NSMC류 자료에 바로 맞는다.

### 3-3. 라벨이 없을 때 — 토픽 모델링·워드클라우드·클러스터링

이 연습은 라벨(0/1)이 있는 **지도학습**이었다. 라벨 없는 리뷰 더미에서 "무슨 이야기가 많은가"를 보려면 TF-IDF 행렬에 day19의 비지도 기법을 그대로 올린다 — `TruncatedSVD`(희소 PCA)로 줄여 KMeans로 묶거나, `LatentDirichletAllocation`으로 **토픽**(함께 나오는 단어 묶음)을 뽑고, 토픽별 상위 단어를 워드클라우드로 그린다. 텍스트 마이닝의 두 축 — 감성 분석(지도)과 토픽 모델링(비지도) — 이 같은 TF-IDF 행렬 위에서 갈린다.

### 3-4. 다음에 볼 키워드

- NSMC·KorNLI·KLUE — 한국어 NLP 벤치마크
- `normalize_coda`·자모 정규식(`ㄱ-ㅎㅏ-ㅣ`) — 댓글 전처리
- 도메인 적응(domain adaptation) — 쇼핑 모델을 영화에 쓸 수 없는 이유
