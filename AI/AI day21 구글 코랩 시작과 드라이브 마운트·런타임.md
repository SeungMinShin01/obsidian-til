## 1. 배운 내용

### 1-1. 코랩은 "브라우저로 쓰는 남의 컴퓨터의 주피터"

`day20/s-14.ipynb`도 주피터 노트북이었지만 그건 내 PC에서 돌렸다(`Python 3 (ipykernel)`). 코랩은 같은 `.ipynb` 형식을 **구글이 빌려주는 리눅스 가상 머신** 위에서 실행하고, 화면만 브라우저로 보는 서비스다. 그래서 `dl-1.ipynb`의 첫 셀 출력이 `Mounted at /content/drive`인데 — `/content`는 내 PC에 없는 경로고, 코랩 가상 머신의 작업 폴더다. 출력이 들어 있다는 것은 이 파일이 코랩에서 실행된 뒤 저장소로 내려받아진 것이라는 뜻이다.

| | 로컬 주피터 (day20까지) | 구글 코랩 (day21부터) |
| --- | --- | --- |
| 실행되는 곳 | 내 PC | 구글 클라우드의 가상 머신(= **런타임**) |
| 파일 위치 | `C:\...\KDT_2026\...` | `/content/` (임시) · `/content/drive/MyDrive/` (내 드라이브) |
| 패키지 | 내가 `pip install` | 넘파이·판다스·사이킷런·텐서플로·파이토치가 **미리 설치** |
| GPU | 없음(또는 내 그래픽카드) | 런타임 유형에서 **T4 GPU** 선택 가능 |
| 상태 유지 | 커널을 끄기 전까지 | 런타임이 끊기면 변수·설치·`/content` 파일 전부 초기화 |
| 비용 | 없음 | 무료(한도 있음) / 유료 Pro |

핵심은 두 줄이다. **GPU가 있다**는 것(딥러닝을 로컬 CPU로 돌리면 몇 시간이 몇 분이 된다), 그리고 **머신이 일회용**이라는 것(그래서 1-2의 드라이브 마운트가 첫 셀이다).

### 1-2. 첫 셀 — `drive.mount('/content/drive')`

```python
from google.colab import drive
drive.mount('/content/drive')
# Mounted at /content/drive
```

`google.colab`은 코랩 런타임에만 있는 모듈이라 로컬에서는 import 자체가 안 된다. `drive.mount(경로)`를 실행하면 구글 계정 인증 창이 뜨고, 허용하면 내 구글 드라이브 전체가 가상 머신의 `/content/drive` 폴더 아래에 **디스크처럼 붙는다**(마운트). 내 드라이브의 파일은 `/content/drive/MyDrive/...` 경로로 보인다 — `MyDrive`는 드라이브 웹 화면의 "내 드라이브"다.

이걸 맨 먼저 하는 이유는 1-1 표의 "상태 유지" 줄이다. 코랩 런타임은 일정 시간이 지나거나 유휴 상태가 길어지면 끊기고, 끊기면 `/content`에 두었던 CSV·학습한 모델 `.pkl`·그린 그림이 전부 사라진다. 드라이브 아래에 두면 머신이 바뀌어도 남는다. day14~18에서 `joblib.dump`로 저장하던 모델 파일을 코랩에서는 `/content/drive/MyDrive/...` 아래에 떨어뜨려야 다음 날 `load`할 수 있다.

| 경로 | 성격 | 런타임이 끊기면 |
| --- | --- | --- |
| `/content/` | 가상 머신 로컬 디스크(작업 폴더) | 사라진다 |
| `/content/sample_data/` | 코랩이 넣어 둔 예제 CSV | 사라진다(다음 머신에도 다시 있음) |
| `/content/drive/MyDrive/` | 마운트된 내 구글 드라이브 | **남는다** |

### 1-3. 둘째 셀 — 셀 실행과 "모두 실행"

```python
print('코랩에서 파이썬 시작')
# ctrl + enter 셀 단위 실행 # 노트 모두 실행
# 런타임: 현재 노트가 실행하는 클라우드PC 상태 # 런타임 유형변경 (CPU/T4 GPU)
```

주석 세 줄이 코랩 사용법의 뼈대다. 먼저 **셀 실행**.

| 조작 | 하는 일 |
| --- | --- |
| `Ctrl + Enter` | 현재 셀만 실행, 커서는 그 자리 |
| `Shift + Enter` | 현재 셀 실행 후 다음 셀로 이동(없으면 새 셀) |
| `Alt + Enter` | 현재 셀 실행 후 아래에 새 셀 삽입 |
| 런타임 > 모두 실행 | 위에서부터 전부 순서대로 실행 |
| 런타임 > 이전 셀 실행 / 이후 셀 실행 | 현재 셀 기준 앞쪽·뒤쪽만 |

`.py` 파일은 위에서 아래로 한 번에 돌지만, 노트북은 **셀을 실행한 순서대로 상태가 쌓인다**. 아래 셀을 먼저 돌리고 위 셀을 고친 뒤 다시 안 돌리면, 화면의 코드와 메모리의 변수가 어긋난다. 그래서 공유하거나 다음 날 이어 할 때는 "런타임 > 세션 다시 시작 및 모두 실행"으로 처음부터 한 번 쭉 도는지 확인하는 편이 안전하다. 셀 왼쪽의 `[1]`, `[2]` 번호가 실행 순서다 — `dl-1.ipynb`에서 첫 셀은 `[1]`, 둘째 셀은 아직 실행 번호가 없다(`execution_count: null`).

### 1-4. 런타임 — "지금 이 노트를 돌리는 클라우드 PC"

주석의 정의 그대로다. **런타임 = 현재 노트가 실행되는 클라우드 PC의 상태.** 오른쪽 위 "연결" 버튼을 누르거나 셀을 실행하면 가상 머신 하나가 배정되고, 그 옆에 RAM·디스크 사용량이 표시된다.

**런타임 유형 변경**(런타임 > 런타임 유형 변경)에서 하드웨어 가속기를 고른다.

| 선택 | 쓰는 자리 |
| --- | --- |
| CPU | 판다스 전처리, 사이킷런 모델(day12~20 내용은 전부 여기로 충분) |
| **T4 GPU** | 딥러닝 학습 — 행렬 곱을 수천 개 코어로 병렬 처리 |
| TPU | 구글 전용 가속기, 텐서플로/JAX 대규모 모델 |

유형을 바꾸면 **새 머신으로 교체**되어 1-2의 마운트도, 변수도 다시 해야 한다. 그러니 GPU가 필요한 노트는 처음부터 T4로 시작하고, 그 다음 첫 셀에서 마운트하는 순서가 맞다. 무료 등급은 GPU 사용 시간에 한도가 있어서, 전처리 단계는 CPU 런타임으로 하고 학습 직전에 GPU로 바꾸는 식으로 아끼기도 한다.

GPU가 실제로 붙었는지는 셸 명령으로 확인한다(2-2).

```
!nvidia-smi
```

### 1-5. 흐름 한 장 — 코랩에서 한 노트를 시작하는 순서

```
런타임 유형 선택(CPU / T4 GPU)
  → 셀 1: drive.mount('/content/drive')   인증 → Mounted at /content/drive
  → 셀 2~: 코드 (Ctrl+Enter 셀 단위 / 모두 실행)
  → 결과물은 /content/drive/MyDrive/... 아래에 저장
  → 끝나면 파일 > 다운로드 > .ipynb 로 받아 저장소에 넣기 (dl-1.ipynb가 이 결과)
```

### 2-2. `!`와 `%` — 셸 명령과 매직 명령

노트북 셀에서 `!`로 시작하면 리눅스 셸 명령이다.

```
!pip install kiwipiepy        # day20의 Kiwi는 코랩에 기본 설치가 아니라 매번 설치
!nvidia-smi                   # GPU 종류·메모리 확인 (T4, 15 GB 근처)
```

`%`는 주피터 자체의 매직 명령이다. `%%time`을 셀 맨 위에 두면 그 셀의 실행 시간이 찍히고(GPU 전후 비교에 유용), `%cd`로 작업 폴더를 바꾼다(`!cd`는 그 한 줄에서만 유효하고 다음 줄에 안 남는다). 설치한 패키지도 런타임이 끊기면 사라지므로, `!pip install` 셀을 노트 맨 위에 두고 "모두 실행"에 포함시키는 편이 다음 날 편하다.

## 3. 더 나아가 알면 좋은 것

### 3-1. 왜 딥러닝에는 GPU인가

사이킷런 모델은 표본 몇 천 개·특성 몇 십 개를 다루어 CPU로 몇 초면 끝났다. 딥러닝은 **가중치가 수백만~수십억 개인 행렬 곱**을 에포크마다 반복한다. CPU는 코어 수 개~수십 개가 복잡한 일을 빠르게 하는 구조이고, GPU는 단순한 곱셈·덧셈을 수천 개 코어가 동시에 하는 구조라 행렬 연산에서 수십 배 빠르다. 코랩 무료 등급의 T4는 16 GB 메모리의 데이터센터용 GPU로, 수업 규모의 이미지 분류·텍스트 모델을 돌리기에 충분하다. 다만 날마다 같은 GPU가 보장되지는 않고, 사용량이 많으면 CPU로 떨어질 수 있다.

### 3-2. 다음에 올 도구 — 텐서플로/케라스와 파이토치

코랩에 둘 다 미리 설치되어 있다. **케라스(Keras)**는 텐서플로 위의 고수준 API로 `Sequential([Dense(...), ...])` → `compile` → `fit` 세 단계가 사이킷런의 `모델() → fit`과 닮아 입문에 자주 쓰인다. **파이토치(PyTorch)**는 연구·현업에서 더 널리 쓰이고 학습 루프를 직접 쓴다. 어느 쪽이든 `fit` 전에 GPU를 쓰는지 확인하는 한 줄이 있다 — 텐서플로는 `tf.config.list_physical_devices('GPU')`, 파이토치는 `torch.cuda.is_available()`. 비어 있거나 `False`면 1-4의 런타임 유형이 CPU인 것이다.

### 3-3. 런타임이 끊길 때를 대비하는 습관

- 학습 중간 결과(체크포인트)를 에포크마다 드라이브에 저장 — 끊겨도 거기서 이어 간다
- 노트 맨 위에 `!pip install`·마운트·경로 변수 셀을 모아 두고 "모두 실행"으로 복구 가능하게
- 무료 등급은 한 세션이 길어지면 끊기고, 브라우저를 닫으면 얼마 뒤 유휴로 끊긴다 — 긴 학습은 Pro, 또는 캐글 노트북(주당 GPU 시간 제공)·로컬 GPU를 고려

### 3-4. 다음에 볼 키워드

- 텐서(tensor) — 넘파이 배열의 딥러닝판, GPU 메모리에 올라가는 다차원 배열
- 에포크(epoch)·배치(batch)·학습률(learning rate) — `fit`의 세 손잡이
- 활성화 함수·손실 함수·옵티마이저(Adam) — day14 로지스틱 회귀의 시그모이드·로그 손실·경사 하강법이 그대로 확장된다
- 과대적합 대책 — 드롭아웃·조기 종료(day18 `early_stopping`의 딥러닝판)
- `!nvidia-smi` 읽는 법 — GPU 메모리 사용량과 사용률
