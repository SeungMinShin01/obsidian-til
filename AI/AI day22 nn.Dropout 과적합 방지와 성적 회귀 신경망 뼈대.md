## 1. 배운 내용

### 1-1. 자료 — day19의 학생 성적을 회귀 문제로

```python
import pandas as pd
url = 'https://raw.githubusercontent.com/arunk13/MSDA-Assignments/master/IS607Fall2015/Assignment3/student-mat.csv'
df = pd.read_csv(url, sep=';')
X = df[['studytime', 'absences', 'G1', 'G2']]
Y = df['G3']

from sklearn.model_selection import train_test_split
X_train, X_test, Y_train, Y_test = train_test_split(X, Y, test_size=0.2, random_state=42)

from sklearn.preprocessing import StandardScaler
ss = StandardScaler()
X_train_scaled = ss.fit_transform(X_train)
X_test_scaled  = ss.transform(X_test)
```

day19 `s-13.py`와 같은 파일(395명 × 33열, 구분자가 쉼표가 아니라 **`sep=';'`**)인데 쓰는 방식이 다르다. day19는 `G3`까지 다섯 열을 전부 특성으로 넣고 정답 없이 그룹을 나눴고(비지도), 오늘은 `G3`를 **타깃**으로 떼어 내고 나머지 네 열로 맞힌다(지도·회귀). 같은 CSV가 문제 설정에 따라 군집 자료가 되기도, 회귀 자료가 되기도 한다.

| | day19 `s-13.py` | day22 `dl-2.ipynb` |
| --- | --- | --- |
| 쓰는 열 | `studytime`·`absences`·`G1`·`G2`·`G3` 다섯 | 특성 넷 + 타깃 `G3` |
| 문제 | 비지도 군집(KMeans·HDBSCAN) | 지도 **회귀**(신경망) |
| 분할 | `train_test_split(X, test_size=0.02)` 둘만 | `train_test_split(X, Y, 0.2, 42)` 넷 |
| `stratify` | — | **없음** — 회귀 타깃은 연속값이라 층화할 범주가 없다 |

앞 노트의 와인 분류에 있던 `stratify=Y`가 빠진 것이 첫 차이다. `G3`는 0~20점 연속 숫자이니 비율을 맞출 클래스가 없다(day12 `train_test_split`과 같은 꼴). 표준화는 그대로 — G1·G2는 0~20, 결석은 0~75, 공부 시간은 1~4로 단위가 제각각이라 신경망에 넣기 전에 반드시 맞춘다.

### 1-2. 텐서 변환 — 특성 넷, 타깃은 실수 그대로

```python
# 1) 딥러닝 하기 위한 파이토치 특성과 타깃 차원 일치화
X_train = torch.tensor(X_train_scaled, dtype=torch.float32)
X_test  = torch.tensor(X_test_scaled,  dtype=torch.float32)
Y_train = torch.tensor(Y_train.values, dtype=torch.float32).unsqueeze(1)
Y_test  = torch.tensor(Y_test.values,  dtype=torch.float32).unsqueeze(1)
```

앞 노트 1-2와 같은 네 줄이다. 분류에서 0.0 / 1.0이던 타깃이 여기선 **점수 그대로**(0~20)의 `float32`가 된다 — 회귀는 정답 숫자를 그대로 맞히는 문제이니 라벨 변환이 필요 없다. 395명의 80 %인 316행이 학습용, 79행이 테스트용이다.

회귀에서도 주석 그대로 **"특성과 타깃 차원 일치화"**가 목표고, 그래서 앞 노트와 똑같이 타깃에 `.unsqueeze(1)`을 붙인다. 출력층 `nn.Linear(8, 1)`은 `(N, 1)`을 내놓으므로 `MSELoss`가 원소끼리 짝을 맞추려면 타깃도 `(316, 1)`이어야 한다. 타깃을 `(N,)` 1차원으로 두면 파이토치가 두 모양을 브로드캐스팅으로 억지로 맞추면서 `Using a target size … different to the input size` 경고를 내고 손실이 전혀 다른 값으로 계산되므로, 분류든 회귀든 **출력층이 `(N, 1)`이면 타깃도 `(N, 1)`**로 맞추는 것이 규칙이다(앞 노트 1-2 표의 둘째 줄과 같은 규칙).

### 1-3. `nn.Dropout(p=0.2)` — 매 순전파마다 은닉 뉴런 20 %를 꺼 버린다

```python
# 2) 신경망 DNN 레이어 컨테이너 설정
import torch.nn as nn
# model = nn.Sequential( 입력층 -> 은닉층 -렐루/드롭아웃-> 은닉층 -> 출력층 )
model = nn.Sequential(
    nn.Linear(4, 32),      # 학습할 특성의 수로 입력층 시작 — 파생 피처 32개는 자유
    nn.ReLU(),             # 활성화 함수
    nn.Dropout(p=0.2),     # 매 순전파마다 은닉층의 20 %를 무작위 비활성화 — 과적합 방지

    nn.Linear(32, 16),     # 앞 층 32노드 수를 따라 다음 입력 수 설정
    nn.ReLU(), nn.Dropout(p=0.2),

    nn.Linear(16, 8),      # 앞 층 16노드 수를 따라
    nn.ReLU(), nn.Dropout(p=0.2),

    nn.Linear(8, 1),       # 출력층 — 1노드로 끝낸다
)
```

첫 `Linear`의 입력 4는 특성 수(앞 노트 1-3의 규칙), 32는 자유롭게 정한 은닉 크기다. 새로 들어온 셋째 층이 **드롭아웃**이다.

| 항목 | 내용 |
| --- | --- |
| 하는 일 | 학습 중 순전파마다 앞 층 출력 32개 중 **무작위 20 %(약 6개)를 0으로** 만든다. 어느 6개인지는 매 바퀴 다르다 |
| 왜 | 특정 뉴런 몇 개에 의존해 학습 자료를 외우는 것을 막는다 — 매번 다른 부분집합으로 학습하니 **작은 신경망 여럿을 평균 내는 효과**(앙상블) |
| 학습 중 | 살아남은 80 %에 `1 / (1 − p)` = 1.25를 곱해 기대값을 유지(inverted dropout) |
| **`eval()` 중** | **아무 일도 하지 않는다** — 전부 통과. 그래서 앞 노트 1-7의 `model.eval()`이 이 층부터 **실제로 의미**를 갖는다 |
| 매개변수 | 0 — 학습하는 숫자가 없다. `p`만 하이퍼파라미터 |
| 위치 | 활성화 함수 **뒤**, 다음 `Linear` 앞 — 꺼지는 것은 "뉴런의 출력"이다 |

규제의 계보로 보면 day13 릿지·라쏘(기울기 크기에 벌점) → day17 트리의 `max_depth`·`min_samples_leaf`(가지치기) → day18 `early_stopping`(멈추기)에 이어 신경망 고유의 넷째 방법이다. 셋 다 "학습 자료를 너무 잘 맞히는 것을 방해한다"는 점에서 같고, 드롭아웃은 **매개변수가 아니라 연결을 무작위로 끊는** 방식이라는 점이 다르다. 비율 0.2~0.5가 흔히 쓰이고, 입력층 바로 뒤에는 보통 두지 않는다(특성 자체를 지우면 정보가 사라진다).

주석 "`-렐루/드롭아웃->`"처럼 `Linear → ReLU → Dropout`이 **한 묶음**으로 세 번 반복되는 것이 깊은 신경망의 기본 리듬이다. 각 `Linear`의 입력 수는 앞 층의 출력 수를 그대로 따라가고(32 → 16 → 8), 출력층 `Linear(8, 1)`만은 뒤에 활성화도 드롭아웃도 없다 — 회귀의 마지막 숫자는 그대로 내보내야 하고, 출력 하나를 20 % 확률로 꺼 버릴 이유도 없다. 은닉 크기 32·16·8은 "아무거나"라는 주석대로 자유롭게 정한 값이고, 입력 4와 출력 1만 문제가 정한다.

| 층 | 모양 | 매개변수 |
| --- | --- | --- |
| `Linear(4, 32)` | `(N, 4)` → `(N, 32)` | 4 × 32 + 32 = 160 |
| `ReLU` · `Dropout(0.2)` | 모양 유지 | 0 |
| `Linear(32, 16)` | → `(N, 16)` | 32 × 16 + 16 = 528 |
| `ReLU` · `Dropout(0.2)` | 모양 유지 | 0 |
| `Linear(16, 8)` | → `(N, 8)` | 16 × 8 + 8 = 136 |
| `ReLU` · `Dropout(0.2)` | 모양 유지 | 0 |
| `Linear(8, 1)` | → `(N, 1)` | 8 × 1 + 1 = 9 |
| 합계 | | **833개** |

앞 노트의 와인 분류가 81개였으니 열 배가 넘는다. 학습 자료는 316행 — 자료 행 수보다 매개변수가 두 배 이상 많은 셈이라, 외우기 딱 좋은 조건이고 그래서 드롭아웃이 세 군데 들어간 것이 장식이 아니다. `model(X_train)`의 결과는 `(316, 1)` — 1-2에서 타깃에 열 축을 붙인 이유가 여기서 맞아떨어진다.

### 1-4. ANN에서 DNN으로 — 이름이 바뀐 이유

앞 노트 주석은 **ANN**(인공신경망), 이 셀 주석은 **DNN**(Deep Neural Network, 심층 신경망)이다. 같은 `nn.Sequential`인데 이름이 달라진 것은 은닉층이 **둘 이상**으로 깊어지기 때문이다.

| 이름 | 구조 | 이 파일에서 |
| --- | --- | --- |
| ANN | 입력 → 은닉 1개 → 출력 | 와인 분류 `Linear(3,16) → ReLU → Linear(16,1)` |
| **DNN** | 입력 → 은닉 **2개 이상** → 출력 (+ 드롭아웃·배치 정규화 등) | 성적 회귀 `Linear(4,32) → Linear(32,16) → Linear(16,8) → Linear(8,1)` — 은닉층 셋, 층마다 ReLU·Dropout |

"딥러닝"의 딥이 바로 이 은닉층 수다. 층이 깊어질수록 더 복잡한 경계를 그릴 수 있지만 매개변수가 늘어 과대적합이 쉬워지고, 그래서 깊어지는 순간 드롭아웃이 함께 들어오는 것이 자연스럽다 — 이 셀의 열 층짜리 컨테이너(`Linear` 넷 + `ReLU` 셋 + `Dropout` 셋)가 그 두 변화를 한 번에 보여 준다.

### 1-5. 3)~5) — 손실 한 줄만 바꾸고 학습 루프는 그대로

```python
# 3) 손실함수: MSELoss() 회귀
crierion = nn.MSELoss()
# 4) 옵티마이저 ; optimizer = optim.AdamW( model.parameters(), lr=학습률)
import torch.optim as optim   # 파라미터(가중치/편향, y(예측값) = w(가중치)·a(값) + b(편향))
optimizer = optim.AdamW(model.parameters(), lr=0.01)
# 5) 에포크(학습수) 단위 학습 (순전파 -> 오차계산 -> 역전파 -> 업데이트)
for epoch in range(7000):
    model.train()                      # 1) 학습 모드 실행 — 필수!
    optimizer.zero_grad()              # 2) 이전 학습에 쓴 기울기 0으로 초기화
    logits = model(X_train)            # 3) 순전파/학습
    loss = crierion(logits, Y_train)   # 4) 손실 계산 (예측값, 정답지)
    loss.backward()                    # 5) 역전파: 오차로 가중치·편향의 기울기 계산
    optimizer.step()                   # 6) 업데이트 — 변경된 파라미터 반영
    if epoch % 100 == 0:
        print(epoch, ": loss: ", loss.item())

# 6) 모델 평가. model.train() 학습모드 , model.eval() 평가/추론모드
# 7) 모델 추론
```

앞 노트 3)~5)와 글자 단위로 비교하면 바뀐 줄은 **`nn.BCEWithLogitsLoss()` → `nn.MSELoss()` 하나**다. 옵티마이저는 `AdamW(lr=0.01)` 그대로, 루프 여섯 줄도 그대로. day21에서 손으로 `(y_pred − y)²`를 구하고 `backward()`를 불렀던 그 `MSELoss`가 이번엔 316행 × 1열에 한꺼번에 적용된다.

| 단계 | 와인 분류(앞 노트) | 성적 회귀(이 셀) | 바뀌는 이유 |
| --- | --- | --- | --- |
| 출력층 | `Linear(16, 1)` 로짓 | `Linear(8, 1)` 점수 | 모양은 같다 — 해석만 "확률 전 단계" → "예측값" |
| 3) 손실 | `BCEWithLogitsLoss` | **`MSELoss`** | `(예측 − 정답)²` 평균 — day21의 그 손실 |
| 4) 옵티마이저 | `AdamW(lr=0.01)` | `AdamW(lr=0.01)` | 문제 종류와 무관 |
| 5) 학습 루프 | 1만 에포크 | 7,000 에포크 | 여섯 줄 **한 글자도 안 바뀜** — `train()`이 이번엔 드롭아웃을 실제로 **켠다** |
| 6) 평가 | `sigmoid ≥ 0.5` → `f1_score` | (주석) 출력 **그대로** → `r2_score`·RMSE | 확률·임계값이 없다 |
| 7) 추론 | — | (주석) 새 학생 한 줄 → 점수 | day14 `s-05.py` 서빙과 같은 그림 |

루프 안 주석이 1)~6) 여섯 번호로 매겨진 것은 앞 노트의 "5박자"에 `model.train()`을 첫 박으로 세운 것이다 — 이 셀부터는 드롭아웃이 있어 `train()`이 생략할 수 없는 한 박이 되었으니 번호를 받을 자격이 생겼다. 순전파 결과를 받는 변수 이름 `logits`는 앞 셀에서 그대로 가져온 것인데, 회귀에서 이 값은 시그모이드를 씌울 전 단계가 아니라 **그 자체가 예측 점수**다 — 손실 함수에 바로 넣고, 6)에서도 그대로 읽는다. 핵심은 **학습 루프는 문제가 바뀌어도 바뀌지 않는다**는 점이다. 바뀌는 것은 손실 함수 한 줄과 평가에서 출력을 읽는 방법뿐 — day12 "알고리즘은 ④ 클래스 이름만 바뀐다"의 딥러닝판이다.

### 1-6. 손실 읽기 — 130에서 4~5로, 그리고 멈추지 않는 요동

100바퀴마다 찍힌 `loss.item()`을 간추리면 이렇다.

| 200 | 11.52 | |
| 500 | 7.48 | |

| 6,900 | 5.00 | 마지막 출력 |

세 가지가 읽힌다.

**첫째, 130이라는 시작값의 뜻.** 가중치가 무작위 초기값이고 입력이 표준화되어 있으면 첫 출력은 0 근처다. 그러면 MSE는 `(0 − G3)²`의 평균, 곧 **`G3` 제곱의 평균**이 된다 — `G3`는 평균 약 10.4·표준편차 약 4.6이니 `10.4² + 4.6² ≈ 130`. 분류의 시작 손실 0.6564 ≈ ln 2가 "아무것도 모르는 상태"였듯, 회귀의 시작 손실은 "전부 0이라고 찍는 상태"다. 손실 함수가 다르니 시작점의 눈금도 다르다.

**둘째, 단위.** `MSELoss`가 찍는 숫자는 점의 **제곱** 단위라 4.5가 큰지 작은지 바로 와닿지 않는다. 제곱근을 씌우면 RMSE ≈ 2.1점 — 0~20점짜리 기말 성적을 평균 두 점쯤 틀린다는 뜻이다(day12 2-2에서 MSE 대신 RMSE를 읽던 그 이야기). 1차·2차 성적을 알고 기말을 맞히는 문제라 두 점 오차는 그럴 법한 자리다.

**셋째, 요동.** 앞 노트의 와인 분류 손실은 0.656 → 0.389 → … → 0.2866으로 매 100바퀴 한 방향으로만 내려갔다. 여기선 2,000바퀴 이후 3.3과 5.7 사이를 계속 오르내린다. 원인은 **드롭아웃**이다. `model.train()` 상태에서 찍힌 손실은 매 바퀴 **다른 20 %가 꺼진 다른 부분 신경망**이 낸 손실이라, 가중치가 거의 같아도 어느 뉴런이 꺼졌느냐에 따라 값이 흔들린다. 316행 전체를 한 번에 넣는 배치 경사하강법이라 자료 쪽 무작위성은 없는데도 요동이 생기는 이유가 바로 그것이다. 거기에 학습률 0.01이 끝까지 그대로라 바닥 근처에서 보폭이 줄지 않는 것도 한몫한다. 그래서 두 가지 습관이 따라온다 — 학습 중 `print`한 손실로 성능을 말하지 않고 꼭 **`eval()`로 다시 재기**(2-1), 그리고 2,000바퀴 이후 뚜렷한 개선이 없으니 7,000까지 돌리는 대신 **검증 손실을 보며 멈추기**(앞 노트 2-2의 조기 종료)를 생각해 보기.

## 2. 추가로 알면 좋은 활용법

### 2-1. 6) 평가 채우기 — `eval()`·`no_grad`, 그리고 사이킷런으로 재기

주석 "`model.train()` 학습 모드, `model.eval()` 평가/추론 모드"가 비어 있는 6)의 전부다. 앞 노트 1-7의 네 단계에서 시그모이드와 임계값만 빼면 된다.

```python
model.eval()                            # 드롭아웃 OFF — 모든 뉴런 통과            # 6)
with torch.no_grad():
    train_pred = model(X_train).numpy()  # (316, 1) 점수 그대로
    test_pred  = model(X_test).numpy()   # (79, 1)
from sklearn.metrics import r2_score, mean_squared_error
import numpy as np
print(r2_score(Y_train.numpy(), train_pred), r2_score(Y_test.numpy(), test_pred))
print(np.sqrt(mean_squared_error(Y_test.numpy(), test_pred)))            # RMSE, 단위 점
```

파이토치가 평가지표를 따로 주지 않으니 day12부터 쓰던 사이킷런 `r2_score`로 잰다 — 사이킷런 ↔ 파이토치 ↔ 사이킷런으로 돌아오는 흐름은 앞 노트 1-8 그림 그대로다. 타깃·예측 둘 다 `(N, 1)`이라 사이킷런이 그대로 받아 준다.

드롭아웃이 있는 모델은 **학습 중 손실과 `eval()` 뒤 점수가 다르게 나오는 것이 정상**이다. 1-6의 4~5는 뉴런 20 %가 꺼진 채 계산한 손실이고, 평가 때는 전부 켜서 계산하므로 같은 학습 자료에 대해서도 보통 평가 쪽 MSE가 더 낮게 나온다. 그래서 1-6의 표를 성능표로 읽지 않고, 꼭 `eval()`로 다시 재는 습관이 필요하다. 학습 R²와 테스트 R² 사이의 격차가 크면 드롭아웃 비율을 올리거나(2-3) 에포크를 줄이는 것이 다음 손질이다.

### 2-2. 7) 추론 — 새 학생 한 명

```python
new_student = pd.DataFrame([[2, 4, 12, 13]], columns=['studytime', 'absences', 'G1', 'G2'])
x_new = torch.tensor(ss.transform(new_student), dtype=torch.float32)   # 같은 스케일러
model.eval()
with torch.no_grad():
    print(model(x_new).item())        # 예측 G3 (점)
```

학습 때 쓴 **같은 `ss`로 `transform`**하는 것이 전부다(day13 "fit은 학습용에만"). 열 이름을 맞춘 데이터프레임으로 넘기면 열 순서 실수를 스케일러가 잡아 준다. 사이킷런 파이프라인이 전처리와 모델을 한 객체로 묶어 주던 편의가 파이토치엔 없으니, 서빙할 때는 **스케일러(`joblib`)와 가중치(`state_dict`)를 따로 저장해 둘 다 불러와야** 한다 — day16 FastAPI 서비스에 올린다면 `Service.py` 생성자에서 두 파일을 함께 읽는 모양이 된다.

### 2-3. 드롭아웃 비율 바꿔 보기 — 효과를 눈으로

`p`를 0 · 0.2 · 0.5로 바꿔 학습 R²와 테스트 R²를 나란히 놓으면 드롭아웃이 하는 일이 보인다. 자료가 316행으로 작고 모델이 커질수록 `p=0`에선 학습 R²만 치솟고 테스트는 떨어지는 간격이 생기고, `p`를 올리면 학습 쪽이 내려오며 간격이 좁아진다. 너무 올리면(0.5 이상) 둘 다 내려가는 **과소적합**이 된다 — day13 `alpha`를 로그 눈금으로 훑던 것과 같은 그림이고, 격차가 가장 작은 `p`가 아니라 **테스트 점수가 가장 높은 `p`**를 고른다. 비교할 때 `torch.manual_seed`를 고정해야 초기 가중치 차이가 섞이지 않는다.

### 2-4. `Dropout` 말고 `BatchNorm1d` — 함께 쓰는 또 하나의 "모드 스위치" 층

`nn.BatchNorm1d(32)`는 배치마다 은닉층 출력을 표준화해 학습을 안정시키는 층으로, 드롭아웃과 함께 `train()`/`eval()`에 따라 동작이 바뀌는 대표 층이다(학습 중엔 배치 통계, 평가 중엔 누적 이동 평균). `Linear → BatchNorm → ReLU → Dropout` 순서가 흔하고, 둘을 같이 쓸 때는 드롭아웃 비율을 낮추는 편이다. 미니배치 크기가 아주 작으면(수십 미만) 배치 통계가 불안정해져 오히려 해롭다는 점도 함께 기억해 둔다.

## 3. 더 나아가 알면 좋은 것

### 3-1. 드롭아웃이 작동하는 원리 — 앙상블과 공적응 방지

드롭아웃 논문(Srivastava 외, 2014)의 설명은 두 갈래다. 하나는 매 바퀴 다른 부분 신경망을 학습해 `2^n`개 모델을 **암묵적으로 평균**하는 앙상블 효과(day17 랜덤 포레스트가 특성·표본을 무작위로 빼고 트리를 여럿 키우던 것과 닮았다). 다른 하나는 뉴런들이 "옆 뉴런이 있을 때만 맞는" 식으로 서로 기대는 **공적응(co-adaptation)** 을 막아 각 뉴런이 혼자서도 쓸모 있는 특징을 배우게 하는 것. 평가 때 전부 켜고 `1/(1−p)` 보정을 해 두면 평균 모델을 한 번의 순전파로 근사하는 셈이다.

### 3-2. 표 자료에서 신경망 vs 부스팅

특성 4개·316행짜리 표 자료에서는 day18의 LightGBM이 신경망보다 적은 수고로 더 좋은 R²를 내는 경우가 많다. 트리 모델은 표준화도 필요 없고 범주형도 `category` 타입으로 바로 먹는다(day18). 표 자료에서 신경망이 이기는 자리는 행이 수십만 이상이거나, 임베딩으로 고차원 범주를 다루거나, 다른 신경망(이미지·텍스트)과 한 모델로 묶어야 할 때다 — 그래서 실무에선 "표는 부스팅, 비정형은 딥러닝"이 기본 출발점이고, 이 수업은 **같은 문제를 신경망으로 풀면 코드가 어떻게 생기는지**를 익히는 데 뜻이 있다.

### 3-3. 회귀 출력층의 변형들

- 타깃 범위가 정해져 있으면(0~20점) 출력에 `sigmoid × 20`을 씌우거나 예측 뒤 `clamp(0, 20)`으로 자를 수 있다(day13 연습의 `np.clip`과 같은 발상).
- 이상치가 많으면 `MSELoss` 대신 `L1Loss`(MAE)나 `HuberLoss`/`SmoothL1Loss`가 안정적이다(day21 2-3 표).
- 타깃이 치우쳤으면(의료비처럼 오른쪽 꼬리) `log1p` 변환 뒤 학습하고 `expm1`로 되돌린다 — day16·18의 로그 타깃 이야기.
- 여러 값을 동시에 맞히면 `Linear(h, k)`로 출력을 `k`개 — 다중 출력 회귀는 손실이 알아서 열별 평균을 낸다.

### 3-4. 다음에 볼 키워드

- `nn.BatchNorm1d`·`nn.LayerNorm` — 정규화 층과 `train()`/`eval()`
- `weight_decay`(AdamW) vs 드롭아웃 — 두 규제를 함께 쓸 때의 균형
- `torch.manual_seed`·`torch.use_deterministic_algorithms` — 드롭아웃 무작위성과 재현성
- `nn.Module` 상속으로 `Linear → ReLU → Dropout` 블록 함수화 (`make_block(in, out, p)`)
- `random_split`·`DataLoader` — 검증 세트 분리와 미니배치 (앞 노트 2-3)
- `ReduceLROnPlateau` — 검증 손실이 멈추면 학습률 낮추기
- 몬테카를로 드롭아웃 — `eval()`에서도 드롭아웃을 켜 예측 불확실성 추정
- 표 자료 딥러닝: `nn.Embedding` 범주 임베딩·TabNet·FT-Transformer
