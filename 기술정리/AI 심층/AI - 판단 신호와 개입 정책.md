# AI - 판단 신호와 개입 정책

> 상위: [[AI 심층 정리 인덱스]]

> 계기: *Good Judgment, Bad Advice: Decision-Model Controllers Raise Agent Cost Without Improving Success* — Naman Vats(단독 저자), arXiv 2610.24649v1 (2026-10-17), HF ▲10~11 (2026-10-22 브리핑)
> 읽은 범위: HF 논문 페이지(초록·저자 코멘트), arXiv HTML 본문 1~7절 전체와 부록 A(프롬프트·안내 메시지·선택지 설명)·B(파라미터)·C(과제별 결과)·D(사전 계획 이탈). **그림은 캡션만 읽었고, GitHub 코드는 보지 않았다.**

## 한 줄 정의

**에이전트 루프에 붙인 "작은 판정자"의 가치는 판단이 얼마나 정확한가가 아니라, 그 판단을 행동으로 바꾸는 규칙(개입 정책)이 비용을 줄이는가로 결정된다** — 그리고 그것은 위약(무작위 개입) 대조군을 두고 **비용을 주 결과**로 재야만 보인다.

## 왜 이게 문제였나 (기존 방식의 한계)

요즘 에이전트 스캐폴드는 "멈출까 / 검증할까 / 접근을 바꿀까" 같은 작은 결정을 비싼 추론 모델 대신 **싼 모델**에 넘긴다. AI 심층의 「비생성 의사결정 모델」 노트에서 본 Jev(TypeSafe) 같은 *typed decision model*이 바로 이 자리를 노린다 — 상태와 선택지를 주면 생성 없이 선택지별 확률을 돌려준다. 이 논문 실행 기준 Jev 1.13은 입력 100만 토큰당 $0.042, 결정 1회 약 **$0.00008**이다.

그런데 이런 판정자의 평가는 대부분 **판단의 질**(정확도, AUROC, LLM-as-judge 일치율)만 잰다. 판정자가 돈을 아끼려면 두 조건이 동시에 필요하다.

1. 판단이 "이 실행이 어떻게 끝날지"에 대한 정보를 담고 있어야 하고,
2. 그 정보를 **행동으로 옮겼을 때** 실제로 비용이 줄어야 한다.

기존 평가는 1만 본다. 2를 보려면 같은 루프에 판정자만 바꿔 끼우고 끝까지 돌려야 하며, "판정자의 *내용* 덕인지, 그냥 *그 순간에 끼어든 것* 덕인지"를 가르려면 **같은 순간에 무작위로 끼어드는 위약**이 있어야 한다. 이 논문이 한 일이 그것이다.

## 어떻게 푸는가 (실험 설계)

비유하면 **약효 시험**이다. 환자(에이전트 루프)·병원(샌드박스)·처방 시점(결정 지점)은 고정하고, 처방하는 의사(컨트롤러)만 바꾼다. 그리고 가짜 약(위약)을 준 군을 같이 둔다.

### 1) 고정된 루프

- 추론 모델: Claude Sonnet 5.5(reasoning effort high, 프롬프트 캐싱). 도구는 `bash`와 `finish` 둘뿐, 도구 호출 없는 응답은 완료 요청으로 친다.
- 실행: Harbor 0.24.0으로 과제 이미지에서 만든 Daytona 샌드박스. 도구 출력은 앞 4,000자 + 뒤 8,000자로 자르고, 컨텍스트는 **압축하지 않는다**.
- 상한(전 조건 동일): 60스텝, 시도당 $1.00. 캘리브레이션에서 통과한 실행은 최대 52스텝·$0.48이었으므로 상한이 결과를 자르지 않게 넉넉히 잡았다(사전 계획의 p90 상한 20스텝·$0.25는 통과 실행 44개 중 5개를 잘라 사실상 "포기 정책"이 되므로 버렸다 — 부록 D).

### 2) 결정 지점은 결정론적으로, 모든 조건에서 똑같이

| 트리거 | 조건 | 컨트롤러에게 묻는 질문 |
| --- | --- | --- |
| T1 반복 실패 | 연속 2회 이상 실패(비정상 종료·타임아웃) | Q-progress: continue / investigate / recover / abandon |
| T2 무진전 | 최근 5개 중 같은 명령 2회, 또는 최근 3개 중 같은 출력 2회 | Q-progress |
| T3 완료 요청 | 에이전트가 finish를 부름 | Q-finish: finish / verify |
| T4 체크포인트 | 10스텝마다 | Q-progress |

한 스텝에 트리거는 하나(우선순위 T1 > T2 > T4), 같은 종류는 3스텝 안에 재발화 금지. **컨트롤러가 없는 조건에서도 트리거는 감지·기록**된다 — 그래야 나중에 오프라인 재생이 가능하다.

### 3) 개입은 "고정 문구 한 줄"뿐

investigate·recover·verify를 고르면 고정된 조언 메시지 하나가 대화에 붙는다(예: verify = "요구사항이 아직 다 확인되지 않았을 수 있다. 끝내기 전에 각 명시적 요구사항을 실제 환경 상태와 대조하라"). 메시지에는 **명령·경로·테스트 정보가 절대 없다**. abandon은 실패로 종료, finish는 정상 종료. 컨트롤러는 압축된 상태(지시문, 트리거, 스텝·지출 대비 상한, 최근 명령 5개와 종료 코드·출력 꼬리, 실패·반복 카운터, 마지막 편집 이후 검증성 명령 실행 여부, 완료 요약, 자기 이전 선택)만 본다 — 테스트·채점 결과·정답은 못 본다.

### 4) 다섯 개의 처방군

| 조건 | 무엇을 하나 | 이 조건이 답하는 질문 |
| --- | --- | --- |
| native | 트리거만 기록, 개입 없음 | 기준선 |
| rules | T1·T2 → recover, T4 → continue, T3 → 마지막 편집 후 검증 명령이 없으면 verify, 예산 40% 이후 연속 4회 실패면 abandon | 모델이 필요하긴 한가? |
| small LLM | Claude Haiku 5.5(추론 끔), 같은 상태·같은 선택지 설명, JSON 하나로 답 | 그냥 싼 LLM이면 안 되나? |
| Jev | typesafe/jev-1.13, 같은 질문을 *choice*로 | 전용 결정 모델 |
| placebo | 개발 단계에서 관찰한 Jev의 선택 **빈도**대로 무작위(Q-progress: continue 0.625 / investigate 0.125 / recover 0.25 / abandon 0, Q-finish: finish 0.652 / verify 0.348) | 효과가 판단 *내용*에서 오나, 끼어드는 *행위*에서 오나? |

모든 컨트롤러 위에 가드가 있다 — G1 하드 상한, G2 abandon은 예산 40% 이후 + (연속 실패 3회 이상 또는 T2 2회 이상)일 때만 허용(아니면 recover로), G3 verify 두 번 뒤 세 번째 완료 요청은 수용, G4 타임아웃·오류·형식 위반은 continue/finish로 대체.

### 5) 사전 등록과 통계

Terminal-Bench 2.1 89과제 중 3개 제외 → 캘리브레이션 30과제를 native로 2회씩 돌려 easy/mid/hard로 층화 → 개발 8과제(아무것도 튜닝하지 않고 위약 분포만 얻음)·**held-out 21과제**(easy 14, mid 3, hard 4). 평가: 21과제 × 5조건 × 3회 = **315회**, 과제·회차 블록 안에서 조건 순서 무작위. 비용 효과는 과제별 "시도당 USD 비"의 기하평균, 과제 단위 부트스트랩 10,000회. 주 비교 C1(Jev vs native)은 사전에 통과율 하한 −10%p를 마진으로 정했다. 평가 모델 비용은 $59.46, 전체 $72.29.

## 실험 결과

### 끝까지 돌려 본 결과 (held-out 21과제, 조건당 63회)

| 조건 | 통과율 | 시도당 USD | 해결당 USD | 스텝 | 결정 횟수/시도 | verify 메시지/시도 |
| --- | --- | --- | --- | --- | --- | --- |
| native | 73.0% | 0.177 | 0.243 | 13.3 | – | – |
| rules | 73.0% | 0.191 | 0.262 | 15.6 | 3.14 | 0.92 |
| small LLM | 76.2% | 0.213 | 0.280 | 17.8 | 3.65 | 1.30 |
| **Jev** | **73.0%** | **0.206** | 0.283 | 16.0 | 2.79 | 0.51 |
| placebo | 71.4% | **0.156** | **0.218** | 13.2 | 2.32 | 0.33 |

| 비교 | 통과율 차 | 비용 비(95% CI) |
| --- | --- | --- |
| C1 Jev vs native | +0.0%p [−11.1, +12.7] | **1.19** [1.02, 1.36], p=0.026 |
| C2 Jev vs small LLM | −3.2%p | 0.81 [0.68, 0.95] |
| C3 Jev vs rules | +0.0%p | 0.96 [0.83, 1.11] |
| C4 Jev vs placebo | +1.6%p | **1.22** [1.08, 1.39], p=0.001 |

- **"Jev가 비용을 낮춘다"는 가설은 기각.** 같은 통과율에 비용 19% 증가. native 대비 rules ×1.24, small LLM ×1.47, Jev ×1.19 — **정보를 쓰는 컨트롤러 셋이 모두 비용을 올렸고, 위약만 올리지 않았다**(×0.98).
- 통과율 하한 −9.5%p가 마진 −10%p 안쪽이지만, 저자는 21과제로는 이게 설계 해상도의 끝이라 "비열등"이 아니라 "큰 하락의 증거는 없음"으로만 읽는다.
- 견고성: Jev가 21과제 중 **15과제에서 더 비쌌고**, 아무 과제 하나를 빼도 비율은 1.16~1.25. 싸진 6과제 중 셋은 native와 3% 이내, 뚜렷하게 싸진 셋은 **hard 과제** — 대부분 타임아웃·예산 상한에서 끝나서 완료 요청이 없고, 따라서 검증할 것도 없었다. 층별 비용 비: easy 1.29, mid 1.48, hard 0.76.

### 판단은 잘했다 — 오프라인 재생

native 실행에서 기록된 트리거 상태를 각 컨트롤러에 **행동 없이** 다시 보여 주고 실제 결과로 채점했다.

| Q-finish (53개 상태) | AUROC | ECE | argmax 정확도 |
| --- | --- | --- | --- |
| 기준율(전부 "끝났다") | 0.50 | 0.00 | **0.87** |
| rules | 0.62 | 0.55 | 0.45 |
| small LLM | 0.60 | 0.70 | 0.30 |
| **Jev** | **0.78** | 0.37 | 0.55 |

- **순위 매기기는 진짜다.** Jev가 P(finish) ≥ 0.5를 준 실행은 96%(24개 중 23개)가 통과, 0.5 미만은 79%(29개 중 23개).
- **그런데 "안 끝났다" 쪽으로 쏠려 있다.** P(finish) 평균 0.50인데 실제 통과는 87%. 그래서 53번 중 **29번 verify**를 골랐고, argmax 정확도(0.55)가 "무조건 끝났다고 하기"(0.87)보다 낮다. **가장 의심한 묶음조차 79%가 이미 맞았다.**
- Q-progress(72개 상태)에서는 어떤 컨트롤러도 **포기를 한 번도 고르지 않았고**, Jev의 포기 확률은 실패/통과를 거의 못 갈랐다(AUROC 0.55).

### 돈은 어디서 샜나

- verify 빈도와 비용이 같이 움직인다: placebo 0.33회(×0.98) → Jev 0.51회(×1.19) → rules 0.92회(×1.24) → small LLM 1.30회(×1.47).
- 다만 Jev의 추가 비용 $0.029/시도 중 **첫 verify 메시지 이후** 쓴 것은 $0.011뿐이다. 나머지는 실행 전반이 길어진 것(16.0 대 13.3스텝)에서 왔고, Jev가 진행 결정 92번 중 30번 investigate/recover를 고른 것과 맞물린다(저자: 이 분해는 상관관계).
- **포기는 0회.** 돈을 아낄 수 있는 유일한 행동이 한 번도 쓰이지 않았다. 가망 없는 make-doom-for-mips는 15회 전부 Harbor 타임아웃(11)이나 $1.00 상한(4)까지 달렸다. native 실패 17개 중 10개가 완료 요청 없이 상한에서 끝났다.
- **판정자 자체 비용은 문제가 아니다.** Jev는 결정당 0.52초, 지출의 0.11%(small LLM 1.46초, 0.47%). 타임아웃·형식 오류 0건.

### 위약이 보여 준 것

위약이 모든 컨트롤러의 통과율에 맞먹으면서 비용은 올리지 않았다. native와만 비교했다면 "Jev는 좀 비싸다"로 끝났을 것을, 위약 덕에 **"끼어든 행위가 아니라 Jev의 선택 내용이 비용을 더했다"**로 좁힐 수 있다.

## 실제로 쓸 수 있나

**결론부터: "판정자를 붙이면 아낀다"는 기본값이 아니다. 아끼는 것은 판정자가 아니라 정책이다.** 백엔드 감각으로 번역하면 다음과 같다.

- **좋은 이상 탐지기 + 나쁜 임계값 = 알림 피로.** AUROC가 높은 탐지기도 임계값을 기준율과 무관하게 0.5에 두면, 대부분 정상인 이벤트에 경보가 울린다. 여기서 "경보"가 verify였고, 경보마다 비싼 모델 호출이 붙었다. 모니터링에서 정밀도(울린 경보 중 진짜 비율)를 **운영 임계값에서** 재는 것과 같다. 순위(AUROC)는 임계값 선택의 *재료*일 뿐이다.
- **기준율을 먼저 본다.** 에이전트의 완료 요청이 87% 맞는 환경에서 "검증하라"의 기대 이득은 최대 13%의 실패를 일부 구하는 것뿐이고, 비용은 개입한 모든 요청에 붙는다. 어제 AI 심층 「실패 예측 조기 중단」(StopLoss)이 임계값을 **"성공한 실행을 5%만 죽이도록"** 보정한 것이 바로 이 논문에 빠져 있던 기준율 인식 임계값이다. 두 논문을 합치면 규칙이 나온다 — *판정자의 확률을 그대로 쓰지 말고, 내 루프의 기준율과 "잘못 개입했을 때의 비용"으로 임계값을 정하라.*
- **아끼는 행동이 실제로 쓰이는지 본다.** 이 실험에서 비용을 줄일 수 있는 행동은 abandon 하나였고 0회 쓰였다. 판정자를 붙일 때 "이 판정자가 고를 수 있는 행동 중 돈을 아끼는 것이 무엇이고, 그게 실제로 몇 번 발화했나"를 로그로 센다. StopLoss는 반대로 *끊는 것만* 하는 감시자였다.
- **A/B에 위약 군을 둔다.** "개입 있음 vs 없음"만 비교하면 개입 *행위*의 효과(에이전트를 한 번 멈춰 세우는 것 자체)와 개입 *내용*의 효과가 섞인다. 같은 시점·같은 빈도로 무작위 개입하는 군을 두면 갈린다. 기능 실험에서 "아무 의미 없는 변경만 준 군"을 따로 두는 것과 같은 발상이다.
- **비용을 주 결과로.** 통과율은 21과제로 ±11~13%p라 거의 아무것도 못 가렸지만, 비용 비는 15/21과제·leave-one-out으로 견고했다. 작은 실험에선 **비용이 더 민감한 지표**다. 에이전트 기능을 평가할 때 성공률만 보고 "차이 없음"이라 결론 내리면, 그 사이 청구서가 19% 오른 것을 놓친다.
- **평가 하네스의 함정 두 개(저자가 덧붙인 교훈).** ① "검증 명령을 돌렸나"를 명령 이름으로 판정하면, 자기 프로그램을 실행해서 확인하는 에이전트를 놓친다(사전 계획의 원래 특징은 캘리브레이션의 모든 완료 요청에서 거짓이었다 — 부록 D). ② 안전 거절은 빈 응답으로 오는데, 도구 호출 없는 응답을 완료 요청으로 치는 루프는 이를 "끝났다"로 오해한다.

「비생성 의사결정 모델」 노트와 연결하면: 그 노트가 경고한 "ECE는 학습 분포 안의 지표이고, 내 데이터로 다시 재야 한다"가 여기서 실측됐다. 실제 에이전트 루프의 완료 판정에서 Jev의 ECE는 0.37이었다.

## 한계와 미검증 지점

- **표본이 작다.** held-out 21과제 중 easy 14·mid 3·hard 4. 통과율 신뢰구간이 ±11~13%p라 통과율 결과는 어느 쪽으로도 약한 증거다. mid·hard 층은 추론에 너무 작다(층별 통과율 차 easy +7.1%p, mid −22.2%p, hard −8.3%p는 참고만).
- **에이전트 하나, 결정 모델 하나.** Sonnet 5.5 + 최소 루프 + Jev 1.13 + 저자의 선택지 문구·안내 메시지 조합 하나다. 사전 계획한 오픈 웨이트 복제(C5)는 OpenRouter 호스트마다 양자화가 달라 모델을 고정할 수 없어 **실행하지 않았다**.
- **비결정성.** Sonnet 5.5 엔드포인트가 temperature를 받지 않아 샘플링이 탐욕적이지 않고, 호스트도 고정하지 않았다(94.6% Claude Platform on AWS, 5.4% Azure, 조건별 비슷).
- **위약의 분포가 얇다.** 개발 표본(진행 결정 8개, 완료 결정 23개)에서 뽑았고 포기 확률이 0이다 — 위약은 *결정 내용*을 시험하지 *개입 빈도*를 시험하지 않는다.
- **오프라인 라벨은 반사실이 아니다.** "그 시점에 다른 결정을 했다면"의 결과가 아니라 실제 시행 결과로 채점했다.
- **저자가 제안만 하고 안 한 것.** 보정된 확률 + 기준율 인식 임계값 + 실제로 쓰일 멈춤 행동으로 새 과제에서 사전 등록 재실험 — 이게 있어야 "판정자는 쓸모없다"와 "이 정책이 쓸모없다"가 갈린다. 지금 결과는 **후자에 대한 증거**다.
- **결정 모델 회사와의 관계.** Jev를 만든 TypeSafe와 저자의 관계는 원문에 없다. 결과가 Jev에 불리한 방향이라 이해 상충 우려는 작지만, 반대로 Jev 측 반론(다른 문구·임계값이면 다르다)도 아직 없다.
- 그림 2(과제별 비용 비 분포)는 캡션만 읽었고 GitHub 코드·로그는 보지 않았다.
