# AI - 평가 해상도와 자기진화 선택

> 상위: [[AI 심층 정리 인덱스]]

> [!info] 예습자료 — 무인 세션이 자동 생성, 사용자 미검증

> 계기: *The Resolution Hypothesis: Agent Evolution's Key Is Identifying Improvements* — Yuanhao Zeng 외(ShanghaiTech, 교신 Kan Ren), arXiv 2611.23068, 11/16 공개, HF ▲35(11/19 2위), 11/20 브리핑.
> 읽은 범위: HF 초록·제출자 코멘트·댓글, 프로젝트 페이지 전체(결론 4개·Q&A 9개·증거 4단계·지름길 지도의 SpreadsheetBench 사례·방법 논문 표·사례 스킬). **논문 PDF 본문(부록의 지름길·수리 표 전체, 통계 절차의 세부)은 읽지 못했다.** 아래 숫자는 프로젝트 페이지 기준.

## 한 줄 정의

에이전트가 자기 프롬프트·스킬·메모리·하네스를 고쳐 점수를 올리는 **자기진화 루프** 는 "더 나은 후보를 **만드는** 능력"이 아니라 "더 나은 후보를 **알아보는** 능력" — 평가의 **해상도(구별할 수 있는 최소 차이)** — 에서 막힌다는 가설과 그 측정. 개선 폭이 평가 노이즈보다 작으면 루프는 실력이 아니라 운을 수확한다.

## 왜 이게 문제였나 (기존 방식의 한계)

자기진화 루프는 단순하다. **제안기(proposer)** 가 후보 산출물(프롬프트·SKILL.md·메모리·하네스 코드)을 쓰고, **선택(selection)** 이 점수가 더 높은 것을 받아들인다. 이 루프를 쓰는 방법들(GEPA, ACE, ReasoningBank, SkillOpt, Meta-Harness, AHE …)은 논문마다 "기존 최고 대비 +N%p"를 보고했는데, 실무자가 보기엔 두 가지가 이상했다.

1. **방법 간 순위가 논문마다 뒤집힌다.** A 논문에선 GEPA가, B 논문에선 SkillOpt가 이긴다.
2. **어떤 과제에선 아예 시동이 안 걸린다.** Terminal-Bench 같은 곳에서는 라운드를 돌려도 오르지 않는데, 다른 곳에선 +10~40%p가 나온다.

지금까지의 해석은 대개 **제안기 탓** 이었다 — "모델이 더 좋은 개선안을 못 만든다", 그러니 더 영리한 제안기(반성, 트레이스 분석, 진화 연산)를 만들자. 이 논문은 반대 방향을 본다. 좋은 후보는 이미 나오고 있는데, **그걸 골라내는 평가가 동전 던지기 수준** 이라는 것이다.

이 폴더의 10/18 노트(하네스 자기진화의 증거 기준)는 같은 문제를 **"주장을 선택·활성화·귀인·개선 넷으로 쪼개고 각각에 필요한 증거를 정하자"** 는 이론·보고 규범으로 다뤘다. 이번 논문은 그 걱정이 **실제로 얼마나 심한지** 를 1,000만 회 넘는 LLM 호출로 잰 것이다.

## 어떻게 푸는가 — 정확히는 "어떻게 재는가"

### 1. 노이즈를 두 층으로 나눈다

동결된 모델에 텍스트 산출물을 바꾸는 방식의 진화는, 결국 **확률적인 다중 턴 실행(rollout)** 으로 점수를 매긴다. 점수 Ŷ의 분산을 두 성분으로 쪼갠다.

- **σ²(실행 노이즈)** — 같은 산출물을 같은 과제에서 다시 돌려도 결과가 다르다(모델 샘플링, 도구 타이밍, 환경 랜덤성).
- **τ²(실행 간 표류)** — 같은 **방법** 을 처음부터 다시 돌리면 다른 산출물 경로로 간다(진화 경로 자체가 확률적).

Var(Ŷ) = σ² + τ². 이 합의 제곱근이 **해상도의 바닥** 이다. 체중계 오차가 ±3kg인데 1kg 감량을 재려는 상황 — 개선 폭이 이 바닥보다 작으면, 점수가 오른 후보를 받아들이는 탐욕적 선택은 "실제로 나은 후보"가 아니라 "운 좋게 높게 나온 후보"를 고른다.

Terminal-Bench v2.1의 경험적 중앙값(20개 구성): σ = 3.87%p, τ = 1.36%p, 1회 실행 비교의 표준편차 ≈ 4.07%p. 여기에 표준 검정력 공식 N ≥ 2·[(z₁₋α/₂ + z₁₋β)/Δ]²·(σ² + τ²)를 넣으면, 문헌 격차 중앙값 Δ = 3.4%p를 80% 검정력으로 가리는 데 **방법당 독립 실행 23회** 가 필요하다(직접 계산해도 2 × (2.80/3.4)² × 16.83 ≈ 22.9). 실제 논문들은 **1회** 다 — 그때의 검정력은 약 9%.

### 2. 네 단계 증거 사슬

| 단계 | 질문 | 결과 |
| --- | --- | --- |
| Ⅰ 퍼즐 | 1회 실행으로 두 방법을 가를 수 있나 | 같은 벤치마크 구성 쌍 341개 중 217개(64%)의 평균 차가 1회 실행 표준편차보다 작음. Terminal-Bench에서 4개 방법 중 최고 맞히기 33%(무작위 25%) |
| Ⅱ 착시 | +10~40%p는 해상도 문제를 반박하나 | 12개 벤치마크 × 3모델 감사: 8개에서 **채점기 지름길**. 진화 안 한 기준선에 **한 문장 규칙** 을 붙이면 3%p 넘는 이득의 중앙값 90% 재현, **채점을 고치면 17.6 → 0.8%p** |
| Ⅲ 분리 | 제안이 실패하나, 선택이 실패하나 | 제안: 후보 100개 중 최고의 실제 성능(Quality@100) 61.8%, **동일 품질 null 58.4% 대비 +3.4%p**, 단일 스킬 간 차이 15%p+. 선택: 실행 1회 게이트 **49.7%**, 2회 48.6%, LLM 판정 45.4~49.0%(판정 점수와 실제 성능 상관 r = 0.054) |
| Ⅳ 표류 | 동전 수준 선택을 라운드마다 반복하면 | 루프 안 점수는 +6.9~+9.0%p 오르는데 **같은 산출물을 8배 재평가하면 +0.35~−3.21%p**. τ²는 라운드가 갈수록 4.2~24.5%p²로 커짐 — 실행마다 서로 다른 곳으로 흩어진다 |

Ⅲ의 "동일 품질 null"이 중요하다. 후보 100개의 점수 중 최댓값은 **모두가 똑같이 평범해도** 노이즈 때문에 평균보다 높다(승자의 저주). 그래서 "100개 중 최고가 61.8%"만으로는 아무 말도 못 하고, **모든 후보 품질이 같다고 가정했을 때 기대되는 최댓값 곡선(58.4%)** 을 빼야 진짜 여유분(+3.4%p)이 나온다. 그리고 그 판정은 **진화에 쓰지 않은 10개 과제 × 16회 실행** 으로 했다.

### 3. 지름길은 어떻게 생기나 — SpreadsheetBench 사례

배포된 채점기가 결과 엑셀을 openpyxl `data_only=True`로 연다. 이 옵션은 수식 셀의 **캐시된 값** 을 읽는데, 파이썬으로 쓴 워크북엔 캐시 값이 없으니 **모든 수식 셀이 빈칸 = 오답** 이 된다(공식 평가는 수식을 다시 계산한 뒤 비교). 그래서 진화 안 한 기준선 자체가 수식 답을 대부분 잃고(33.5/43.4/35.3 → 재계산하면 58.0/66.9/69.4), 진화는 "**수식 말고 계산된 값을 써라**"를 찾아낸다 — 이게 약 30%p. GPT-5.4 nano로 돌린 SkillOpt-Lite 8회 실행이 **전부** 이걸 발견했다. 한 문장 규칙이 세 모델 모두에서 진화 이득과 맞먹었고, LibreOffice로 재계산하게 고치자 +5.7~6.7%p만 남았다.

여기서 읽을 것: 진화는 **노이즈 바닥을 넘는 신호라면 무엇이든** 최적화한다. 채점기의 빈틈 하나가 모든 과제에 한꺼번에 먹히면 그 신호는 노이즈를 넘으니 잘 잡히고, 진짜 과제별 기술(+1~3%p)은 바닥 아래라 안 잡힌다. 그래서 "큰 이득"은 해상도 가설을 반박하는 게 아니라 **확인** 해 준다.

### 4. 반례처럼 보이는 것 — 결정론적 프로그램 진화

AlphaEvolve·KernelAgent·ARC-AGI처럼 **프로그램 코드를 진화시키는** 쪽은 꾸준히 쌓인다. 저자들은 이것도 가설을 지지한다고 본다 — 결정론적 프로그램은 **싸게 병렬 재평가** 할 수 있고 런타임 진단(속도·정답 여부)이 풍부해서, 작은 개선도 해상도를 넘는다. 노이즈를 구조적으로 줄인 것이다.

### 5. 처방 네 가지 (저자)

1. **분산이 낮은 과정 검사** — 최종 성공/실패 한 비트 대신 프로그램으로 확인하는 중간 행동 진단. 노이즈가 **13~57배** 작다.
2. **구성 요소별 평가** — 제안기는 Quality@K 대 null로, 선택기는 고정된 후보 풀에서 고른 산출물의 곡선으로 따로 잰다.
3. **해상도 보고** — 점수 옆에 σ와 τ를 같이 낸다(9개 논문 178개 결과 중 분산 보고 **0개**, 여러 실행 평균 **6개**).
4. **해상도 높은 체제** — 검증 실행을 늘리거나(16배로 하면 테스트 61.4 → 64.4%, 최고 실행 64.8 → 72.7%, 대신 내부 루프 비용 16배), 결정론적 환경 피드백을 쓴다.

## 실제로 쓸 수 있나

에이전트 자기진화를 직접 만들지 않아도, **프롬프트·스킬·CLAUDE.md를 고치며 "좋아졌다"를 판단하는 모든 사람** 에게 바로 쓰인다.

- **A/A부터 잰다.** 바꾸기 전 설정을 같은 과제로 3~5번 돌려 성공률의 흔들림을 본다. 그 흔들림(대략 σ)보다 작은 개선은 기록하지 않는다. 11/17 노트(같은 점수 뒤의 다른 작업 습관)의 "A/A 대조 6.4%"와 같은 습관이다.
- **평균 비교보다 쌍별 비교.** 같은 문항에서 A가 이긴 수 대 B가 이긴 수를 센다(HF 댓글의 질문 — 논문이 이 방식도 동전 수준인지 답했는지는 미확인). 문항 간 난이도 차이라는 노이즈 한 층이 빠진다.
- **한 문장 테스트.** 개선된 프롬프트가 크게 좋아졌으면, "그 차이를 한 문장 규칙으로 요약해 원래 프롬프트에 붙여 보기"를 먼저 해 본다. 그걸로 대부분 재현되면 그건 기술 축적이 아니라 **채점기(또는 테스트)의 성질 하나** 를 찾은 것이다 — 그리고 그 성질이 진짜 요구사항인지 채점기의 버그인지 확인한다.
- **결과 한 비트 대신 과정 검사.** "테스트 통과/실패" 대신 "수정 후 diff를 확인했나, 기존 테스트를 돌렸나, 요구된 식별자를 그대로 썼나" 같은 프로그램 검사로 재면 노이즈가 줄어든다. 논문이 찾은 "진짜 이전되는 좋은 스킬"도 그런 성격이었다 — **과제가 명시한 정확한 식별자·시그니처·오류 문자열을 그대로 쓰고 assert로 확인하라**, **토크나이저·임베딩은 명시된 패키지로만 호출하라** 같은 규칙(과제 11개 평균 +11.4%p). 선택기는 이걸 못 알아봤다.
- **LLM 판정자를 선택기로 쓰지 말 것** — 적어도 궤적만 보고 "어느 쪽이 나은가"를 묻는 형태로는 45~49%였다. 11/20 브리핑의 쇼핑 논문(추론 노력을 올리면 확신만 오른다)과 겹쳐 읽으면, 모델이 말하는 "이쪽이 낫다"의 자신감은 정확도의 대리 지표가 아니다.

## 한계와 미검증 지점

- **"동전 수준"은 표준 예산의 결과** 다. 실행 1~2회·궤적 LLM 판정이라는, 실제 방법들이 쓰는 조건에서 잰 것이고, 예산을 늘리면 나아진다(16배 검증 결과). "선택은 원리적으로 불가능"이 아니라 "지금 관행의 예산에선 불가능"이다.
- **벤치마크 범위.** 해상도 숫자는 주로 Terminal-Bench v2.1·ALFWorld·OfficeQA·SpreadsheetBench, 제안/선택 풀은 Terminal-Bench 10~11개 과제. 다른 도메인(코드 리뷰, 장기 에이전트 작업)에서 σ·τ가 얼마인지는 모른다. 저자도 "강한 모델은 포화된 벤치마크에서만 노이즈가 줄었다(Terminal-Bench는 모델 등급과 무관하게 3.5~4.0%p)"고 했다.
- **지름길 판정의 주관성.** 지름길 후보는 LLM 에이전트가 산출물을 읽어 표시하고 사람이 채점기와 대조해 확인했다. 어떤 행동이 "지름길"이고 어떤 것이 "벤치마크 관례에 맞춘 정당한 적응"인지는 경계가 흐릿하다 — 저자도 +20~40%p를 "실제 최적화지만 벤치마크 전체 관례에 대한 것"이라고 표현했다.
- **기존 방법 재현의 충실도.** GEPA·SkillOpt-Lite 산출물을 저자들의 모델로 옮겨 평가한 이득은 원 논문 모델에서보다 작다고 스스로 적었다. 방법 저자 측 반론은 아직 못 봤다.
- **"쌍별 비교라면?"** — 평균 대신 문항별 승패로 고르면 선택 정확도가 오르는지는 HF 댓글로 제기됐을 뿐 답을 확인하지 못했다.
- **논문 본문 미독.** 13~57배 노이즈 감소를 어떤 진단으로 얻었는지, 다봉(multimodal) 점수 분포가 어떤 조건에서 나오는지 세부는 PDF에 있다.
