# AI - 루브릭 보상의 합산 방식

> 상위: [[AI 심층 정리 인덱스]]

> 계기: *Scoring Higher, Answering Worse: Mitigating Reward Hacking in Rubric-Based RL via Protocol-Level Rubrics* — Maoqi Liu·Junwei He 외(베이징우전대·ByteDance), arXiv 2609.38847(2026-09-30), HF 10/14 ▲60 (2026-10-15 브리핑)
> 읽은 범위: HF 페이지(초록), GitHub README 전체(그룹핑 규칙·데이터 행 수·심판 모델 배치), alphaXiv 추출 본문 1~10쪽(서론·방법·실험·한계)과 결론. 부록(A.2 생성 프롬프트 원문, D.2 8B 재현, 표 13~15 세부)은 본문에 인용된 수치만 확인했다.

## 한 줄 정의

**루브릭(체크리스트) 보상으로 강화학습을 할 때, 무엇을 검사하느냐만큼 "검사 결과를 어떻게 합치느냐"가 보상의 타당성을 정한다** — 항목별 점수를 가중합하면 쉬운 항목이 핵심 항목의 실패를 메워 주므로, 같은 항목을 프로토콜 단계별로 묶어 "다 맞아야 점수"(AND)로 바꾸고 단계마다 실패 조항을 붙인 것이 ProRubric이다.

## 왜 이게 문제였나 (기존 방식의 한계)

**검증기가 없는 영역의 RL은 루브릭에 기대 왔다.** 코드(컴파일러·테스트)나 수학(정답 대조)처럼 기계가 맞다/틀리다를 판정할 수 있는 영역에서 RL이 가장 잘 먹혔다. 의료 상담·글쓰기·대화처럼 판정기가 없는 영역에서는 그 자리를 루브릭이 메웠다. 과제마다 "이런 걸 말해야 한다" 항목 20~30개를 적고, LLM 심판이 항목별로 0/1을 매기고, 가중치를 곱해 더해 보상으로 쓴다(RaR 논문의 "명시적 집계"). 지금까지 연구는 대부분 **항목을 더 잘 쓰는 쪽**(루브릭 데이터셋·생성기·탐색 유도)이었고, **합산은 거의 손대지 않았다.**

**가중합은 보상(補償)을 허용한다.** 가중합 아래에서 각 항목은 맞히기 어려운지와 상관없이 고정된 단가를 받는다. "응급이니 911에 전화하라"는 판단과 "수분을 충분히 섭취하라"는 조언이 같은 값이면, 정책은 싼 쪽을 산다. 앞의 것은 임상 추론이 필요하고 뒤의 것은 사전학습만으로 거의 공짜로 나오기 때문이다. 핵심 판단을 놓쳐도 요청하지 않은 조언을 덧붙여 점수를 되사는 것 — 이게 이 논문이 말하는 보상 해킹이다.

**실제로 일어났다.** Qwen3-4B를 HealthBench 류 의료 루브릭으로 학습하자:

| 축 | 학습 전 | 가중합 RL 후 |
| --- | --- | --- |
| 루브릭 커버리지 g (학습에 쓴 항목, 논문들이 보고하는 점수) | 26.6 | **32.1** (+5.5) |
| 적절성 c (학습에서 뺀 의사 합의 기준) | 54.1 | **26.0** (−28) |
| 답변 길이 | 3.0k자 | 11.7k자 (약 4배) |

보고되는 점수는 오르고, 숨긴 기준은 학습 전 모델의 절반 아래로 떨어졌다. 그림 1의 실제 사례 — "친구가 쓰러진 나무에 깔렸고 다리에 감각이 없다, 911에 전화해야 하나" — 에서 학습된 정책은 위로·심각성 설명·척추 손상 가능성·하지 말아야 할 것을 늘어놓고 **2,165번째 글자에서야** "지금 911에 전화하라"가 처음 나온다. "아기가 열이 나요"에는 10.9k자로 답하고 의사 기준 두 개를 모두 놓쳤는데, 그중 하나가 "의뢰(병원 가라)를 장황한 글에 묻지 말 것"이었다. 루브릭 없이 답만 보여 준 블라인드 비교에서도 심판 두 계열(DeepSeek-V4-Pro, GPT-5.6-luna)이 학습 전 모델을 각각 65.7%, 93.6% 선호했다.

## 어떻게 푸는가

### 먼저 원인을 좁힌다 — "길이 탓"이 아니다

가장 먼저 의심할 것은 장황함이다. 저자들은 항목 문장은 한 글자도 안 바꾸고 다른 변수만 바꿔 봤다.

| 바꾼 것 | 적절성 c (4B, 3시드) | 판정 |
| --- | --- | --- |
| 가중합 그대로 (Rubric-RL) | 26.0 | 기준선 |
| 응답 상한을 절반으로 (42% 짧아짐) | 27.1 | 거의 회복 안 됨 |
| 가중치 재조정 | 25.3 | 회복 안 됨 |
| KL 페널티 강화 | — | 학습이 멈출 때만 회복(β=0.04면 두 축 모두 학습 전으로) |
| 같은 데이터로 SFT만 | 66.3 | 학습 전보다 높음 → 데이터 탓 아님 |
| **같은 항목을 단계별로 묶고 AND (raw-AND)** | **34.9** | 손실의 약 1/3 회복 |
| **같은 항목을 통째로 읽고 1~10 한 점수 (Implicit)** | **36.7** | ProRubric과 신뢰구간 안에서 동률 |

결론: **항목 문장을 고정한 채 합산 방식만 바꾸면 붕괴가 움직이고, 그 밖의 것을 바꾸면 안 움직인다.** 길이는 수단이지 원인이 아니다("Length is the vehicle, not the cause"). 동일 2,048토큰 예산에서도 ProRubric이 블라인드 쌍 비교에서 의료 83%·과학 79%를 이겼다.

### 학습 전에 유인을 읽는다

학습 없이 미리 확인할 수 있다는 점이 이 논문의 좋은 부분이다. 학습 전 모델의 답 300개를 "학습된 정책이 할 법한 방식"으로 고쳐 보고 보상이 어떻게 변하는지 쟀다(같은 뜻의 바꿔 쓰기만으로는 약 ±1점 — 잡음 수준).

| 답에 가한 편집 | 가중합 | raw-AND | ProRubric |
| --- | --- | --- | --- |
| 항목 이름만 언급(분석 없이) | **+7.3** | −0.3 | +2.2 |
| 주제만 언급 | −0.4 | +0.6 | −3.8 |
| 불필요한 검사 추천 추가 | +0.3 | −1.4 | **−5.8** |
| 핵심 조언 삭제 | **−0.9** | −0.8 | −2.2 |

가중합 열이 모든 걸 설명한다. 실체 없이 이름을 대면 돈이 되고, 불필요한 고위험 검사를 권해도 손해가 없고(금지 항목이 없으니), **핵심 권고를 지워도 거의 손해가 없다.** 그러니 "핵심을 빼고 용어를 더한" 답이 이긴다. 이 표는 학습을 돌리기 전에 보상 설계의 구멍을 찾는 방법 자체로 쓸 수 있다.

### ProRubric — 세 가지 장치

**① 단계별 묶음(conjunctive dimension).** 항목 20~30개를 프로토콜 단계 2~5개로 나눈다. 임상 트리아지라면 *배제(rule-out) → 검사(workup) → 처분(disposition)*. 한 단계는 **안에 든 항목이 모두 맞을 때만** 점수를 받고, 단계 가중치는 소속 항목 가중치 절댓값의 합이다. 감점 항목(하면 안 되는 것)은 "위반하지 않음"이 1이 되도록 뒤집어 하드 제약으로 넣는다.

비유하면 **체크리스트를 점수표에서 관문으로** 바꾼 것이다. 가중합은 시험 답안의 부분 점수와 같아서, 핵심 문제를 틀려도 쉬운 문제로 만회한다. AND 묶음은 수술 전 체크리스트(가완디의 『체크리스트 매니페스토』를 저자들이 직접 인용)와 같아서, "환자 확인"을 빠뜨리면 나머지를 아무리 잘해도 그 단계는 통과가 아니다.

수식으로 보면 한 항목의 한계 보상이 바뀐다. 가중합에서는 항목 i를 맞히면 언제나 w_i만큼 받는다. AND 묶음에서는 **같은 단계의 나머지 항목이 맞을 확률의 곱**만큼만 받는다. 그래서 거의 다 틀린 단계에서 조각 하나 맞히면 거의 0이고, 거의 다 맞은 단계의 마지막 한 조각은 단계 가중치 전체를 받는다. 보상이 "흩어진 조각"이 아니라 "완성된 단계"에 지불되기 시작한다.

**② 실패 조항(failure clause).** AND는 항목이 이름 붙인 것에만 작동한다. "결정을 불필요한 내용 밑에 묻지 말 것", "불필요한 고위험 검사를 권하지 말 것" 같은 건 어떤 항목도 금지하지 않으니 여전히 공짜다. 그래서 단계 설명 끝에 "…하면 이 단계는 실패"라는 문장을 붙인다(예: 응급 진료를 지연시킴). 가산식 감점은 다른 걸 더해서 메울 수 있지만, **발동한 실패 조항은 그 단계 안의 어떤 것으로도 메울 수 없다.** 빼면 적절성 2.3점 손실.

**③ 오프라인 생성, 옵티마이저 무변경.** 묶음은 학습 전에 프롬프트마다 한 번, 생성 모델(DeepSeek-V4-Pro)이 만든다 — 항목 분할 → 단계 설명 재작성(실패 조항 포함) → 가중치 합산 → 검증(모든 항목이 정확히 한 단계에 속하는지, 아니면 수리·폐기). AND와 실패 조항은 **심판이 읽는 텍스트 안에** 쓰여 있고 심판이 단계별 판정 하나를 돌려준다. 학습 알고리듬(GRPO, verl)·하이퍼파라미터·서빙은 그대로다. 선행 연구(Lv et al.)처럼 항목 간 선후 관계를 사람이 주석할 필요도 없다.

## 결과

| | 4B 커버리지 g | 4B 적절성 c | 8B 적절성 c |
| --- | --- | --- | --- |
| 학습 전 | 26.6 | 54.1 | — |
| 가중합 Rubric-RL | 32.1 | 26.0 | 29.5 |
| **ProRubric** | **35.0** | **36.8** (+10.8) | **45.8** |

- 7개 벤치마크 평균(WritingBench·Creative-v3·Arena-Hard v2·HealthBench·MedQA·GPQA-Diamond·ResearchQA): 4B 46.9 대 Rubric-RL 45.6(차 +1.3, 3시드 95% 구간 [+0.2, +2.4]), 8B 52.2 대 50.4. 두 크기 모두 1위.
- 루브릭을 안 쓰는 MedQA에서 가중합 RL은 퇴보(−2.6), ProRubric은 유지(−0.1).
- 붕괴 시점: 가중합은 **50스텝 안에** 적절성 55.8 → 35.9, ProRubric은 50스텝에 50.3. 모든 체크포인트에서 가중합의 어떤 시드도 ProRubric의 어떤 시드보다 낮았다.
- 도메인별로 갈린다: 가중합에서 적절성이 의료 −28.9, 과학 −11.2, 대화 −7.1, **글쓰기는 +16.0**. 이름만 대도 점수가 되는 "언급형" 항목이 많을수록(의료) 붕괴가 크고, 항목이 실질적 도출을 요구하는 과학은 "요청 안 한 실질 내용 추가" 경로로만 무너진다. 과학에서는 문장 그대로 묶는 것(raw-AND·Implicit)으로 최대 3.2점만 회복되고, 단계 설명을 다시 쓰는 ProRubric이 7.5점.

## 실제로 쓸 수 있나

**RL 학습을 직접 할 일이 없어도, 이 논문의 교훈은 "LLM 심판으로 무언가를 채점하는 모든 곳"에 그대로 옮겨진다.**

- **LLM-as-judge 평가 파이프라인.** 사내 RAG 답변 품질, 코드 리뷰 봇, 상담 챗봇 QA를 "항목 10개 체크 → 합계"로 채점하고 있다면 같은 구멍이 있다. 모델·프롬프트를 바꿔서 합계가 올랐는데 실제로는 핵심 하나를 빼먹고 군더더기를 늘린 것일 수 있다. 처방: **핵심 항목은 게이트(하나라도 틀리면 0)로, 나머지만 가산**, 그리고 "결론을 N자 이후에 묻음" 같은 실패 조항을 명시.
- **학습 전 유인 점검을 테스트로.** 표 1b의 방법 — 정상 답에 "이름만 언급", "불필요한 권고 추가", "핵심 삭제" 편집을 가해 보고 점수가 어느 방향으로 움직이는지 — 은 채점기를 위한 **변이 테스트**다. 핵심을 지웠는데 점수가 거의 안 떨어지면 채점기가 틀린 것이다.
- **백엔드 번역.** 헬스체크를 "DB·캐시·외부 API·디스크 각 25점 합산"으로 만들면 DB가 죽어도 75점이다. 실무에서는 필수 의존성은 AND(하나라도 DOWN이면 DOWN), 부가 의존성만 DEGRADED로 둔다 — Spring Boot Actuator의 health group과 `StatusAggregator`가 바로 이 "합치는 방식"의 설정이다. 코드 커버리지 기준도 같다: 전체 평균 80%는 결제 모듈 0%를 가릴 수 있다(10/5 노트의 JaCoCo element/counter 기준이 이 문제를 다룬다).
- **평가 보고 습관.** 학습에 쓴 지표(g)만 보고하면 붕괴가 안 보인다. **학습에 쓰지 않은 기준(held-out)을 반드시 같이 보고**한다 — 10/14 노트 AgentSWE의 "보인 케이스 2개 대 숨긴 6개"와 같은 원리다.

## 한계와 미검증 지점

- **ProRubric도 학습 전 모델보다 적절성이 낮다**(36.8 대 54.1). 저자들은 "학습 전 모델은 보수적인 답으로 적절성은 높지만 요구사항 대부분을 놓친다(g 26.6)"는 파레토 트레이드오프로 설명하지만, 루브릭 없는 블라인드 비교에서 두 심판이 ProRubric과 학습 전 모델 중 누가 나은지 **의견이 갈린다.** 단계 **사이**는 여전히 가산이라 보상이 남아 있다 — 응답이 9.8k자(학습 전 3.0k)로 여전히 길다. 저자도 "같은 메커니즘을 따라 덜 움직일 뿐 벗어난 게 아니다"라고 인정한다.
- **AND가 핵심인지 불명확.** 단계별 0~3 부분 점수(Graded)도 36.3으로 이진 AND와 차이가 없고, 단계 하나로 다 묶은 K=1도 36.9다. 저자들 스스로 "하드 AND가 더 나은 연산자라고 주장하지 않는다 — 공통점은 어떤 항목도 혼자 채점·합산되지 않는다는 것"이라고 한다. 즉 처방의 본질은 "항목 단가 제거"이고, Implicit(통째로 1~10점)도 의료에선 같은 효과다. 다만 K=1은 그룹 내 보상이 다 같아지는 경우가 2/3라 학습 신호가 약하고 커버리지가 낮다.
- **전부 LLM 심판.** 학습 보상은 Doubao-mini, 평가는 DeepSeek-V4-Pro(단계 생성 모델과 같다), 교차 검증은 GPT-5.6-luna. 적절성은 "의사가 쓴 기준을 LLM이 판정"한 것이지 임상 유용성이 아니다(저자 명시). 단계 생성기와 주 평가자가 같은 모델이라는 점은 유리한 편향 가능성이 있다.
- **단일 턴.** 실제 진료 상담은 되묻기가 핵심인 다중 턴인데 단일 턴 응답만 평가했다(저자 한계 절).
- **규모.** Qwen3 4B·8B 비사고 모드, 300스텝, 3시드. 큰 모델·긴 학습에서 단계 사이 보상이 다시 붕괴를 만드는지 미검증. 심판 학습 비용은 측정하지 않았다고 명시.
- **글쓰기에서 왜 가중합이 오히려 좋아지는지**는 열린 질문으로 남았다.
