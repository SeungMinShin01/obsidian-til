# AI - Φ-Bench 인프라 엔지니어링 벤치마크

> 예습자료 — 자동 수집, 사용자 미검증. 정리본이 아니다.
> 2026-09-11 Hugging Face Daily Papers 1위(업보트 54). StepFun, 저자 12명. arXiv 2609.10226

## 한 줄

**"LLM이 자기를 떠받치는 인프라를 직접 엔지니어링할 수 있는가"** 를 재는 벤치마크. 결론은 아직 아니다 쪽이고, 그 "아직"의 위치를 구체적으로 그려 보인 것이 이 논문의 값이다.

## 무엇이 문제였나

기존 코딩 벤치마크가 재는 것은 대체로 이런 모양이었다.

- 고립된 커널 하나 최적화
- 미리 정해진 연산자(operator)를 구현
- 최적화 목표가 이미 지정된 상태에서 수치 올리기

세 가지 공통점은 **문제가 이미 정의돼 있다**는 것이다. 저자들의 문제의식은 여기서 출발한다 — 그래서 모델이 90점을 받아도 "그럼 실제 인프라 최적화를 맡길 수 있나"에는 답이 되지 않는다. 실제 인프라 일은 **무엇을 고쳐야 하는지부터 찾아야 하는** 열린 문제이기 때문이다.

> 익숙한 형태로 옮기면 이렇다. "이 메소드의 N+1 쿼리를 고쳐라"는 정의된 문제다. "이 Spring Boot 서비스의 응답이 느린데 원인을 찾아 고쳐라"는 열린 문제다. 둘은 같은 능력을 재지 않는다. 전자는 코드를 쓸 줄 아는가를, 후자는 **프로파일링 → 가설 → 검증 → 수정**의 루프를 돌 줄 아는가를 묻는다.

## Φ-Bench가 재는 것

**LLM 인프라 스택 전체**를 대상으로 삼는다. 난이도가 층으로 구성돼 있다.

| 층 | 과제의 성격 |
| --- | --- |
| 국소(localized) | 커널 수준의 함수 완성 |
| 장기(long-horizon) | 긴 호흡의 구현 |
| 전체(end-to-end) | 시스템 단위 최적화 |

과제의 출처가 두 갈래라는 점이 중요하다 — **최신 연구에서 다뤄진 최적화 문제**, 그리고 **실제 코드 저장소**. 즉 합성 문제가 아니라 누군가가 실제로 풀었던 문제를 옮겨 왔다.

## 결과

프론티어 모델들을 돌린 결과, 논문의 표현으로는 **"자율적 AI 인프라 최적화로 가는 길에는 여전히 지속적인 난관이 있다"**. 공개된 초록·페이지 수준에서는 개별 모델명과 점수, 과제 수, 층별 문항 분포가 확인되지 않는다 — 이 노트는 거기까지만 적는다. 수치가 필요하면 GitHub 저장소와 PDF를 직접 확인해야 한다.

## 왜 이게 1위였나

업보트 54는 절대 수치로는 크지 않지만 그날 1위였다. 같은 날 HF 목록의 다른 논문들과 겹쳐 보면 맥락이 잡힌다.

- **SAEScientist-Bench** — 에이전트가 해석가능성 *연구*를 자율 수행할 수 있나
- **Discovery Certification Protocol** (CMU) — 벤치마크 점수가 올랐다는 사실만으로 발견을 증명할 수 없다
- **Φ-Bench** — 에이전트가 인프라 *엔지니어링*을 할 수 있나

셋이 같은 질문의 세 변주다. **"에이전트가 코드를 짤 수 있나"에서 "에이전트가 일을 할 수 있나"로 질문이 한 칸 올라갔고, 그 올라간 질문을 재는 자가 아직 없다**는 것. 2026년 9월 둘째 주에 이 계열 논문이 몰린 것은 우연이 아니다.

그리고 이 흐름은 같은 날 Shopify의 React Native 이탈 발표와 정확히 맞물린다. 그쪽은 "에이전트에게 통째로 던지면 유지보수 불가능한 코드가 나온다"는 실무 쪽 관찰이었고, Helix라는 체크포인트 시스템으로 그 빈틈을 메웠다. Φ-Bench는 그 빈틈이 **어디에 얼마나** 있는지를 재는 자를 만들려는 시도다. 현장과 벤치마크가 같은 지점을 가리키고 있다.

## 읽고 나서 남는 질문

- "열린 문제"를 어떻게 채점하는가 — 정답이 하나가 아닌 최적화 과제에 점수를 매기는 기준이 무엇인지가 이 벤치마크의 신뢰도를 좌우한다
- 과제를 실제 저장소에서 뽑았다면, 그 저장소가 모델 학습 데이터에 이미 들어 있을 가능성(오염)은 어떻게 통제했는가
- 층별로 성능이 어디서 꺾이는지 — 국소는 되고 전체는 안 된다면, 못하는 것이 코딩인가 계획인가
