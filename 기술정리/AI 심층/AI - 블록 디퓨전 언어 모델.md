# AI - 블록 디퓨전 언어 모델

> 상위: [[AI 심층 정리 인덱스]]

> [!info] 예습자료 — 무인 세션이 자동 생성, 사용자 미검증 · 계기: DiffuSpace 「Clover-35B-A3B-Preview Technical Report」(arXiv 2611.24636, HF 그날 3위 ▲36, 11/24 브리핑). 읽은 것: HF 초록, DiffuSpace 프로젝트 블로그(중·영) 전문. **논문 본문·그림·벤치마크 표(이미지)·코드는 읽지 못했다.** 블록 디퓨전과 Gated DeltaNet의 일반 원리는 배경지식으로 적었고, 그 부분은 본문에 따로 표시했다.

## 한 줄 정의

문장을 일정 길이의 **블록** 으로 나눠, **블록과 블록 사이는 왼쪽에서 오른쪽으로(자기회귀)**, **블록 안은 가려 둔 자리를 여러 번에 걸쳐 동시에 채우는(디퓨전·디노이징)** 생성 방식. Clover는 여기에 **지나온 문맥은 고정 크기 순환 상태(Gated DeltaNet)로 압축해 들고 가고, 현재 블록 안은 양방향 softmax 어텐션으로 보는** 혼합 구조를 얹어 총 35B·활성 3B MoE로 키웠다.

## 왜 이게 문제였나 — 기존 방식의 한계

**① 자기회귀의 직렬 병목.** 지금 쓰는 LLM 대부분은 토큰 하나를 내려면 모델 전체를 한 번 돌린다. 특히 **배치 크기 1**(에이전트 한 세션이 혼자 GPU를 쓰는 상황)에서는 매 토큰마다 가중치를 메모리에서 읽어 오는 대역폭이 병목이라 연산기는 대부분 논다(배경지식). Clover 블로그가 강조하는 것도 이 지점이다 — 에이전트는 "결정 → 실행 → 피드백 → 조정"을 반복하므로 **생성 지연이 단계마다 누적** 된다.

**② 전체 디퓨전 언어 모델의 한계(배경지식).** 이미지 생성처럼 시퀀스 전체를 가려 두고 여러 번 고쳐 쓰는 방식은 한 번에 여러 토큰을 확정해 빠를 수 있지만,
- 출력 길이를 미리 정해야 하고,
- 모든 위치가 서로를 보는(양방향) 구조라 **KV 캐시를 재사용하기 어렵고**,
- 같은 스텝에 병렬로 확정한 토큰끼리 서로를 모른 채 정해져 **어긋날 수 있다** — 한 글자만 틀려도 깨지는 코드에서 치명적이다.

HKU NLP의 Dream 7B(2025-04)가 "디퓨전도 자기회귀와 맞붙을 수 있다"를 보였고, Clover 블로그가 던진 질문은 그다음이다: **"규모를 키워도 경쟁력을 유지하면서, 전역 생성의 속도 이점을 지킬 수 있나?"**

**③ 블록 디퓨전이라는 절충과 남은 숙제(배경지식).** 블록 단위로는 자기회귀, 블록 안에서만 디퓨전을 하면 — 끝난 블록은 확정이므로 캐시할 수 있고, 병렬성은 블록 안에서 얻는다. 남는 숙제는 **"지나온 블록들을 얼마나 싸게 들고 가느냐"** 다. 지나온 문맥 전체에 어텐션을 걸면 KV 캐시가 길이에 비례해 커진다.

| 방식 | 비유 |
| --- | --- |
| 자기회귀 | 한 글자씩 타자기로 친다. 친 글자는 못 고친다 |
| 전체 디퓨전 | 원고 전체를 흐릿한 초안으로 깔고 여러 번 퇴고해 한꺼번에 선명하게 |
| 블록 디퓨전 | 한 문단씩 쓰되, 문단 안은 여러 번 퇴고하며 동시에 채우고, 끝난 문단은 잉크로 굳힌다 |

## 어떻게 푸는가 — Clover의 네 가지 설계(블로그·초록 기준)

### ① 기억과 현재 블록을 다른 계산 방식으로

- **이미 생성된 문맥** → Gated DeltaNet(GDN)의 **순환 상태** 로 압축. 상태 크기가 고정이라 문맥이 길어져도 메모리가 늘지 않는다.
- **현재 블록의 토큰들** → **양방향 softmax 어텐션**. 아직 확정되지 않은 토큰끼리라 서로를 다 봐야 하고, 블록이 짧으니 양방향 어텐션 비용도 작다.

GDN이 무엇인지(배경지식): 선형 어텐션 계열로, "키 → 값" 연관을 고정 크기 행렬 상태에 써 넣는다. 그냥 더하지 않고 **델타 규칙** — 쓰기 전에 그 키로 지금 기억이 내놓는 값을 빼고 **차이만** 기록한다(틀린 만큼만 고친다) — 을 쓰고, **게이트** 로 오래된 기억을 감쇠시킨다. 같은 계열을 다룬 AI 심층 「AI - 지우기와 쓰기를 따로 다는 선형 어텐션」이 지우기·쓰기의 비대칭을 따로 다뤘다.

### ② 기억 판독값을 "한 칸짜리 토큰"으로 — 같은 softmax에서 경쟁

순환 상태에서 읽어 낸 값을 **독립된 정보 단위** 로 만들어, 현재 블록 토큰들과 **같은 softmax 안에 나란히** 넣는다. 그러면 모델이 위치마다 "지난 문맥에 기댈지, 지금 블록 안의 단서를 쓸지"를 어텐션 가중치로 스스로 고른다.

비유: 회의 참석자들(현재 블록 토큰) 사이에 **"지난 회의록 요약"을 한 사람처럼 앉혀 두고 발언권을 경쟁** 시키는 것. 요약이 중요하면 많이 듣고, 지금 논의가 중요하면 덜 듣는다.

### ③ 블록 크기 보정 — softmax의 희석을 되돌리기

softmax는 후보가 많을수록 각자의 몫이 줄어든다. 블록 안 토큰이 늘면 "기억 칸 하나"의 몫이 **자연히 희석** 된다. 아무 학습이 없다고 치고 균등하게만 나눠도(설명용 예시, 원문 수치 아님): 블록이 토큰 4개면 기억 칸 몫은 1/5 = 20%, 32개면 1/33 ≈ 3%다. 그래서 **학습 가능한 블록 크기 보정** 항을 둬 블록 크기가 바뀌어도 기억의 비중이 무너지지 않게 했다.

### ④ 오른쪽 문맥용 합성곱 가지를 0에서 시작

GDN 계열은 보통 앞뒤 몇 토큰을 섞는 짧은 **인과(왼쪽만 보는) 합성곱** 을 쓴다. 블록 안에서는 오른쪽도 봐야 하므로, **오른쪽 문맥을 보는 별도 가지를 0으로 초기화** 해 붙였다. 학습 시작 시점엔 기존(사전학습된) 인과 합성곱과 동작이 똑같고, 학습하며 오른쪽 특징을 따로 배운다. LoRA에서 한쪽 행렬을 0으로 시작해 처음엔 원래 모델과 똑같이 동작하게 하는 것과 같은 **"기존 능력 보존" 기법** 이다(비유는 배경지식). 블로그는 감사 문구에서 Qwen의 공개 아키텍처·학습 생태계를 출발점으로 들었다 — 사전학습된 자기회귀 계열에서 개조했음을 시사하지만, 정확한 출발 체크포인트는 확인하지 못했다.

### 덤: 결합 예측 — 관련 질문을 한 번의 디노이징으로

같은 자료에 딸린 질문 **최대 8개** 를 한 번의 디노이징 과정에서 **동시에** 답한다(결정 모델 변형, 출시 예정). 자기회귀라면 질문마다 따로 부르거나 순서대로 답해야 하지만, 디퓨전은 답들이 생성 도중 **서로를 참조** 할 수 있다. 블로그 예시: 같은 계약서에서 "통지가 기한 내였나"와 "보증금을 유보할 수 있나"는 규칙상 연결돼 있는데, 따로 판단하면 "통지 지연"이라 해 놓고 "유보 가능"(통지가 제때일 때만 가능)을 고르는 모순이 생길 수 있다. 결합 모드는 이 모순을 줄인다고 한다. 비교 대상으로 TypeSafe의 Jev가 직접 언급되는데, Jev 계열은 AI 심층 「AI - 비생성 의사결정 모델」에서 다뤘다.

## 한계와 미검증 지점

- **속도 수치의 대부분이 "내부 에이전트 워크로드"** 라 외부에서 재현할 수 없다. 공개 벤치마크 기준 속도는 MATH-500(소비자 GPU) 하나뿐이다.
- **비교군이 같은 크기 모델과 다른 디퓨전 모델** 이다. 프런티어 모델과의 비교는 없다.
- **초록과 블로그 숫자가 어긋난다.** 에이전트 지표는 초록 "일곱 개 전부 1위" 대 블로그 "여섯 개". 결합 예측은 초록이 문항 90.37% → 93.88%·전부 정답 그룹 65.4% → 77.0%, 블로그는 89.8% → 95.0%·62.4% → 80.4%(500그룹·2,420문항). 같은 내부 세트로 보이는데 값이 다르다 — 버전 차이인지 확인하지 못했다.
- **블록 크기, 블록당 디노이징 스텝 수, 품질-속도 노브** 가 무엇인지 모른다(논문 본문 미독). 디퓨전의 고질적 문제인 **병렬 확정 토큰끼리의 불일치·반복** 을 어떻게 다뤘는지도 확인하지 못했다.
- **사고 모드(thinking)** 가 블록 디퓨전에서 어떻게 동작하는지(사고 토큰도 블록 단위로 병렬 생성하나) 모른다.
- **데모 비교(경로 탐색 28단계 대 30단계 실패 등)는 단일 실행** 이다. 11/20 노트(평가 해상도: 실행 간 노이즈가 방법 간 격차보다 클 수 있다)를 떠올리면 한 번의 데모로 결론 내기 어렵다.
- 결정 모델 변형은 **아직 미출시** 다.
