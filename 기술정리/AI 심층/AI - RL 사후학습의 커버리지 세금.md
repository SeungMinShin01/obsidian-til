# AI - RL 사후학습의 커버리지 세금

> 상위: [[AI 심층 정리 인덱스]]

> 계기: *Sharpening Tax in Post-Training* — Changdae Oh, Qi Zeng, Qi Qi, Andrey Zhmoginov, Deren Lei, Yun He, Hoang Phan, Hangoo Kang, Azalia Mirhoseini, Sharon Li (Meta Superintelligence Labs · UW–Madison · NYU · Stanford), arXiv 2610.01509, HF ▲11 (2026-10-03 브리핑)
> 읽은 범위: HF 초록 전문, GitHub README, alphaXiv 구조화 보고서(방법·결과·한계 절). arXiv HTML 전문은 프록시 속도 제한(429)으로 읽지 못해 **세부 수식은 보고서의 서술로만 확인**했다.

## 한 줄 정의

사후학습(RL 등)은 과제들을 "항상 풀림 / 절대 안 풀림" 양 극단으로 밀어 **한 번에 맞힐 확률(pass@1)을 올리는 대신 여러 번 시도하면 풀 수 있던 과제의 폭(pass@K)을 깎는다** — 그 손실을 "기반 모델의 재시도 이득 − 사후학습 모델의 재시도 이득"으로 잰 진단 지표가 Sharpening Tax이고, 프롬프트 난이도별로 샘플링 온도를 바꿔 세금을 줄이는 방법이 PTGS다.

## 왜 이게 문제였나 (기존 방식의 한계)

**평가가 pass@1 하나에 묶여 있었다.** 모델 비교표는 대부분 "한 번 시켜서 맞힌 비율"이다. 그런데 실제 사용 방식은 둘로 갈린다.
- **한 번 쓰는 사용** — 사용자가 질문하고 답을 받는 챗봇. 여기선 pass@1이 전부다.
- **여러 번 뽑아 고르는 사용** — 코드 후보를 여러 개 생성해 테스트를 통과한 것만 채택, best-of-N, 검증기와 결합한 탐색, 에이전트의 재시도. 여기선 "K번 안에 한 번이라도 맞히나(pass@K)"가 기준이다.

수학·코딩에서는 이미 **날카로워짐(sharpening) 가설**이 관찰됐다 — "RL은 새 능력을 만들지 않고, 기반 모델이 원래 할 수 있던 행동 중 일부의 확률을 높일 뿐이다." 그 결과 pass@1은 오르지만 K가 커지면 기반 모델이 따라잡거나 앞선다. 문제는 **에이전트 과제에도 이게 적용되는가**였다. 에이전트는 구조화된 도구 호출, 환경 피드백 반응, 멀티턴 일관성이 필요하고, 이건 기반 모델에 없고 사후학습에서 **새로 배우는** 능력일 수 있다. 그렇다면 날카로워짐이 아니라 진짜 확장일 수도 있었다.

또 하나: pass@K 곡선 전체를 비교하는 건 번거롭고, 특정 K 한 점의 점수로는 "시도를 늘렸을 때 얼마나 더 얻는가(확장성)"가 안 보인다. **이 손실을 숫자 하나로 요약할 지표가 없었다.**

## 어떻게 푸는가

### 1) 측정 설계 — 기반 모델을 에이전트로 쓸 수 있게 만든다

- 14개 기반/사후학습 체크포인트 쌍: Gemma-4·Ministral-3·Qwen2.5·Qwen3.5 네 계열, 약 3B~35B
- 3개 **과정 지향** 벤치마크: BFCL v4 멀티턴, WebShop, ACEBench — 최종 답이 아니라 중간 행동을 거쳐 올바른 환경 상태에 도달해야 성공. 운 좋은 최종 답으로 점수를 얻는 경우를 줄이려는 설계
- 과제당 최대 **128회** 롤아웃. pass@1(단발 정확도), pass@K(커버리지), pass^K(K번 모두 성공 = 일관성) 세 지표를 같이 본다
- 기반 모델은 도구 호출 형식을 모르므로, 모델 독립적인 **가벼운 하네스**(도구 설명·형식 지시·생성된 도구 호출 파서)를 붙였다. 사후학습 모델은 벤치마크 기본 스캐폴딩

### 2) 핵심 관찰 — 양 극단으로의 쏠림

비유: 학생 100명이 시험을 여러 번 칠 수 있다고 하자. 과외(사후학습) 전에는 대부분이 "운 좋으면 붙는" 중간층이었다. 과외 후에는 일부는 매번 붙는 상위권이 되지만, 나머지는 아예 매번 떨어지는 쪽으로 굳는다. 한 번 시험 기준 합격률은 올라도, **여러 번 치게 해 주면 한 번이라도 붙는 학생 수는 오히려 줄 수 있다.**

실제 수치 (Gemma-4-31B, WebShop):

| 과제 범주 | 기반 모델 | 사후학습 모델 |
| --- | --- | --- |
| 가끔 풀림 (시도하면 풀림) | 87.6% | 30.0% |
| 항상 실패 | 12.4% | 44.0% |
| 항상 성공 | 0% | 26.0% |
| **pass@128** | **87.6%** | **56.0%** |

재시도는 "가끔 풀림" 과제에서만 값이 있다. 항상 풀리는 과제는 첫 시도로 끝나고, 절대 안 풀리는 과제는 몇 번을 해도 안 된다. 그래서 중간층이 줄면 K를 늘려도 얻을 게 없다.

**규모 의존성** — 기반 모델과 사후학습 모델의 pass@K 곡선이 교차하는 지점이 큰 모델일수록 앞당겨진다. Gemma-4 WebShop에서 4B는 128회 안에서 교차하지 않고, 31B는 **약 3회**에서 교차한다. 기반 모델이 원래 가진 행동이 넓을수록 반복 샘플링으로 캐낼 게 많아서, 그걸 깎는 비용이 커진다는 해석이다. 반대로 작은 모델은 사후학습이 도구 호출 형식 같은 **없던 기본기를 고쳐 주는** 효과가 커서 사후학습이 순이득인 경우가 많다.

### 3) Sharpening Tax — 손실을 숫자 하나로

- **원시 확장성 A(K)** — 모든 낮은 예산 k에 대해 (pass@K − pass@k)의 차이를 합한 것. "시도를 늘렸을 때 추가로 건지는 성공"의 총량이다. 논문은 이를 "예산 안에서 첫 성공 전까지 실패한 시도 수의 기댓값"으로도 해석한다. 항상 성공·항상 실패 과제는 0을 기여한다.
- **보정 확장성 S(K)** — A(K)를 모델의 단발 실패율과 예산으로 정규화. pass@1이 이미 높은 모델은 올라갈 여지가 적으니 그만큼 보정한다.
- **세금 = 기반 모델 확장성 − 사후학습 모델 확장성.** 양수면 기반 모델이 재시도로 더 많이 얻는다는 뜻.

결과: K=128에서 보정 세금이 **42개 조합 중 36개에서 양수.** 음수는 주로 작은 모델(사후학습이 형식을 고쳐 준 경우). 그리고 **싸게 추정 가능** — K=8로 추정한 보정 세금이 K=32 세금과 스피어만 상관 **0.85**(보류 과제 부분집합 기준). README의 예시: Gemma-4-31B WebShop K=128에서 tax_A 4.49, tax_S 0.036.

### 4) PTGS — 문제마다 다른 온도

온도를 전역으로 올리면 다양성은 돌아오지만 정확도가 떨어진다. PTGS(posterior-tempered group sampling)는 **프롬프트마다** 온도를 정한다.
1. 프롬프트별로 최근 성공·실패 횟수를 (오래된 것일수록 할인해서) 센다
2. 그걸로 성공 확률에 대한 **Beta 사후분포**를 만든다
3. 톰슨 샘플링으로 난이도 추정치를 하나 뽑아, 다음 롤아웃 그룹의 온도를 정한다 — **어려운 문제는 높은 온도(탐색), 쉬운 문제는 낮은 온도(안정)**

Qwen2.5-7B-Instruct를 PPO·GRPO로 Sokoban·FrozenLake에서 학습:

| Sokoban | pass@1 | pass@128 | 보정 세금 |
| --- | --- | --- | --- |
| PPO 고정 온도 | 46.5% | 55.0% | 0.094 |
| PPO + PTGS | 61.1% | 69.7% | 0.081 |
| GRPO 고정 온도 | — | 55.3% | 0.081 |
| GRPO + PTGS | — | 72.5% | 0.025 |

pass@1과 pass@128이 **둘 다** 올랐다는 점이 핵심 — 정확도와 폭이 꼭 교환 관계만은 아니라는 것. PTGS는 출력 엔트로피를 더 높게 유지하고, **성공이 하나도 없는 롤아웃 그룹**의 비율을 줄였다. GRPO 같은 그룹 기반 알고리즘은 그룹 안 상대 비교로 학습하므로, 전부 실패한 그룹에서는 학습 신호가 0이다. 어려운 문제를 더 탐색적으로 뽑으면 그 그룹에 성공 하나라도 생겨 신호가 살아난다(GRPO에서 개선폭이 더 큰 이유로 보인다).

## 실제로 쓸 수 있나

**모델을 고를 때 — 사용 방식을 먼저 정한다.**
- 한 번 호출로 답을 쓰는 기능(챗봇, 단발 분류) → pass@1 높은 사후학습 모델
- **생성 → 검증 → 채택** 구조(테스트 통과 코드만 채택, 정답 검사기가 있는 문제 탐색, 에이전트 재시도 루프) → pass@K가 기준. 큰 모델이라면 기반 모델 + 하네스, 또는 세금이 적은 모델이 나을 수 있다. 다만 비용(시도 횟수만큼 토큰)이 함께 늘어나므로 "같은 비용에서의 pass@K"로 비교해야 공정하다

**평가할 때 — pass@1만 보고하지 않는다.** 내 과제 셋에서 모델을 비교한다면 과제별로 8번 정도 돌려 성공 횟수 분포를 본다. "0 아니면 8"로 쏠려 있으면 재시도 루프를 붙여도 이득이 적고, "가끔"이 많으면 재시도·best-of-N이 효과적이다. 논문의 K=8 추정 결과(상관 0.85)가 이 정도 비용으로도 경향을 볼 수 있다는 근거다.

**RL을 직접 돌린다면** — PTGS는 플러그인형이라 기존 PPO·GRPO 롤아웃 단계에 붙일 수 있다(GitHub에 2초짜리 장난감 데모). 어려운 문제에서 전부 실패해 신호가 죽는 GRPO의 고질적 문제에 대한 간단한 처방이다.

**이 폴더의 다른 노트와 같이 보면** — 「추론 길이 압축」(줄인 것과 같이 줄어든 것), 「표현 공간 잔차 외삽 증류」(RL 이전 체크포인트를 기준점으로)와 같은 축이다. 셋 모두 "RL이 정확히 무엇을 바꾸는가"를 다른 각도에서 잰다. 특히 RIDE는 "RL이 만든 방향으로 더 밀면 좋아진다"고 했는데, 이 논문은 "RL은 폭을 좁히는 방향"이라고 한다 — 두 결과를 겹치면, RL 방향으로 더 미는 것은 pass@1은 올리되 세금도 더 키울 가능성이 있다(두 논문 모두 이 조합을 재지 않았으니 미검증 추론).

## 한계와 미검증 지점

- **관찰 연구다.** 공개 체크포인트의 학습 데이터·레시피가 비공개라, 효과를 RL 탓으로 특정하지 못한다. 논문 스스로 "post-trained"를 실용적 라벨로만 쓴다고 밝힌다(SFT·선호 최적화가 섞였을 수 있음). 브리핑의 "RL 후처리가 다양성을 깎는다"는 단정은 논문보다 강하다.
- **조건이 비대칭이다.** 기반 모델은 논문이 만든 하네스, 사후학습 모델은 벤치마크 기본 스캐폴딩. 차이의 일부가 가중치가 아니라 프롬프트·인터페이스에서 왔을 수 있다.
- **이진 성공만 본다.** 부분 점수·품질 차이가 있는 과제(글쓰기, 긴 리팩터링)에는 세금 정의가 그대로 적용되지 않는다. 텍스트 에이전트·벤치마크 3개뿐, 멀티모달 미검증.
- **비용 축이 빠져 있다.** pass@128은 128배의 토큰을 쓴다. 기반 모델이 커버리지에서 이겨도 "같은 비용"에서 이기는지는 별개이고, 실무 판단은 그쪽이 더 중요하다.
- **PTGS는 장난감 환경 두 개(Sokoban·FrozenLake), 모델 한 계열.** 실제 에이전트 벤치마크에서의 PTGS 결과는 없다. GRPO 고정 온도의 pass@1 수치는 보고서에서 확인하지 못했다.
- **세금이 작은 모델에서 음수**인 구간이 있다 — "사후학습은 해롭다"가 아니라 "규모·예산·사용 방식에 따라 다르다"가 정확한 결론.
- 상관 0.85는 K=8 → K=32 예측이고, K=128 같은 큰 예산까지의 외삽은 별도로 검증되지 않았다.
