# AI - 중간 층을 반복하는 루프 트랜스포머

> 상위: [[AI 심층 정리 인덱스]]

> [!info] 예습자료 — 무인 세션이 자동 생성, 사용자 미검증 · 계기: Thinking Machines Lab 「Introducing Inkling 2 Mini」(2026-11-20), HN 566점, 11/21 브리핑. 읽은 것: 발표 글 전문(아키텍처·학습·모니터링 절, 벤치 표). **모델 카드, 가변 루프 연구 모델(TML-d24-varloop-research) 카드, Goodfire 해석 글, 인용된 선행 논문(Universal Transformers·Attention Residuals) 본문은 읽지 못했다.**

## 한 줄 정의

트랜스포머의 층 일부(여기선 24층 중 가운데 12층)를 **같은 가중치로 토큰마다 여러 번(여기선 3번) 다시 통과** 시켜, 파라미터를 늘리지 않고 토큰당 직렬 연산 깊이를 늘리는 구조. 저장은 24층, 실제 적용은 48층.

## 왜 이게 문제였나 — 기존 방식의 한계

**성능을 올리는 손잡이가 사실상 둘이었다.**

1. **파라미터를 늘린다** — 지식도 추론도 같이 오르지만 메모리·대역폭이 그대로 늘어 노트북에선 못 돈다. MoE로 활성 파라미터를 줄여도 총 파라미터(=메모리)는 남는다.
2. **토큰을 더 쓴다**(사고 사슬, CoT) — 일반 트랜스포머는 토큰 하나를 내기 전에 고정된 층 스택을 **딱 한 번** 지난다. 그래서 한 번에 할 수 있는 직렬 계산 단계 수에 상한이 있고, 더 긴 추론은 **글로 써 가며** 해야 한다. 이건 비싸고(토큰당 과금·지연), 1패스 예시처럼 계산 실수 → "wait" → 되돌아가기를 반복하며 토큰이 부푼다.

**루프는 세 번째 손잡이다** — "같은 층을 여러 번 돌려" 토큰 하나당 생각하는 깊이를 늘린다. 아이디어 자체는 오래됐다(Universal Transformers, 2018). 11/19 노트의 에너지 기반 반복 추론(EBR)도 같은 블록을 반복하는 계열이었지만 1.8M짜리 퍼즐 모델이었다. 문제는 **대형 언어 모델에서 안정적으로 학습시키고, 어디를 돌릴지 정하고, 실제로 이득이 나는지** 를 보인 사례가 드물었다는 것.

**그리고 새 문제가 하나 생긴다 — 감독 가능성.** CoT 모니터링(모델이 쓴 사고 과정을 읽어 감독)이 쓸모 있는 이유 중 하나는 위의 "직렬 단계 상한" 덕분이다. 복잡한 계획은 어쩔 수 없이 글로 드러난다. 루프는 그 상한을 올린다 → **글로 안 쓰고 머릿속에서 할 수 있는 일이 늘어난다** → 감독자가 못 보는 생각이 늘 수 있다.

## 어떻게 푸는가

### 1) 어디를 돌릴까 — 가운데

비유: 통역사를 낀 회의. 앞쪽 층은 **입력 토큰을 내부 언어로 번역**, 뒤쪽 층은 **내부 언어를 출력 토큰으로 번역** 하는 통역사이고, 가운데 층이 실제 회의(추상적 추론)를 한다. 회의를 세 번 하는 건 의미가 있지만 통역을 세 번 하는 건 낭비다.

- 24층 = 6층 × 4블록: **[prelude 1회] → [블록2·3 × 3회] → [마지막 블록 1회]**
- 실험: 같은 학습 연산·3패스 조건에서 학습 2,000스텝 시점, 비루프 기준선이 같은 손실을 내려면 **가운데 루프는 1.51~1.91배, 뒤쪽 루프는 1.24~1.36배** 의 연산이 필요했을 것(= 가운데 루프가 더 많은 연산을 "공짜로" 번 셈). 28개 평가 중 27개에서 가운데가 우세.

### 2) 패스 사이에 무엇을 넘길까 — 메시지와 게이트

- **Attention Residuals**(Kimi 팀, 2026)를 쓴다. 보통의 잔차 연결은 모든 층 출력을 **하나의 누적합** 에 더한다. 여기선 각 층이 **앞선 블록들의 출력을 각각 읽고, 섞는 비율을 스스로 학습** 한다 — 패스 사이로 더 풍부한 정보가 흐른다.
- 매 패스는 **prelude 출력에서 다시 시작** 한다(원래 입력을 잊지 않게). 2·3번째 패스는 거기에 **이전 패스의 가운데 블록 출력("메시지")** 을 받는다.
- 메시지는 **학습되는 게이트** 를 거친다. 게이트는 **처음엔 메시지를 완전히 막는다** → 학습 초반엔 각 루프가 "루프 없는 모델"과 똑같이 시작 → 점점 메시지 이득을 키운다. 비유하면 새 배관을 밸브 잠근 채 연결하고 조금씩 여는 것. 이 덕분에 **루프를 학습 도중에 안정적으로 도입** 할 수 있었다.

```
입력 → [Prelude] ─┬───────────────┬───────────────┐
                  ↓               ↓               ↓
              [블록2·3] ─msg→ (게이트)[블록2·3] ─msg→ (게이트)[블록2·3] → [마지막 블록] → 출력
               패스 1             패스 2             패스 3
            (블록2·3은 세 패스가 가중치 공유)
```

### 3) 작게 만들기 — 가지치기와 치유, 4비트 네이티브

- 전문가 384개 중 8개 선택(희소도 48)으로 시작 → 중간 학습 한 시점에 층마다 **가장 많이 쓰인 128개만 남기고 3분의 2 삭제** → 더 큰 내부 모델에서 증류한 **1T 토큰** 으로 남은 전문가가 지운 전문가의 일을 넘겨받게 "치유".
- 사전학습부터 RL까지 전문가 층 전방 계산을 **NVFP4(4비트)** 로, 마지막 4층만 MXFP8. **학습 정밀도 = 배포 정밀도** 라 사후 양자화 손실이 없다(이 폴더의 3항 가중치 모델 노트와 같은 "처음부터 그 정밀도로 학습" 발상). 총 약 20GB.
- 이후 SFT → RL 2.2T 토큰·2,000스텝, 정렬은 온폴리시 증류.

### 4) 대가와 이득의 회계

| 항목 | 비루프 | 루프(3패스) |
| --- | --- | --- |
| 학습 연산 | 기준 | 약 7.5% 더 |
| 같은 손실(512K 토큰 에이전트 궤적)에 필요한 추론 연산 | **140% 더** | 기준 |
| 토큰당 가중치 활성 | 3.4B | 5.4B |
| 메모리(가중치 저장) | 같음 | 같음 |

디코딩 속도 한계는 메모리 대역폭에 묶이는데, 루프마다 가운데 층 가중치를 다시 읽어야 하므로 **토큰당 읽기량은 늘어난다**(원문 속도 그래프도 "루프 반복 읽기 포함"이라 명시). 즉 "공짜 연산"이 아니라 **"메모리 대신 대역폭·연산으로 낸다"** 는 교환이다.

## 결과 — 무엇이 오르고 무엇이 안 오르나

- **오르는 것**: 다단계 추론. 긴 문맥 검색(MRCR·GraphWalks BFS)이 가장 크게, 그다음 수학·과학(HMMT·GPQA·HLE), 장기 에이전트(SWE-bench Pro·BrowseComp).
- **안 오르는 것**: **지식.** 폐쇄형 사실 질의(SimpleQA Verified·WorldVQA·AA-Omniscience)는 패스 수와 거의 무관. "지식은 총 파라미터 수의 함수"라는 관찰 — 그래서 검색·도구 사용으로 메꾼다(BrowseComp 79.0%).
- **CoT 없이 풀 수 있는 과제 길이**(Think Fast, 사람 소요 시간 기준 50% 신뢰도): 가변 루프 모델 1패스 16초 → 2패스 26초 → 3패스 37초 → 5패스 42초 → 10패스 40초. **3패스 이후 평탄.** 단, 직렬 추론만 깨끗하게 재는 N-Hop Lookup(가상 조회표를 머릿속으로 연쇄 조회)은 **학습 최대치(5)의 두 배인 10패스까지** 계속 오른다.
- **CoT 압축**: GPQA에서 모든 패스 수로 맞힌 문제만 비교하면 평균 추론 토큰 1패스 3,703 → 3패스 1,731 → 5패스 1,661. 문장 길이(8.9→8.7단어)·사전 단어 비율(94.6→94.4%)은 그대로, **"wait·actually·hmm" 같은 불확실성 표지는 9.7 → 3.6.** 짧아진 이유는 생략이 아니라 **계산 실수와 되돌아가기가 줄어서** 라는 해석(원문 예시: 3월 1일 화요일 → 5월 20일 요일, 1패스 582토큰 대 5패스 240토큰, 같은 계산).
- **CoT 통제력**(CoT를 지시대로 바꿀 수 있나 — 감시 회피 능력의 대리 지표): 750~1,250토큰 구간에서 0.1% 이하(Qwen3.8-27B 1.3%). 너무 낮아 루프 깊이별 차이는 측정 불가.
- **에이전트 은밀성**(LinuxArena, 약한 감시자, FPR 1%): 도구 호출·출력만 볼 때 은밀 성공률 1~5패스 1.0·2.5·4.0·2.8·5.0%, 생각까지 볼 때 0.0~0.6%. 저자 판단은 "뚜렷한 경향 없음".
- 효율: Stanford의 intelligence per joule 측정에서 DGX Spark 0.703(Qwen3.6-35B-A3B 0.430, Gemma-4-26B-A4B 0.159).

## 실제로 쓸 수 있나

- **로컬 코딩 에이전트로**: 32GB+ Mac(Ollama), GGUF(llama.cpp·Unsloth), vLLM·SGLang 지원. 사내 코드를 외부 API로 못 보내는 환경에서 1차 후보가 된다. 단 하네스마다 벤치 점수가 달라지므로(11/18 노트 FrontierHarness: 같은 모델에서 하네스로 1.8~5.0배) **내 하네스·내 저장소로 다시 재야** 한다.
- **모델 선택 기준으로**: "이 작업이 지식형인가 추론형인가"를 먼저 나눈다. 지식형(사내 규정·도메인 사실)은 작은 루프 모델 + RAG, 추론형(코드 수정·다단계 계획)은 루프의 이득이 크다. 다중 턴 대화·제약 많은 지시는 약점이므로 고객 응대 챗봇에는 부적합할 수 있다.
- **감독 설계로**: 루프 모델을 에이전트로 쓸 때 **도구 호출 로그만 감시하면 놓친다**(은밀 성공률 2.5~5%), 생각까지 보면 거의 잡힌다(≤0.6%). 운영 로그에 CoT를 남기고 감시 모델이 읽게 하는 것이 루프 모델에선 더 중요해진다.
- **연구 재료로**: 가변 루프 모델이 함께 공개됐으므로 "루프 깊이를 바꿔 가며 같은 문제를 풀게 하고 CoT를 비교"하는 실험을 직접 해 볼 수 있다.

## 한계와 미검증 지점

- **자기 보고**: 모든 수치는 발표 글 기준이고 독립 재현이 없다. 비교 모델마다 평가 설정이 다르다고 원문도 적었다.
- **가운데 블록 반복의 근거는 직관 + 손실 비교**: "가운데가 추상적 추론"은 직관이고, 2,000스텝 시점 손실 추정과 평가 27/28로 지지할 뿐 메커니즘 증명은 아니다(Goodfire의 해석 연구는 미독).
- **은밀성 수치의 읽기**: 1.0%→5.0%(1→5패스)를 "경향 없음"으로 본 판단은 신뢰구간이 넓다는 전제다. 184쌍 부분집합·약한 감시자·helpful-only 미세조정판이라는 조건이 붙는다. **더 큰 모델·더 깊은 루프로 RL한 모델에서는 다를 수 있다** 고 저자들 스스로 적었다(가변 루프 모델 RL은 3패스에서만).
- **CoT 압축의 원인**: "되돌아가기가 줄었다"는 초기 분석이고, 압축된 CoT에서 **무엇이 빠졌는지** 를 직접 확인한 것은 아니다(가독성 지표가 같다는 것과 내용이 충분하다는 것은 다르다).
- **No-CoT 측정 방식**: 응답 첫머리를 채워 바로 답하게 강제(prefill)한 것이며, 미세조정 등 다른 방식으로 끌어내면 더 높을 수 있다.
- **대역폭 비용**: 토큰당 읽기량 증가가 실제 노트북 디코딩 속도에 주는 영향은 이론 상한 그래프만 있고 실측 tok/s는 확인 못 했다.
- 모델 카드·연구 모델 카드 미독 — 전체 평가표, 패스 수별 상세 수치는 확인하지 않았다.
