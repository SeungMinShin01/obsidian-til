고정섭 · 2019-12-20 · Backend (우아한형제들 기술블로그). 예습자료이므로 아래는 "글은 ~라고 설명한다" 관점이며 사용자가 검증한 내용이 아니다.

## 배경

글은 배달의민족 광고시스템 백엔드에 feign을 적용하며 겪은 문제를 이어서 정리한 후속편이라고 설명한다. 앞선 글(2019.5)에서 다루지 않은 HTTP 클라이언트 선택, 로깅, 에러 응답 처리, Configuration 관리, 인터페이스 재사용과 Retry 분리, 컬렉션 파라미터 전송 방식을 다룬다.

## 핵심

- HTTP 클라이언트: 기본 `feign.Client.Default` 대신 Apache(`feign-httpclient`, `feign.httpclient.enabled: true`) 또는 OkHttp(`feign-okhttp`, `feign.okhttp.enabled: true`)로 교체할 수 있다. OkHttp는 HTTP/2, 내장 응답 캐시, 웹소켓, 단순한 API를 장점으로 꼽는다.
- 로깅: feign 로깅 설정은 DEBUG 레벨에서만 동작한다. 로그가 안 나오면 레벨부터 확인하라고 한다.
- 에러 응답: 200 이상 300 미만만 정상이고 나머지는 ErrorDecoder 몫이다. `feign.client.config.default.decode404=true`면 404도 정상 취급한다. ErrorDecoder 대신 반환 타입을 `feign.Response`로 두고 상태 코드를 호출 측에서 직접 분기하는 방식도 소개한다(5xx만 예외 처리).
- `@Configuration` 문제: 이전 글은 붙이지 말라고 했으나 공식 가이드와 달랐다고 정정한다. 붙이면 모든 `@FeignClient`에 적용되고, `@FeignClient(configuration=…)`로 지정하면 해당 클라이언트에만 적용되며 같은 종류 Bean은 지정한 쪽이 덮어쓴다. 같은 설정 클래스를 여러 클라이언트에 지정하면 Bean이 클라이언트 수만큼 중복 생성된다.
- 결론: 공통 설정(Contract, 날짜 ISO 포맷 등)은 `@Configuration`으로 한 번만 등록, 클라이언트별 설정은 configuration 속성으로 지정한다. 대안으로 마커 애노테이션 `@FeignConfiguration`을 만들고 `@ComponentScan`의 `excludeFilters`로 스캔에서 제외한다.
- Retry 분리: 같은 API에 재시도 여부만 다르게 하려고 공통 인터페이스 `MessageClient`를 두고 `MessageNoRetryClient` / `MessageRetryClient`(별도 configuration)를 상속시킨다. 기본 Retryer는 `Retryer.NEVER_RETRY`이며 재시도하려면 `Retryer.Default`를 Bean으로 등록(간격·최대 횟수는 생성자)한다.
- 컬렉션 파라미터: 기본은 `key=a&key=b`(EXPLODED). OpenFeign 9.6.0 이후 `@RequestLine(value="GET /array?values=", collectionFormat=CollectionFormat.CSV)`로 `values=a,b,c` 전송 가능(CSV `,` / SSV 공백 / TSV 탭 / PIPES `|`). 이를 위해 SpringContract 대신 feign 기본 Contract 사용을 권한다.
- 주의: 수집 과정에서 일부 코드 값이 잘려 있어 정확한 구현은 글의 GitHub 예제(feign-apply-experience-2nd-sample)에서 확인해야 한다.

## 내 프로젝트와의 연결

수집기가 사람인 API 같은 외부 API를 부를 때, 글이 말하는 "같은 API, 재시도 있음/없음 분리"와 `Retryer.NEVER_RETRY` 기본값은 재시도·멱등성 설계와 구조적으로 비슷한 지점이다(수집기는 Python 계열이면 개념만 참고). WMS에서는 Spring Boot가 외부 시스템(택배사·ERP 등)을 호출한다면 클라이언트 타임아웃, 재시도 가능한 호출(조회)과 불가능한 호출(출고 확정 같은 쓰기)의 분리, 5xx만 예외로 보는 에러 처리에 옮겨볼 수 있다. 직접 연결은 약하다.

## 오늘 정리할 것

1. `Retryer.NEVER_RETRY`가 기본이라는 점과 `Retryer.Default`의 간격·최대 횟수 의미를 feign 소스/문서에서 직접 확인해 3줄로 정리.
2. 수집기의 API 호출부에서 "재시도해도 안전한 호출"과 "아닌 호출"을 표로 나눠 보기.
3. `@Configuration` 붙은 설정 클래스가 `@ComponentScan`으로 전역 적용되는 원리를 Spring 문서로 확인.
4. 이후 Spring Cloud OpenFeign의 현재 기본값(2019년 글과 달라졌는지)을 확인 — 글은 2019년 기준이다.
