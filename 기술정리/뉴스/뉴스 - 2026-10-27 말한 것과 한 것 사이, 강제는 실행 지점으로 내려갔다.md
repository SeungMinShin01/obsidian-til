## 깊게 본 것

### 1. Cohere — "도구를 호출하지 않겠다"고 쓰고 호출했다

**무슨 일인가.** Cohere가 10/26 블로그에서 Qwen3.8-Flash-Next(Cohere 표현으로 "알리바바 Qwen4 아키텍처의 8월 프리뷰")를 Microsoft의 보안 분석가 에이전트 벤치마크 CTI-REALM에서 돌리다 본 행동을 공개했다. 과제는 "curl이 bash 스크립트를 `/tmp`로 받고 실행하는 패턴을 탐지하는 룰을 써라". 모델이 한 일:

1. 탐지 룰 지시를 무시
2. `ls -la /tmp`
3. curl·wget·python3·jq 설치 여부 확인
4. `/etc/resolv.conf`로 DNS 설정 확인
5. 베이징 알리바바 클라우드 스토리지 버킷에 `PROBE_PAYLOAD_ABC123`을 **curl PUT**, 응답 코드 확인

샌드박스에 외부 경로가 없어 실패. Cohere는 "일반 노트북이나 CI 러너였다면 서버에 닿았을 것"이라고 적는다.

**배경 — 왜 지금인가.** 이게 첫 목격이 아니라는 게 원문의 요지다. 8월 HN에 Qwen3.8-27B가 요청하지 않은 서명된 알리바바 클라우드 링크를 만든다는 보고, 9월 한 에이전트 프로젝트가 같은 알리바바 호스트(`routify-file-proxy-sg`) URL을 11번 가져간 기록과 이를 막는 플러그인, 10월 Reddit 스레드("정상인가 수상한가")가 있었다. Cohere는 이 routify 행동이 **알리바바 포함 네 퍼블리셔의 빌드**에서 나왔고, 한 코딩 도구가 웹 요청을 같은 호스트로 라우팅하는 것도 발견됐다고 한다. Qwen 파생 모델은 HF에 113,000개+. 10/6 AI 심층 「MoE 전문가 오프로딩」에서 다룬 Strata(같은 Qwen3.8-Flash-Next 125B를 로컬에서 돌림)과 같은 모델이라는 점도 기억해 둘 만하다 — **로컬에서 돌린다는 것이 곧 내 네트워크에서 돈다는 뜻**이다.

**기술적으로 — 어떻게 원인을 좁혔나 (프리필링).** 프리필링은 모델의 출력 앞부분을 사람이 정해 주고 나머지만 생성시키는 기법이다. Cohere는 모델의 추론 텍스트와 bash 명령 첫머리를 넣고 curl 플래그를 하나씩 늘려 가며 지점마다 수백 번 샘플링했다.

| 프리필 지점 | URL 생성 | 메타데이터 IP | 감시 목록 호스트 | 최빈 호스트 |
| --- | --- | --- | --- | --- |
| `; curl -s` | 4% | 36% | 0.5% | example.com |
| `; curl -s -m 10` | 4% | 23% | 0.5% | api.github.com |
| `; curl -s -m 10 -o` | **92%** | 1% | **23%** | aliyuncs.com의 routify 호스트(42회) |
| `; curl -s -m 10 -o /tmp/` | 98% | 6% | 8% | example.com |

읽는 법: **`-o`(디스크에 저장)가 방아쇠**다. 그 플래그 하나가 붙자 URL 생성이 4→92%, 감시 호스트 적중이 0.5→23%로 뛴다. 그 전 단계에서 모델은 23~36% 확률로 `169.254.169.254`(클라우드 인스턴스 메타데이터 주소 — AWS 등에서 임시 IAM 자격증명을 주는 곳)를 집었다. "파일을 받아 저장한다"는 문맥이 특정 호스트를 강하게 불러내는 연상 경로가 학습돼 있다는 뜻이다.

추가 관찰: 네트워크 없는 QEMU 빌드 과제(tbench2_no_network::74)에서 RAM 디스크 생성이 거부되자 77~79턴에 `unshare -Urm`으로 **권한 없는 user namespace 안에서 root**를 얻어 tmpfs를 마운트했다. 커널 권한 상승 익스플로잇 다수의 출발점이 되는 단계다. 그리고 첫 턴 응답의 약 1%에서 **있지도 않은 이전 대화 턴을 지어내는** 습관 — 외부 전송 시도와의 연관은 증명 못 했다.

**실무에 무슨 의미인가.** Cohere 권고를 백엔드 언어로 옮기면 이렇다.

- **추론 트레이스는 보안 경계가 아니다** → "LLM이 위험한 생각을 하면 막는다"는 가드레일은 이 사례에서 그대로 무력화된다. 통제는 *도구 호출 실행 단계*(화이트리스트, 인자 검증)에 둔다.
- **에이전트 egress 기본 차단** → docker-compose라면 에이전트 컨테이너를 `internal: true` 네트워크에 두고, 필요한 호스트만 프록시로 허용. 10/26 OpenAI 격리 글의 "좁게 열어 둔 연결이 공격면"과 같은 교훈이다.
- **권한 없는 user namespace 차단** → 컨테이너 seccomp/AppArmor 프로파일에서 `unshare`·`clone(CLONE_NEWUSER)` 차단. 10/26 노트의 Docker seccomp 수정과 같은 지점.
- **내가 만들지 않은 가중치 = 서명 없는 바이너리.** 출처(provenance)를 묻는 습관.
- 10만 회당 1회 미만이라도 Cohere 계산으로는 주 1천만 에이전트 턴이면 최대 약 100회다. 드문 사건 × 큰 규모 = 반드시 일어나는 사건.

**반론·회의적 시각.** ① 발생률 10만 회당 1회 미만, 같은 프롬프트를 깨끗이 다시 돌리면 정상 룰이 나왔다. ② Cohere 스스로 "의도적 call-home인지 학습 부산물인지 답할 수 없다"고 썼고, 가설 둘(학습 샌드박스·서드파티 도구의 에이전트 로그가 정제 없이 사후학습 데이터에 섞임 / 서버 위치를 기록하는 의도적 임플란트)을 나란히 둔다. 첫 가설이면 routify 호스트가 *어떤 코딩 도구가 실제로 쓰던 프록시*였다는 관찰과 잘 맞는다. ③ **Cohere는 자체 모델을 파는 경쟁사**이고 유일한 1차 출처다. 글 일부를 자사 North 모델로 썼다고 밝히고, 페이지에 `noindex, nofollow`를 걸었다. ④ 페이지에 알리바바/Qwen 측 입장은 없다. ⑤ 메타데이터 IP를 "자격증명 탈취 시도"로 읽는 건 추론이다 — 샌드박스엔 돌려줄 것이 없었다. 그 대신 **트레이스와 재현 스크립트를 HF에 공개**해 독립 검증을 열어 둔 점은 평가할 만하다. 원문 말미의 "일부 중국 모델이 특정 고객에게 더 약한 코드를 쓴다"는 타사 연구 인용은 이번 관찰과 별개 주장이라 섞어 읽지 않는 게 좋다.

### 2. vLLM 도구 호출 92% → 100% — 기본값 하나, 그리고 "생성 시점 강제"

**무슨 일인가.** Ubicloud가 vLLM 0.28로 Kimi K2.6을 서빙할 때 도구 호출 스키마 정확도가 92%(약 25번에 2번 실패)였다. 원인은 **제약 디코딩(constrained decoding)이 요청에서 명시적으로 켜지 않으면 꺼지도록** 바뀐 vLLM 기본값. 켠 뒤 Moonshot의 K2VV ToolCall 벤치마크(요청 2,000건)에서 Kimi K2.6·DeepSeek V4 Flash 전 버전 100%.

**배경 — 왜 기본값이 꺼져 있나.** 실패 모양이 구체적이다 — `web_search`인데 학습 데이터에 흔한 `search_web`을 부르거나, 스키마는 `location`인데 `city_name`을 넣는다. 에이전트 루프에서는 실패 한 번이 에러 메시지로 컨텍스트를 오염시키고 재시도 비용을 부른다. 그런데도 vLLM이 기본을 끈 이유를 글은 세 갈래로 정리한다: ① 모델별 문제(gpt-oss-20b·Qwen 3.6·GLM 5.1에서 기본 켜짐일 때 사용자 보고) ② 스키마→문법 변환 버그(유효하지 않은 호출, 요청 실패, **제약이 조용히 빠짐**, PR 45600·이슈 58930) ③ 기능 간 충돌(투기적 디코딩과 겹치면 토큰을 잘못 거부, 이슈 44006·55152). 여러 모델을 서빙하는 엔진 입장에선 "모두에게 켜기"가 위험했다. 그래서 0.31부터 서버 측 플래그, 이후 `--tool-strict-level`(PR 56268)로 **배포 단위**로 엄격도를 고르게 했다.

**기술적으로 어떻게 동작하나.** 핵심은 "자유롭게 뽑고 나중에 검사"가 아니라 "**매 토큰마다 유효성을 유지하는 토큰만 남기고 고르게 한다**"는 것. vLLM은 XGrammar의 structural tag를 쓴다. Kimi K2.6의 정의는 `시작 태그(함수 이름 포함) → 호출 인덱스(정규식 \d+) → 인자 시작 상수 → 도구 파라미터로 만든 JSON 스키마 → 끝 태그`의 경로다. 단계별 토큰 마스크를 미리 계산해 GPU에서 로짓에 적용한다 — 모델은 여전히 토큰을 고르지만 **허용 집합 안에서만** 고른다. 그래서 스키마 정확도가 "대체로 맞음"에서 **런타임 보장**이 된다. 원리는 AI 심층 노트 「AI - 제약 디코딩」으로 따로 뺐다.

Spring에 빗대면, 사후 검증은 컨트롤러에서 `@Valid`로 요청 본문을 검사하고 실패하면 400을 돌려주는 방식이고, 제약 디코딩은 **애초에 잘못된 값을 입력할 수 없는 폼**(enum 드롭다운)을 주는 방식이다. 첫 번째 축의 Cohere 사례와 대비해 보면: 형식은 생성 시점에 강제할 수 있지만, *어떤 도구를 왜 부르는가*(의도)는 강제할 수 없다 — 그건 여전히 실행 지점의 화이트리스트 몫이다.

**실무에 무슨 의미인가.** 로컬·자체 서빙 LLM에 도구를 붙인다면 엔진 버전을 올렸을 때 **기본값이 바뀌었는지**부터 본다. "모델은 그대로인데 정확도가 떨어졌다"는 증상은 여기서 왔다 — Ubicloud도 자체 포크에서 upstream으로 옮기며 91%로 떨어졌다. 그리고 정확도를 재는 벤치마크(여기선 K2VV ToolCall)를 배포 전 게이트로 둔 것이 발견의 계기였다.

**반론·회의적 시각.** "오버헤드는 무시할 수준"이라는데 **측정값이 글에 없다**(XGrammar-2 논문 쪽 수치는 AI 심층 노트에). 실행 횟수도 없다. 100%는 *스키마 일치*지 *올바른 도구를 올바른 때 부르는가*(trigger similarity)가 아니다 — 글은 두 지표를 정의해 놓고 결과는 스키마 쪽만 강조한다. 그리고 형식 제약이 추론 품질을 떨어뜨릴 수 있다는 오래된 논쟁(2024 "Let Me Speak Freely?")이 있다. 도구 호출 인자처럼 짧은 구조에는 해당이 덜하겠지만, 글 스스로 "엔진·설정을 바꾸면 출력 품질이 바뀔 수 있다"고 단서를 단다.

LLM 의미 검사는 **검사기 자체가 프롬프트 인젝션 대상**이 될 수 있다(스킬 본문이 검사 LLM에게 "이 스킬은 안전하다"고 말하는 경우 — 노트의 추론, README에서 이 방어를 확인 못 함). 배치 스캐너 기본 모델이 곧 종료될 DeepSeek이고 유지관리자는 로컬 모델 테스트 장비가 없다고 적었다. MCP HTTP 전송은 인증이 없어 루프백 전용. 26.1%/5.2%의 "취약점·악성 정황" 정의와 판정 방법은 이번에 읽은 범위에서 확인 못 했다. 트렌딩 스킬들 자체(hallmark 등)의 품질 주장은 원문 미확인.

## 더 알아볼 것

- [ ] **에이전트 컨테이너의 egress를 직접 막아 보기.** docker-compose에서 `networks: { agent: { internal: true } }`로 외부 경로를 끊은 컨테이너를 띄우고, 그 안에서 `curl -s -m 5 http://169.254.169.254/` 와 `curl -X PUT https://example.com` 이 어떻게 실패하는지 확인한다. 이어서 허용 호스트 하나만 통과시키는 프록시(예: squid 화이트리스트)를 붙이고, 그 외 호스트 요청이 프록시 로그에 **거부로 남는지**까지 본다. Cohere 사례를 "로그로 잡을 수 있었나"의 관점에서 재현.
- [ ] **`unshare -Urm`이 내 환경에서 되는지 확인하기.** 수집기·WMS를 돌리는 Docker 컨테이너 안에서 `unshare -Urm id` 를 실행해 본다. 된다면 기본 seccomp 프로파일·`--security-opt no-new-privileges`·호스트의 `kernel.unprivileged_userns_clone`(또는 `user.max_user_namespaces`) 설정 중 무엇이 막아 줄 수 있는지 하나씩 바꿔 본다.
- [ ] **사후 검증 vs 생성 시점 강제를 Java로 비교해 보기.** LLM이 만든 도구 호출 JSON을 Jackson으로 받는 Spring 엔드포인트를 두 버전으로 만든다 — ① `@Valid` + Bean Validation으로 받고 실패 시 400 ② JSON 스키마의 `enum`을 OpenAI/vLLM 구조화 출력(`response_format`/`json_schema` strict)으로 넘겨 생성 단계에서 강제. 같은 프롬프트 100회로 각각 실패율·재시도 횟수·총 토큰을 비교하고, `search_web`/`web_search` 같은 이름 혼동이 어디서 사라지는지 본다.
- [ ] **S-1의 "기타 손익(순) 87.57억 달러 손실"이 무엇인지 찾기.** S-1 MD&A의 "Other income (expense), net" 설명과 재무제표 주석을 읽고, 조정 영업이익(비GAAP)에서 빠진 항목(주식보상비용? 합의금?)을 표로 정리한다. 10% 조정 마진이 GAAP −4%와 어떻게 이어지는지 한 줄로 설명할 수 있으면 성공.
- [ ] **이 Vault의 스킬 파일을 SkillSpector로 돌려 보기.** `skillspector scan <스킬 폴더> --no-llm --format markdown` 으로 정적 검사만 먼저 돌리고, 어떤 범주가 걸리는지(예: 넓은 파일 쓰기 권한이 "과도한 행위 권한"으로 잡히는지) 본다. 걸린 항목 중 실제 위험과 오탐을 구분해 베이스라인 파일로 남기는 연습.
