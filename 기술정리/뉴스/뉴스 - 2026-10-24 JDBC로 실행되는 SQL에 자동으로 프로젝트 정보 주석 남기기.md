우아한형제들(WoowaTech 표기) · 2018-08-16 · Backend

## 배경

글은 모놀리식 구조에서 여러 서비스가 하나의 공용 DB를 쓰는 상황을 문제로 든다. 특정 팀의 비효율 쿼리나 대량 배치가 DB 부하를 일으켜도 IP만으로는 어느 팀·프로젝트인지 찾기 어려웠다고 설명한다. 그래서 SQL 앞에 팀·프로젝트 정보를 주석으로 붙이는 방식을 생각했다고 한다. 사용하는 ORM·드라이버가 Hibernate, jOOQ, QueryDSL, MyBatis, Spring JdbcTemplate 등으로 제각각이라 특정 기술에 묶이지 않는 방법이 필요했다는 것이 글의 전제다.

## 핵심

- 작성자가 과거 글에서 쓴 방식(Hibernate·MySQL JDBC 드라이버에 종속)은 범용성이 부족해 채택하지 않았다고 한다.
- 기본 아이디어는 DataSource·Connection·Statement를 감싸는 프록시를 두고, 실행 직전 SQL 문자열에 주석을 끼워 넣는 것이다. 프록시를 처음부터 만들 수도 있었지만 작업량을 줄이려 Tomcat JDBC Connection Pool의 JDBC Interceptor 기능을 택했다고 한다.
- 구현은 `SqlCallerInfoCommentInterceptor`(저장소 woowabros/tomcat-jdbc-pool-sql-caller-info-comment)이며 `StatementDecoratorInterceptor`를 상속한다.
- `Connection.prepareStatement`와 일반 Statement 생성 시 `SqlChangeStatementProxy`를 만들고, execute·executeQuery·executeUpdate 계열 호출 때 SQL 앞에 주석을 붙인다.
- 설정은 Spring Boot YAML 또는 Java 코드에서 Interceptor에 `projectName` 파라미터(예시 값 `baemin_in_woowabros`)를 넘기는 방식이다. 결과는 `/* 프로젝트명 */` 형태의 주석이 달린 SQL이다.
- SQL 인젝션을 막기 위해 주석 값은 영문·숫자·밑줄만 허용하도록 제한했다(한글은 필요 시 수정).
- 작성자 스스로 Tomcat Pool 의존 구현이 이해하기 어렵다고 평가하며, DataSource부터 직접 프록시를 만들면 더 간결하고 특정 Pool에 묶이지 않을 것이라고 제안한다.
- 마무리로, 공용 DB 환경이라면 Java 외 프로젝트에서도 비슷하게 하거나, 최소한 DBA가 바로 연락할 수 있도록 SQL 앞에 주석을 남기는 습관을 권한다.

## 내 프로젝트와의 연결

WMS에서 구조적으로 비슷한 지점은 부하 테스트·인덱스·N+1 측정 단계다. 슬로우 쿼리나 락 대기가 로그에 찍혔을 때 어느 기능(입고·재고 선점·출고)에서 나온 SQL인지 알 수 있으면 Before/After 기록이 쉬워질 수 있다. 다만 이 글은 팀이 공용 DB를 나눠 쓰는 환경이 전제이고, 구현은 Tomcat JDBC Pool 전용이다(Spring Boot 기본 풀은 HikariCP). 수집기의 SQLite 저장 계층에는 직접 연결이 약하다.

## 오늘 정리할 것

1. 글의 Interceptor가 하는 일을 "DataSource → Connection → Statement 프록시 → 실행 직전 SQL 변경" 흐름으로 손으로 그려 본다.
2. WMS가 쓸 풀(HikariCP)에서 같은 효과를 낼 수 있는 지점(DataSource 래핑, 로깅 계층 등)이 무엇인지 찾아 목록으로 남긴다.
3. MySQL 슬로우 쿼리 로그/performance_schema에서 SQL 앞 주석이 어떻게 보이는지 확인할 수 있는지 조사한다.
4. 주석에 입력값을 넣을 때 인젝션이 왜 문제인지(글이 문자 제한을 둔 이유)를 한 문장으로 정리한다.
