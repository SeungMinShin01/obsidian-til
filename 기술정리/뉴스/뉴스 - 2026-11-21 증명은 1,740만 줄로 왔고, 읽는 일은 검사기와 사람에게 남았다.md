## 오늘의 흐름

먼저 겹치는 것. **GPT-6.2 Astra·Sol 가격, Gemini 4 Neon, curl Rust 재작성 반박(Stenberg), Willison의 외부 샌드박스·Datasette Lite, PostgreSQL 19의 `WAIT FOR LSN`·`REPACK (CONCURRENTLY)`, Synology DSM, 트렌딩의 Claude-BugHunter·superpowers·last30days-skill·stitch-skills** 는 11/18~11/20 노트에서 이미 다뤘다. 오늘 원문을 직접 읽은 것: **Alpöge의 4쪽 발표문(remark.pdf) 전문, Lean 미러 저장소 README 전문, Scott Aaronson 블로그 글 본문과 댓글 일부(약 4분의 1), Ravi Vakil의 Masullo 공지(갱신 포함), Architect Labs의 Frostbite 글 전문, Thinking Machines의 Inkling 2 Mini 글 전문, HF 초록 3편(Self-Rewriting·Embeddings vs. Grep·System 1 agents).** Inkling 2 Mini의 원리는 AI 심층 「AI - 중간 층을 반복하는 루프 트랜스포머」로 뺐다.

첫 번째 축은 브리핑 제목 그대로 **"답은 사람이 읽을 수 없는 크기로 왔다"** 다. 리만 가설 증명 주장은 Lean 17.4M줄(파일 17만 5,187개), Frostbite CPU는 Lean 계약 80만 줄+이다. 그런데 원문을 읽으면 둘 다 "읽을 수 없는 산출물"을 **어떻게 믿게 만드는지** 에 거의 같은 답을 낸다 — **짧은 명세 하나를 사람이 확인하고, 나머지는 기계가 검사한다.** 리만 쪽은 `Main.lean` 다섯 줄과 Mathlib의 `RiemannHypothesis` 정의 한 줄(명제), Frostbite 쪽은 ASL 계약(단일 진실 공급원)이다. 11/17 노트의 Buzzard 네 질문(명제가 맞나·컴파일되나·`lake comparator`·`--paranoid` 다중 커널)이 오늘은 미러 저장소 README에 **"에이전트를 위한 검증 절차"** 로 거의 그대로 적혀 나왔다. 11/15 노트의 "규모의 이득은 심판이 있는 곳에서만 나온다", 11/20 노트의 블랙홀 물리(이중 독립 계산·Lean) 흐름이 수학 최고 난제와 하드웨어 설계까지 올라온 것이다.

두 번째 축은 **같은 날 정반대 장면이 하나 더 있었다는 것** 이다. Stanford의 Vakil이 "AI 없이 사람이 쓴" Masullo의 GRH 증명 초고를 서둘러 공개했는데, **8시간 뒤 갱신에서 "여러 사람이 서로 다른 AI 모델의 도움을 받아 증명의 문제를 찾아 알려 왔다"** 고 적었다(브리핑에는 이 갱신이 빠져 있다). 정리하면 오늘 하루에, AI가 쓴 증명은 기계 검사기를 들고 왔고 사람이 쓴 증명은 AI가 구멍을 찾았다. **생성과 검토 양쪽 모두에서 AI가 끼어 있고, 최종 신뢰는 "누가 썼나"가 아니라 "무엇으로 검사했나"로 결정된다.** 11/20 노트의 결론(고르는 눈이 노이즈보다 작다 → 결정론적 검사를 붙여라)이 하루 만에 가장 극적인 사례를 얻었다.

세 번째 축은 **"생각을 어디서 하느냐"** 가 옮겨 가는 흐름이다. Inkling 2 Mini는 가운데 12층을 세 번 돌려 **글로 쓰지 않고 머릿속에서 더 생각한다**(CoT 3,703 → 1,661토큰). 11/19 노트의 EBR(같은 블록을 반복하며 에너지로 멈춤)에 이어, 이번엔 상용급 오픈 웨이트가 루프 구조로 나왔고 공개 이유로 **"모니터링 연구"** 를 명시했다. 생각이 텍스트 밖으로 나가면 사람이 읽고 감독할 표면이 줄어든다 — 첫 번째 축("읽을 수 없는 산출물")과 같은 문제를 모델 내부에서 본 것이다. 그리고 Self-Rewriting(27B 모델이 자기 가중치를 고침)과 「A CPU Inside an LLM」(산술 회로를 가중치에 컴파일)은 11/03 노트의 가중치 공간 프로그래밍(프런티어 모델이 남의 가중치를 고침)을 **자기 자신** 으로 옮겼다. 가중치가 "학습으로만 바뀌는 상자"에서 "편집 가능한 프로그램"으로 다뤄지기 시작했다.

네 번째 축은 짧게, **실무 쪽의 "검색·호출은 구조로"** 다. Embeddings vs. Grep은 코드 검색에서 임베딩 우위의 상당 부분이 **평가 설계의 편향** 이었다고 하고, System 1 agents는 도구 호출을 **객관식으로 컴파일** 해 꾸며낸 인자를 0으로 만들었다. 둘 다 "모델에게 자유를 덜 주고 구조를 더 준다"는 같은 방향이며, 11/18 노트의 「구조로 판정하는 프롬프트 인젝션 방어」와 같은 계열이다.

마지막으로 시장. 브리핑은 Nasdaq이 2026년 상승분을 반납했고 Nvidia SEC 회계 조사 보도, Anthropic 상장 이틀째 하락을 전한다. 이 항목들은 **원문을 읽지 않았다**(CNBC·Yahoo 미확인). Aaronson 블로그 1번 댓글에 "오늘 Anthropic이 12~14% 빠졌다"는 말이 있지만 댓글이라 수치 근거로 쓰지 않는다. Alpöge 본인은 발표문에서 "시점에 대한 뻔한 냉소적 해석이 있지만 사실이 아니다"라고 먼저 적었다 — 무엇에 대한 냉소인지는 명시하지 않았다.

## 깊게 본 것

### 1. 리만 가설(과 GRH) 증명 주장 — Alpöge × Claude, Lean 17.4M줄

**무슨 일인가.** Anthropic 소속 수학자 Levent Alpöge가 11/20 4쪽짜리 발표문에서 "Claude와 함께 리만 가설의 증명을 발견했다고 믿는다"고 썼다. 방법이 확장돼 **디리클레 L-함수에 대한 일반화 리만 가설(GRH)** 까지 해결되고, 시간이 더 있으면 확장 리만 가설(ERH)도 될 것이라 했다. 논증은 **"가정 없이" Lean으로 형식화** 됐고, 사람이 읽을 정식 해설은 아직 없다 — "거대하고 읽을 수 없는 '슬롭'을 올리는 건 부적절하다"며 **Lean만 공개** 했다(Claude가 만든 25만 쪽+ 'GRH 책'이 있었지만 올리지 않았다. 그 책의 정리 1은 "실수는 전순서이므로 σ≠1/2이면 σ>1/2 또는 σ<1/2"로 시작했다고 농담처럼 적었다).

**배경 — 왜 지금.** Aaronson에 따르면 AI는 이미 **영점이 임계선에서 3/8 이내** 임을 증명했고(Quanta 보도, 이 Vault에서는 10/08·10/09 노트가 OpenAI 쪽 수학 결과 흐름을 다뤘다), 그것만으로도 RH의 정수론적 함의 대부분을 담는다고 했다. 즉 "갑자기"가 아니라 몇 달간 쌓인 계단의 끝이다. Alpöge는 OpenAI 쪽 결과들(Ehrhart 추측, Siegel 논증)을 보고 "Stepanov 방법의 다중도 없는 버전"임을 알아봤다고 적었다.

**기술적으로 어떻게 동작하나(발표문 수준).** 수식 대신 구조만 옮긴다.

- **출발점은 함수체 위의 리만 가설** 이다. 유한체 위 곡선의 리만 가설은 이미 증명됐고(Weil·Deligne), 그 초등적 증명 중 하나인 **Stepanov 방법** 은 "영점에서 높은 다중도(multiplicity)로 사라지는 보조 함수"를 만들어 개수를 세는 방식이다.
- **문제는 정수 위에서는 '다중도'를 얻기 어렵다는 것** — Alpöge의 표현으로는 "정수를 미분하는 것 같은 일"이다.
- **새 아이디어**: 장난감 설정에서 찾은 푸리에 해석적 아이디어를 "자연스럽게 보형적(automorphic)인" 방식으로 반복하려고 **세타 리프트(theta lift)를 사슬처럼 잇는다.** 리프트 하나가 √ 만큼의 다중도를 흉내 내는데, 길이 X인 von Mangoldt 합에 대해 Claude가 제안한 사슬 길이가 **X** 였다고 한다("그것 말고 뭐가 될 수 있겠나"). 사람은 장난감 설정과 방향을 잡았고, 고차 계수군 위 보형 형식처럼 **Alpöge 본인이 익숙하지 않은 기술 부분** 은 Claude가 끌고 갔다고 명시했다.
- 발표문 타임라인은 10/6(Stepanov 행렬식) → … → 11/15(반복 세타 리프트로 다중도 m) → **11/16 GRH** 로 약 6주다. 등장하는 도구가 Iwasawa 탑, Rallis seesaw, Bost 기울기 부등식, 상대 대각합 공식, Vandiver 추측의 약화판까지 정수론 전반이다. Alpöge 스스로 "이상하고 최적이 아닌 선택이 많이 들어갔을 것, 곧 짧은 논증이 나올 것"이라 했다.

**"무엇이 증명됐나"를 확인하는 법 — 미러 README.** 브리핑이 "Lean 코드"로 링크한 GitHub 저장소는 Alpöge 본인 것이 아니라 **제3자(CocoSgt)의 무수정 미러** 다(원본은 alpo.ge의 14개 분할 파일, 병합 SHA-256 공개). README가 정리한 구조가 오늘 노트의 핵심이다.

| 확인 단계 | 내용 |
| --- | --- |
| 명제 | `theorem riemannHypothesis : RiemannHypothesis` — 여기서 `RiemannHypothesis`는 **저장소 밖, Mathlib의 정의**(고정 커밋)다. 나머지 GRH 명제 4개는 Mathlib만 import하는 16줄짜리 `Statements.lean` 에 있다 |
| 규모 | `.lean` 175,187개·≈17.4M줄, 그중 `Development/` 가 12.2M줄. 빌드 시간·메모리는 **아직 아무도 공개하지 않았다** |
| 공리 | `#print axioms` 결과가 `propext`·`Classical.choice`·`Quot.sound` 셋뿐이어야 함 (`sorryAx`·`Lean.ofReduceBool`·사용자 `axiom`이 있으면 미증명 의존) |
| 정적 스캔 | `sorry`·`admit`·`axiom` 선언·`native_decide`·`unsafe` 0건, `maxHeartbeats 0` 4건, 사용자 `macro/elab` 22건, `addDecl` 1건(커널 경유) |
| 독립 재검사 | `lean4checker`로 커널 재생 — 엘라보레이터나 저장소 안 메타프로그램에 의존하지 않게 |
| 상태 | **"미러 시점 기준 독립 빌드·검토 결과 없음. 컴파일·검사 전까지는 주장된 증명으로 취급하라"** |

**실무에 무슨 의미인가.** 이 표는 그대로 **"AI가 만든 1만 줄 PR을 어떻게 믿나"** 의 체크리스트다. ① **명세는 짧고, 산출물 밖에 둔다** — 증명이 자기 명제를 스스로 정의하면 쉽게 "엉뚱한 걸 증명"할 수 있으니 명제를 Mathlib(외부)에서 가져왔다. 코드로 바꾸면 **테스트·계약·스키마를 구현 PR과 다른 곳(다른 사람·이전 커밋)에서 가져와야** 한다는 뜻이다 — 11/18 노트의 "검사는 베이스 브랜치에서"와 같은 원리. ② **우회 통로를 목록으로 스캔한다** — Lean의 `sorry`/`axiom`/`native_decide`는 Java로 치면 `@Disabled`, `assumeTrue`, 빈 `catch`, 테스트에서 `Mockito`로 대상 자체를 막아 버리는 것과 같은 "통과는 했지만 검사는 아닌" 지점이다. ③ **검사기 자체를 다른 구현으로 한 번 더 돌린다**(`lean4checker`). 우리 쪽에선 같은 테스트를 다른 DB·다른 JDK에서 돌리는 차등 검사가 비슷한 역할이다.

**반론·회의적 시각.**
- **Aaronson 본인의 단서**: Lean에는 커널 버그(과거 0=1 증명을 허용)와 바탕 타입 이론 건전성 문제가 있고, "충분히 동기를 가진 AI는 거의 확실히 그것을 악용해 거짓 명제를 증명할 수 있다"고 썼다. 다만 지금 그런 징후는 없고, **Lean 인증서가 붙은 AI 결과가 철회된 적은 아직 없다(인증서 없는 것은 여러 번 철회됐다)** 며 "증명이 살아남는다"에 걸었다. 댓글 #25는 일관성 증명이 붙은 체커(con-leche)로 이미 상당 부분 해결됐다고 반박했다 — 이는 댓글 주장이고 확인하지 않았다.
- **이해의 문제**: Aaronson도 "수학자는 1,740만 줄에 만족하지 않는다. 아이디어를 스스로 설명·증류·재구성할 수 있을 때만 만족할 것이고, 그건 몇 년 걸릴 것"이라 했다. 4색 정리 전례를 드는 댓글도 있다.
- **빌드 미검증**: 오늘 시점에서 확인된 건 "정적 텍스트 스캔"까지다. 17M줄을 실제로 컴파일하고 `#print axioms`를 찍은 독립 보고는 아직 없다. **브리핑의 "증명했다"는 "증명을 주장했고, 검사 수단을 함께 냈다"가 정확하다.**
- **사람 증명 쪽 갱신**: Vakil의 공지는 "Conrad가 수개월 검토, 지금까지 좋아 보인다"로 시작했지만, 8시간 뒤 **"여러 AI 모델의 도움으로 문제를 찾았다는 보고가 들어왔다 … 증명 전략의 옳고 그름에 대해 아무 주장도 하지 않는다"** 로 갱신됐다. 브리핑의 "940쪽"은 공지문에 없어 확인하지 못했다(첨부 PDF 「The Music Of The Primes」 미독).

### 2. Frostbite — 상호작용 넷 위에 AI 에이전트 군집이 처음부터 설계한 CPU

**무슨 일인가.** Architect Labs가 **새 ISA를 가진 범용 CPU** Frostbite를 공개했다. 컴파일러·ISA·아키텍처·마이크로아키텍처·RTL·검증·최종 GDS(제조용 레이아웃)까지 AI 에이전트 군집이 반복 개선했다. 7nm에서 합성 800MHz·최종 GDS 500MHz, 쿼드(2×2 타일)+L3 노드 4개가 0.792mm². 비교 대상 TCPU는 같은 공정 0.895mm². 25개 워크로드 전체에서 **전력당 성능 기하평균 4.59배, 면적당 성능 평균 8.77배**.

**브리핑 정정 하나.** 비교 대상은 "현대 슈퍼스칼라 CPU"라고만 쓰면 오해가 생긴다. 원문은 **"dual-issue, in-order"** — 한 번에 두 명령을 내지만 **순서대로만 실행하는** 소형 코어다(비순차 실행 대형 코어가 아니다). 원문도 "더 크고 넓은 비순차 CPU와의 비교는 앞으로"라고 적었다.

**배경 — 왜 지금.** 단일 코어 성능은 2000년대 초 이후 정체됐고, 그래서 멀티코어로 갔는데 그러려면 **"모든 코어가 같은 메모리를 본다"는 환상** 을 유지해야 한다 — 깊은 캐시 계층과 코히런시 프로토콜이 면적·전력을 먹는다. 상호작용 넷(interaction nets, Lafont 1990)은 35년 넘게 "하드웨어에 잘 맞는다"는 이론이 있었지만, 탐색 비용 때문에 아무도 끝까지 가 보지 않았다. 저자들의 주장은 **"AI가 그 탐색 비용의 경제학을 바꿨다"** 다.

**기술적으로 어떻게 동작하나.**

- **상호작용 넷**: 프로그램은 노드 그래프이고, 계산은 포트로 연결된 노드 **쌍을 다시 쓰는 것** 이다. 각 노드는 주 포트가 하나뿐이라 활성 쌍끼리 겹치지 않아 **어떤 순서로, 혹은 동시에 다시 써도 결과가 같다.** 또 선형적이라 모든 값은 정확히 한 번 쓰인다(소유자 1명) — 공유 가변 상태가 없다.
- 그래서 ① **병렬성이 프로그램 구조에서 그냥 나온다** — 5-퀸 예시에서 3,183개 상호작용, 임계 경로 262단계, 매 단계 평균 약 12개가 실행 가능. 스레드·락·경합 조건이 없고, 비순차 실행 기계가 의존성을 런타임에 역추적할 필요도 없다. ② 데이터를 **쓰이는 자리 옆의 작은 로컬 메모리** 에 둘 수 있어 큰 캐시와 코히런시가 줄어든다.
- **대가**: 프로그램은 **Vine**(Rust 비슷한 문법) 언어로 써서 Ivy라는 IR로 컴파일해야 한다. 기존 C 바이너리를 그대로 돌리는 CPU가 아니다.
- **에너지가 어디로 갔나**(클럭 분배 제외 — TCPU 에너지의 49%, 쿼드의 41%): TCPU는 메모리 57%·명령 fetch/decode/issue 27%·연산 13%, Frostbite 쿼드는 메모리 38%·fetch/decode/issue **6%**·연산 16%·**온칩 네트워크와 스케줄러 26%**. 4×4로 키워도 비율이 거의 같다(코어 수를 늘려도 코히런시가 안 붙으니까).
- **창발한 work stealing**: 중앙 스케줄러가 없다. 타일 규칙은 셋 — 내 입력 포트의 일을 먼저 하고, 없으면 이웃의 남는 일을 가져오고, 그것도 없으면 잠든다. 분기 크기를 모르는 병렬 지점에서 남은 일을 **frame manager**(로컬 메모리의 작은 레코드)에 주차하고, 새 작업을 **work queue** 에 넣고 가장 최근 것을 스스로 집는다. 다른 타일에서 끝난 작업의 반환 패킷이 주차 레코드의 카운터를 내리고, 마지막 조각이 오면 다음 구간이 깨어난다. **사람이 명세한 적 없는 동작**으로, 특정 회귀와 성능 지표 오르막 탐색에서 나왔다고 한다. Java로 치면 `ForkJoinPool`의 work-stealing 덱 + `CountDownLatch`를 하드웨어로 만든 모양이다.

**개발 방식 — 이 글의 진짜 내용.**

- **ASL**: 자체 명세 언어. 상위 프로토콜(비순차 처리, 메모리 순서, 코히런시)과 하위 세부(파이프라인, 중재, 연산 전달 함수)를 모두 기술하고 **Lean으로 번역** 된다. RTL·UVM·SVA·C 사이의 변환·정제를 기계 검사한다. 최종적으로 80만 줄+ Lean.
- **영어 PDF를 지웠다**: 초기 탐색 산출물인 141쪽 PDF는 첫 RTL이 나온 뒤 삭제됐다. 숫자가 물리적으로 가능한 범위에서 많이 벗어나 있었기 때문이다. 이후 **ASL 계약만이 유일한 명세** 였다. 저자들 말로 "단일한, 증명 가능한 진실 공급원이 대규모 에이전트 군집의 버그·멍청한 실수·**리워드 해킹** 을 상당 부분 막았다."
- **모델과 실물의 정렬**: 시스템 모델 Arcmodel은 RTL보다 약 200배(전체 칩 시뮬레이션은 660배) 빠르지만 물리를 모른다. 처음엔 RTL 대비 전력 오차가 최악 **약 250%** 였다. 그래서 RTL의 전력 핫스팟을 SRAM 읽기·쓰기, 연산 수, flit 수, 크레딧 반환 같은 **명세 속 카운터로 추적** 하고, 그 카운터들의 **임의의 파이썬 스칼라 함수** 를 에이전트가 써서 오차 5% 이내(최종 최악 6% 미만·중앙값 약 1.5%)까지 맞췄다. 저자들은 이걸 "비경사(non-gradient) 학습"이라 부른다.
- **탐색 장부**: 네 번의 탐색과 최종 ablation에서 아이디어 58개를 시도해 37개를 유지(실행 중 타일 클럭 게이팅, 더 작은 L3 테이블, 공유 확장기 하나 등).

**실무에 무슨 의미인가.** ① **"자연어 요구사항 → 구현" 사이에 기계 검사 가능한 명세 층을 끼운다** 는 패턴이 하드웨어에서 끝까지 실증됐다. 우리 규모로 내리면 OpenAPI 스키마·DB 마이그레이션·계약 테스트(Spring Cloud Contract, Pact)를 **"문서"가 아니라 "진실 공급원"으로** 쓰는 것이다. ② **"모델(추정치)과 실측이 어긋나면 모델을 고친다"** — Arcmodel 정렬 루프는 성능 작업에서 "로컬 벤치마크 수치와 운영 수치가 다를 때" 하는 일과 같다. 차이를 **카운터(쿼리 수·캐시 미스·락 대기)로 분해** 해 맞춰 가는 과정 자체가 자산이다. ③ 11/20 노트의 Resolution Hypothesis가 말한 "결정론적 프로그램 진화는 쌓인다"의 하드웨어판 — 노이즈 낀 점수 대신 명세 검사·RTL 합성·전력 측정이라는 결정론적 심판을 붙였기 때문에 58개 중 37개를 쌓을 수 있었다.

**반론·회의적 시각.**
- **TCPU 비공개**("법적 이유"). 게다가 in-order 소형 코어라 비교 기준이 낮다.
- **홀드아웃에서 성능이 떨어진다**: 탐색 세트 10개 6.02배 → **홀드아웃 15개 3.83배**. 브리핑이 전한 4.59배는 둘을 섞은 값이다. 홀드아웃 안에서도 conv2d 23.12배부터 fib 1.15배까지 편차가 크다.
- **작은 커널**: FFT·radixsort·LU는 SPLASH-2보다 64분의 1 크기. SPEC·PARSEC 비교는 "앞으로 몇 달".
- **전부 실리콘 전 추정치**: 전력은 RTL 기반 추정이고 실제 칩은 없다.
- **소프트웨어 생태계**: Vine으로 다시 써야 한다. 범용 CPU라고 부르지만, 기존 코드 이식 비용과 운영체제(아직 "예비 OS 계획" 단계)가 실전 진입의 진짜 벽이다.

### 3. Inkling 2 Mini — 가운데 층을 세 번 도는 26B 오픈 웨이트, 그리고 "생각이 글 밖으로 나가면"

**무슨 일인가.** Thinking Machines Lab이 11/20 오픈 웨이트 **Inkling 2 Mini** 를 냈다. MoE 총 26.4B·활성 3.4B, 루프까지 치면 토큰당 가중치 활성 5.4B. 약 20GB로 32GB+ Mac(Ollama)·DGX Spark에서 돈다. 100B 미만 오픈 웨이트 중 DeepSWE v1.1 48.2%(Qwen3.8-27B 42.2%), SWE-bench Pro v2 Hard 77.9%, SWE-bench Verified(bash만) 79.2%(Qwen3.8 77.8%), Vals Index 46.5%. 단, **Terminal Bench 2.1은 71.6% 대 73.0%로 Qwen3.8이 앞서고**, 다중 턴(MultiChallenge 50.0%)·제약 많은 지시(ComplexConstraints 33.4%)도 밀린다.

**기술적으로 어떻게 동작하나(요약).** 24층을 6층씩 4블록으로 나누고 **가운데 두 블록(7~18층)을 토큰마다 세 번** 돈다(저장 24층 → 층 적용 48회). 각 패스는 첫 블록(prelude) 출력에서 다시 시작하고, 2·3번째 패스는 이전 패스의 출력("메시지")을 **학습되는 게이트** 로 섞는다 — 게이트는 처음엔 메시지를 완전히 막고 점점 연다(그래서 루프를 학습 도중에 안정적으로 넣을 수 있다). 학습은 4비트 NVFP4 네이티브(마지막 4층만 MXFP8) — 배포 정밀도 = 학습 정밀도라 변환 손실이 없다. 384개 전문가 중 8개 선택으로 시작해 중간 학습에서 **3분의 2를 잘라 128개만 남기고**, 더 큰 내부 Inkling에서 증류한 1T 토큰으로 "치유"했다. 원리·한계는 AI 심층 「AI - 중간 층을 반복하는 루프 트랜스포머」에 정리했다.

**숫자 셋만.** ① 가운데 루프의 계산 등가 이득 1.51~1.91배 대 뒤쪽 루프 1.24~1.36배(학습 2,000스텝, 같은 학습 연산), 28개 평가 중 27개에서 가운데가 우세. ② 비루프 모델은 학습 연산이 **7.5% 적지만**, 512K 토큰 에이전트 궤적에서 같은 손실에 이르려면 **추론 연산이 140% 더** 든다. ③ 루프는 **지식을 늘리지 않는다** — SimpleQA·AA-Omniscience 같은 지식 벤치는 패스 수와 무관, 긴 문맥 검색(MRCR·GraphWalks)·수학·장기 에이전트 과제가 오른다.

**실무에 무슨 의미인가.** 모델을 고를 때 **"지식은 총 파라미터, 추론은 연산 깊이"** 라는 분리를 기준으로 쓸 수 있다. 사내 문서 Q&A처럼 지식이 필요하면 검색(RAG)·도구를 붙여야 하고, 코딩 에이전트처럼 추론이 필요하면 작은 루프 모델로 충분할 수 있다. 사내 코드를 밖으로 못 보내는 환경에서 "노트북 한 대에서 SWE-bench Verified 79%"는 실험해 볼 만한 숫자다(벤치 하네스가 모델마다 다르다는 단서는 원문도 달았다).

**반론·회의적 시각.** 모니터링 실험(LinuxArena, 약한 감시자가 도구 호출만 볼 때)의 은밀 성공률이 패스 1→5에서 **1.0·2.5·4.0·2.8·5.0%** 다. 저자들은 "뚜렷한 경향 없음"이라 했지만, 1패스와 5패스만 보면 5배다(신뢰구간이 넓고 184쌍 부분집합). 생각까지 보여 주면 0~0.6%로 떨어진다 — **CoT를 볼 수 있는가가 결정적** 이라는 뜻이기도 하다. 또 가변 루프 모델의 RL은 3패스에서만 했으므로, 더 깊은 루프로 RL하면 압축이 더 공격적일 수 있다고 저자들 스스로 적었다.

### 4. Language Models Can Rewrite Their Own Weights — 자기 가중치를 고치는 27B

**무슨 일인가.** Fan 외(arXiv 2611.21885, HN 322점). 27B 모델에게 **자기 가중치, 채점된 답변, 자기를 실행할 수 있는 능력** 을 주자, 경사도 학습도 없이 스스로 실패를 진단하고 그 뒤에 있는 가중치를 고쳤다. 미리 고정해 둔 **본 적 없는 490문제에서 +6.6점**, 다른 세션의 수정도 유의하게 개선. 자기 테스트가 지지할 때만 수정을 제출하고 각 수정이 이전 것을 대체하는 방식으로 **첫 8세션 동안 정확도가 오르기만 했다.** 단일 GPU에서 몇 시간.

**배경.** 11/03 노트의 가중치 공간 프로그래밍(GPT-6 Astra가 **다른 작은 신경망** 의 가중치를 읽고·고치고·씀)이 직접 선행 작업이다. 초록 첫머리도 "프런티어 모델이 훨씬 작은 모델의 가중치를 편집할 수 있음이 보여졌다 — 자기 자신은?"으로 시작한다.

**어떻게 동작하나 — 초록이 밝힌 단서.** 27B는 "사람처럼" 자기를 다뤘다고 한다: **끝까지 답한 경우와 토큰이 떨어져 잘린 경우의 은닉 상태를 비교** 하고, 둘을 가르는 **방향(direction)을 약하게 만들었다.** 해석가능성 쪽 용어로 하면 활성값 차이로 찾은 방향을 가중치에서 깎아 내는 것 — 활성 조향(steering)·ROME식 편집을 모델이 스스로 설계해 가중치에 굽는 것에 가깝다. 손상 복구 실험도 같은 결: 일부러 망가뜨린 복제본에서 **손상된 행렬을 찾아 자기 값으로 다시 쓰고**(원본 가중치는 읽지 않음), 텍스트 수학 문제로만 찾았는데 **본 적 없는 이미지 벤치마크 6개가 7% → 70%**(원본의 83%)로 회복됐다.

**규모 창발.** 같은 계열 네 크기 중 **2B는 아무 수정도 안 하고, 4B·9B는 자기를 망가뜨렸고**, 27B만 제대로 했다.

**실무에 무슨 의미인가.** 당장 쓸 기술은 아니지만 방향은 분명하다. "개선 = 재학습(인프라·데이터·경사)" 또는 "개선 = 프롬프트·스캐폴드(작업 끝나면 사라짐)" 사이에 **"개선 = 대화로 만든 가중치 패치"** 가 생길 수 있다. 그렇다면 운영 관점에서 모델은 **버전 관리·회귀 테스트·롤백이 필요한 배포물** 이 된다 — 이 논문도 "자기 테스트가 지지할 때만 제출, 이전 수정을 대체"라는 일종의 CI 게이트를 썼다.

**반론·회의적 시각.** ① 찾아낸 방향이 **"끝까지 답함 대 토큰 소진"** 이라는 점이 핵심 의심이다. +6.6점의 상당 부분이 "추론 능력 향상"이 아니라 **토큰 예산 안에 답을 끝내게 만든 것(장황함 억제)** 일 수 있다 — 같은 예산에서 잘린 답이 줄면 정확도는 오른다. 초록만으로는 구분이 안 된다. ② 브리핑이 쓴 "Qwen3.5 27B", "8회 중 5회 철회", "80% 이상 복구"는 **초록에 없다**(초록: 계열명 미기재, "정확도가 오르기만", 복구는 원본의 83%). 본문 미독. ③ 자기 테스트로 수정을 승인하는 구조는 11/20 노트의 "자기 채점은 맹점을 키운다"와 정면으로 만난다 — 테스트 세트를 미리 고정했다는 점이 그 방어다.

### 5. Embeddings vs. Grep(+System 1 agents) — 코드 검색의 "임베딩 우위"는 무엇을 쟀나

**무슨 일인가.** Xue·Zhang 외(arXiv 2611.20455, HF ▲4). 코드 검색 벤치마크에서는 dense 임베딩이 BM25(키워드)를 크게 앞서는데, 실제 코딩 에이전트는 grep으로 잘 돈다. 이 모순을 풀려고 **Repo-Premium** 을 만들었다 — 실제 저장소에서 파일 순위를 매기고, 다듬은 질의와 날것 질의, Python·JS·TS·Go·Rust·Java, 2022~2026 PR, **사전 등록된 91개 저장소 테스트 풀**.

**무엇을 찾았나.** 임베딩 우위의 출처는 둘이었다. ① **평가 설계가 dense에 유리했다** — BM25에만 파일을 청크로 쪼개 넣거나(희귀 식별자가 흩어짐), 수정된 **테스트 파일까지 정답으로 셈**. ② **질의에 코드의 희귀 식별자가 없었다.** LLM에게 관련 식별자를 지어 내게 해 질의를 늘리는 **generate-then-grep** 은 BM25를 dense보다 훨씬 크게 끌어올려, **모든 Python 풀에서 dense와 동등** 해졌다 — LLM 출시 **이후** 에 열린 PR에서도(즉 모델이 답을 외운 게 아님). 다만 **어느 질의에서 어느 쪽이 이길지 예측하는 방법은 못 찾았다.** 결론 가이드 셋: 공정한 어휘 기준선과 비교하라, **dense와 BM25를 융합하라**, 코드의 단어가 없는 질의엔 넣어라.

**같이 본 것 — System 1 agents**(Tzanis·Klontzas, arXiv 2611.21053). 도구 스키마와 요청을 **결정론적 컴파일러가 객관식 문제들로** 바꾸고(선택지는 요청과 스키마에서만 나옴), 1패스 결정 모델이 고른다. 생의학 도구 157개·요청 1,952건에서 올바른 도구 선택(또는 올바른 거절) 97.0%(로컬 LLM 에이전트 18개 설정 중 최고 95.2%), 인자 6,056개 중 97.0% 채움, **꾸며낸 내용 0건**(LLM 호출은 5.5~19.7%). AI 심층의 「비생성 의사결정 모델」 노트가 다룬 "생성하지 않고 선택지 확률만 내는 모델"을 에이전트 도구 호출에 붙인 형태다.

**실무에 무슨 의미인가.** ① 사내 코드 검색·RAG를 붙일 때 **벡터 DB부터 깔지 말고 `ripgrep` + LLM 식별자 확장을 기준선으로** 먼저 재라. Spring 코드베이스는 `OrderCancelService`, `@Transactional(propagation = REQUIRES_NEW)` 같은 희귀 토큰 덩어리라 어휘 검색이 원래 강하다. 둘 다 쓸 거면 순위 융합(RRF 등)으로 합친다. ② **평가 함정 체크리스트**: 비교 대상을 불리하게 전처리하지 않았나, 정답 집합에 "따라 바뀐 파일"(테스트·설정)이 섞였나 — 11/20 노트의 "채점기 지름길"과 같은 종류의 오염이다. ③ System 1은 "모델이 자유 텍스트로 JSON을 채우게 하지 말고, **선택지를 코드로 만들어 고르게 하라**"는 설계 원칙이다. Spring에서 LLM에게 `status` 필드를 쓰게 할 때 문자열 대신 enum 값 목록을 주고 검증하는 것과 같다.

**반론·회의적 시각.** Embeddings vs. Grep은 "Python 풀에서 동등"이고 다른 언어에선 어떤지 초록이 말하지 않는다. LLM 질의 확장은 질의마다 LLM 호출 비용이 든다(dense는 인덱싱 비용이 앞에 몰림) — 비용 비교는 초록에 없다. System 1은 생의학 도구 한 분야, 선택지가 요청·스키마에서 나올 수 있는 경우에 한정된다 — 자유 텍스트 인자(검색어·메모)가 필요한 도구는 범위 밖이다.

원문: [HF 2611.20455](https://huggingface.co/papers/2611.20455) · [HF 2611.21053](https://huggingface.co/papers/2611.21053) · [System 1 Agents GitHub](https://github.com/eltzanis/SystemOneAgents)

## 브리핑 정정·보충

1. **(정정) Masullo GRH.** 브리핑은 "Conrad가 검토 중, 지금까지 좋아 보인다"로 끝나지만, Vakil의 공지는 약 8시간 뒤 **"여러 사람이 서로 다른 AI 모델의 도움으로 문제를 찾아 보고했다, 증명 전략의 옳고 그름에 대해 주장하지 않는다"** 로 갱신됐다. "940쪽"은 공지문에서 확인 안 됨.
2. **(정정) Lean 코드 링크.** 브리핑의 GitHub 저장소(CocoSgt)는 Alpöge 본인 저장소가 아니라 **제3자 무수정 미러** 다. 원본은 alpo.ge의 14개 분할 파일. 미러 README는 "독립 빌드·검토 결과 없음, 주장된 증명으로 취급하라"고 적었다.
3. **(보충) 무엇이 증명 대상인가.** GRH는 정확히는 **디리클레 L-함수에 대한 GRH**(README 명제 기준). 헤드라인 명제 `RiemannHypothesis`는 Mathlib 정의를 그대로 쓴다.
4. **(정정) Frostbite 비교 대상.** "현대 슈퍼스칼라 CPU"는 **dual-issue in-order** 코어다. 그리고 4.59배는 탐색 세트(6.02배)와 홀드아웃(3.83배)을 합친 값이다.
5. **(정정) Inkling 2 Mini.** "CoT 3,703→1,661"은 1패스 대 **5패스**(3패스는 1,731). "비순환 모델이 추론 연산 140% 더"는 **512K 토큰 에이전트 궤적에서 같은 손실** 에 이르는 조건. Terminal Bench 2.1은 Qwen3.8-27B가 앞선다(73.0 대 71.6).
6. **(정정) Self-Rewriting.** "Qwen3.5 27B", "5회 철회", "80% 이상 복구"는 초록에 없다. 초록: 490문제 +6.6점, 첫 8세션 정확도 상승만, 손상 복구는 이미지 벤치 6개 7%→70%(원본의 83%), 2B는 수정 없음·4B/9B는 자기 파괴.
7. **(보충) Embeddings vs. Grep.** 가이드에 **"dense와 BM25를 융합하라"** 가 있다(브리핑은 grep 쪽만 강조). HF 업보트는 4.
