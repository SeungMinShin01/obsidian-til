## 배경

글은 배차를 "라이더 상태를 수치화해 푸는 수리 최적화 문제"로 설명한다. 라이더 1명에게 신규 배달 N건을 붙이면 정점이 2N개, 간선이 C(2N,2)개가 되고 모든 간선에 거리값이 필요하다. 알뜰배달 이후 동시 배차가 늘어 주말 피크 기준 분당 15만~20만 건의 경로를 계산하게 됐고, 2건 배차 기준이면 분당 120만 건(초당 약 2만 건)의 실거리가 필요하다. 상용 내비게이션은 호출당 비용 때문에 현실성이 없다고 보았다.

## 핵심

- 거리 엔진은 오픈소스 OSRM을 선택하고, 공통시스템팀의 지도 미디에이터 서비스를 거쳐 API로 받는다. 글은 배차용 거리와 배달료 산정용 거리는 별개라고 짚는다.
- 한 배달이 평균 3~5회 다른 조합으로 재계산되므로 "실시간 계산" 대신 "미리 계산해 저장·재사용"하는 구조를 택했다.
- Kafka에서 거리 계산에 필요한 이벤트만 구독한다: DeliveryCreated, PickupLocationChanged, DeliveryLocationChanged, DeliveryDelivered, DeliveryCanceled. EventProcessorFactory가 이벤트별 프로세서를 만들고, @KafkaListener 컨슈머는 지원하지 않는 이벤트는 즉시 acknowledge 후 리턴한다.
- 이벤트 키가 배달 ID면 같은 지역의 동시 생성 이벤트 순서가 꼬여 직전 배달이 빠질 수 있다. 그래서 키를 지역 ID로 바꿔 재발행(리파티션)해 파티션 내 순차 처리를 얻었다.
- Redis String(지역 ID → JSON 전체)은 한 건 갱신에도 지역 전체를 읽고 쓰므로 대역폭 위험이 있다. ElastiCache r6g.large는 baseline 0.75Gbps·burst 10Gbps이고, 지표는 NetworkBandwidth{In,Out}AllowanceExceeded다.
- Zstd 압축(RedisSerializer 직접 구현)은 1,000개 좌표 기준 약 24MB → 약 3MB였으나, 3MB여도 초당 약 3,400회 조회를 버티기 어렵다고 판단해 기각했다. 문자열 포맷 축소도 효과가 미미했다.
- 채택안은 Redis Hash: key=지역 ID, field=좌표 두 개, value=Integer 거리. 필요한 필드만 접근하고, 다중 인자 커맨드(HMGET/HMSET/HDEL)로 호출 횟수를 줄이되 요청당 최대 인자 3,999개를 넘지 않도록 청크로 나눈다(O(N) 슬로우 쿼리 방지).
- 처음엔 모든 HMSET에 6시간 EXPIRE를 붙였으나, 배달 종료 시점 가정이 비현실적이고 TTL 갱신이 네트워크·복제 비용이라 폐기했다. 완료/취소 시 같은 위치가 지역에 더 없을 때만 관련 거리를 명시적으로 삭제한다.
- 마스터-레플리카는 쓰기가 Primary에 몰리므로 클러스터 모드로 쓰기를 분산했다. 같은 키에 대해서만 멀티 연산을 하므로 서비스 코드 변경 없이 적용됐고, 지역별 점진 배포 후 전 지역으로 확장했다. 글에 배차 성공률 같은 정량 개선 수치는 없다.

## 내 프로젝트와의 연결

수집기와의 직접 연결은 약하다. 구조적으로 비슷한 지점은 둘이다. 수집기의 "같은 데이터를 여러 번 재요청하지 않고 저장해 재사용"은 이 글의 재계산 억제와 같은 동기이고, 키 설계가 순서와 분산을 정한다는 점은 WMS 재고 도메인에도 옮겨볼 만하다. WMS에서 같은 SKU/로케이션 이벤트를 순서대로 처리해야 한다면 "이벤트 키 = 순서를 지킬 단위(SKU 또는 로케이션)"로 잡는 사고방식이 대응된다. 또 TTL 대신 도메인 이벤트(완료·취소)로 정리한다는 판단은 재고 선점·해제 데이터의 수명 관리와 닮았다. 다만 WMS 규모에 Kafka·Redis Cluster가 필요한지는 별개의 문제다.

## 오늘 정리할 것

1. 이벤트 키를 배달 ID에서 지역 ID로 바꾸면 왜 순서가 보장되는지, Kafka 파티션·키·오프셋 관계를 그림으로 그려 보기.
2. Redis String(JSON 통째)과 Hash(필드 단위)의 읽기/쓰기 전송량을 숫자로 비교해 보기(필드 1,000개 가정).
3. TTL 만료와 명시적 삭제의 장단점을 표로 정리하고, WMS의 재고 선점 데이터에는 어느 쪽이 맞을지 한 줄 결론 써 보기.
4. 글의 "실거리 수 = C(2N,2)" 식을 N=1,2,3으로 직접 계산해 6·15가 나오는지 확인하기.
