## 그날의 축

**"에이전트가 개발 비용 구조를 바꾸니 지난 5년의 기술 선택이 다시 계산된다."**

Shopify가 2020년에 갈아탔던 React Native를 버리고 네이티브로 돌아가는 이유로 성능도 버그도 아닌 "LLM이 코드 공유의 전제를 무너뜨렸다"를 공개 선언했고, 같은 날 Microsoft는 Rust를 사내 1티어 언어로 승격시켰다. 모델 쪽은 성능이 아니라 **가격**이 전면에 나왔고, 논문 쪽은 "에이전트가 진짜 연구·운영을 할 수 있나"를 재는 벤치마크가 쏟아졌다.

전날(9/10)과 이어 읽으면 흐름이 보인다 — 9/10의 축이 "학습 방법의 이동(post-training)"이었다면, 9/11은 그 결과가 **조직의 기술 선택을 실제로 뒤집기 시작한** 날이다.

## 큰 건

### 1. Shopify, React Native를 접고 네이티브로 (HN 552pt / 386댓글)

2020년부터 이어온 React Native 전면 투자를 접는다. Shop 앱은 프로토타입부터 앱스토어 배포까지 **12주** 만에 재작성을 끝냈고, 화면 300개가 넘는 본체 Shopify 앱은 마이그레이션 중으로 2026년 후반 출시 예정. 2025년 1월에 "React Native 투자를 계속하겠다"고 공개적으로 못 박았던 회사라 반향이 컸다.

이유가 핵심이다. 성능도 생태계도 아니라고 명시한다. 원문 표현은 "코딩 모델이 극적으로 좋아져서, 우리 앱과 우리 팀에 한해 같은 기능을 Swift와 Kotlin으로 각각 만드는 비용이 예전 같지 않다". 즉 **"두 플랫폼에 같은 코드를 쓰면 인건비가 절반"** 이라는 크로스플랫폼의 근본 전제가 약해졌고, 대신 네이티브로 가면 프레임워크 레이어가 줄어 플랫폼 신기능·1st-party 툴링에 바로 붙는다는 계산이다.

순탄하지 않았다는 점도 함께 적혀 있다. 에이전트가 시뮬레이터를 다루는 게 느리고 불안정해서(접근성 트리·스크린샷 의존) 몇 초짜리 피드백 루프가 몇 분씩 걸렸고, **"그냥 LLM에 던져서 포팅하면 안 된다 — 유지보수 불가능한 코드가 산더미로 나온다"** 고 원문이 직접 인정한다. 그래서 만든 게 **Helix**다.

> **Helix — 이 글에서 실무적으로 가장 쓸모 있는 대목**
> 한 방 생성 대신 **체크포인트 반복**. 화면 하나를 리뷰 가능한 작은 조각으로 쪼개고, 각 조각마다 ① 자동 테스트 통과 ② 실행 중인 앱과의 시각적 대조 ③ **적대적 코드 리뷰 2회** ④ 사람 승인 을 거쳐야 다음으로 넘어간다. 피드백이 누적되면서 시스템이 점점 더 자율적으로 간다.
> 에이전트로 리팩터링·마이그레이션을 할 때 그대로 옮겨 쓸 수 있는 구조다.

오픈소스 처리: **React Native Skia** 2026년 말까지 후원 후 원저자 William Candillon이 포크·개명, 원 저장소는 아카이브. **FlashList**(주당 약 200만 다운로드)는 치명적 이슈만 계속 고치며 장기 관리자를 찾는 중. **Restyle**은 2026년 말 아카이브.

**반론.** 원문 자체가 "React Native 앱도 빠를 수 있다, 우리 것도 빨랐다"고 인정한다. HN 쪽 지적은 두 갈래다 — ① 이건 연 매출 수천억짜리 회사의 계산이지 3인 팀의 계산이 아니다(에이전트로 두 벌을 유지해도 리뷰·테스트·릴리스 파이프라인은 두 벌이 필요하고, 그 고정비를 감당할 조직에서만 성립) ② 지금은 발표에 "LLM 덕분에"를 붙이는 게 유행이라 진짜 동기가 다른 데 있을 거라는 냉소.

**읽는 법** — React를 배우는 입장에서 이건 "React 배우지 마"가 아니라 **"크로스플랫폼의 명분이 바뀌었다"** 는 신호다. 코드 공유의 가치가 내려가면 그 자리를 채우는 건 "플랫폼을 얼마나 아느냐"다. 웹으로 옮겨 보면, 프레임워크 추상화 아래에서 브라우저·런타임이 실제로 뭘 하는지 아는 쪽의 값이 올라간다는 뜻이기도 하다.

### 2. Rust가 Microsoft 사내 1티어 언어 (HN 483pt / 269댓글)

Rust Foundation의 Microsoft 게스트 포스트. 1티어는 분위기가 아니라 정의가 있는 등급이다 — "로컬 개발부터 프로덕션까지 포장된 길(paved path)"을 제공한다는 뜻이고, 구체적으로 보안 검증된 툴체인 빌드·개발자 툴링·품질 워크플로·플랫폼 깊은 통합, 그리고 사내 **SDL(보안 개발 수명주기) 요구사항 준수**까지 갖췄다는 의미다. C++·C#·TypeScript와 동급.

핵심 투자는 `rustc_codegen_utc` — Rust 컴파일러의 코드 생성 백엔드를 MSVC에 연결하는 대체 백엔드다. 이게 있어야 윈도우 툴링 생태계·바이너리 하드닝·Rust↔C++ 크로스 언어 최적화·통합 디버깅이 자연스럽게 붙는다. 2026년 초부터 프로덕션 레디, Rust 1.90부터 셀프 호스팅, 현재 사내 100개 이상 저장소가 이걸로 빌드.

회의론은 구체성 부족을 짚는다 — 제품명을 하나도 대지 않았고 "100개 이상 저장소"는 Microsoft 규모에서 해석하기 나름이며, C#·TypeScript를 밀 때도 비슷한 톤의 글이 있었다는 것. 반대편은 "MSVC 백엔드를 직접 만들어 붙이는 건 블로그 글 한 편보다 훨씬 비싼 약속"이라고 본다.

**읽는 법** — "Rust를 지금 배워라"가 아니라 **메모리 안전성이 취향에서 컴플라이언스로 넘어가고 있다**는 쪽이다. SDL 준수 항목에 들어갔다는 게 그 뜻이다. Java/Spring 진영에도 같은 흐름이 와 있다 — 공급망 보안(SBOM), 서명된 빌드, 재현 가능한 빌드가 "잘하면 좋은 것"에서 "없으면 납품 못 하는 것"으로 이동 중.

### 3. 코딩 모델 가격 전쟁 — DeepSeek V4.1 Flash와 Cognition SWE-2가 같은 날

**DeepSeek V4.1 Flash** (HN 868pt / 493댓글). 비피크 기준 100만 토큰당 입력 캐시 히트 $0.003 / 캐시 미스 $0.15 / 출력 $0.6, 피크는 2배. "V4 Pro를 모든 주요 지표에서 넘는다"고 주장하면서 **구체적 벤치마크 수치와 측정 조건을 전혀 공개하지 않았다.** 게다가 V4.1 Pro가 나오기 전까지 Pro 요청을 전부 Flash로 라우팅하되 Flash 요금으로 청구한다고 해서 "전환 기간 없이 모델을 갈아끼운다"는 반발. 이전 V4 Flash에서 언어 일관성·tool calling 불안정 보고가 있었던 터라 프로덕션 신뢰도 우려도 함께.

**Cognition SWE-2** (HN 215pt / 101댓글). Kimi K3(2.8T 파라미터) 기반에 강화학습을 태운 에이전틱 코딩 모델.

| 벤치마크 | SWE-2 | Fable 5.1 | GPT-6 Astra |
| --- | --- | --- | --- |
| Terminal-Bench 2.1 | **92.8%** | 91.4% | 89.9% |
| FrontierCode 1.1 | 50.0% | 50.9% | **53.3%** |
| DeepSWE 1.1 | 73.0% | 67.4% | **74.1%** |

홍보 포인트는 성능이 아니라 **가격**이다 — "FrontierCode에서 Fable 5.1과 1점 차인데 64% 싸다", "GPT-6 Astra와 몇 점 차인데 1/4 가격".

겹쳐 보면 신호는 명확하다. 최상위 성능은 이미 1~3점 차로 촘촘하고, 경쟁이 옮겨간 축은 **토큰당 비용과 에이전트 워크로드에서의 안정성**이다. 다만 논쟁적 발표이기도 하다 — 공개 수치 없는 성능 주장, 강제 라우팅, "벤치마크 92.8%가 내 레거시 코드베이스에서 뭘 의미하냐"는 오래된 회의.

**읽는 법** — 학습용으로 에이전트를 쓰고 있다면 지금이 **모델을 갈아끼우기 가장 쉬운 시기**다. 프롬프트와 툴 정의를 코드에서 분리하고 모델 이름을 설정값으로 빼두면 이런 발표마다 한 줄만 바꾸면 된다. DeepSeek의 강제 라우팅 건은 교훈이 하나 더 있다 — 외부 API는 내가 고른 모델을 계속 준다는 보장이 없으므로, 작은 골든 셋 + 자동 비교 같은 회귀 장치가 있어야 조용한 품질 저하를 잡는다.

### 4. 수학자들이 "AI가 우리 연구를 선점한다"고 말하기 시작했다 (HN 344pt / **447댓글**)

OpenAI가 미공개 모델로 Navier–Stokes 존재성·매끄러움 문제(밀레니엄 문제)를 다뤘다고 발표했다. 투입량 자체가 화제였다 — 여러 문제에 걸쳐 490만 건의 메시지, 3,000억 토큰. 발표 직후 수학자 Tristan Buckmaster가 "우리가 거의 1년간 발전시켜 온 작업을 가로챘다(scoop)"고 공개 제기하면서, 성과보다 **연구 윤리와 관행**이 논점이 됐다. 오늘 1면에 오른 건 Andreas Thom 등이 "미공개 연구를 OpenAI에 맡겨도 되는가"를 이어간 논의다. 댓글이 포인트를 넘는다는 것 자체가 합의가 없다는 신호.

Terence Tao의 지적이 본질을 짚는다 — 열린 연구 문제들이 "재생 불가능한 방식으로 채굴되고" 있으며, "누군가 어떤 문제를 붙들고 있다는 소문만으로도 대규모 AI 물량이 투입돼 그 문제를 먼저 납작하게 만들 수 있다". 그러면 "지금 뭘 연구 중인지 서로 이야기한다"는 오픈 사이언스의 기본 관행이 각자에게 손해가 되고 다들 입을 닫게 된다. 반대편도 분명하다 — 문제가 풀렸으면 된 것 아니냐, 선점 경쟁은 AI 이전에도 있었다, 낡은 건 학계의 크레딧 배분 제도지 도구가 아니다.

**읽는 법** — 구조는 개발자에게도 같다. "아이디어를 공개하면 하루 만에 누가 에이전트로 만들어 버린다"면 무엇을 언제 공개할지가 개인에게도 전략 문제가 된다. 동시에 반대 방향의 기회도 생긴다 — 구현 난이도가 해자가 아니게 되면 남는 해자는 도메인 지식·데이터·신뢰·유통이다.

## 개발 실무

- **JEP 544: Ahead-of-Time Code Compilation** — JDK에 사전 컴파일 코드 캐시를 도입해, JVM이 뜨며 인터프리터 → C1 → C2로 올라가는 **예열 구간**을 이전 실행의 컴파일 결과 재사용으로 건너뛰자는 방향. Spring Boot를 쓰면 남 얘기가 아니다 — 컨테이너에서 뜨는 Java 앱의 첫 요청이 느린 원인이 정확히 그 구간이고, GraalVM 네이티브 이미지로 갈 수밖에 없던 이유이기도 하다. (원문은 403이라 제목·HN 토론 기준)
- **Neki — PlanetScale의 샤딩된 Postgres.** 구조가 배울 만하다: 앱은 Postgres 와이어 프로토콜을 말하는 **라우터**에 붙어 기존 드라이버·ORM을 그대로 쓰고, 라우터가 쿼리를 파싱해 샤드를 정한다. 샤드 하나하나가 진짜 Postgres(프라이머리 1 + 리플리카 2 이상, AZ 분산)이고, 커넥션 풀링은 인스턴스 옆 사이드카, 스키마 변경·버전 업그레이드·리샤딩은 점검 시간이 아니라 컨트롤 플레인의 내장 워크플로. 논리 테이블→물리 샤드 매핑은 "data topology" JSON. 현재 플랫폼 프리뷰(프로덕션 사용 금지 명시)
- **Python의 set·dict가 이차 시간이 될 수 있다** (Daniel Lemire) — 원인 둘. ① 해시 충돌: `values = [i * (2**61 - 1) for i in range(1, n+1)]` 처럼 고르면 n이 두 배일 때 시간이 네 배 ② 메모리 계층: 키 100만 개면 키당 약 116바이트로 캐시를 벗어나 조회가 22ns → 202ns로 **9배**. 키가 미리 정해진 읽기 전용이면 fastconstmap이 키당 9바이트·11.8ns. "해시맵은 O(1)"에 단서를 달아둘 글
- **⚠️ Forgejo ≤16.0.3 치명적 RCE — 16.0.4로 올릴 것.** 셀프호스팅 Git 서비스. 소스 저장소를 잡히면 배포 자격증명까지 연쇄로 털리는 구조라 우선순위가 높다
- **Rust never 타입 `!` 머지** — "바닥 타입"보다 "빈 타입"으로 이해하는 게 정확. 값이 하나도 존재할 수 없는 타입이라 "이 함수는 절대 정상 반환하지 않는다"를 타입으로 표현할 수 있다. Java에는 대응 타입이 없어 컴파일러가 도달 불가 코드를 추론하기 어렵다
- **Proliferate** — 코딩 에이전트 여러 개를 병렬로 굴리며 진행 상황을 한 화면에 동기화하는 IDE. 경쟁축이 "모델 성능"에서 **"여러 작업을 동시에 돌릴 때의 관리 UX"** 로 넘어가는 사례. 실제로 돌려 보면 병목은 모델이 아니라 사람이 리뷰하는 속도다
- **Magic.dev: 10배 이상 효율적인 사전학습** — HN 98pt/51댓글로 반응은 미지근. 재현 조건 공개 전까지 유보적으로 보는 게 기본이나, 이번 주 가격 경쟁과 묶으면 "학습 비용 자체를 깎는다"는 축도 같은 방향의 압력
- **Stockfish 19** (HN 240pt) · **Old New Thing: Windows XP가 초기 사용자 그림을 고르던 알고리즘** (306pt/148댓글) — 후자의 가치는 재미보다 **제약 아래에서의 설계 결정**을 당사자 설명으로 볼 수 있다는 데 있다
