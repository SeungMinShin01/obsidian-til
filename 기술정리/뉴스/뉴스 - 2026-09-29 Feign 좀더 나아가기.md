## 배경

글은 배달의민족 광고시스템 백엔드에서 외부 API 호출에 Feign을 쓰며 겪은 실무 포인트를 이전 글에 이어 보완한다고 설명한다. 기본값 그대로 쓰면 나중에 막히는 지점(HTTP 클라이언트, 로깅, 에러 처리, 설정 범위, 인터페이스 재사용, 컬렉션 파라미터)을 하나씩 다룬다.

## 핵심

- **HTTP 클라이언트**: 기본값은 `feign.Client.Default`. ApacheHttpClient는 의존성 추가 후 `feign.httpclient.enabled: true`, OkHttpClient는 `feign-okhttp` 의존성 + `feign.okhttp.enabled: true`. 글은 OkHttp의 장점으로 HTTP/2, 내장 응답 캐시, 웹소켓, 단순한 API, TLS 기본값 관리를 든다.
- **로깅**: Feign 로깅은 `DEBUG` 레벨에서만 동작한다고 한다(설정 문서에 명시).
- **에러 처리**: 200~299는 정상, `feign.client.config.default.decode404: true`면 404도 정상, 그 외는 errorDecoder가 실행된다. 대안으로 반환 타입을 `feign.Response`로 받아 status를 직접 확인하고 5xx면 예외를 던지는 방식을 소개한다.
- **@Configuration 함정**: Feign 설정 클래스에 `@Configuration`을 붙이면 컴포넌트 스캔되어 모든 Feign 클라이언트에 공통 적용된다(Spring Cloud 문서도 붙이지 않아도 된다고 하며, 붙일 땐 `@ComponentScan`에서 제외하라고 경고). 클라이언트별 설정이 목적이면 붙이지 않고 `@FeignClient(configuration=...)`로 지정한다. 완화책으로 마커 어노테이션(`@FeignConfiguration`)을 만들고 `excludeFilters`(`FilterType.ANNOTATION`)로 스캔에서 제외한다. 같은 설정을 여러 클라이언트에 적용하면 클라이언트마다 빈이 생성된다.
- **인터페이스 재사용**: 같은 API를 retry 유/무로 나눠 쓰려면 공통 인터페이스(`MessageClient`)를 두고 각각 `@FeignClient`로 확장(`MessageNoRetryClient` / `MessageRetryClient`)한다. Retryer 기본값은 `NEVER_RETRY`라 재시도가 필요하면 Configuration에서 `feign.Retryer.Default`를 명시해야 한다.
- **컬렉션 파라미터**: 기본은 `key=v1&key=v2`(EXPLODED). OpenFeign 9.6.0+ 와 Feign 기본 Contract(Spring Contract 아님)에서 `@RequestLine(collectionFormat = CollectionFormat.CSV)` 등으로 CSV·SSV·TSV·PIPES를 고를 수 있다고 한다. Boot 2.1.x → Greenwich(OpenFeign 10.1.0), Boot 2.0.x → Finchley.SR2 이상.
- 2019년 글이라 현재 Spring Cloud OpenFeign 버전과 차이가 있을 수 있다(사용자 미검증).

## 내 프로젝트와의 연결

수집기는 사람인 API 같은 외부 API를 호출하므로 "재시도가 필요한 호출과 아닌 호출을 인터페이스 단위로 분리"하는 구조, 그리고 Retryer 기본값이 `NEVER_RETRY`라는 점이 닿는다(멱등한 조회는 재시도, 부작용 있는 호출은 무재시도). WMS에서 외부 연동(택배사·ERP 등)을 붙일 때 타임아웃·에러 디코딩·`@Configuration` 스캔 범위 문제가 구조적으로 비슷하다. 다만 프로젝트가 Feign을 쓰지 않으면 직접 연결은 약하고, RestClient/WebClient에서 같은 문제를 어떻게 푸는지 비교하는 관점이 적합하다.

## 오늘 정리할 것

1. 수집기의 외부 API 호출부에서 재시도 정책(횟수·대상 예외·멱등 여부)을 표로 정리
2. 설정 클래스에 `@Configuration`을 붙였을 때/붙이지 않았을 때 빈 등록 범위가 어떻게 달라지는지 작은 예제로 확인
3. 4xx/5xx를 예외로 바꿀지 응답 객체로 직접 볼지, 수집기 에러 처리 기준을 한 줄씩 적어보기
4. 컬렉션 파라미터 직렬화(EXPLODED vs CSV)가 대상 API마다 다를 수 있음을 API 문서에서 확인
