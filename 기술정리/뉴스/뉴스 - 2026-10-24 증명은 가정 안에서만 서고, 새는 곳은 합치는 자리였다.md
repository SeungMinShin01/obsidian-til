> 이전: [[뉴스 - 2026-10-24 JDBC로 실행되는 SQL에 자동으로 프로젝트 정보 주석 남기기]]

## 오늘의 흐름

겹치는 것부터. 오늘(10/24) 브리핑의 큰 건 넷 중 셋이 이미 다룬 사건이다 — PHP RCE 2건과 엠바고 붕괴·eMudhra(10/21~10/23), WorldTUI(10/23 깊게), Agent Skills의 AAIF 기증과 cloudflare/security-audit-skill(10/22~10/23 짧게), "LLM에게 확신도를 묻지 말라"(10/23 깊게). 이 노트는 **새 항목과 재등장 항목의 새 사실만** 본다. 새 큰 건은 Anthropic·Theorem의 **어셈블리 수준 정형 검증 123개 라이브러리**이고, 재등장 중 새 사실이 가장 큰 것은 PHP 쪽이다 — 독립 분석가의 재현 글이 자기 주장을 **CVSS 5.3, RCE 미입증**으로 스스로 정정했다(아래 '정정').

첫 번째 축은 **"보장은 선언한 가정 안에서만 선다."** 정형 검증 발표가 가장 공들여 쓴 절은 결과가 아니라 한계다 — 증명된 것은 "musl에 정적 링크된 단일 스레드 RISC-V 바이너리가, Theorem이 만든 RISC-V·Linux 프로세스 의미론 위에서, 64MB 미만 입력에 대해 ASan이 잡는 오류 없이 끝난다"이고, 실제 배포는 대부분 glibc 동적 링크 x86/ARM이다. 증명 1억 8천만 줄은 사람이 읽지 않는다. 믿는 것은 Rocq 검사기, 의미론 모델, 그리고 *정리 문장 자체*다. PHP 쪽도 같은 모양으로 갈라졌다 — PHP 재단은 "Apache+mod_php 기본 설정에서 인증 없는 RCE가 시연됐다"고 하고, 독립 재현 글은 같은 경로가 **Apache prefork+mod_php와 내장 서버에서만** 성립하고 PHP-FPM·CGI에선 프로세스가 죽어 닿지 않는다고 했다. 둘이 모순이라기보다, **같은 버그도 어느 실행 모델을 가정하느냐에 따라 등급이 다르다**는 것이다. 10/23의 "확신의 모양을 한 신호는 싸졌다"를 반대편에서 본 것 — 신호가 싸진 만큼, 신호가 *어떤 가정 위에서 나왔는지*를 읽는 능력이 비싸진다.

두 번째 축은 오늘 새로 보이는 흐름이다. **"새는 곳은 개별 문서가 아니라 합치는 자리다."** Agent Mosaic은 문서 하나하나의 열람 권한이 다 통과해도, 에이전트가 여러 문서를 합친 *결론*이 기밀이 되는 문제를 측정했다 — 선의 질의에서도 최고 모델이 7.08% 노출. Raw-RAG 논문은 거꾸로 *잃는* 쪽에서 같은 자리를 짚는다 — 대화 기록을 요약·원자적 사실·그래프로 가공하는 메모리 계층이, 나중에 답에 필요한 **값 사이의 경로**를 버린다(원자적 사실로 바꾸면 −19.62점). 하나는 합치면 *새고*, 하나는 미리 쪼개면 *잃는다*. 둘 다 "개별 조각 단위로 관리하면 전체의 성질을 놓친다"는 이야기다. 10/23의 "비밀은 기록 속에서 샜다"가 *어디에* 비밀이 있었나의 문제였다면, 오늘은 *언제* 비밀이 생기나 — 합치는 순간 — 의 문제다.

세 번째 축은 **"강제는 에이전트 바깥에 둔다."** 오늘 나온 도구 셋이 모두 같은 설계 원칙을 쓴다. 정형 검증에서 Claude는 증명을 쓰지만 판정은 Rocq 검사기가 하고, 코드를 고치면 패치마다 벌점·감사가 붙는다. Cloudflare 스킬에서 **찾은 에이전트는 검증하지 않는다**. NVIDIA OpenShell에서 **에이전트는 진짜 자격증명을 보지 못하고**, 승인된 엔드포인트로 나가는 요청에만 런타임이 주입한다. 마지막 것은 어제 LiteLLM 사후 보고서의 직접적인 반대 그림이다 — 그 사고는 에이전트 도구가 손에 쥔 GitHub 토큰을 응답 본문에 흘린 데서 시작했다. 에이전트가 토큰을 *쥐지 않으면* 흘릴 것도 없다.

네 번째는 몇 주째 이어진 **기준선 다시 재기**(10/16 "기준선을 다시 재자 이득이 줄었고")의 연속이다. Raw-RAG(복잡한 메모리 12종을 단순 검색+리랭킹이 7설정 중 6에서 이김), Physical AI 재귀 자기개선 리뷰("재귀 자체에 기인한 이득을 분리한 물리 실험은 없다"), OpenDS-World(살아 있는 웹에서 최고 39.0%). 새 기법보다 "그게 정말 기준선보다 나은가"를 묻는 논문이 HF 상위에 꾸준히 오른다.

## 깊게 본 것

### 1. Claude가 쓴 증명 1억 8천만 줄 — 퍼즈 테스트를 명세로 (요약, 구조는 AI 심층)

**무슨 일인가.** Anthropic Frontier Red Team이 정형 검증 스타트업 Theorem과 함께, Google OSS-Fuzz에 등록된 오픈소스 라이브러리 **123개의 퍼징 진입점 239개**에 대해 "**64MB 미만의 어떤 입력**에도 메모리 안전 오류나 assertion 실패 없이 끝난다"를 기계 증명했다(10/22). 대상은 소스가 아니라 **컴파일된 RISC-V 바이너리**(중위값 18,000 명령어), 증명은 Claude가 **완전 자율로** 쓰고 **Rocq**(구 Coq) 검사기가 확인했다. 전체 약 1억 8천만 줄, 전형적인 증명 하나 약 60만 줄.

**배경 — 왜 지금인가.** 정형 검증의 두 병목은 ① 명세를 누가 쓰나 ② 증명을 누가 쓰나였다. seL4는 구현 2인년, 검증 20인년이었다(GeekNews 요약이 전한 기사 내 수치). 이 작업은 ①을 **이미 있는 퍼즈 테스트**로 해결했다 — 퍼즈 하니스는 "이 함수에 무엇을 넣어도 죽으면 버그"라는 선언이므로, 그 진입점 + "크래시 없음" + RISC-V/Linux 의미론을 합치면 정리(theorem) 문장이 기계적으로 나온다. ②는 토큰으로 샀다.

**어떻게 동작하나(요지).** 라이브러리+퍼즈 하니스 → RISC-V 정적 바이너리 → 의미론과 결합해 명세 자동 생성 → Claude가 증명 → Rocq 검사. 증명 중 버그가 나오면 Claude가 코드를 패치하고 명세를 *다시 생성*해 다시 증명한다. 정리를 쉽게 만들려고 프로그램을 망가뜨리는(예: 입력을 다 무시하고 곧장 종료) 보상 해킹을 막기 위해 **모든 패치에 벌점**, "패치가 영향을 주는 입력이 얼마나 적은지"를 증명하면 가산점, 모든 패치를 로깅·감사. 에이전트 팀은 다른 팀의 증명(런타임 초기화·ASan 관련처럼 겹치는 부분)을 복사해 고쳐 썼다.

**찾은 것.** "수백 건". 약 20MB 입력의 희귀 레이아웃에서만 터지는 압축 해제기 카운터 언더플로(범위 밖 쓰기), 64MB 입력·2GB 이상 메모리가 필요한 이미지 디코더 범위 밖 읽기, **같은 파일을 가리키는 핸들 2개**에 대한 특정 호출 순서, libexpat CVE-2026-56132 재발견, 크래시는 아니지만 "로드 가능한 파일 제한" 기능이 항상 강제되지 않는 논리 버그. 이름 비공개 PDF 리더에서는 **일주일에 보통 1년치 분량**의 보안 버그와 10년 넘은 논리 버그. 브리핑에 없는 사례 둘: Claude가 RFC 1950(zlib) 명세를 쓰고 **Linux 커널 zlib을 x86 바이너리 수준에서** 증명(x86 의미론도 Claude가 생성, 발견 버그는 경미·악용 불가), Claude가 Rust로 쓴 Python 부분집합 인터프리터를 Verus로 CPython 의미론에 맞춘다고 증명(무작위 프로그램 약 170만 개 중 99.95% 일치).

**실무에 무슨 의미인가.**

- **퍼즈 하니스가 자산이 된다.** 지금 써 두는 퍼즈 테스트·속성 기반 테스트(Java라면 jqwik, JUnit의 `@ParameterizedTest` 넘어선 것)가 나중에 *명세*로 재활용될 수 있다. "무엇을 넣어도 이 불변식은 지킨다"를 코드로 적는 습관의 가치가 올라간다.
- **"증명됨"을 읽는 법.** 라이브러리 README에 "verified"가 붙으면 ① 어떤 속성(크래시 없음? 기능 정확성?) ② 어떤 실행 모델(아키텍처·libc·스레드) ③ 어떤 입력 경계 ④ 무엇을 신뢰 기반으로 두나를 확인해야 한다. 오늘 발표는 이 넷을 스스로 다 적어 둔 좋은 본보기다.
- **비용 곡선.** 증명 하나에 수억 토큰. 다만 OSS-Fuzz 소형 과제 36개(과제당 5M 토큰 예산, 단일 에이전트 3회)에서 Opus 5.5가 절반을 Opus 5보다 약 40% 적은 토큰으로 증명했고, 공유 작업공간이 토큰 17%를 더 줄였다.

**반론·회의적 시각.** 발표 자신이 적은 것: 명세가 현실을 정확히 모델링하지 않으면 버그가 남는다, 실제 배포 환경과의 차이, ASan이 모든 메모리 버그를 잡지 않음, 모든 진입점을 하지 않았고 데드 코드는 비커버, 호출자의 오용. HN·GeekNews 쪽 회의: AI가 명세까지 만들면 **증명하기 쉬운 명세로 미끄러질** 수 있다(여기서는 명세가 퍼즈 하니스+고정 속성에서 기계적으로 나오므로 이 위험은 *패치* 쪽으로 옮겨 간다 — 그래서 패치 벌점이 핵심 장치), 에이전트 증명은 레지스터·분기를 하나하나 풀어 써서 사람이 유지보수할 수 없다, 비용. 그리고 이 글은 Anthropic의 자사 모델 홍보이기도 하다 — 증명 일부는 공개됐지만(아래 링크) "수백 건"의 버그 목록은 미패치 때문에 공개되지 않았다.

### 2. 복잡한 에이전트 메모리, 정말 필요한가 — 생 기록에 검색+리랭킹이 12종을 이겼다

**무슨 일인가.** 시안교통대 팀(Bao 외, arXiv 2610.30755, HF ▲15)이 장기 대화 메모리 시스템 12종(EverMemOS, MemOS, EMem, SimpleMem, MemU, MemMachine, Mem0, Memora, Nemori, MemoryOS, A-MEM, RecMem)과 **Raw-RAG** — 아무 가공 없는 대화 기록에 밀집 검색+리랭킹만 — 를 LoCoMo·LongMemEval·MEME·MemoryAgentBench에서 비교했다. 7개 벤치마크-모델 설정 중 **6개에서 Raw-RAG 1위**.

**기술적으로 — Raw-RAG가 정확히 무엇인가.** 대화를 타임스탬프·이미지 캡션과 함께 직렬화 → **256토큰 창, 32토큰 겹침**으로 자름 → 평평한 임베딩 인덱스(본문 표는 `text-embedding-3-small`) → 질문과 코사인 유사도 상위 **128개** → 크로스 인코더 리랭커(Cohere Rerank-v3.5)로 **15개** → 리더 LLM이 시간 순서·상태 변화를 *스스로* 해석. 끝. 메모리 쓰기 시점에 LLM 호출이 없다.

| --- | --- | --- |
| LoCoMo · GPT-4o-mini | 89.07 | MemMachine 88.12 |
| LoCoMo · GPT-4.1-mini | 93.70 | EverMemOS 93.05 |
| LongMemEval · GPT-4.1-mini | 87.53 | Memora 87.40 |
| MEME · GPT-4o-mini | 39.30 | MemMachine 37.06 |
| MEME · DeepSeek-V4-Flash | 43.19 | **MemMachine 44.71** (유일한 패배) |
| MemoryAgentBench · GPT-4o-mini | 48.32 | Memora 43.84 |
| MemoryAgentBench · DeepSeek-V4-Flash | 53.41 | Memora 47.88 |

**왜 이기나 — 커버리지 대 활용률.** 논문은 정답에 필요한 근거가 리더에게 도착했나(커버리지)와 도착한 근거를 맞게 썼나(활용률)를 나눠 쟀다. MemoryAgentBench에서 시스템 간 커버리지는 **19.07~45.29%**로 크게 갈리는데 활용률은 **80.00~89.71%**로 비슷하다. Raw-RAG는 활용률이 최고가 아닌데도(84.43%) 커버리지가 최고(45.29%)라 이긴다. MEME의 "경로 보존"(값만이 아니라 그 값을 유도하는 관계 사슬이 남았나)은 Raw-RAG 62.34%, MemMachine 56.70%, MemU **9.62%**. 결정적 실험: 가공된 메모리 저장소 *전체*를 리더에게 다 줘도(오라클) 생 근거보다 **7.58~29.38점 낮다** — 가공하는 순간 정보가 빠진다는 뜻이다(저자도 순수한 정보 손실 측정은 아니라고 단서를 단다).

**비용.** MEME 10에피소드·110문항에서 추가+검색 305.91초 — 다음 시스템보다 5.1배, EverMemOS보다 30.4배 빠름. 메모리 관리형 시스템은 MemoryAgentBench 11개 소스에 LLM 토큰 2,160만~1억 930만·2.9~8.8시간, Raw-RAG 약 12분. 소거 실험: 리랭커 빼면 −3.92, 상위 1개만 −11.73, **원자적 사실로 변환 −19.62**, 요약 덧붙이기 −5.81, 그래프 확장 −5.78, 청크 128~1,024토큰은 유의미한 차이 없음.

**실무에 무슨 의미인가.** 챗봇·에이전트에 "기억"을 붙일 때 첫 구현은 **원본 저장 + 검색 + 리랭킹**이어야 하고, 복잡한 메모리 프레임워크는 그 기준선이 *왜* 실패하는지 확인한 뒤에 들인다. Spring 쪽으로 옮기면 Spring AI `VectorStore`(pgvector)에 대화 원문을 창 단위로 넣고 리랭커 하나 붙이는 정도다 — 11월 예정인 Vault RAG 프로젝트의 기준선 설계에 그대로 쓸 수 있는 결과다(다른 구역 이야기라 서술로만). 또 "요약하면 빠진다"는 10/20 AI 심층 「객체 지향 컨텍스트 폴딩」(압축만 하면 악화)·10/23 「캐시 엔지니어링」(요약형 정확도 −5%p)과 같은 방향이다.

**반론·회의적 시각.** 오프라인 공개 벤치마크의 대화 과제만 봤다 — 상호작용·멀티모달·운영 환경은 아니다(저자 명시). 리더는 GPT-4o-mini·GPT-4.1-mini·DeepSeek-V4-Flash·Qwen3.5 정도로 제한적이고, 약한 리더에게는 명시적 상태 유지가 도울 수 있는지 미검증. MEME·DeepSeek 설정에서는 **Full-context가 Raw-RAG보다 19.98점 높았다** — 컨텍스트에 다 들어가면 검색 자체가 손해라는 뜻이기도 하다. 원본 보존은 저장·프라이버시·삭제 요구(잊힐 권리)와 충돌한다. 그리고 메모리 시스템들의 하이퍼파라미터를 각 저자만큼 잘 맞췄는지는 재현 논문의 고질적 질문이다.

### 3. Agent Mosaic — 각각은 볼 수 있는 문서가 합쳐지면 기밀이 된다

**무슨 일인가.** USC(Ruiz·Luceri·Ferrara, arXiv 2610.30418, HF ▲11). 정보기관 용어인 "모자이크 효과" — 개별로는 공개인 정보 조각을 모으면 기밀이 드러나는 것 — 를 LLM 에이전트에서 측정했다. 사이버보안·의료·군사 30개 합성 시나리오, 통제 시뮬레이션에서 에이전트 3종의 최종 답 **10,800건**, 오픈소스 하네스 2종에서 실제 에이전트 답 **1,440건**. 질의는 선의이고 각각 단일 문서로 답할 수 있게 설계.

**결과(초록).** 최고 성능 모델(**GPT-5.6-Sol**)도 선의 질의에서 금지된 복합 결론을 **7.08%**(95% CI 3.75~10.67%) 노출, 실제 하네스에서는 더 나쁨. 눈에 보이는 분류 헤더 + 명시적 집계 규칙을 넣어도 **모든 의도에 걸쳐** 시뮬레이션 답의 **32.37%**(28.33~36.19%)에서 안전하지 않은 공개. 거부가 늘어도 보호가 안 됐다 — 거부 문장 자체가 금지된 결론을 드러내는 경우가 있었다("그 일정은 기밀이라 말할 수 없습니다"가 일정의 존재를 확인).

**기술적으로 — 왜 기존 권한 모델로 안 막히나.** RBAC·ABAC는 "주체가 객체에 접근 가능한가"를 묻는 **객체 단위** 판정이다. 모자이크 누출은 객체 접근이 아니라 **추론의 산출물**에서 생긴다. 에이전트는 RAG로 문서 10개를 한 컨텍스트에 넣고 합쳐 추론하므로, 각 검색 결과에 권한 필터를 거는 표준 방식(문서별 ACL 메타데이터 필터)은 전부 통과한다. 막으려면 ① 무엇을 *함께* 가져올 수 있는가(집계 제한, 데이터베이스 보안의 "추론 통제" 문제) ② 답에서 무엇을 *말할* 수 있는가(출력 쪽 정책)를 따로 다뤄야 한다.

**실무에 무슨 의미인가.** 사내 문서 RAG를 만들 때 "문서별 권한 필터를 걸었으니 안전"은 필요조건일 뿐이다. 기밀 등급이 섞인 코퍼스라면 같은 질의에서 함께 검색될 수 있는 문서 조합을 제한하거나, 답변을 별도 판정기로 거르는 층이 필요하다. 오늘 흐름의 둘째 축 — 새는 곳은 합치는 자리 — 의 가장 직접적인 사례다. 그리고 "프롬프트 가드레일로 32%가 남는다"는 셋째 축(강제는 바깥에)의 근거이기도 하다.

**반론·회의적 시각.** 초록만 읽었다. 30개 **합성** 시나리오라 "금지된 복합 결론"의 정의가 저자 설계에 달려 있다. 32.37%는 "모든 의도에 걸친" 수치라 선의 질의의 7.08%와 **같은 조건의 전후 비교가 아닐 수 있다** — 가드레일이 오히려 나빠졌다고 읽으면 안 된다(브리핑의 "가드레일을 넣어도 32%가 남는다"는 이 차이를 지웠다). 벤치마크·코드는 "TBP"(미공개).

### 4. NVIDIA OpenShell — 에이전트에게 토큰을 쥐여 주지 않는 런타임

**무슨 일인가.** 에이전트마다 격리된 샌드박스를 주고, 정책으로 파일·시스템콜·네트워크를 선언해 런타임이 강제하는 오픈소스(Rust, Apache-2.0, 0.1.x). 하루 +1,119★(누적 18,772), HN 414pt.

**어떻게 동작하나(README 범위).** 구성은 **게이트웨이**(샌드박스·정책·접근의 컨트롤 플레인) + 수퍼바이저 + 샌드박스. 커널 수준 계측으로 에이전트가 접근할 파일과 호출할 시스템콜을 제한하고, **모든 외부 연결은 샌드박스를 떠나기 전 정책 검사**를 받는다. 핵심 둘:

- **자격증명 주입.** 에이전트는 진짜 자격증명을 보지 못한다. "프로바이더"라는 단위로 등록된 자격증명은 **승인된 엔드포인트로 가는 요청에만** 런타임이 덧붙인다(추론 API 키 포함).
- **정책 변경 검증.** 정책 변경이 승인되기 전에 형식적 검사가 위험한 새 접근(자격증명을 받는 새 호스트, 새 API 메서드 허용)을 표시하고 **사람 리뷰**를 기다린다. README는 advisor·prover 문서로 링크만 한다.

Linux·Apple Silicon macOS·WSL2(실험적), Docker/Podman/호스트 가상화 필요, Kubernetes는 Helm(CNI가 `NetworkPolicy`를 강제해야 함). **익명 텔레메트리 기본 켜짐**(`OPENSHELL_TELEMETRY_ENABLED=false`).

**배경·의미 — 어제 LiteLLM 사고와 겹쳐 읽기.** LiteLLM 사후 보고서의 첫 고리는 "에이전트 도구가 사용자의 GitHub CLI 토큰을 응답 본문에 넣었다"였다. 에이전트 프로세스가 토큰을 *가지고 있는* 한, 어떤 경로로든(로그·응답·프롬프트 인젝션) 흘러나갈 수 있다. OpenShell의 답은 "가지게 하지 말라" — 이건 새 발상이 아니라 서비스 메시의 사이드카가 mTLS 인증서를 앱 대신 쥐는 것, 클라우드의 IMDS·워크로드 아이덴티티가 장기 키 대신 단기 토큰을 붙이는 것과 같은 원리를 에이전트에 옮긴 것이다. Spring으로 치면 `RestClient`에 `ClientHttpRequestInterceptor`로 토큰을 붙이되, 그 인터셉터가 앱 *밖*(사이드카/egress 프록시)에 있는 구조다.

**반론·회의적 시각.** 0.1.x, 미해결 이슈 290·PR 176(브리핑 수치). README에는 Landlock·seccomp·네임스페이스 같은 구체 메커니즘 이름도, 정책 파일 예시도, egress가 프록시로 구현되는지도 없다 — 이 노트는 그 수준까지 확인하지 못했다. 자격증명 주입은 "토큰 유출"은 막아도 "승인된 엔드포인트에 에이전트가 시키는 대로 요청하는 것"(혼동된 대리인)은 막지 못한다 — 10/19 노트의 OpenAI 정렬 실패 사례들(GET만 열린 샌드박스를 자기제출 폼으로 POST 대행)이 정확히 그 모양이었다.

### 5. "Docker는 이상하다" — 컨테이너는 제약을 건 평범한 프로세스

**무슨 일인가.** 작은 컨테이너 런타임을 만들던 저자의 기록(HN 552pt). 요지: 컨테이너는 리눅스의 특별한 기능이 아니라 **호스트 커널이 그대로 돌리는 프로세스**에 여러 커널 기능을 겹쳐 건 것 — "트렌치코트를 입은 리눅스 기능 다섯 개". 이름을 대는 것은 **네임스페이스**(무엇이 보이나)와 **cgroups**(얼마나 쓸 수 있나)이고, 네트워크 격리는 본인도 다 이해 못 했다고 고백한다. 이미지는 디렉터리 트리이고 `chroot`/`pivot_root`로 그 폴더를 새 루트로 만든다.

**기술적으로 가장 재밌는 대목 — Go와 runc.** runc는 Go로 쓰였는데, Go 런타임은 시작하자마자 멀티스레드다. 그런데 네임스페이스 진입(`setns`) 같은 일부 시스템콜은 **단일 스레드 상태**에서 해야 한다. 그래서 runc에는 Go 런타임이 초기화되기 *전에* 도는 C 코드(`nsenter`)가 들어 있다. 또 Go에는 쓸 만한 `fork`가 없어서(fork는 호출 스레드 하나만 복사 → 다른 스레드가 쥔 락이 영원히 안 풀림) runc는 **`/proc/self/exe`를 특수 인자로 다시 실행**해 자식 프로세스를 흉내 낸다. 커널 API가 역사적으로 root를 요구해서 Docker 데몬이 root로 돌았고, 루트리스 런타임의 최대 난관은 네트워킹(사용자 공간에 네트워크 스택을 다시 구현).

**실무에 무슨 의미인가 — Spring Boot를 컨테이너로 띄울 때.**

- **JVM 메모리.** 컨테이너 안 프로세스도 호스트 커널의 `/proc/meminfo`를 보므로, 옛 JVM은 호스트 전체 메모리를 기준으로 힙을 잡아 cgroup 한도를 넘고 OOM Killer에 죽었다. JDK 10부터 `UseContainerSupport`(기본 켜짐)가 cgroup 한도를 읽고, `-XX:MaxRAMPercentage`로 한도 대비 힙 비율을 정한다 — 기본 25%는 컨테이너 전용 머신에선 보통 너무 작다.
- **PID 1.** 컨테이너의 첫 프로세스가 PID 1이 되고, PID 1은 기본 시그널 핸들러가 없어 `SIGTERM`을 무시할 수 있다. `ENTRYPOINT ["java", ...]`(exec 형식)로 JVM이 직접 PID 1이 되게 하거나 `tini`를 쓰는 이유이고, Spring Boot `server.shutdown=graceful`이 실제로 동작하려면 시그널이 JVM에 닿아야 한다.
- **보안 경계.** 같은 커널을 공유한다는 것은 커널 취약점 하나가 경계를 무너뜨린다는 뜻이다. 오늘 OpenShell이 "커널 계측"과 별개로 호스트 가상화 옵션을 두는 이유와 이어진다.

**반론·회의적 시각.** 저자 스스로 초기 단계 학습 기록이라 밝혔고, 네임스페이스 종류·overlayfs·스토리지 드라이버·네트워크(veth·브리지·slirp4netns/pasta)는 다루지 않는다. "다섯 개"의 나머지는 글에 명시되지 않았다(흔히 capabilities·seccomp·LSM 등을 꼽지만 이건 이 노트의 보충).

**브리핑 정정·보충**

1. **(정정·주의) PHP 버그의 등급은 출처마다 다르다.** 브리핑은 CVSS 9.2·"session.upload_progress의 직렬화 상태 재사용 UAF"로 적었다. 브리핑이 링크한 GeekNews 기술 분석(원문 jackalsyn.com)은 그 메커니즘(`memory_limit` 초과로 세션 인코딩이 중단되면 `BG(serialize)`가 해제된 메모리를 가리킨 채 남고, 같은 프로세스의 다음 요청이 재사용)을 PHP 8.4.4 ASan으로 재현했지만, 10/21에 스스로 **정정해 캐시 포인터 경로는 철회(CVSS 0.0), 남은 경로는 CVSS v4.0 5.3, RCE 미입증(SIGSEGV만)**이라 했고, 성립 환경을 **Apache prefork+mod_php·내장 서버**로 한정했다(FPM·CGI·LSAPI는 첫 요청 실패 시 프로세스 종료). 이건 *한 분석가의 한 경로* 재현이고, PHP 재단은 비공개 보고된 익스플로잇으로 RCE를 시연받았다고 한다. 결론은 10/23과 같다 — 패치는 하고, 등급은 내 실행 모델로 정한다. 완화책 `session.upload_progress.enabled = Off`는 multipart 파서 경로를 막지 못한다는 지적도 같이 있다.

## 더 알아볼 것

- [ ] **내 코드에 퍼즈/속성 테스트 하나를 써 본다.** jqwik(`@Property`, `@ForAll`)으로 WMS의 재고 차감 로직 같은 순수 함수에 "어떤 수량 조합에도 재고는 음수가 되지 않는다"를 적어 보고, 그것이 정형 검증 글의 "퍼즈 하니스 = 명세"와 어떻게 같은지/다른지(입력 경계 64MB 같은 *한정*이 내 테스트에는 무엇인지) 한 문단으로 적는다.
- [ ] **"verified" 라벨 읽기 연습.** `theorem-labs/oss-verify-proofs`에서 라이브러리 하나를 골라 ① 증명된 속성 ② 실행 모델 ③ 입력 경계 ④ 신뢰 기반을 표로 채우고, 그 라이브러리를 내가 x86 glibc 환경의 Java JNI로 쓴다면 어떤 보장이 *사라지는지* 표시한다.
- [ ] **Raw-RAG 기준선을 직접 만든다.** 이 Vault의 노트 몇십 개를 256토큰 창·32 겹침으로 잘라 pgvector(또는 Spring AI `SimpleVectorStore`)에 넣고 상위 128 → 리랭커 15 → LLM으로 답하게 한 뒤, 같은 노트를 "요약해서 넣은" 버전과 질문 10개로 비교한다. 리랭커를 빼면 몇 개가 틀리는지도 본다.
- [ ] **모자이크 누출을 내 RAG 설계에서 찾아본다.** 문서별 ACL 필터만 있는 구조에서, 각각 열람 가능한 두 문서를 합쳐야 나오는 "말하면 안 되는 결론"의 예를 하나 만들어 보고, 막는 방법 세 가지(검색 조합 제한·답변 판정기·문서 등급별 컨텍스트 분리)의 비용을 비교한다.
- [ ] **Spring Boot 컨테이너의 메모리·시그널을 확인한다.** `docker run -m 512m`으로 띄운 앱에서 `java -XX:+PrintFlagsFinal -version | grep -E "MaxHeapSize|MaxRAMPercentage|UseContainerSupport"`를 보고, `ENTRYPOINT`를 셸 형식과 exec 형식으로 바꿔 `docker stop` 시 graceful shutdown 로그가 찍히는지 비교한다.
