## 배경

글은 결제정산개발팀 신입이 입사 첫날 받은 5주짜리 파일럿 과제를 다룬다. 주제는 배민(CSV)과 배달이(EXCEL) 두 거래 데이터의 상태를 비교하는 배치 애플리케이션이다. 글쓴이는 배치를 처음 접해 개발 전 2일간 배치 개념과 Spring Batch를 공부했고, 대용량 처리를 웹 서버에서 하면 I/O에 자원이 몰려 사용자 요청에 지장이 생기므로 배치로 분리한다고 설명한다. 기술 스택은 Spring Batch, JPA, Gradle Multi Module, S3, Elastic Beanstalk, S3Mock.

## 핵심

- Job 3개로 분리: ① 파일 → MySQL 원천 저장, ② 배민 거래내역 Compact(성공/실패 분리 후 중복 제거), ③ 상태비교(배민 기준으로 배달이 대비 누락·상태 불일치 저장 + CSV 출력)
- Step은 chunk 방식 Reader/Processor/Writer: 여러 파일이라 `MultiResourceItemReader`(delegate는 구분자 지정한 커스텀 `FlatFileItemReader`), Processor에서 DTO → `OrderHistory` 엔티티, Writer는 `JpaItemWriter`(`EntityManagerFactory` 설정 필수)
- 비교 방식: 처음엔 모든 조건을 SQL에 넣었으나 요구사항이 늘며 쿼리가 복잡해져 반려 → DB에서 읽어 메모리에 올려 코드로 비교. 글은 데이터가 약 300만 건이라 메모리에 올려도 무리가 없었고 동시 요청을 고려하지 않아도 되는 요구사항이어서 가능했다고 단서를 단다
- `compareResultJob`은 `RunIdIncrementer`로 4개 Step(배달이 적재 → 배민 적재 → 비교 → 결과 리포트)을 순서대로 실행
- 파일 공유: API 서버(업로드/다운로드)와 배치 서버를 분리했더니 배포 후 서로 파일을 못 봄 → S3를 공유 저장소로 사용. Gradle Multi Module + Elastic Beanstalk로 모듈별 배포
- 리뷰에서 `RunIdIncrementer` 지적: 같은 JobParameter면 Job이 재실행되지 않는 것(JobKey = Job + JobParameter)이 오히려 장점(집계 중복 실행 방지)임을 깨달음. 테스트는 `JobParametersBuilder`에 현재 시간을 넣어 `launchJob()`
- 로컬·테스트가 같은 S3를 쓰는 문제는 S3Mock(findify)으로 해결: `AmazonS3Client`가 Mock을 바라보게 하고 `putInitS3Object()`에서 버킷과 초기 파일을 만들어 개발자마다 독립 저장소를 가짐
- 글에 없는 것: 실제 chunk size 값, retry/skip, restart 설정, 스케줄링 방식, 메타데이터 테이블 운영. 일부 코드(@Profile, @DependsOn 값)도 비어 있어 설계 흐름 중심으로 읽어야 한다

## 내 프로젝트와의 연결

수집기와는 구조적으로 비슷한 지점이 있다. 글은 "같은 파라미터로 재실행되지 않는 것이 장점"이라 설명하는데, 이는 수집기의 멱등성(같은 날짜·같은 소스를 다시 돌려도 중복 저장 안 됨) 문제와 같은 결을 가진다. 다만 글이 쓴 것은 Spring Batch의 JobRepository이고 수집기는 GitHub Actions + SQLite이므로, 장치가 아니라 "재실행 키를 무엇으로 정의할까"라는 질문만 옮겨올 수 있다. WMS 쪽에서는 입고·재고 대사(두 데이터 비교)나 야간 정산 배치를 만든다면 "SQL로 비교 vs 메모리 비교"의 판단 기준(데이터 규모, 동시성 요구)을 참고할 수 있다. 연결은 약한 편이다.

## 오늘 정리할 것

1. 수집기에서 "같은 실행을 다시 돌렸을 때 결과가 같은가"를 확인할 키(예: 날짜 + 소스)가 코드에 무엇인지 찾아 적어 본다
2. Spring Batch의 JobInstance가 JobKey(Job 이름 + JobParameters)로 식별되는 방식과 `RunIdIncrementer`의 역할을 공식 문서에서 확인해 3줄로 정리한다
3. 글의 "SQL에 조건을 다 넣다가 메모리 비교로 전환" 사례를 WMS 재고 대사에 대입해, 데이터 몇 건까지 메모리로 충분한지 가정을 적어 본다
4. 테스트에서 외부 저장소를 대체하는 방식(S3Mock)을 수집기의 외부 API 호출 테스트에 쓴다면 무엇으로 대체할지 한 줄 적는다
