# RAG 중복 규약

트랙 B(부트)와 트랙 S(레거시)를 폴더로 분리하면 **같은 개념을 두 번 쓰게 된다.** 이것은 의도된 중복이다 — 두 스택의 서술이 달라야 대조가 성립하기 때문이다.

문제는 나중에 Vault RAG가 붙었을 때다. "스프링 컨테이너 부팅 흐름"을 물으면 부트 노트와 레거시 노트가 둘 다 걸려서 답이 중복되거나 섞인다. 이를 막는 최소 규약이다.

## 폴더

```
기술정리/Spring/
├─ _상태/                운영 파일 (검사·동기화 제외)
├─ Boot/                 트랙 B. 접두사 `Spring Boot - `
└─ Legacy/               트랙 S. 접두사 `Spring 레거시 - `
                         대조 노트는 접두사 `Spring 대조 - ` 로 여기에
```

## 정리본 frontmatter 추가 키 3개

기존 키(`출처`·`작성일`·`tags`)에 아래를 더한다.

```yaml
개념키: spring/container-bootstrap    # 같은 개념이면 같은 값
트랙: 부트                             # 부트 | 레거시 | 대조
정본: false                            # 그룹 대표 여부
```

- **개념키** — 중복 판정의 기준. 폴더가 달라도 같은 개념이면 같은 값을 쓴다. 소문자 슬러그, `spring/` 접두
- **트랙** — 어느 스택의 서술인지
- **정본** — 같은 개념키 그룹에서 대표로 노출할 노트. 그룹당 정확히 하나

## 정본 판정 규칙

같은 개념키를 가진 노트가 여럿일 때, 아래 우선순위로 하나만 `정본: true`가 된다.

1. `트랙: 대조` 노트가 있으면 **그것이 정본** (두 스택을 모두 설명하므로)
2. 없으면 `트랙: 부트`
3. 부트도 없으면 `트랙: 레거시`

대조 노트가 새로 생기면 기존 정본을 `false`로 내리고 대조를 `true`로 올린다. 이 갱신은 기술정리 세션이 배치할 때 수행한다.

## RAG 동작 규약

- **임베딩은 전부 한다.** 내용이 실제로 다르므로 인덱싱 단계에서 버리지 않는다
- **검색 결과 후처리**에서 같은 개념키 그룹은 `정본: true` 하나만 본문으로 반환하고, 나머지는 "관련 노트" 링크로만 접는다
- 질문에 트랙이 명시되면(예: "레거시에서는 어떻게 했어?") 개념키 그룹 안에서 **해당 트랙 필터를 우선** 적용한다
- 문장 단위의 완전 중복은 DELTAMEM 잔차 판정이 이미 걸러낸다. 이 규약이 다루는 것은 **같은 개념을 다른 스택으로 서술한 의도적 중복**이다

| --- | --- | --- | --- |

| `spring/configuration` | B04·B06 | S04 | 설정 방식 |
| `spring/mvc-dispatch` | B07 | S03 | MVC 등록 |
| `spring/data-access` | B09 | S06 | 데이터 접근 |
| `spring/transaction-proxy` | B09 | S08 | 트랜잭션 프록시 |
| `spring/authentication` | B08 | S10 | 인증 방식 |
| `spring/packaging-deploy` | B13 | S01 | 패키징·배포 |
