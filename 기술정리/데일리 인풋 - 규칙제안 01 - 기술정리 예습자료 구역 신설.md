# 데일리 인풋 - 규칙제안 01 - 기술정리 예습자료 구역 신설

> 작성 세션: 데일리 인풋 세션
> 장부: [[데일리 인풋 - 규칙제안 기록]]

## 발견

사용자가 매일 아침 AI·개발 뉴스를 지메일로 받고, 그 내용을 더 깊게 분석한 노트를 Vault에 자동으로 쌓기를 요청했다. 함께 Spring 공식 문서도 하루 한 모듈씩 자동 정리해 두기를 요청했다.

현재 규칙으로는 처리할 근거가 없다.

1. **쌓을 곳이 없다.** `구역 규칙.yaml`의 어느 zone도 "외부 뉴스"를 담당하지 않는다. `AI` 구역은 KDT 학습이 담당하는 수업 노트 구역이고, `기술정리`는 "사용자가 먼저 정리한 글을 다듬은 정리본"만 받는다
2. **자동 생성물의 지위가 정의돼 있지 않다.** 지금까지 Vault의 모든 노트는 사용자가 읽고 이해한 뒤 남긴 것이다. 자동 생성 노트는 **사용자가 아직 읽지 않은 글**이므로 정리본과 같은 지위를 줄 수 없다
3. **Spring 학습 설계와 충돌한다.** `기술정리/Spring/_상태/`의 트랙 B 설계는 "사용자가 먼저 말로 요약하는 관문"이 핵심이다. 자동 생성본을 `_인박스/`에 넣으면 정리본으로 배치되어 그 관문을 무력화한다
4. **무인 세션의 쓰기 권한이 규정돼 있지 않다.** 기존 세션은 전부 사람과 대화하며 진행한다. 사람 확인 없이 파일을 만드는 세션은 처음이다

## 제안

### 1. 「예습자료」라는 새 성격 정의

`구역 규칙.yaml`의 `성격` 값에 **`예습자료`**를 추가한다.

| 성격 | 뜻 | 기존 예 |
| --- | --- | --- |
| 사실노트 | 중복 제거 대상 | 코드정리, 기술정리 정리본 |
| 학습기록 | 중복 허용 | 코드실습, 프로젝트 코드 분석 |
| 프로젝트기록 | 중복 허용, 소급 정리 제외 | 프로젝트 노트 |
| **예습자료** | **자동 생성. 사용자가 아직 읽지 않음. 정리본으로 승격되기 전 재료** | (신설) |

예습자료의 규약:

- **사람의 검증을 거치지 않았다**는 것이 이 성격의 핵심이다. 다른 노트가 예습자료를 근거로 삼지 않는다
- 정리본으로 **승격 가능**하다. 사용자가 읽고 자기 말로 정리하면 그 결과물이 정리본이 되고, 원본 예습자료는 남겨둔다(출처 추적용)
- frontmatter에 `성격: 예습자료` 키를 둔다. 검사기·RAG·Sync는 이 키로 예습자료를 식별한다
- **개념 승격 대상이 아니다.** 사용자가 이해하지 않은 내용에서 개념 노드를 뽑지 않는다

### 2. 폴더 3개 신설 — 전부 `기술정리/` 하위

`기술정리/`는 이미 고립 구역이고 "외부에서 읽은 것을 흡수하는 곳"이라는 성격이 가장 가깝다. 최상위 폴더를 새로 만들지 않는다.

| 폴더 | 담을 것 | 파일명 접두사 |
| --- | --- | --- |
| `기술정리/뉴스/` | 매일 아침 뉴스 브리핑의 심층 분석본 | `뉴스 - YYYY-MM-DD` |
| `기술정리/AI/` | 그날 뉴스 중 AI 모델·논문 한 건을 깊게 판 노트 | `AI - <주제>` |
| `기술정리/Spring/예습자료/` | 트랙 B 모듈별 공식 문서 예습 노트 | `Spring 예습 - BNN <모듈명>` |

각 폴더에 인덱스 노트를 둔다 (`뉴스 인덱스`·`AI 정리 인덱스`·`Spring 예습 인덱스`). `기술정리 MOC`의 「주제 폴더」 목록에 `뉴스`·`AI`를 추가한다.

> `기술정리/AI/`는 최상위 `AI/` 구역(KDT 수업 노트)과 **다른 폴더**다. 이름이 겹치는 것이 혼동을 부른다면 마스터 세션이 `기술정리/AI 심층/` 같은 대안을 정해도 된다 — 판단 지점에 남긴다.

### 3. 링크 규칙

`기술정리` 구역의 기존 규칙(고립·인덱스 → 잔차 트리)을 따르되, 예습자료는 잔차 판정(Root/Δ)을 **하지 않는다**. 검증 안 된 글끼리 잔차를 따지는 것은 의미가 없다.

- 뼈대: `인덱스 → 예습자료 노트` (한 칸)
- 날짜 사슬: `기술정리/뉴스/`는 이전/다음 날짜 노트를 앞뒤로 잇는다
- 가로 링크: 금지
- 폴더 바깥으로의 링크: 금지 (`기술정리` 고립 원칙 그대로). Spring day 노트 참조는 본문 서술로만
- 승격 시: 정리본 → 예습자료 **단방향** 링크 (출처 표기). 역방향은 걸지 않는다

### 4. Spring 예습자료의 진도 연동

`기술정리/Spring/_상태/학습 지도.md`의 트랙 B 표를 읽어 **아직 학습 전인 가장 빠른 번호**의 모듈을 예습한다. 학습 지도 표에 `예습` 컬럼을 하나 추가해 예습자료 링크를 남긴다.

예습자료는 **답을 주지 않는다.** 학습 세션의 요약 관문을 죽이지 않기 위해, 다음 형식을 지킨다.

- 공식 문서에서 **무엇을 다루는지**(범위·목차·핵심 용어)를 정리한다
- **결론을 대신 내려주지 않는다.** "이건 이렇게 동작한다"가 아니라 "문서는 여기서 X를 설명한다"로 쓴다
- 「학습 세션에서 확인할 것」 절에 질문 3~5개를 남긴다
- 사용자가 KDT에서 이미 다룬 모듈이면 「수업에서 안 다뤘을 만한 지점」을 짚는다

### 5. 태그

`태그 사전.md`에 영역 태그 **`뉴스`** 를 추가한다. 유형 태그는 기존 `학습`을 쓴다.

- `기술정리/뉴스/` → `tags: [학습, 뉴스]`
- `기술정리/AI/` → `tags: [학습, ai]` (기존 어휘)
- `기술정리/Spring/예습자료/` → `tags: [학습, spring]` (기존 어휘)

### 6. 무인 세션의 쓰기 권한

세션 역할 분담표에 **데일리 인풋 세션**을 추가한다.

| 항목 | 내용 |
| --- | --- |
| 실행 방식 | Cowork 스케줄 작업. 사람 없이 매일 정해진 시각에 실행 |
| 쓰기 관할 | `기술정리/뉴스/` · `기술정리/AI/` · `기술정리/Spring/예습자료/` 및 각 인덱스 |
| 금지 | 위 폴더 밖의 어떤 파일도 수정하지 않는다. 규칙 파일·정리본·MOC·학습 지도 본문에 손대지 않는다 (`학습 지도`의 예습 컬럼만 예외) |
| 커밋 | `데일리 인풋 - <날짜> <요지>` |
| 실패 처리 | 소스 수집 실패 시 그날 노트를 만들지 않는다. 빈 노트·추측 노트를 남기지 않는다 |

### 7. 노션 동기화·검사기

- **노션 동기화 제외**(`notion: false`). 검증 안 된 자동 생성물을 외부에 내보내지 않는다
- **검사기 대상 포함.** 단 잔차 판정·개념 승격 후보 탐지에서는 제외한다
- **RAG 인덱싱 포함하되 낮은 신뢰도로.** `성격: 예습자료` 키를 신뢰도 신호로 쓴다

## 판단이 필요한 지점

- `기술정리/AI/`가 최상위 `AI/` 구역과 이름이 겹친다. 그대로 둘지, 다른 이름을 쓸지
- 예습자료가 쌓이는 속도가 빠르다(하루 2~3개). 몇 달 뒤 폴더가 비대해질 때 **월별 하위 폴더**로 쪼갤지, 오래된 미열람 노트를 정리할지 — 아직 판단 이르다. 3개월 뒤 재제안 대상으로 남긴다
- 예습자료 → 정리본 승격을 **누가** 하는지. 기술정리 세션의 일로 볼지, 별도 절차를 둘지
- 무인 세션이 볼트에 쓰려면 사용자 컴퓨터가 그 시각에 켜져 있어야 한다. 꺼져 있던 날의 처리(건너뜀 / 다음 실행 때 몰아서)를 정해야 한다
