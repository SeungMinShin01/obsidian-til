# 08. AI 사용 규칙

AI(Claude, ChatGPT, Copilot, Cursor 등) 사용은 자유다. 다만 다섯 명이 각자 다른 AI를 쓰면 다섯 가지 스타일의 코드가 나온다. 이걸 막는 규칙.

## 규칙 다섯 줄

1. **리포 루트의 `CLAUDE.md`가 팀 공용 프롬프트다.** 어떤 AI를 쓰든 작업 시작 전에 이 파일 내용을 컨텍스트에 넣는다. (Claude Code는 자동, Cursor는 `.cursorrules`로 복사, ChatGPT는 첫 메시지에 붙여넣기.)
2. **AI가 짠 코드도 PR 리뷰는 똑같이 받는다.** "AI가 짜줬어요"는 설명이 아니다.
3. **본인이 설명 못 하는 코드는 병합하지 않는다.** 구두 설명 세션에서 "왜 이렇게 했어?"에 답 못 하면 다음 날까지 이해하고 다시 설명한다.
4. **새 라이브러리·의존성은 AI가 제안했어도 팀 결정을 거친다.** 결정 로그 한 장 쓰고 넣는다.
5. **용어 사전에 없는 이름이 AI 코드에 나오면 사전 먼저 고치고 코드를 고친다.** AI가 만든 이름을 그대로 두지 않는다.

## AI에게 시킬 때 좋은 것 / 나쁜 것

| 좋음 | 나쁨 |
|---|---|
| "이 컨벤션(`CLAUDE.md`)대로 OrderController 껍데기 만들어줘" | "주문 기능 만들어줘" (범위 없음, 이름 제멋대로) |
| "이 에러 원인 후보 3개 말해줘" | "이 에러 고쳐줘" 하고 결과를 이해 없이 붙여넣기 |
| "이 코드에서 N+1 생기는 지점 찾아줘" | "성능 좋게 해줘" |
| "이 결정의 대안과 트레이드오프 정리해줘" | AI가 고른 걸 결정 로그 없이 채택 |

**Spring Boot 4 주의**: AI와 블로그 예제는 대부분 Boot 3 기준이다. AI 코드에서 `spring-boot-starter-web`, `com.fasterxml.jackson.databind`, springdoc 2.x가 보이면 Boot 4 방식으로 고친다 (`09_환경_버전_통일.md`의 "Boot 4 주의사항").

## 왜 이렇게 하나

발표와 면접에서 물어보는 건 "무엇을 만들었나"가 아니라 "왜 그렇게 했나"다. AI는 "무엇"은 빠르게 만들어주지만 "왜"는 본인이 채워야 한다. 구두 설명 세션이 그 훈련이다.

# CLAUDE.md (리포 루트에 이 파일로 커밋)

아래 내용을 `CLAUDE.md`라는 이름으로 리포 루트에 둔다. 프로젝트 이름·도메인은 채워 넣는다.

```markdown
# 프로젝트: {프로젝트명}

{한 줄 설명. 예: 식품 상온 창고의 입고·재고·FEFO 출고를 관리하는 WMS}

## 스택 (버전 고정)
- Java 17, Spring Boot 4.1.1, Spring Data JPA, MySQL 8.0, Flyway
- React(최신, package-lock.json 고정), Vite, axios, Node 24
- 자세한 버전: build.gradle, package.json, docker-compose.yml 참고

## Spring Boot 4 규칙 (Boot 3 예제를 그대로 쓰지 말 것)
- 웹 starter: spring-boot-starter-webmvc (spring-boot-starter-web 아님)
- Flyway: spring-boot-starter-flyway + flyway-mysql
- Swagger: springdoc-openapi-starter-webmvc-ui 3.x
- Jackson 3: tools.jackson.* 패키지 (com.fasterxml.jackson.databind 아님). 애노테이션(@JsonFormat 등)만 com.fasterxml.jackson.annotation
- ddl-auto는 validate. 스키마 변경은 Flyway 마이그레이션 파일로만

## 코드를 쓸 때 반드시 지킬 것
- 패키지: domain/{도메인}/controller|service|repository|entity|dto, 공통은 global/
- 컨트롤러에 로직 금지. 엔티티를 컨트롤러 밖으로 내보내지 않는다 (DTO 변환).
- 응답은 항상 global.response.ApiResponse<T>로 감싼다.
- 예외는 BusinessException(ErrorCode)만 던진다.
- 상태값은 enum(EnumType.STRING). 문자열 상태 금지. 상태 변경은 엔티티의 행동 메서드 안에서만.
- 엔티티에 @Setter 금지. 연관관계 @ManyToOne(LAZY) 단방향.
- 재고(stock) 수량은 StockService로만 바꾼다.
- 프론트: 컴포넌트에서 직접 axios 호출 금지, api/{도메인}.js를 거친다.
- 새 의존성 추가 금지. 필요하면 제안만 하고 사람이 결정한다.

## 네이밍
- 엔티티 단수 PascalCase / 테이블·컬럼 snake_case
- DTO: {도메인}{동작}Request, {도메인}Response
- 메서드: create / get / getList / update / delete
- boolean: is/has 접두. 상수 UPPER_SNAKE
- 프론트: 컴포넌트 PascalCase, 훅 useXxx, 핸들러 handleXxx, props 콜백 onXxx

## 용어 사전 (한 개념 = 한 단어. 여기 없는 단어는 새로 만들지 말고 물어볼 것)
(docs/용어사전.md의 엔티티 표를 붙여 넣는다)

## API 규칙
- /api/v1/{복수명사}, kebab-case, 동사 금지 (상태 변경은 PATCH /{id}/{행동})
- 목록: page, size, sort 파라미터. 응답 content/page/size/totalElements/totalPages
- 날짜 ISO 8601, 금액 정수, enum 대문자 문자열

## 응답 형식
{ "success": true, "data": {...}, "message": null }
{ "success": false, "data": null, "message": "...", "code": "ORDER_001" }

## 작업 방식
- 코드를 만들 때 왜 그렇게 했는지 한두 줄 설명을 함께 준다.
- 대안이 있으면 대안과 트레이드오프를 먼저 말하고, 선택은 사람이 한다.
- 파일을 통째로 다시 쓰지 말고 바뀌는 부분만 보여준다.
```
