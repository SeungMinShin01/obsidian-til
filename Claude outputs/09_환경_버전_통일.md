# 09. 환경 구축 · 버전 통일

> 버전 통일은 말로 하지 않는다. **파일로 한다.** 리포에 커밋된 파일이 곧 규칙이다.
> 확정 버전 (2026-09-18): **Java 17 · Spring Boot 4.1.1 · MySQL 8.0 · Node 24 · React 최신(lock 고정)**

## 버전을 고정하는 파일

| 대상 | 버전 | 고정하는 파일 | 비고 |
|---|---|---|---|
| Java | **17** | `build.gradle` → `java { toolchain { languageVersion = JavaLanguageVersion.of(17) } }` | 로컬 JDK가 달라도 Gradle이 맞춘다. Boot 4는 Java 17 이상이면 동작 |
| Spring Boot | **4.1.1** | `build.gradle` → plugins 버전 | 팀 전원 동일. 아래 "Boot 4 주의사항" 필독 |
| Gradle | wrapper | `gradle/wrapper/gradle-wrapper.properties` | `./gradlew`만 쓴다. 로컬 gradle 금지 |
| Node | **24** | `.nvmrc`(`24`) + `package.json`의 `engines` | `nvm use`로 맞춤. Vite는 Node 20.19+ / 22.12+ 필요 → 24는 충족 |
| React / npm 패키지 | 최신으로 설치 후 고정 | `package-lock.json` 커밋 | 설치는 `npm ci`. `npm install`은 의존성 추가할 때만 |
| DB | **MySQL 8.0** | `docker-compose.yml` → `image: mysql:8.0` | 로컬 설치 MySQL 버전과 무관. 컨테이너로 전원 동일 |
| Redis (필요 시) | — | `docker-compose.yml`에 추가 | 필요할 때 |
| 코드 스타일 | — | `.editorconfig`, Spotless 설정, `.prettierrc`, `.eslintrc` | 에디터 무관하게 동일 |
| 에디터 | — | `.vscode/settings.json`, IntelliJ `.idea/codeStyles/` 커밋 | — |

## Spring Boot 4 주의사항 (블로그·AI 예제는 대부분 Boot 3 기준이다)

| 달라진 것 | 이렇게 쓴다 |
|---|---|
| 웹 starter 이름 | `spring-boot-starter-web` ❌ → **`spring-boot-starter-webmvc`** |
| Flyway | `flyway-core`만으로는 자동 설정 안 됨 → **`spring-boot-starter-flyway`** + MySQL용 **`flyway-mysql`** |
| Swagger (springdoc) | 2.x는 Boot 3용 → **`springdoc-openapi-starter-webmvc-ui:3.x`** |
| Jackson 3 | `com.fasterxml.jackson.databind.*` ❌ → **`tools.jackson.*`** (`ObjectMapper` 등). `@JsonFormat` 같은 애노테이션은 `com.fasterxml.jackson.annotation` 그대로 |
| 테스트 starter | 기술별로 분리 (예: `spring-boot-starter-webmvc-test`). Initializr 구성을 따른다 |

## build.gradle 의존성 (Initializr로 생성한 뒤 이것과 비교)

```groovy
dependencies {
    implementation 'org.springframework.boot:spring-boot-starter-webmvc'
    implementation 'org.springframework.boot:spring-boot-starter-validation'
    implementation 'org.springframework.boot:spring-boot-starter-data-jpa'
    implementation 'org.springframework.boot:spring-boot-starter-security'
    implementation 'org.springframework.boot:spring-boot-starter-flyway'
    implementation 'org.flywaydb:flyway-mysql'
    implementation 'org.springdoc:springdoc-openapi-starter-webmvc-ui:3.1.1'
    runtimeOnly    'com.mysql:mysql-connector-j'
    compileOnly    'org.projectlombok:lombok'
    annotationProcessor 'org.projectlombok:lombok'
    testImplementation 'org.springframework.boot:spring-boot-starter-webmvc-test'
}
```

새 의존성은 팀 결정 후 추가한다(08 규칙 4).

## docker-compose.yml (뼈대에 포함)

```yaml
services:
  db:
    image: mysql:8.0
    ports: ["3307:3306"]          # 로컬에 MySQL이 깔려 있어도 겹치지 않게 3307
    environment:
      MYSQL_ROOT_PASSWORD: root
      MYSQL_DATABASE: wms_db
      TZ: Asia/Seoul
    command: --character-set-server=utf8mb4 --collation-server=utf8mb4_unicode_ci
    volumes: ["db-data:/var/lib/mysql"]
volumes:
  db-data:
```

`docker compose up -d` 한 줄로 전원 같은 DB. 각자 자기 노트북에서 띄우며 서로 연결되지 않는다(데이터 공유 없음). 초기화는 `docker compose down -v`.

## 설정 파일 분리

```
application.yml              # 공통. 커밋 (ddl-auto: validate, open-in-view: false, flyway 경로)
application-local.yml        # 로컬 DB 접속 (localhost:3307/wms_db, root/root). 커밋 — docker 기준이라 비밀 없음
application-prod.yml         # 배포용. 커밋하되 비밀값은 환경변수 ${DB_PASSWORD}
.env                         # 프론트 환경변수. .gitignore
.env.example                 # 키 이름만. 커밋
```

- **`spring.jpa.hibernate.ddl-auto: validate`** — 스키마는 Flyway(`db/migration/V1__…`, `V2__…`)만 만든다. `update`/`create` 금지
- 샘플 데이터 `db/sample/sample_data.sql`은 Flyway 경로 밖, 수동 실행

**비밀번호·토큰·키는 절대 커밋하지 않는다.** 첫날 `.gitignore`를 전원 확인.

## 전원 확인 (10분)

1. `git clone` → `docker compose up -d` → `./gradlew bootRun` → 로그에 Flyway V1·V2 적용 → `http://localhost:8080/swagger-ui.html` 열림
2. (S1) `npm ci` → `npm run dev` → 화면 열리고 헬스체크 API 응답이 화면에 뜸
3. 저장하면 자동 포맷됨
