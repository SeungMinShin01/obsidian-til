# 코드실습 - 자료구조 속도 체감

## 미션

List와 Set에 문자열 10만 개를 채우고, 존재하지 않는 값으로 `contains`를 반복 호출해 걸리는 시간을 비교한다.

## 코드 원문

```java
import java.util.ArrayList;
import java.util.HashSet;
import java.util.List;
import java.util.Set;

public class practice1 {
    public static void main(String[] args) {
        List<String> list1 = new ArrayList<>();
        Set<String> list2 = new HashSet<>();
        for (int i = 0; i < 100000; i++) {
            list1.add("" + i);
            list2.add("" + i);
        }
        System.out.println("시작");
        long start = System.nanoTime();
        for (int i = 0; i < 10000; i++) {

            list1.contains("target");
            if (i == 9999) {
                long end = System.nanoTime();
                System.out.println((end - start) / 1_000_000.0 + "ms");
            }

        }
        System.out.println("2번쨰 시작");
        start = System.nanoTime();
        for (int i = 0; i < 10000; i++) {

            list2.contains("target");
            if (i == 9999) {
                long end = System.nanoTime();
                System.out.println((end - start) / 1_000_000.0 + "ms");
            }

        }
    }
}
/*
 * List는 배열(또는 연결된 순서)을 앞에서부터 하나씩 equals()로 비교하며 훑는다.
 * 찾는 값이 없으면(최악의 경우) 끝까지 다 훑어야 끝난다 -> 데이터 개수(n)에 비례해서 느려짐 = O(n)
 * 반대로 찾는 값이 맨 앞에 있으면 1번 비교로 끝나서 오히려 HashSet보다 빠를 수 있음 (best case O(1))
 * HashSet은 순서대로 비교하지 않는다.
 * "target" 문자열을 hashCode()로 정수 하나로 계산 -> 그 정수로 내부 배열의 칸 번호를 계산 -> 그 칸으로 바로 점프
 * 값이 어디 있든(맨 앞이든 없는 값이든) 이 계산+점프 과정은 거의 항상 같은 비용 -> 데이터 개수(n)와 거의 무관 = O(1)
 * (단, 서로 다른 문자열이 같은 칸으로 계산되는 "충돌"이 생기면 그 칸 안에서만 equals로 추가 확인)
 */
```

## 실행 결과

- List: 5555.4395ms
- Set: 0.4834ms
- List가 Set보다 약 11500배 느림 — 데이터 10만 개에서 "존재하지 않는 값"을 찾을 때 O(n) vs O(1) 차이가 그대로 드러남

## 고치면 좋은 점

- 측정을 1번만 돌렸다. `성능 측정 도구` 노트의 원칙대로 "한 번 재고 결론 내지 않는다 — 여러 번 돌린 평균으로 말한다"를 적용하면, 같은 측정을 3~5회 반복해 평균을 내는 게 좋다. 특히 첫 실행은 JIT 워밍업 때문에 유독 느리게 나올 수 있어 한 번의 숫자만으로는 오차가 섞일 수 있다
