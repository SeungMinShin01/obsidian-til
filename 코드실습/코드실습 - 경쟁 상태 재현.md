# 코드실습 - 경쟁 상태 재현

## 미션

스레드 2개가 같은 카운터의 `count++`를 각각 1000번씩 호출하게 하고, synchronized 없이/있이 결과를 비교한다.

## 코드 원문

```java
public class pracitce2 {
    public static void main(String[] args) throws InterruptedException {
        // 경쟁상태 재현
        Increase i1 = new Increase();
        Thread t1 = new Thread(() -> {
            for (int i = 0; i < 1000; i++) {
                i1.Increase();
            }
        });
        Thread t2 = new Thread(() -> {
            for (int i = 0; i < 1000; i++) {
                i1.Increase();
            }
        });
        t1.start();
        t2.start();
        t1.join();
        t2.join();
        System.out.println("실제값: " + i1.count);

    }
}

class Increase {
    public int count;

    public synchronized void Increase() {
        count++;
    }
}

/*
 * 경쟁 상태
 *
 * count++는 3단계다: 읽기 → +1 계산 → 쓰기.
 *
 * 두 스레드가 각자 이 3단계를 도는데, 한 스레드가 쓰기 전에 다른 스레드가 같은 값을 읽어버리면 증가 하나가 증발한다. 예:
 *
 * count=100
 * A: 읽음(100)
 * B: 읽음(100) ← A가 아직 안 썼는데 겹침
 * A: 101 씀
 * B: 101 씀 ← 원래 102여야 하는데 101에 그침
 *
 * 이게 2000번 도는 동안 랜덤한 타이밍에 여러 번 발생 → 최종 count가 2000보다 작고, 실행마다 값이 다름. 스레드 종료
 * 타이밍과는 무관.
 *
 * synchronized
 *
 * increase()에 붙이면, 호출 한 번(읽기→+1→쓰기 전체)이 끝날 때까지 다른 스레드는 그 메소드에 못 들어오고 대기한다.
 * 2000번의 호출이 겹치지 않고 한 번에 하나씩 순서대로 처리됨 → 항상 2000 나옴. 스레드 종료를 기다리는 게 아니라 메소드 호출
 * 단위로 잠그는 것.
 */
```

## 실행 결과

- synchronized 없이 실행: 2000이 아닌 값이 나옴 (실행마다 다름) — 경쟁 상태 직접 확인함
- synchronized 적용 후(현재 코드): 항상 2000

## 고치면 좋은 점

- 메소드 이름이 `Increase()`로, 클래스명 `Increase`와 완전히 같고 대문자로 시작한다. `JAVA 클래스 문법` 노트의 관례 "변수·메소드는 소문자 시작 카멜 표기"를 따르면 `increase()`가 맞다. 지금 이름 그대로면 `new Increase()`(생성자 호출)와 헷갈리기 쉽다
