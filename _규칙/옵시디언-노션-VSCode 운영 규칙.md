# 옵시디언 · 노션 · VSCode 운영 규칙

## 0. 원칙

**옵시디언이 원본(Single Source of Truth)입니다.**
노션은 옵시디언의 거울이고, VSCode는 읽기 전용 입력원입니다.

```
VS Code (읽기 전용)
   ↓ 분석
Claude              ← 노트를 쓰는 주체
   ↓ 작성
Obsidian Vault      ← 원본 (Single Source of Truth)
   ↓ 미러링
Node.js Sync Engine ← 동기화 담당
   ↓
Notion (거울)
```

**최초 구축이 끝난 뒤 Claude는 노션 미러링에 개입하지 않습니다.** Claude의 담당 구간은 `VS Code → Obsidian`까지입니다.

## 1. 원본 보존

직접 쓴 노트에 손댈 수 있는 범위는 다음과 같습니다.

| 구분 | 가능 여부 |
| --- | --- |
| **디자인·형식 정리** — 제목 계층, 표 정리, 코드블록 언어 지정, 들여쓰기, 오탈자 | **가능** |
| **추가 설명** — 기존 내용 아래·옆에 보충 설명, 예시, 링크 덧붙이기 | **가능** |
| **문맥 정리** — 문장 연결, 순서 재배치, 중복 문장 정리 | **가능** |
| **내용 삭제** — 원래 있던 설명·코드·판단을 지우기 | **불가** |
| **의미 변경** — 원래 쓴 내용의 뜻을 바꾸기 | **불가** |

- **덜어내지 않고 더하는 방향**으로만 고칩니다. 형식은 다듬되 원래 담긴 내용은 남깁니다
- 원래 내용이 사실과 다르면 지우지 말고 **아래에 보충**합니다
- 위 표에서 "불가"에 해당하는 수정이 필요하면 **먼저 보고하고 승인을 받습니다**
- VS Code 코드처럼 대응하는 원본 노트가 없으면 → 새 파일로 만듭니다

## 2. 폴더 구조

```
Vault/
├── Java/                    day01~09 + 주제별 심화
├── Python/
├── JavaScript/              day02~14 + 과제
├── HTML/                    day02, 04, 15
├── CSS/                     day05~15
├── RPA/
├── AI/
├── CS 이론/                 SQL day01~03 + 정보처리기사
├── 프로젝트 코드 분석/        이전에 진행한 실제 프로젝트 (KDT 학습코드 제외)
├── _규칙/                   이 문서
└── KDT_2026 학습 지도.md     최상위 허브
```

- **폴더 제목에 이모지를 붙이지 않습니다.**
- 언어 폴더는 언어명 그대로 (`JS` 아닌 `JavaScript`)
- 새 언어·주제가 생기면 최상위에 폴더를 추가하고, 노션에도 같은 이름으로 만듭니다.
- **`프로젝트 코드 분석/`은 부트캠프 학습 코드가 아니라 실제 프로젝트 전용**입니다.

## 3. 노트 종류와 이름 규칙

| 종류 | 형식 | 예 |
| --- | --- | --- |
| 허브 (MOC) | `<주제> MOC.md` | `Java MOC.md` |
| 최상위 허브 | `<저장소> 학습 지도.md` | `KDT_2026 학습 지도.md` |
| 학습 일자별 | `<언어> day<NN> <주제>.md` | `JS day11 DOM 조작.md` |
| 주제별 심화 | `<주제>(분석).md` | `CSS 배경(분석).md` |
| 이관본 | `<주제>(이관).md` | `Python 코드 해석 문제(이관).md` |
| 사용자 원본 | 원래 이름 그대로 | `day03` |
| 프로젝트 분석 | `<프로젝트명> <관점>.md` | `쇼핑몰 코드 리뷰.md` |

## 4. 노트 앞머리(frontmatter)

모든 Claude 작성 노트는 다음을 포함합니다.

```yaml
---
출처: Claude 분석
원본: KDT_2026/2026_FE/day11
작성일: 2026-08-10
tags: [javascript, day11, DOM]
---
```

`출처` 값은 `Claude 분석` / `내가 작성` / `이관` 셋 중 하나이며, 노션 DB의 `출처` 속성과 1:1 대응합니다.

## 5. 그래프뷰 연결 규칙

옵시디언 그래프뷰에서 관련 노트가 뭉치도록 **위키링크로 반드시 엮습니다.**

**① 모든 day 노트는 상하 링크를 갖습니다**
```markdown
> 허브: [[Java MOC]] · 이전: [[Java day03 연산자]] · 다음: [[Java day05 클래스와 인스턴스]]
```

**② 문서 맨 아래에 `## 관련 노트` 섹션을 둡니다**
```markdown
## 관련 노트
[[Java MOC]] · [[Java day03 연산자]] · [[JS day04 조건문]] · [[KDT_2026 학습 지도]]
```

**③ MOC는 소속 노트를 전부 링크합니다** (표 형태 권장)

**④ 언어 간 대응 관계를 명시적으로 링크합니다**
```
Java 배열       ↔  JS 배열
Java 클래스     ↔  JS 객체
Java 콘솔 게시판 ↔  JS localStorage 게시판
SQL JOIN        ↔  JS 배열 조인
CSS 선택자      ↔  JS querySelector
```
이 교차 링크가 그래프뷰에서 언어 덩어리들을 이어주는 다리 역할을 합니다.

**그래프뷰에서 언어를 갈라 보는 것은 링크가 아니라 태그·Groups로 처리합니다.** 링크는 의미 관계를 그대로 두고, 시각적 분리는 그래프뷰 설정에서 합니다. → 11항

**⑤ 본문 중간에서 개념을 언급할 때도 링크를 겁니다**
```markdown
→ [[CSS day08 flexbox]] 참고
```

## 6. 문체 규칙

노트는 **한 사람이 공부하며 직접 정리한 것처럼** 씁니다. 남이 쓴 코드를 평가하는 말투를 쓰지 않습니다.

| 쓰지 않음 | 대신 |
| --- | --- |
| 주석이 정확합니다 | 정리하면 이렇습니다 |
| ~하신 게 좋습니다 | ~하는 편이 안전합니다 |
| 이미 쓰셨습니다 / 적으신 | (2인칭 자체를 쓰지 않음) |
| 이 저장소에서 가장 ~ | 지금까지 만든 것 중 ~ |
| 잘한 점 / 인상적입니다 | (평가하지 않음) |

- 2인칭(하신·쓰셨·적으신·만드신)을 쓰지 않습니다
- 원본 코드의 오류·오타는 기록하지 않습니다. 필요하면 파일을 지목하지 않고 일반 주의사항으로 씁니다
- 문체를 노트 전체에서 일정하게 유지합니다

### 폴더별 형식

| 폴더 | 형식 | 템플릿 |
| --- | --- | --- |
| 언어별 폴더 (Java, JS, CSS, HTML, CS 이론 …) | **학습노트** — 배운 내용 → 활용법 → 심화 | `_템플릿/학습노트 템플릿.md` |
| `프로젝트 코드 분석/` | **개발자 일지** — 목표 → 살펴본 것 → 판단·근거 → 막힌 것 | `_템플릿/프로젝트 분석 템플릿.md` |

## 7. 학습노트의 3단 구성

VSCode 코드를 분석할 때는 항상 이 순서를 지킵니다.

1. **배운 내용 정리** — 코드에서 실제로 다룬 개념
2. **추가로 알면 좋은 활용법** — 실무 관용구, 함께 쓰면 좋은 문법
3. **더 나아가 알면 좋은 것** — 다음 단계 기술, 심화 키워드

**원본 코드의 오류·오타·버그는 지적하지 않습니다.** 개념 설명에 필요한 경우에는 특정 파일을 지목하지 않고 일반적인 주의사항으로 서술합니다.

마지막에 **참고한 원본 파일 목록**과 **관련 노트**를 반드시 남깁니다.

## 8. VSCode 취급 규칙

- **읽기 전용.** 코드를 직접 수정하지 않습니다.
- 읽는 범위: `exam/` 폴더 우선, 그리고 `.txt` · 확장자 없는 노트 파일 전부 포함
- **원본 코드의 오류·오타는 기록하지 않습니다.** 학습에 필요한 일반 주의사항만 서술합니다
- `bin/`, `.class`, `node_modules`, `assets/`(바이너리)는 읽지 않습니다

## 8.5 GitHub 백업 (obsidian-git 담당)

- 원격: `github.com/SeungMinShin01/obsidian-til` (Public)
- **자동**: obsidian-git이 30분마다 commit-and-sync (`vault backup: {{date}}`), 옵시디언 시작 시 pull
- **작업 단위**: Claude는 작업을 마칠 때마다 의미 있는 메시지로 커밋을 남긴다 (예: `SQL day04 노트 추가`). 푸시는 가능하면 즉시, 아니면 다음 자동 동기화에 편승
- 제외 목록은 `.gitignore` 참고 — `workspace.json` · `.smart-env/` · `.trash/` · `_규칙/sync-config.json`
- 노션 미러(9항)와 독립적으로 동작한다. 노션은 보기용 거울, GitHub은 원본의 백업·이력

## 9. 노션 동기화 (Node.js Sync Engine 담당)

- **방향: 옵시디언 → 노션 단방향**
- 담당: Node.js Sync Engine. Claude는 개입하지 않습니다
- 상세 사양: [[Sync Engine 명세]] / 설정값: `_규칙/sync-config.json`
- 노션은 **폴더 구조가 아니라 Master DB 한 개**로 통합되어 있습니다. Vault 폴더명은 `Category` 속성이 됩니다

### 노션 구조

```
정리본 (루트)
├── Dashboard              ← 진입점. 뷰·통계 모음
├── Knowledge Base
│   └── Notes Master (DB)  ← 모든 노트가 행으로 저장
└── Programmars            ← 동기화 대상 아님. 기존 유지
```

기존 언어별 폴더(Java, Python 등)는 Master DB로 통합되었으므로 삭제해도 됩니다.

## 10. 기존 노션 콘텐츠 취급

- 기존 페이지의 **내용은 절대 삭제하지 않습니다.**
- 다른 폴더로 재분류한 경우, 원본 제목 뒤에 표시만 남깁니다.
  - 전부 옮긴 경우: `(이동됨)`
  - 일부만 발췌한 경우: `(일부 발췌됨)`
- 실제 삭제는 사용자가 노션 앱에서 직접 합니다.
- 이 재분류는 **1회성 작업**이며, 이후 정기 동기화에서는 기존 콘텐츠를 건드리지 않습니다.
