# 개념 - 싱글톤

여러 노트에 걸쳐 반복해서 나온 개념을 모아둔 관문 노트다. 각 지점에서 이 노트로 들어오고, 이 노트에서 다른 지점으로 나간다.

## 뜻

**클래스의 인스턴스를 프로그램 전체에 하나만 두는 패턴**이다. 세 줄이 골격이다.

```java
public class BoardDAO {
    private BoardDAO() { }                                    // 1. 외부 생성 차단
    private static final BoardDAO instance = new BoardDAO();  // 2. 하나만 미리 생성
    public static BoardDAO getInstance() { return instance; } // 3. 그 하나를 반환
}
```

- `private` 생성자 — 밖에서 `new BoardDAO()`를 못 하게 막는다
- `static final` 필드 — 클래스에 딱 하나, 바꿔치기 불가
- `getInstance()` — 그 하나를 꺼내 쓰는 유일한 통로

## 왜 필요한가

저장소(DAO)가 데이터를 들고 있기 때문이다. `new BoardDAO()`를 여러 번 하면 리스트가 여러 개 생겨서, 저장한 글이 사라진 것처럼 보인다. **저장소는 프로그램 전체에 하나여야** 한다. 그래서 저장·조회 계층은 싱글톤으로 만들고, 계층 간 연결도 `getInstance()`로 잇는다.

```java
private BoardController bc = BoardController.getInstance();  // View 안에서
private BoardDAO bd = BoardDAO.getInstance();               // Controller 안에서
```

## 함께 보면 좋은 것

- 손으로 만든 `getInstance()`를 프레임워크가 대신해 준다 — 스프링 빈은 기본이 싱글톤이고, `@Autowired` 의존성 주입이 `getInstance()` 호출 자리를 대신한다. 직접 만들어 본 경험이 있어야 프레임워크가 무엇을 해주는지 보인다
- 조립을 한 곳에 모으는 `AppConfig`의 `static final` 싱글톤이 [[Repository Pattern]]에서 "new는 여기서만 한다"로 이어진다
