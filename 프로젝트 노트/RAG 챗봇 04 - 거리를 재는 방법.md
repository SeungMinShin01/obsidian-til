# RAG 챗봇 04 - 거리를 재는 방법

> 허브: [[RAG 챗봇 프로젝트 MOC]]

**물어본 것:** 숫자 배열 두 개를 놓고 "가깝다"를 어떻게 재는가.

## 1. 배운 내용

### 1-1. 후보는 둘

**유클리드 거리** — 두 점 사이의 직선 거리. 흔히 아는 그 거리다.

**코사인** — 두 화살표가 벌어진 **각도**를 본다. 길이는 보지 않는다.

이 구조는 코사인을 쓴다. 컬렉션을 만들 때 지정한다.

### 1-2. 왜 각도인가

임베딩 벡터는 원점에서 뻗어나간 화살표로 보는 것이 맞고, 의미를 담고 있는 것은 **방향**이지 길이가 아니다.

2차원으로 줄여 보면 분명해진다. `(3, 4)` 와 `(6, 8)` 은 방향이 완전히 같다. 뒤엣것은 앞엣것을 2배 늘린 것뿐이다. 유클리드로 재면 꽤 멀지만 각도로 재면 0도, 즉 같다.

이것이 중요한 이유는 길이가 의미가 아니라 **분량이나 강조를 반영하는 경향**이 있기 때문이다.

```
"동작 전압 2.3~5.5V"                     <- 짧다
"이 소자의 동작 전압은 2.3V에서 5.5V이다"  <- 길다
```

같은 말인데 길이가 다르다. 유클리드로 재면 이 차이가 거리에 섞여 들어간다. 각도로 재면 **무슨 얘기를 하고 있는가만 남는다.**

### 1-3. 계산하는 법

각도를 구하는 것이 아니라 코사인 값을 바로 구한다.

```
cos(A, B) = (A · B) / (|A| × |B|)
```

분자는 **내적** — 같은 자리끼리 곱해 전부 더한다.

```
A · B = a1*b1 + a2*b2 + ... + a1536*b1536
```

분모는 각 벡터의 길이다. 길이로 나누는 것이 **길이 영향을 지우는** 동작이다.

| 코사인 값 | 각도 | 뜻 |
| --- | --- | --- |
| 1 | 0도 | 방향이 같다 = 의미가 같다 |
| 0 | 90도 | 서로 무관하다 |
| -1 | 180도 | 정반대 |

### 1-4. 유사도를 거리로 뒤집는다

검색 결과에 나오는 것은 유사도가 아니라 **거리**다. 작을수록 가깝다로 정렬이 자연스러워지기 때문이다.

```
코사인 거리 = 1 - 코사인 유사도
```

| 유사도 | 거리 | 상태 |
| --- | --- | --- |
| 1.0 | 0.0 | 같은 의미 |
| 0.7 | 0.3 | 꽤 관련 있음 |
| 0.0 | 1.0 | 무관 |
| -1.0 | 2.0 | 정반대 |

범위가 0에서 2다. 상한 0.75는 **유사도 0.25 이상만 통과**시킨다는 뜻이다. 실제 감각은 대략 0.2~0.4면 잘 찾은 것, 0.8 이상이면 거의 무관이다.

### 1-5. 이론과 구현이 만나는 두 지점

**정규화된 벡터면 나눗셈이 필요 없다** — 임베딩 모델이 길이 1짜리 벡터를 돌려주면 분모가 1이라 **내적만 계산해도 코사인이 된다.** 그런데도 코사인으로 설정해두는 것은, 나중에 정규화되지 않은 모델로 바꿔도 안 깨지게 하려는 것이다. 그때 설정 고치는 것을 잊으면 거리 값이 조용히 이상해진다.

**전부와 재면 느리다** — 질문 하나에 저장된 조각 전부와 계산하면 조각 수만큼 곱셈이 늘어난다. 그래서 벡터 DB가 근사 최근접 이웃 색인을 쓴다. 전부 재는 대신 가까울 법한 후보만 추려서 잰다.

### 1-6. 거리는 절대 척도가 아니다

`0.4` 라는 값이 "관련 있음"을 뜻한다는 보장이 없다. 이 숫자는 다음에 따라 통째로 움직인다.

- 어떤 임베딩 모델을 썼는가
- 질문과 문서의 **언어가 같은가**
- 문서가 어떤 분야인가 — 전문 용어가 빽빽한 문서는 조각들이 서로 다 비슷해져 거리가 좁게 모인다

그래서 상한 값은 **이론에서 나오는 값이 아니라 실측해서 정하는 값**이다. 질문 20~30개를 던져 정답 조각의 거리와 엉뚱한 조각의 거리가 어디서 갈라지는지 보고 그 사이에 선을 긋는다.
