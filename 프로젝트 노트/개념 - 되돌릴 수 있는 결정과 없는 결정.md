# 개념 - 되돌릴 수 있는 결정과 없는 결정

프로젝트 여러 곳에서 같은 판단이 반복돼 개념으로 뺀 노트다. 「지금 정할 일인가, 겪고 정할 일인가」를 가르는 축이다.

## 1. 무엇인가

> 되돌릴 수 있는 것은 겪은 뒤에 정한다. **되돌릴 수 없는 것만 지금 확정한다.**

결정을 두 종류로 나눈다.

| 종류 | 성격 | 다루는 법 |
| --- | --- | --- |
| **되돌릴 수 있는 결정** | 나중에 바꿔도 비용이 작다 | 관측하고 정한다. 미리 정하면 대개 틀린다 |
| **되돌릴 수 없는 결정** | 한 번 지나가면 복구가 안 된다 | 시작 전에 확정한다. 이것만 미리 한다 |

미리 만든 유연성은 대개 쓰이지 않고 정작 필요한 형태는 다르다. 그래서 되돌릴 수 있는 것은 전부 미룬다 — 미루는 것이 게으름이 아니라 **더 나은 정보를 기다리는 것**이다.

이 판단은 아마존의 「1방향 문과 2방향 문」(one-way / two-way door)이라는 이름으로도 알려져 있다. 2방향 문은 다시 나올 수 있으니 빨리 통과하고, 1방향 문 앞에서만 신중해진다.

## 2. 이 프로젝트에서 되돌릴 수 없는 것

한 줄로 요약된다.

> 판정 로직은 나중에 바꿔도 되지만, **수집하지 않은 데이터는 영원히 얻을 수 없다.**

오늘 받아오지 않은 공고는 내일이면 사라진다. 그래서 원문 수집만 지키면 나머지 결정은 전부 유예할 수 있다.

## 3. 같은 판단이 나온 자리들

| 어디 | 판단 | 방향 |
| --- | --- | --- |
| 재공고 스키마 | 원문을 보존하니 해시는 나중에 다시 계산 가능 | 유예 |
| 인증키 | 커밋되면 git 이력에 남는다 | **먼저 확정** |
| 크롤링의 법적 판단 | 법적 문제는 겪고 고칠 수 없다 | **먼저 확정** |
| 개인정보 필드 | DB에 있는 것 자체가 보유 | **먼저 확정** — 스키마에서 배제 |
| 실행 빈도 | 언제든 올릴 수 있다 | 낮게 시작 |
| 서버 필터 | `ncsCdLst`로 좁히면 그 밖은 영영 안 온다 | **넓게 받는다** — 거르기는 저장 후 |
| 원문 `raw` 저장 | 컬럼에 없는 필드도 나중에 꺼낼 수 있다 | 전부 담는다 |
| 옛 DB 삭제 | 가짜 3건뿐인 마지막 시점 | 공짜 재시작 — 지금만 가능 |
| 12일의 공백 | 그 사이 마감된 공고는 없다 | **손해로 겪은 첫 사례** |

여덟 번째까지는 원칙을 지켜서 얻은 것이고, 마지막은 원칙을 어겨서 잃은 것이다. 둘 다 같은 축 위에 있다.

## 4. 판정 기준

결정 앞에서 이 질문 하나를 던진다.

> **이걸 틀리게 정하면, 나중에 무엇으로 복구하는가.**

- 코드를 고치면 된다 → 되돌릴 수 있다 → 미룬다
- 데이터를 다시 받으면 된다 → 그 데이터가 그때도 있는가 → 없으면 되돌릴 수 없다
- 복구 방법이 없다 → 지금 확정한다

## 5. 관측 후 결정의 실제 이득

서버 필터를 안 걸고 전부 받은 뒤 분포를 봤더니, 개발 공고가 정보통신(8건)보다 보건.의료·연구·사무 분류에 더 많이 흩어져 있었다. 미리 정했다면 추측이었고 관측하고 정하니 근거가 됐다. **미룬 결정이 더 정확한 결정이 된다.**

## 6. 다른 축과의 관계
