# 개념 - 멱등성

여러 노트에 걸쳐 반복해서 나온 개념을 모아둔 관문 노트다. 각 지점에서 이 노트로 들어오고, 이 노트에서 다른 지점으로 나간다.

## 뜻

**같은 작업을 몇 번 실행해도 결과가 같고, 두 번째부터 실패하지 않는 성질**이다. idempotent를 옮긴 말이다.

수학에서 온 개념이다. 어떤 연산을 여러 번 적용해도 한 번 적용한 것과 결과가 같으면 멱등이라고 한다. 절댓값이 그렇다. `abs(abs(-3))`은 `abs(-3)`과 같다.

## 무인 시스템에서 왜 중요한가

매일 자동으로 도는 프로그램은 **같은 코드가 90번 실행된다.** 첫 실행에서만 통하는 코드는 둘째 날 죽는다.

그리고 무인 운영에서는 죽는 것보다 나쁜 상황이 있다. **정상적인 재실행이 실패로 보고되는 것**이다. 알림이 늑대소년이 되면 진짜 장애를 놓친다.

그래서 판단 기준은 이렇게 된다.

> **이미 되어 있으면 아무것도 하지 않는다. 그리고 그것은 실패가 아니다.**

## 이 프로젝트에서 나타난 지점

| 지점 | 코드 | 없으면 |
| --- | --- | --- |
| [[수집기 05 - main.py 코드 분석]] | `mkdir(exist_ok=True)` | 둘째 날 "폴더가 이미 있다"로 실패 |
| [[수집기 06 - SQLite 저장 계층]] | `CREATE TABLE IF NOT EXISTS` | 둘째 날 "테이블이 이미 있다"로 실패 |

같은 발상이 워크플로우에도 들어가 있다.

```bash
git diff --staged --quiet || git commit -m "..."
```

변경사항이 없으면 커밋을 건너뛴다. `git commit`은 커밋할 것이 없으면 에러로 끝나는데, 매일 도는 시스템에서 "오늘은 새 공고가 없음"은 정상 상태이므로 실패로 만들면 안 된다.

## 앞으로 나올 자리

- `INSERT OR IGNORE` — 이미 있는 공고를 다시 넣어도 조용히 넘어간다
- 마크다운 재생성 — 같은 내용을 다시 써도 파일이 같아야 한다
- 실행이 중간에 끊겼다가 다시 돌 때 — 어디까지 했든 처음부터 다시 돌려도 결과가 같아야 한다

## 함께 보면 좋은 것

멱등성과 붙어 다니는 두 가지가 있다.

- **EAFP** — 확인하지 않고 시도한 뒤 예외로 처리하는 방식. `exist_ok=True`가 내부에서 쓰는 전략이다
- **경쟁 상태** — 확인과 실행 사이에 상태가 바뀌는 문제. 멱등하게 만들면 이 틈이 문제가 되지 않는다
