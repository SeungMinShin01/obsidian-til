# RAG 챗봇 프로젝트 MOC

데이터시트 PDF를 올리면 질문에 **출처 페이지와 함께** 답하는 챗봇을 만드는 팀 프로젝트의 허브다. 이미 쓰여 있는 코드를 읽으며 "왜 이렇게 되어 있는가"를 이해한 것을 쌓는다.

## 프로젝트 개요

| 항목 | 내용 |
| --- | --- |
| 목표 | 펌웨어·하드웨어 데이터시트를 인덱싱해두고, 질문하면 근거 페이지를 붙여 답하는 챗봇 |
| 위치 | `Desktop/진로탐색` |
| 구성 | FastAPI 웹 + PDF 인제스천 파이프라인 + 벡터 DB + 답변 생성 모듈 |
| 언어 | Python |
| 담당 경계 | 업로드부터 검색까지가 내 몫. 검색 결과를 넘겨받아 답변을 만드는 모듈은 팀원 몫 |
| 최우선 목표 | **정확한 답변.** 틀린 답보다 "데이터시트에 없습니다"가 낫다 |

## 이 프로젝트의 작성 원칙 (다른 프로젝트와 다른 점)

**물어본 것만 적는다.**

수집기·WMS는 **설계 기록**이 목적이라 "무엇을 왜 선택했나"를 쌓는다. 이 프로젝트는 코드가 이미 다 쓰여 있고 그것을 **읽어서 이해하는 것**이 목적이라 방향이 반대다. 그래서 다음을 지킨다.

- 채팅에서 **실제로 물어본 질문만** 노트가 된다. 물어보지 않은 내용을 곁들여 채우지 않는다
- 각 노트 머리에 그때 물어본 질문을 그대로 적어둔다
- 번호는 **물어본 순서**다. 읽는 순서를 바꾸고 싶으면 파일명이 아니라 아래 표의 줄 순서를 옮긴다
- 설계 변경 기록·로드맵 장부는 두지 않는다. 이 프로젝트에서 설계를 정하는 일이 없기 때문이다
- 지금은 **이론 단계**다. 코드 자체를 읽는 것은 나중에 하고, 그때 노트가 다시 갈라진다

## 진행 상태

| 단계 | 상태 |
| --- | --- |
| 업로드 · 저장 · 검증 | 코드 완성 |
| 파싱 · 전처리 · 청킹 | 코드 완성, 청크 덤프로 눈 검증까지 진행 |
| 임베딩 · 벡터 DB 저장 | 코드 완성, 아직 실행 전 |
| 검색 · 답변 연결 | 코드 완성, 아직 실행 전 |
| 프론트엔드 | 없음 |
