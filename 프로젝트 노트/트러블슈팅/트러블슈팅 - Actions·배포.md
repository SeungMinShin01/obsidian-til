# 트러블슈팅 - Actions·배포

무인 실행·배포에서 터진 것들. 증상별로 쌓는다.

---

## `실패 소스 moef(KeyError)` — 초록불인데 수집 0건

**언제** 2026-08-19 ~ 08-30, 12일

**증상** 매일 `수집 0건 ... 실패 소스 moef(KeyError)`가 run-log에 찍히는데 Actions 빌드는 초록불, 실패 메일 없음.

**원인** moef 어댑터를 푸시하면서 GitHub Secret 등록과 `collect.yml`의 `env:` 블록을 빠뜨렸다. VM에 `MOEF_SERVICE_KEY` 변수 자체가 없어 `os.environ[...]`에서 KeyError → 격벽(`try/except`)이 잡아 프로그램은 정상 종료 → 실패 메일 안 옴.

**조치**
1. Settings → Secrets and variables → Actions → `MOEF_SERVICE_KEY` 등록 (Encoding 키)
2. `collect.yml` 수집기 실행 step에 `env: MOEF_SERVICE_KEY: ${{ secrets.MOEF_SERVICE_KEY }}`
3. 푸시 → Run workflow

**비용** 12일치 신규 공고. 그 사이 마감된 것은 복구 불가.

**재발 방지** 새 소스는 **Secret 먼저, 푸시 마지막**. — 단, 이 12일은 *감지* 문제가 아니었다. "Secret 먼저 안 넣으면 터진다"고 사전 경고를 받았고 로그에도 매일 찍혀 **알고 있었다.** 프로젝트 주간과 겹쳐 손을 못 댄 **우선순위** 문제였다. 그래서 교훈은 둘 — ① 알려진 실패를 미루지 않기(트리아지), ② 실패가 **로그 한 줄이 아니라 실제 알림으로 와서 미루기 어렵게** 만들기.

일반적으로는, 격벽이 실패를 잡으면 run이 초록불이 돼 Actions 실패 메일이 안 오므로(「초록불 ≠ 의도한 결과」, 「수집기 03」) *예상 못 한* 소스 실패는 로그를 봐야만 안다. 이 함정과 12일은 구분한다 — 12일은 이미 알고 있었고, 몰라서가 아니라 미뤄서 흘렀다.

## `실패 소스 moef(URLError)` — 어제는 됐는데 오늘 안 됨

**증상** 복구 다음 실행에서 `수집 0건 ... 실패 소스 moef(URLError)`. 직전 실행은 성공(348건 수집).

**원인** URLError는 **서버까지 못 감** — DNS 실패·연결 거부·타임아웃. HTTPError(서버가 거절)나 KeyError(설정 문제)와 층이 다르다. 직전이 성공했으니 영구 차단이 아니라 일시적.

**조치** 대개 다음 실행에서 정상. `main.py` except에 `traceback.print_exc()`를 넣어 Actions 로그에 상세(`timed out`인지 `Name resolution`인지)가 남게 했다.

**재발 방지** 반복되면 재시도+지수 백오프를 `_call`에 넣는다(상한 2회). 한 번이면 그 회차 포기하고 다음 회차에 맡긴다.

**예외 종류 구분표**

| 예외 | 어디까지 갔나 | 성격 |
| --- | --- | --- |
| KeyError | 코드 안 | 설정 문제, 고정 |
| HTTPError | 서버 응답함 | 키·권한·한도 |
| URLError | 서버 못 감 | 대개 일시적 |

## 빈 워크플로우 푸시 → 즉시 실패 메일

**언제** 프로젝트 초기

**증상** 내용 없는 `collect.yml`을 커밋·푸시하자 Actions가 바로 실패.

**원인** 워크플로우는 **푸시되는 순간 살아난다.** 문법이 없거나 틀리면 즉시 티가 난다. "저장 ≠ 커밋 ≠ 푸시"를 처음 겪은 계기.

**재발 방지** yml은 저장 → 세션이 검사(탭·파싱·step 목록) → 커밋 순서. 편집 중 step이 통째로 사라지는 사고도 있었으니 step 목록을 눈으로 확인.
