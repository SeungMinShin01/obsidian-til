# RAG 챗봇 02 - 패키지 초기화 파일이 비어 있는 이유

> 허브: [[RAG 챗봇 프로젝트 MOC]]

**물어본 것:** 폴더마다 있는 초기화 파일(`__init__.py`)은 왜 빈 파일인가.

## 1. 배운 내용

### 1-1. 내용이 아니라 존재가 신호다

이 파일은 **"이 폴더는 파이썬 패키지다"**라고 표시하는 역할이다. 그래서 안이 비어 있어도 제 일을 한다.

이것이 있어야 아래 같은 불러오기가 안정적으로 동작한다.

```python
from app.ingestion import parser, preprocess, chunker
```

파이썬 3.3부터는 파일이 없어도 폴더를 패키지로 인식하는 방식이 생겼지만, 경로가 꼬였을 때 조용히 실패하는 경우가 있어 명시적으로 두는 것이 관례다.

### 1-2. 비워두는 것도 선택이다

초기화 파일에 코드를 쓰면 그 패키지를 불러오는 순간 **무조건 실행된다.** 여기에 하위 모듈을 미리 불러오는 문장을 잔뜩 써두면, 패키지 이름만 건드려도 하위 모듈이 전부 로딩된다.

파이썬은 모듈을 불러올 때 그 파일의 **최상위 코드를 전부 실행한다.** 함수 정의만 있으면 정의만 되고 끝나지만, 최상위에 실제 호출이 섞여 있으면 불러오기만 해도 그 호출이 일어난다. 그래서 시험 삼아 돌려보는 코드는 진입점 가드로 감싸는 것이 관례다.

```python
if __name__ == "__main__":
    ...
```

이 가드가 없는 모듈을 손댈 수 없는 상황이라면, 불러오는 시점 자체를 뒤로 미루는 방법이 있다. 서버가 뜰 때가 아니라 **실제로 그 기능이 처음 필요해진 순간**에 불러오는 것이다. → [[RAG 챗봇 06 - 구현 범위와 담당 경계]]
