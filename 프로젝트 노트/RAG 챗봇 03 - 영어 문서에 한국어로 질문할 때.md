# RAG 챗봇 03 - 영어 문서에 한국어로 질문할 때

> 허브: [[RAG 챗봇 프로젝트 MOC]]

**물어본 것:** 영어로 된 PDF를 전처리하는데 질문을 한국어로 하면 생기는 문제가 있는가.

## 1. 배운 내용

### 1-1. 전처리는 영향을 받지 않는다

전처리는 문서 쪽만 건드리고 질문은 나중 단계에서 들어온다. 문제는 **검색**에서 생긴다.

### 1-2. 언어가 다르면 벡터가 멀어진다

임베딩 모델은 다국어를 지원해서 같은 뜻이면 언어가 달라도 어느 정도 가까운 자리에 찍힌다. 그래서 한국어 질문으로 영어 조각이 검색되기는 한다.

문제는 **같은 언어끼리보다 확실히 멀다**는 것이다.

```
"Operating voltage"  <-> "Operating voltage: 2.3V to 5.5V."   거리 가까움
"동작 전압"           <-> "Operating voltage: 2.3V to 5.5V."   거리 더 멀다
```

언어 간 정렬은 학습된 부수 효과이지 보장된 성질이 아니다. **의미가 맞아도 거리가 벌어진다.**

### 1-3. 그래서 거리 상한에 걸린다

거리 상한을 넘으면 버리고, 다 버려지면 "해당 정보가 없습니다"가 나간다.

한국어 질문의 거리는 영어 질문보다 위로 밀려 있으니, **맞는 답을 찾아놓고도 상한에 걸려 버려질 수 있다.** 검색 실패가 아니라 "정보가 없다"는 답으로 나가서 로그를 봐도 원인이 안 보인다. 실질적으로 가장 먼저 겪게 될 증상이다.

그리고 영어 질문과 한국어 질문의 거리 분포가 다르므로 **상한 하나로 둘을 다 잡지 못한다.** 느슨하게 잡으면 관련 없는 조각이 들어와 오답을 만든다. 정확도가 최우선일 때 특히 아픈 맞바꿈이다.

### 1-4. 반대로 유리한 점 — 영어 앵커

데이터시트라서 생기는 이점이 있다. 한국어 질문에도 영어 토큰이 섞여 들어간다.

```
"VCC 동작 범위가 어떻게 돼?"     <- VCC
"I2C 최대 속도 알려줘"           <- I2C
```

이런 것들은 **번역되지 않는 앵커**라 언어 장벽을 그냥 통과한다. 실무에서 한국어 질문이 생각보다 잘 먹히는 이유다.

거꾸로 말하면 **순수 한국어로만 물을 때 약해진다.** "전원 전압 범위 알려줘" 처럼 앵커가 없으면 온전히 언어 간 정렬에 의존하게 된다.

### 1-5. 번역어가 갈린다

영어 원문은 `Supply Voltage` 하나인데 한국어는 사람마다 다르게 쓴다 — 동작 전압, 공급 전압, 전원 전압, 구동 전압. 어느 것을 쓰느냐에 따라 검색 결과가 달라진다.

데이터시트 용어는 특히 번역이 정착되지 않은 것이 많다. `slew rate`, `quiescent current`, `propagation delay` 같은 것은 한국어 표현이 여러 개거나 그냥 영어로 쓴다.

### 1-6. 답변 단계에도 위험이 있다

찾아온 조각은 영어인데 답변은 한국어로 쓴다. 즉 **모델이 검색과 번역을 동시에 한다.**

여기서 왜곡될 수 있는 것이 하필 데이터시트에서 가장 중요한 것들이다.

- `Typical` 을 "최대값"으로 옮기는 것
- 범위를 "약 2V대에서 5V대"로 뭉개는 것
- 시키지도 않은 단위 변환을 하는 것

프롬프트에 최소·최대·전형·권장을 혼동하지 말 것, 숫자와 단위를 임의로 바꾸지 말 것 규칙이 들어 있는 것이 정확히 이것을 막으려는 장치다. 영어에서 한국어로의 번역이 끼어 있기 때문에 필요한 규칙이다.

## 2. 추가로 알면 좋은 활용법

### 2-1. 먼저 재본다

추측할 것이 아니라 측정할 문제다. 검색만 하는 통로는 비용이 0이므로 같은 질문을 한국어와 영어로 각각 던져 거리를 비교해보면 된다. 이 차이가 상한을 얼마로 잡을지의 근거가 된다.

### 2-2. 질문을 영어로 바꿔서 검색한다

효과가 가장 확실한 방법이다. 한국어 질문을 영어로 옮긴 뒤 그것으로 검색하면 **영어 질문과 영어 문서**가 되어 언어 간 거리 문제가 통째로 사라진다. 답변은 그대로 한국어로 하면 된다. 비용은 짧은 번역 호출 하나다.

### 2-3. 용어 사전을 둔다

번역 호출도 아깝다면, 데이터시트 용어 30~50개를 한국어-영어로 매핑해두고 질문의 단어를 치환해도 상당 부분 해결된다. **여러 후보를 같이 넣으면** 번역어가 갈리는 문제도 함께 잡힌다.

### 2-4. 키워드 검색을 섞는다

부품 번호나 기호형 파라미터명처럼 **정확히 일치해야 하는 것**은 벡터 검색보다 키워드 매칭이 확실하다. 두 결과를 합치는 방식이고, 표 인식 다음으로 데이터시트에서 효과가 크다.

## 3. 더 나아가 알면 좋은 것

### 3-1. 다음에 볼 키워드

- 다국어 특화 임베딩 모델 — 언어 간 정렬 성능이 더 좋은 모델로 교체하는 선택지
- 질문 재작성(query rewriting)과 질문 확장(query expansion)
- 하이브리드 검색에서 두 점수를 합치는 방식
