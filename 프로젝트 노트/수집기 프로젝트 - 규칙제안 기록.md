# 수집기 프로젝트 - 규칙제안 기록

> 지침서: [[CLAUDE]]

수집기 프로젝트를 진행하면서 Vault 전체 규칙(`CLAUDE.md`, `_규칙/옵시디언-노션-VSCode 운영 규칙.md`)에 반영을 요청한 제안들을 쌓아두는 장부다.

작업 중에 규칙이 필요해지면 세션 안에서 임시로 운용하다가, 굳어지면 제안서로 정리해 Vault 운영 세션에 넘긴다. **채택 여부와 이유를 함께 남겨서, 나중에 제안들을 모아놓고 판단할 수 있게 한다.**

## 이 노트가 지침서에 연결된 이유

제안의 대상이 `CLAUDE.md`이므로 그 문서 아래에 매다는 것이 의미상 맞다. 프로젝트 MOC는 프로젝트 진행 내용의 목차이지 규칙 논의의 자리가 아니다.

다만 이 연결은 `프로젝트 노트/` 고립 규칙(폴더 안에서만 링크)을 넘어선다. **의도한 예외이며, 허용 여부에 대한 판단을 [[수집기 프로젝트 - 규칙제안 01 - 노트 연결 체계]]에서 함께 요청하고 있다.** 허용되지 않으면 링크를 걷어내고 이름만 적는 방식으로 되돌린다.

역방향 링크(`CLAUDE.md`에서 이 노트로)는 걸지 않았다. 그 문서는 운영 세션의 관할이므로 필요 여부를 그쪽에서 판단한다.

## 상태 표기

| 상태 | 뜻 |
| --- | --- |
| 검토 요청 | 운영 세션에 넘겼고 답을 기다리는 중 |
| 채택 | 규칙 문서에 반영됨 |
| 부분 채택 | 일부만 반영. 어느 부분이 빠졌는지 제안 노트에 기록 |
| 보류 | 지금은 결정하지 않기로 함. 재검토 조건을 남긴다 |
| 기각 | 반영하지 않기로 함. 이유를 남긴다 |

기각된 제안도 지우지 않는다. **같은 문제를 다시 만났을 때 이미 논의했다는 사실과 그때의 이유가 남아 있어야** 같은 논의를 반복하지 않는다.

## 작성 규칙

- 제안 하나당 파일 하나로 만든다. 이 장부에는 목록과 상태만 둔다
- 파일명은 `수집기 프로젝트 - 규칙제안 NN - 제목` 형식이다
- 제안서 첫머리에 **작성 세션**을 명시한다. 여러 세션이 같은 Vault를 쓰므로 누가 낸 제안인지 남아야 한다
- 답을 받으면 제안서의 「결정 기록」 절과 이 장부의 상태를 함께 갱신한다
