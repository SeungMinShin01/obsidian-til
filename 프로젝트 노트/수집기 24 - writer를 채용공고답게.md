# 수집기 24 - writer를 채용공고답게

> 허브: [[수집기 프로젝트 MOC]]

`moef_303923.md`에 제목·회사·시각만 있던 노트를, 파일명에 제목이 들어가고 본문에 지원자격·우대사항·전형방법이 채워진 형태로 바꾼 기록이다. 「수집기 11」의 함수 셋을 전부 손댔다.

## 1. 배운 내용

### 1-1. 상세 API를 부르지 않기로 한 근거

"상세 API까지 돌려서 세부 내용을 채우고 싶다"에서 시작했는데, 먼저 목록 `raw`에 뭐가 있는지 관측했다. 상세가 더 주는 것은 첨부파일과 전형단계뿐이었다. 본문에 필요한 텍스트는 이미 DB에 있었다.

**요청 0번 추가로 원하는 것을 만들 수 있었다.** `raw`에 원문을 통째로 넣어둔 결정이 회수된 순간이다. 첨부파일이 정말 필요해지면 신규 건만 상세를 부른다 — 보류.

### 1-2. 파일명에 제목이 들어가면 방어가 넓어진다

```python
_FORBIDDEN = re.compile(r'[\\/:*?"<>|\n\r\t]')

def _safe_name(text, limit=60):
    cleaned = " ".join(_FORBIDDEN.sub(" ", text).split())
    return cleaned[:limit].rstrip(". ")
```

id만 다룰 때는 `:`와 `/`면 충분했다. **제목은 내가 만들지 않은 문자열**이다. 윈도우 금지 문자 아홉 개와 줄바꿈을 지우고, 길이를 자르고(공공기관 공고 제목은 아주 길다), 끝의 점과 공백을 뗀다 — 윈도우는 그렇게 끝나는 파일명을 거부한다.

### 1-3. 폴더를 먼저 비운다

```python
for old in JOBS_DIR.glob("*.md"):
    old.unlink()
```

파일명에 제목이 들어가는 순간 새 문제가 생긴다 — **형식을 바꿀 때마다 옛 이름의 파일이 고아로 남는다.** 이 폴더는 전부 DB에서 다시 만들 수 있는 산출물이므로, 매번 비우고 새로 그리는 것이 멱등성을 지키는 가장 단순한 길이다. #멱등성 → [[개념 - 멱등성]]

대신 사람이 생성 노트에 적은 메모는 다음 실행에 사라진다. 「수집기 11」에서 유예해둔 그 한계가 그대로다.

### 1-4. `row_factory` — 예고했던 시점

「수집기 11」에 "열이 늘어나면 그때 바꾼다"고 적어뒀다. 컬럼이 15개가 되면서 튜플 언패킹은 순서 사고를 기다리는 코드가 됐다.

```python
conn.row_factory = sqlite3.Row
rows = conn.execute("SELECT * FROM jobs ORDER BY first_seen_at").fetchall()
row["title"]
```

이름으로 꺼내므로 SELECT 순서와 무관해진다. 그리고 `_to_markdown(job_id, title, ...)`이 **`_to_markdown(row)` 하나**로 줄었다 — 컬럼이 늘 때마다 함수 서명을 고치던 일이 사라진다.

### 1-5. frontmatter 확장은 계약 확장이다

```
지역: {row['region']}
직무분류: {row['ncs']}
마감일: {row['end_at']}
```

옵시디언에서 속성으로 잡혀 `["직무분류":정보통신]`, `["마감일":2026-08-19]` 같은 검색이 된다. 이름을 한번 정하면 그 이름으로 만든 검색·필터가 전부 의존하므로 추가는 쉽고 변경은 비싸다.

### 1-6. 컬럼에 없는 것은 `raw`에서 꺼낸다

```python
raw = json.loads(row["raw"])
raw.get("recrutNope")            # 모집인원
raw.get("scrnprcdrMthdExpln")    # 전형방법
```

표현이 원하는 것이 늘 때 스키마를 안 건드린다. 컬럼은 최소로, 원문은 전부 — 그 구조가 여기서도 일한다.

빈 절은 만들지 않는다. 값이 없는데 `## 우대사항`만 덩그러니 있는 노트가 안 생기게 반복문에 `if text`를 둔다.

### 1-7. 가짜 파일이 부활한 이유

DB에서 가짜 행을 안 지운 채 md 파일만 지웠더니 다음 실행에 다시 생겼다. **writer는 DB 기준으로 전부 다시 그린다.** 산출물을 지우려면 원본을 지워야 한다.

## 2. 옵시디언에서 보는 법

### 2-1. 공개 Vault에는 한 건도 안 들어간다

생성 위치는 `수집기\collector\data\채용\`이지 `옵시디언\Vault\`가 아니다. Vault는 GitHub에 Public으로 동기화되므로 수집 데이터를 넣으면 「수집기 14」의 공개 경계가 무너진다.

옵시디언은 Vault를 여러 개 연다. `collector\data`를 **두 번째 Vault로 열면** 된다 — 「폴더를 보관함으로 열기」. 이 Vault에는 obsidian-git 같은 동기화 플러그인을 설치하지 않는다. 처음 그렸던 "옵시디언에 저장"의 실체는 **옵시디언이라는 도구로 보되 공개 Vault와 격리된 폴더에**다.

### 2-2. 색인이 늦을 수 있다

수백 개 파일을 처음 물면 검색·그래프에 다 안 잡힐 때가 있다. 재시작이 털어낸다. 정확한 개수 확인은 그래프가 아니라 검색 `path:"채용"`의 결과 수로 한다.

### 2-3. 이 Vault에서 그래프뷰는 쓸모가 없다

공고 노트끼리 링크가 없으니 점구름이다. 실제로 쓰는 도구는 전체 검색(`Ctrl+Shift+F`, 본문까지)과 속성 필터다. 기관명이 제목에 없는 공고(예: 국립중앙의료원 "계약직 전산행정 채용 공고")는 파일명 검색으론 안 잡히고 `["회사":국립중앙의료원]`으로 잡는다.

### 2-4. 대괄호는 위키링크와 충돌한다

`[moef_303923] 제목.md` 형식은 `[[...]]` 안에 `[`가 못 들어가서 **다른 노트에서 위키링크로 걸 수 없다.** 열람·검색·필터는 정상이고 생성 노트에 링크 걸 일은 드물어 실용상 문제없다. 필요해지면 `moef_303923 - 제목` 형태로 writer 한 줄이면 바뀐다 — 폴더를 비우고 다시 그리니 파일명 변경도 깨끗하다.
