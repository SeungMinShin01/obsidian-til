# WMS 스토리 백로그 — 애자일 일정 (2026-09-19 ~ 10-16)

> 지라 없이 쓰는 텍스트 백로그다. 스프린트 시작 때 각자 여기서 스토리를 가져가고, 끝나면 체크한다.
> 기준 문서: `WMS/주말_MVP_명세_v2.md`, `WMS/설계서_v2.md`, `팀규칙/01_스프린트_운영규칙.md`

>
> **이 백로그의 전제**
> - 거래처 테이블은 만들지 않는다. 발주에는 `공급처명`(텍스트), 주문에는 `배송지명·주소·연락처`(텍스트)를 둔다. 화주 도입 후에도 사라지지 않는 구조다
> - 발주·주문의 영문 이름을 3PL 기준(입고예정·출고요청)으로 바꿀지는 결정 대기. 스토리는 한글 용어로만 적어서 결정과 무관하게 쓸 수 있다

## 1. 공통 규칙

### 스토리 형식

```
### ST-000 제목                                  [담당] 크기 · 스프린트
> 누구로서 / 무엇을 하고 싶다 / 왜
- 선행: ST-xxx

  - [ ] 확인 가능한 문장 (API 응답·DB 상태·테스트 이름으로)
```

크기: **S** 반나절 · **M** 하루 · **L** 이틀(스프린트 전체). L보다 크면 쪼갠다.

2. 로컬에서 API 호출(Talend) 또는 화면 동작을 직접 확인했다
3. Swagger가 갱신됐다
4. PR 리뷰 1명 승인
5. develop에 병합됐다

추가로 이 프로젝트에서는:

6. **재고를 바꾸는 스토리는 이력 합계 = 현재고를 확인한다**
