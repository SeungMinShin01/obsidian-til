# KDT_1차 정규프로젝트 MOC

KDT 1차 정규프로젝트(3조, 4인, 2026-09-15 ~ 10-16) — 식품·건강기능식품 상온 창고 WMS의 설계 문서 모음.
React + Spring Boot + MySQL. 입고 → 재고 → FEFO 할당 → 피킹 → 출고확정까지 재고 정합성과 상태 전이를 중심으로 만든다.

> 이 MOC와 아래 문서들은 서로만 연결되고, 바깥으로는 [[프로젝트 노트 MOC]] 하나에만 연결된다. 다른 프로젝트 MOC(WMS 프로젝트 MOC 등)와는 잇지 않는다.

## 읽는 순서

1. **주말 MVP 명세 v2** — 지금 만드는 것의 기준. 기능 요구사항 → ERD → API → 테스트 시나리오
2. **테이블 설계 근거** — 왜 이 테이블·컬럼인지, 상태 전이를 어떻게 구현하는지
3. **코드 구조 예시** — 파일 위치와 계층별 코드 모양
4. **스토리 백로그** — 스프린트별 할 일과 완료 조건
5. **용어사전** — 코드·DB·대화에서 쓰는 이름
6. **설계서 v2 3PL 목표** — 화주·Portal을 붙인 뒤의 방향 (참고)

## 현재 결정 요약

- 단일 WMS로 먼저 만들고, 화주(멀티테넌시)는 이후 `tenant_id` 추가로 붙인다
- 재고 한 행 = 품목 × 로케이션 × 소비기한 (로트 번호 없음), 재고 변경은 `StockService` 한 곳에서만 + 이력
- 거래처 테이블 없음 — 공급처명·배송지는 발주·주문에 텍스트
- 구역(A/B/C)은 품목·화주별로 나누지 않음. 섞임은 칸 단위 규칙(한 칸 = 한 품목·한 소비기한, 칸 용량 = 품목의 팔레트 적재수량)으로 막음
- 상태는 문서 머리의 enum 컬럼. 행동마다 API, 상태 변경은 엔티티의 `transitionTo()` 한 곳. 전이 규칙 검사는 주말 이후 추가

## 결정 대기

- 발주·주문을 3PL 이름(입고예정·출고요청)으로 바꿀지
- 문서 상태 동시 변경 방지 `@Version` 도입 시점
- 분할입고: 새 발주로 처리(A) vs 입고 건 분리(B)
