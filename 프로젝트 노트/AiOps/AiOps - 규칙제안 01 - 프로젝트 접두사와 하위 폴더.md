# AiOps - 규칙제안 01 - 프로젝트 접두사와 하위 폴더

> 장부: [[AiOps - 규칙제안 기록]]

**작성 세션:** AiOps 프로젝트 세션
**대상:** `_규칙/구역 규칙.yaml` → `zones.프로젝트 노트` · `CLAUDE.md` → 「세션 역할 분담」

## 1. 무엇이 문제인가

`프로젝트 노트/`에 네 번째 프로젝트(AiOps)가 들어왔다. 사용자 지시로 노트를 **하위 폴더 `프로젝트 노트/AiOps/`** 에 모았는데, 구역 규칙에는 접두사 목록도 하위 폴더 목록도 등록돼 있지 않다.

```yaml
프로젝트 노트:
  prefix: "수집기 |WMS |RAG 챗봇 "
  하위폴더_prefix: { 변경이력: "변경이력 - ", 트러블슈팅: "트러블슈팅 - ", 수집기 코드분석: "코드분석 - ", WMS 정리내용: "WMS 정리 - " }
```

`AiOps NN - 제목` 형식은 미등록 접두사로, `AiOps/` 폴더는 미등록 하위 폴더로 검사기에 잡힌다. 세션 역할표에도 이 프로젝트 행이 없다. 두 파일 모두 마스터 관할이라 직접 고치지 않고 제안으로 올린다.

## 2. 제안

### 2-1. 접두사·하위 폴더 등록

```yaml
프로젝트 노트:
  prefix: "수집기 |WMS |RAG 챗봇 |AiOps "
  하위폴더_prefix: { …기존…, AiOps: "AiOps " }
```

하위 폴더 안의 규칙제안 노트(`AiOps - 규칙제안 NN`)와 장부(`AiOps - 규칙제안 기록`)도 같은 접두사를 쓴다.

### 2-2. 세션 역할표에 행 추가

| 세션 | 관할 (쓰기 가능) | 하는 일 |
| --- | --- | --- |
| **AiOps** | `프로젝트 노트/AiOps/` | KDT 2차 팀 프로젝트(Spring Boot Starter 기반 에러 수집·설명 서비스)의 **코드·환경 작업 기록**. 설계 문서는 레포 `docs/`·claude.ai 프로젝트에 두고 여기엔 "실제로 어떻게 했고 어디서 막혔나"만. 파일명 `AiOps NN - 제목`, 세부 파생(`NN-1`) 없는 순수 리스트 변형(WMS와 동일) |

### 2-3. 하위 폴더를 쓰는 것에 대한 승인 요청

기존 세 프로젝트는 `프로젝트 노트/` 바로 아래에 접두사로만 구분했고, 하위 폴더는 성격이 다른 보조 자료(변경이력·트러블슈팅·정리내용)에만 썼다. AiOps는 **프로젝트 본 노트까지 폴더에** 넣는 첫 사례라 승인을 남겨 둔다. 폴더 안 링크 규칙(번호 트리 + 앞뒤 사슬, 가로 금지, 바깥으로는 `프로젝트 노트 MOC` 하나)은 그대로 지킨다.
