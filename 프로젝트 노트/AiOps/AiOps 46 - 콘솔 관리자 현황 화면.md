# AiOps - 콘솔 관리자 현황 화면

> 허브: [[AiOps 프로젝트 MOC]]

**`[AI-99]` 2부의 셋째 조각** (브랜치 `feat/console-AI-99-admin`, 11/16) — 새 파일 4개, 고친 파일 4개. 관리자가 모든 팀을 한 표로 보는 화면을 가짜 응답으로 그린다. "할 일" 칸의 버튼은 모양만 있고, 누르는 동작은 김지환의 AI-101.

## 1. 배운 내용

### 1-1. 표 한 줄 = 팀 하나

팀 · 조장 · 상태(조장 대기/활성/정지) · 로컬 · 운영 · 24시간 에러 · 디스코드 · 할 일. 응답은 서버의 `OverviewRow` 그대로다. 에러 **내용**은 이 화면에 없다 — 수와 상태만 본다 (내용은 팀마다 "에러 보기"로 들어가서, D-103).

### 1-2. 코드로 보기: "연결됨"은 화면이 판정한다

```js
const CONNECTED_WITHIN_MS = 3 * 60 * 1000;

function isConnected(lastSeen, now) {
  return lastSeen !== null && now - new Date(lastSeen).getTime() <= CONNECTED_WITHIN_MS;
}
```

서버는 "마지막 신호 시각"만 준다. 3분 안이면 연결됨, 넘으면 "끊김 · 2시간 전", 시각이 없으면 "한 번도 안 옴". 3분은 Starter가 60초마다 보내는 신호를 세 번까지 놓쳐도 봐준다는 뜻이고, 서버 설정(`aiops.console.connected-within`)과 같은 값이다.

값이 두 군데(서버 설정, 콘솔 상수)에 있는 것은 약점이다. 서버 값을 바꾸면 여기도 바꿔야 한다. 팀 화면의 연결 배지는 서버가 판정한 `state`를 받으므로 이 문제가 없다.

### 1-3. 코드로 보기: 기준 시각은 "받은 시각"

```js
const now = overview.dataUpdatedAt;   // TanStack Query가 기록한, 응답을 받은 시각
```

`Date.now()`를 그리는 도중에 부르면 줄마다 기준이 조금씩 달라지고, 화면을 다시 그릴 때마다 "2분 전"이 바뀐다. 받은 시각을 기준으로 삼으면 한 번 받은 데이터는 한 가지로만 그려진다. 30초마다 다시 받으므로 오래 묵지도 않는다.

### 1-4. 30초마다 다시 불러오기

```js
useQuery({ ..., refetchInterval: 30_000 })
```

관리자 화면은 켜 두고 보는 화면이다. 한 줄이면 된다. 탭이 뒤에 가 있으면 TanStack Query가 알아서 멈춘다.

### 1-5. 기수 버튼은 받은 데이터에서 만든다

기수 목록을 따로 부르지 않고, 받은 줄들의 `cohort`를 세어 버튼을 만든다(`Map`에 이름 → 개수). 기수가 없는 팀은 "기수 없음"으로 묶는다. 걸러 보는 것도 화면에서 한다 — 팀이 수십 개 수준이라 서버에 다시 물을 이유가 없다.

### 1-6. 값이 없는 칸

| 값 | 화면 |
|---|---|
| `ownerLogin` null | "아직 없음" (흐리게) |
| `lastSeen…` null | "한 번도 안 옴" |
| `errors24h` null | "—" (그 팀만 집계에 실패한 것. 0과 다르다) |
| `cohort` null | "기수 없음" |

0과 "모름"을 같은 글자로 그리지 않는다. 0건은 조용한 팀이고, 모름은 확인이 필요한 팀이다.

## 2. 실수 기록

- 터미널에 `http proxy error … ECONNREFUSED`가 찍혔다. 화면이 진짜 서버(8080)에 붙으려다 거절당한 것이다. `npm run dev`(진짜 서버용)로 띄웠거나, `dev:mock`인데 가짜 응답 파일이 읽히다 실패한 경우다. 브라우저 Console에 `[MSW] Mocking enabled.`가 있는지 보면 구분된다.
- 쓰는 곳이 없어진 import(`ComingSoon`)를 남겨 두면 lint가 오류를 낸다. 화면을 진짜로 바꿔 끼울 때는 import도 같이 지운다.
