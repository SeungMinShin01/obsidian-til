# AiOps - 콘솔 에러 상세 화면

> 허브: [[AiOps 프로젝트 MOC]]

**`[AI-99]` 2부의 둘째 조각** (브랜치 `feat/console-AI-99-detail`, 11/16) — 새 파일 2개, 고친 파일 7개. 에러 하나를 열었을 때의 화면을 가짜 응답으로 그린다. 상태 버튼·평가 버튼은 모양만 있고, 누르는 동작은 김지환의 AI-100.

## 1. 배운 내용

### 1-1. 화면의 순서

```
← 에러 목록
[열림] [로컬] [실행 중 발생]          상태 · 환경 · 단계
NullPointerException                  예외 이름 (패키지는 뺀다)
OrderService 클래스의 place 메서드     위치를 풀어서
횟수 · 처음 · 마지막
[해결로 표시] [무시]                  모양만
AI 설명 (원인 후보 / 확인 방법 / 해결 방향)   ← 스택보다 위
스택 (우리 팀 코드만 밝게)
원인 체인 · 최근 14일 막대 · 최근 발생
```

AI 설명을 스택보다 위에 둔 이유: 디스코드 알림을 휴대폰으로 받고 들어온 사람이 먼저 읽고 싶은 것은 "왜"다. 스택은 그다음에 확인하러 내려가는 것이다.

### 1-2. 코드로 보기: AI 설명을 세 칸으로 (`splitExplanation`)

```js
const EXPLANATION_TITLES = ["원인 후보", "확인 방법", "해결 방향"];
for (const title of EXPLANATION_TITLES) {
  const at = text.indexOf(title, from);
  if (at === -1) return null;        // 하나라도 없으면 나누지 않는다
  ...
}
```

서버는 LLM이 준 글을 그대로 저장한다(규칙 13: 서버가 해석하지 않는다). 화면도 **자르기만** 한다. 제목 세 개가 순서대로 다 있을 때만 세 칸으로 나누고, 형식이 다르면 `null`을 돌려 글을 통째로 보여 준다. LLM은 형식을 가끔 어기므로 "못 나누는 경우"가 반드시 있다.

### 1-3. 코드로 보기: 우리 팀 코드 강조 (`teamPrefix`)

```js
// 'dev.shop.order.OrderService#place' → 'dev.shop.'
const segments = parts.packageName.split(".");
return `${segments.slice(0, 2).join(".")}.`;
```

서버는 스택을 글자 목록으로만 준다. 어느 줄이 팀 코드인지는 알려 주지 않는다. 그래서 위치(`location`)의 패키지 앞 두 마디로 시작하는 줄을 팀 코드로 **짐작**한다. 두 마디인 이유: 패키지 전체(`dev.shop.order`)로 하면 같은 앱의 다른 패키지(`dev.shop.common`)가 빠진다. 표시용 짐작일 뿐이라 틀려도 잃는 것은 강조뿐이다.

### 1-4. 일별 막대는 라이브러리 없이

```jsx
<span className="bar" style={{ height: `${Math.round((day.count / maxCount) * 100)}%` }} />
```

막대 14개는 높이만 다른 네모다. 가장 큰 날을 100%로 두고 나머지를 비율로 그린다. 차트 라이브러리를 넣지 않기로 한 규칙을 지키면서도 한 줄이면 된다. `maxCount`를 `Math.max(1, ...)`로 잡은 것은 전부 0일 때 0으로 나누지 않으려는 것이다.

### 1-5. 없는 경우를 먼저 그린다

| 경우 | 화면 |
|---|---|
| 설명이 아직 없음 (`aiExplanation` null) | "설명을 준비하고 있어요" |
| 원본이 보관 기간을 넘겨 사라짐 (`recentEvents` 빈 목록) | 스택 자리에 "원본이 남아 있지 않습니다 (보관 n일)" |
| 위치를 모름 (`location` null) | "위치를 알 수 없음" |
| 없는 번호 / 다른 팀 그룹 (404) | "에러를 찾을 수 없어요" |
| 내 팀이 아님 (403) | 권한 없음 화면 |

가짜 데이터에 이 경우들을 일부러 넣었다(3번 = 설명 없음·시작 실패, 6번 = 원본 없음·위치 없음). 정상인 1번만 보고 끝내면 실제 서버에서 처음 만나는 빈 값에 화면이 깨진다.

## 2. 실수 기록

- **import 줄을 "바꾸라"는 것을 "추가"로 넣었다.** 같은 이름(`errorGroups`)을 두 번 가져오면 JavaScript는 파일 전체를 읽지 않아 화면이 통째로 안 뜬다. 오류 메시지가 줄 번호까지 알려 주므로 그 줄만 보면 된다.
- **CSS 클래스 이름이 다른 사람 것과 겹쳤다.** `base.css`의 `.section-head`·`.section-title`·`.tag`가 조현우의 `settings.css`에도 있었다. CSS는 파일이 달라도 이름이 같으면 한 화면에 같이 적용된다. 내 스타일이 설정 화면의 제목 크기와 꼬리표 모양을 바꾸고 있었다. 에러 화면 쪽 이름을 `block-head`·`block-title`·`env-tag`로 바꿔서 풀었다. lint도 빌드도 이것은 잡지 못한다 — 두 화면을 눈으로 봐야 한다.

## 3. 시안과 다른 점

| 시안 | 실제 | 이유 |
|---|---|---|
| 발생마다 커밋 | 스레드 이름 | 커밋은 상세 응답에 없다 (잠정) |
| 앱 환경 (Java·Boot 버전) | 없음 | 같은 이유 |
| (없음) | 최근 14일 막대 | API가 `dailyCounts`를 주고 명세에 있다 |
| 상태·평가 버튼이 눌림 | 꺼진 채 모양만 | 연결은 AI-100 |
