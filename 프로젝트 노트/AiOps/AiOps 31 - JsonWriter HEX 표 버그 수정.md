# AiOps - JsonWriter HEX 표 버그 수정

> 허브: [[AiOps 프로젝트 MOC]]

**PR #46 `[AI-37] JsonWriter 제어문자 이스케이프 버그 수정`** — 브랜치 `fix/starter-AI-37-jsonwriter-hex`. 커밋 2개: 테스트(`03b3af6`, 빨강) → 수정(`a068186`, 초록). 11/12 머지. 설계 대비 점검(11/12)에서 코드를 읽다가 발견한 버그.

## 1. 배운 내용

### 1-1. 무엇이 틀렸나

```java
private static final char[] HEX = "0123456789bcdef".toCharArray();   // a가 빠져 15글자
...
if (c < 0x20) {
    out.append("\\u00").append(HEX[c >> 4]).append(HEX[c & 0xF]);     // 제어문자 → \u00XX
}
```

16진수 한 자리는 0~15 → 표는 **16글자**여야 한다. `a`가 빠져서 10번 칸부터 한 칸씩 밀렸다.

| 제어문자 | 아래 4비트 | 결과 |
|---|---|---|
| 0x00~0x09, 0x10~0x19 | 0~9 | 정상 (숫자 칸은 안 밀림) |
| 0x0B~0x0E, 0x1A~0x1E | 11~14 | **틀린 글자** (`b` 자리에 `c`…). ANSI ESC(0x1B)가 여기 |
| 0x0F, 0x1F | 15 | `HEX[15]` → **ArrayIndexOutOfBoundsException** |

- 0x0A(`\n`)·0x0D(`\r`)·0x09(`\t`)는 위쪽 `switch`에서 먼저 처리돼 이 표를 안 탄다. 그래서 흔한 글자는 멀쩡했다.
- 예외가 나면 `JsonWriter.write`가 통째로 실패 → 그 **묶음(최대 100건)이 전부 유실**. 에러 하나에 색 코드 한 글자가 들어 있으면 같이 묶인 99건도 사라진다.
- 틀린 글자 쪽은 예외 없이 **조용히 다른 문자**가 서버에 저장된다. 더 찾기 어렵다.

### 1-2. 왜 기존 테스트가 못 잡았나

기존 표의 제어문자 케이스는 `"a\u0001b"` 하나였다. 0x01은 **숫자 칸(0, 1)만** 쓴다. 16진수 표를 검사하면서 a~f 칸을 한 번도 안 밟은 것.

교훈: **표(lookup table)를 테스트할 때는 경계 칸을 밟는다.** 첫 칸, 마지막 칸, 숫자에서 글자로 넘어가는 칸(9 → a).

### 1-3. 테스트를 어디에 넣었나

새 테스트 메서드를 만들지 않고 기존 `escapes()` 표에 3줄을 추가했다.

```java
Arguments.of("제어문자 0x0F", "a\u000fb", "\"a\\u000fb\""),   // 마지막 칸 → 예외 나던 곳
Arguments.of("ESC 0x1B",     "a\u001bb", "\"a\\u001bb\""),   // 밀린 칸 → 틀린 글자 나던 곳
Arguments.of("제어문자 0x1F", "a\u001fb", "\"a\\u001fb\""));
```

기존 `이스케이프` 테스트가 한 번에 두 가지를 본다: ① 결과 문자열이 기대와 같은가 ② **Jackson으로 다시 읽으면 원래 글자가 나오는가(왕복)**. ②가 있어서 "우리끼리만 맞는 형식"이 아님이 보장된다.

### 1-4. 커밋 순서: 빨강을 먼저 남긴다

1. 테스트만 커밋 → 3개 빨강(0x0F·0x1F는 예외, ESC는 글자 불일치)
2. 수정 커밋(`"0123456789abcdef"`) → 초록

수정이 한 글자라서, 테스트 없이 고치면 "정말 버그였는지"가 기록에 안 남는다. 빨강 커밋이 **버그가 있었다는 증거**다.

## 2. 설계와 다르게 한 곳

없음. 같은 파일 73줄의 메서드 참조(`::`)는 이번에 건드리지 않았다(커밋 하나에 한 가지, MVP 후 리팩터링 목록).

## 3. 더 나아가 알면 좋은 것

- JSON 명세(RFC 8259): U+0000~U+001F는 반드시 이스케이프. `\u` 뒤는 16진수 4자리(대소문자 모두 허용)
- 직접 만든 직렬화기(D-085: Starter는 Jackson을 안 씀)의 비용 — 이런 표 하나도 우리가 책임진다. 대신 팀 앱의 Jackson 버전과 충돌하지 않는다
- 왕복 테스트(round-trip)와 속성 기반 테스트: 0x00~0x1F 전부를 돌리는 한 줄짜리 반복이 더 확실했을 것
