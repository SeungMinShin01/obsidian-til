# AiOps - LLM 기본 모델과 실패 로그

> 허브: [[AiOps 프로젝트 MOC]]

**PR #58 `[AI-54] LLM 기본 모델 변경, 실패 로그 보강`** (hotfix) — 커밋 3개, 11/15 머지. 실제 키로 처음 돌렸을 때 설명이 계속 비어 있던 문제를 찾은 기록.

## 1. 배운 내용

### 1-1. 무슨 일이 있었나

| 본 것 | 뜻 |
|---|---|
| `llm_usage.call_count`는 오르는데 `ai_explanation`은 NULL | 호출은 나갔는데 답을 못 받았다 |
| 서버 로그: 정확히 20초 뒤 `RestClientException` | 읽기 타임아웃(20초)에 걸렸다 |
| 같은 키·주소로 직접 호출: 90초 동안 0바이트 | 서버 코드 문제가 아니라 그 모델이 답을 안 한다 |
| 모델만 `gemini-3.5-flash-lite`로 바꾸니 1.9초에 200 | 모델을 바꾼다 (D-107) |

직접 호출할 때 `curl -v`는 쓰지 않는다. `-v`는 `Authorization` 헤더(키)를 화면에 찍는다.

### 1-2. 고친 것

- `application.yml` 기본 모델을 `gemini-3.5-flash-lite`로.
- 실패 로그에 `cause=`(가장 안쪽 예외의 **클래스 이름만**)와 `model=`을 추가. 전에는 "실패"만 찍혀서 타임아웃인지 인증 오류인지 알 수 없었다.
- 200인데 본문이 비어 있으면 경고 한 줄. (답이 없는데 오류도 없는 경우)

예외 **메시지**를 로그에 넣지 않는 이유: 메시지에 요청 주소나 본문 조각(프롬프트 = 팀의 스택)이 섞일 수 있다. 클래스 이름은 `SocketTimeoutException`처럼 종류만 알려 준다 (규칙 10).

### 1-3. 같이 겪은 실수

- `.env`에 `AIOPS_LLM_MODEL=AIOPS_LLM_MODEL=gemini-…`처럼 이름을 두 번 붙여 넣었다. 서버 시작 로그의 `model=` 값으로 알아챘다.
- `.env`의 값이 있는지 "이름만" 확인하는 스크립트가 Windows 줄바꿈(CR)을 값으로 세어 "값이 있다"고 잘못 답했다. 줄 끝의 CR을 지우고 다시 세야 한다.

## 2. 남은 것

- 3.8-flash가 왜 답하지 않는지(일시적 과부하인지 무료 등급 때문인지)는 모른다. 유료 등급으로 바꿀 때(D-101) 모델을 다시 고른다
- AI가 위험한 조언(`ddl-auto: create` 등)을 할 수 있다 → 프롬프트에 한 줄 추가하는 PR을 따로 제안해 둠
