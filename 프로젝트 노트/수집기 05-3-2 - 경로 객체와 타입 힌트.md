# 수집기 05-3-2 - 경로 객체와 타입 힌트

> 상위: [[수집기 05-3 - append_run_log 함수 분석]]

`append_run_log`를 뜯어보다 걸린 두 가지를 따로 파고든 기록이다.

---

## `DATA_DIR = Path("data")`

### 세 조각으로 나뉜다

```python
DATA_DIR   =   Path("data")
  이름     담는다    값
```

상수로 지정한 것은 **값**이고, 그 값은 `data`라는 경로를 가리키는 **객체**다.

### `Path("data")`는 객체를 만드는 것이다

`Path`는 클래스이고 `Path("data")`는 그 클래스로 객체를 하나 만드는 호출이다. 자바의 `new`에 해당한다.

```java
Path DATA_DIR = Paths.get("data");     // 자바
```
```python
DATA_DIR = Path("data")                # 파이썬
```

### 이 줄은 폴더를 만들지 않는다

```python
DATA_DIR = Path("data")    # 폴더가 생기지 않는다
DATA_DIR.mkdir()           # 여기서 비로소 생긴다
```

`Path` 객체는 **주소를 적은 쪽지**다. 그 주소에 건물이 있든 없든 쪽지는 쓸 수 있다. 실제로 존재하지 않는 경로로도 만들 수 있다.

```python
p = Path("존재하지않는폴더/어딘가/파일.txt")   # 에러가 나지 않는다
p.exists()                                    # False
```

그래서 `Path` 객체가 하는 일은 두 가지다.

1. **경로를 기억한다** — `"data"`
2. **경로를 다루는 기능을 제공한다** — `.mkdir()`, `.exists()`, `.parent`, `.open()` 등

그냥 문자열 `"data"`를 썼다면 이런 기능이 없어서 `os.path.join()` 같은 것을 매번 불러야 한다. **문자열과 경로 관련 기능을 한 덩어리로 묶은 것**이 `Path`다.

### 상대 경로라는 함정

`"data"`는 `/home/...`처럼 시작점이 없는 **상대 경로**다. 그래서 **프로그램을 실행한 위치를 기준**으로 해석된다.

```
cd .../collector
python collector/main.py          → collector\data\ 에 생성

cd C:\Users\harry
python Desktop\수집기\collector\collector\main.py    → C:\Users\harry\data\ 에 생성
```

같은 코드인데 어디에서 실행하느냐에 따라 다른 곳에 만들어진다. 항상 저장소 루트에서 실행하면 문제가 없지만, 파일이 엉뚱한 곳에 생긴다면 대개 이것이 원인이다.

## 타입 힌트란

변수나 함수에 **여기에는 이런 종류의 값이 들어간다고 적어두는 메모**다.

### 세 군데에 붙는다

```python
name: str = "홍길동"                    # ① 변수
def greet(name: str) -> str:           # ② 매개변수  ③ 반환값
    return f"안녕 {name}"
```

- `이름: 타입` — 매개변수나 변수
- `-> 타입` — 반환값

### 파이썬은 이것을 무시한다

```python
def f(x: int) -> int:
    return "문자열입니다"      # int라고 해놓고 문자열을 반환

f("숫자 아님")                 # int라고 해놓고 문자열을 전달
```

이 코드는 그대로 실행된다. 에러가 나지 않는다. 자바라면 컴파일조차 되지 않는다.

파이썬은 원래 타입을 적지 않는 언어였고 나중에 **선택적으로** 추가된 기능이라 그렇다. 그래서 이름이 타입 선언이 아니라 **타입 힌트**다.

| | 자바 | 파이썬 |
| --- | --- | --- |
| 적는 위치 | 이름 앞 (`String name`) | 이름 뒤 (`name: str`) |
| 강제 여부 | 컴파일 시 검사 | 무시된다 |
| 적지 않으면 | 컴파일 에러 | 잘 돌아간다 |

### 무시되는데 왜 적는가

**① 편집기가 도와준다**

```python
def greet(name: str):
    name.        # ← 문자열 메서드 목록이 뜬다 (upper, strip, split ...)
```

타입을 적지 않으면 편집기가 `name`이 무엇인지 모르므로 아무것도 알려주지 못한다.

**② 검사 도구가 실수를 잡는다**

`mypy` 같은 도구를 돌리면 실행하기 전에 타입이 맞지 않는 곳을 찾아준다. 자바 컴파일러가 하는 일을 별도 도구가 대신한다.

**③ 문서 역할을 한다**

```python
def upsert_jobs(conn: sqlite3.Connection, jobs: list[dict], seen_at: str) -> int:
```

이 한 줄만 봐도 무엇을 넣고 무엇을 받는지 드러난다. 본문을 읽지 않아도 된다.

### 자주 쓰는 타입 이름

| 표기 | 뜻 | 예 |
| --- | --- | --- |
| `str` | 문자열 | `"안녕"` |
| `int` | 정수 | `42` |
| `float` | 실수 | `3.14` |
| `bool` | 참/거짓 | `True` |
| `None` | 값 없음 | `None` |
| `list[str]` | 문자열들의 목록 | `["a", "b"]` |
| `dict[str, int]` | 문자열에서 정수로 가는 사전 | `{"a": 1}` |
| `str \| None` | 문자열이거나 없거나 | 마감일이 없는 공고 |

### 이 프로젝트의 코드에서

```python
def now_utc() -> str:                              # 문자열을 돌려준다
def append_run_log(message: str) -> None:          # 문자열을 받고 아무것도 돌려주지 않는다
def connect() -> sqlite3.Connection:               # DB 연결 객체를 돌려준다
def count_jobs(conn: sqlite3.Connection) -> int:   # 연결을 받고 개수를 돌려준다
```

`DATA_DIR = Path("data")`에 타입 힌트가 없는 것은 `Path("data")`를 보면 타입이 뻔하기 때문이다. 명시하려면 이렇게 쓰지만 중복이라 보통 생략한다.

```python
DATA_DIR: Path = Path("data")
```

##  `LOG_FILE = DATA_DIR / "run-log.md"`

`data` 폴더 안의 `run-log.md`라는 **파일을 가리키는 경로**다.

```python
DATA_DIR = Path("data")               # data 폴더
LOG_FILE = DATA_DIR / "run-log.md"    # data/run-log.md 파일
```

`LOG_FILE`도 `DATA_DIR`과 똑같은 `Path` 객체다. 폴더를 가리키느냐 파일을 가리키느냐만 다르고 `Path` 입장에서는 둘 다 그냥 경로다.

그리고 이 줄도 파일을 만들지 않는다. 실제로 만들어지는 것은 `append_run_log` 안의 이 줄이다.

```python
with LOG_FILE.open("a", encoding="utf-8") as f:   # 여기서 없으면 만들어진다
```

### `/`의 정체 — 연산자 오버로딩

```python
DATA_DIR / "run-log.md"
```

`/`는 원래 나눗셈 기호인데 `Path` 클래스가 이 기호에 경로를 이어붙인다는 의미를 부여해두었다. 이것을 **연산자 오버로딩**이라고 한다.

```python
10 / 3                      # 나눗셈 → 3.33
Path("data") / "a.md"       # 경로 결합 → data/a.md
```

같은 기호인데 왼쪽에 무엇이 있느냐에 따라 동작이 달라진다. 파이썬은 클래스가 `+`, `-`, `/`, `==` 같은 기호의 동작을 직접 정의할 수 있게 해준다.

자바에는 이 기능이 없다. 유일한 예외인 `String`의 `+`는 언어가 특별히 봐준 것이지 직접 만들 수 있는 것이 아니다.

```java
Paths.get("data").resolve("run-log.md");    // 자바는 메서드 호출
```
```python
Path("data") / "run-log.md"                 // 파이썬은 연산자
```

이어붙이기도 된다.

```python
Path("data") / "채용" / "2026-08" / "공고.md"      # data/채용/2026-08/공고.md
```

### 왜 `Path("data/run-log.md")`라고 쓰지 않았나

**구분자를 직접 쓰지 않아도 된다**

```python
Path("data/run-log.md")       # 슬래시를 문자열에 박아 넣는다
DATA_DIR / "run-log.md"       # Path가 알아서 처리한다
```

첫 번째도 파이썬이 처리해주기는 하지만 두 번째가 OS를 신경 쓸 필요가 없다는 점에서 더 명확하다.

**폴더 경로를 한 곳에서만 정의한다**

이쪽이 더 중요한 이유다. 앞으로 이렇게 늘어난다.

```python
DATA_DIR = Path("data")
LOG_FILE = DATA_DIR / "run-log.md"
JOBS_DIR = DATA_DIR / "채용"
NEWS_DIR = DATA_DIR / "뉴스"
```

여기서 `data`를 `output`으로 바꾸려면 첫 줄만 고치면 나머지가 전부 따라온다. 문자열로 일일이 적었다면 네 군데를 고쳐야 하고 하나를 빠뜨리면 조용히 엉뚱한 곳에 파일이 생긴다.

같은 정보를 두 군데 이상 적지 않는다는 원칙을 **DRY**(Don't Repeat Yourself)라고 한다.
