# RAG 챗봇 - 규칙제안 01 - 프로젝트 접두사와 세션 등록

> 장부: [[RAG 챗봇 - 규칙제안 기록]]

**작성 세션:** RAG 챗봇 프로젝트 세션
**대상:** `_규칙/구역 규칙.yaml` → `zones.프로젝트 노트` · `CLAUDE.md` → 「세션 역할 분담」

## 1. 무엇이 문제인가

`프로젝트 노트/`에 세 번째 프로젝트가 들어왔는데, 구역 규칙의 접두사 목록이 두 개로 고정되어 있다.

```yaml
프로젝트 노트:
  prefix: "수집기 |WMS "
```

`RAG 챗봇 NN - 제목` 형식의 노트는 이 목록에 없으므로 검사기가 미등록 접두사로 보고하게 된다. 세션 역할표에도 이 프로젝트의 관할 행이 없어, 어느 세션이 이 노트들을 쓰는지가 문서에 없는 상태다.

두 파일 모두 마스터 세션 관할이므로 이 세션이 직접 고치지 않고 제안으로 올린다.

## 2. 제안

### 2-1. 접두사 등록

```yaml
프로젝트 노트:
  prefix: "수집기 |WMS |RAG 챗봇 "
```

### 2-2. 세션 역할표에 행 추가

| 세션 | 관할 (쓰기 가능) | 하는 일 |
| --- | --- | --- |
| **RAG 챗봇** | `프로젝트 노트/` (`RAG 챗봇` 접두사 노트) | 데이터시트 RAG 챗봇 팀 프로젝트의 **코드 이해 정리**. 파일명 `RAG 챗봇 NN - 제목` |

### 2-3. 이 프로젝트의 작성 원칙을 다르게 두는 것에 대한 승인 요청

기존 두 프로젝트와 목적이 반대라서, 노트를 만드는 기준을 다르게 두려 한다.

| | 수집기 · WMS | RAG 챗봇 |
| --- | --- | --- |
| 코드의 상태 | 만들어가는 중 | 이미 다 쓰여 있음 |
| 노트의 목적 | 설계 기록 — 무엇을 왜 선택했나 | 코드 이해 — 왜 이렇게 되어 있나 |
| 노트가 되는 계기 | 결정을 내린 순간 | **채팅에서 질문한 순간** |
| 장부 | 설계 변경 기록 · 로드맵 | 두지 않음 (정할 설계가 없음) |

구체적으로는 다음을 지킨다.

- 노트 하나가 질문 하나에 대응한다. **물어보지 않은 내용을 곁들여 채우지 않는다**
- 번호는 물어본 순서다
- 세부 노트(`NN-1`)는 질문이 실제로 갈라질 때만 만든다

구역 규칙의 `성격` 항목은 `프로젝트기록(중복 허용)` 그대로 두면 되고, 위 원칙은 프로젝트 MOC에 적어두는 선에서 운용할 수 있다고 본다. 다만 다른 세션이 이 폴더를 읽을 때 혼동하지 않도록 **승인 여부를 남겨두는 것**이 목적이다.
