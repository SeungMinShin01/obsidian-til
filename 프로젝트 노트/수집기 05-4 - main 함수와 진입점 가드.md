# 수집기 05-4 - main 함수와 진입점 가드

> 상위: [[수집기 05 - main.py 코드 분석]]

```python
def main() -> None:
    stamp = now_utc()
    append_run_log(f"실행: {stamp} UTC (python)")
    print(f"기록 완료: {stamp} UTC")


if __name__ == "__main__":
    main()
```

## 1. `main()` — 순서를 지휘하는 자리

이 함수는 스스로 일을 하지 않는다. **다른 함수들을 어떤 순서로 부를지만 정한다.** 이런 역할을 **오케스트레이터**라고 한다.

```python
stamp = now_utc()                 # 값을 받아온다
append_run_log(...)               # 파일에 남긴다
print(...)                        # 화면에 알린다
```

파일이 자라도 이 구조는 유지된다. 지금은 세 줄이지만 나중에는 이렇게 된다.

```python
def main() -> None:
    raw = saramin.fetch(keywords=[...])   # 수집
    jobs = normalize.to_jobs(raw)         # 정규화
    result = store.upsert(jobs)           # DB 대조·저장
    writer.render(result.new)             # 마크다운 생성
```

**이 함수만 읽으면 시스템이 무슨 순서로 일하는지 파악된다.** 실제 작업은 각 모듈이 맡고 여기는 흐름만 남긴다.

### `stamp` 변수에 담아둔 이유

```python
stamp = now_utc()
append_run_log(f"실행: {stamp} ...")
print(f"기록 완료: {stamp} ...")
```

`now_utc()`를 두 번 부르면 그 사이에 초가 넘어가 **파일에 적힌 시각과 화면에 찍힌 시각이 달라질 수 있다.** 한 번 찍어서 재사용한다.

### f-string

`f"..."`는 중괄호 안의 변수를 문자열에 끼워 넣는다. `stamp`가 `2026-08-12 08:58:53`이면 `실행: 2026-08-12 08:58:53 UTC (python)`이 된다.

### `print`를 넣은 이유

파일에만 쓰면 실행 중에 무엇이 일어났는지 알 수 없다. Actions 로그에 보이게 하려고 넣었다. 파일은 결과, `print`는 과정이다.

## 2. `if __name__ == "__main__":` — 진입점 가드

**이 파일이 직접 실행됐을 때만 아래를 실행하라**는 뜻이다.

### `__name__`은 파이썬이 자동으로 채운다

만들지 않았는데 모든 파일에 존재하고, 값은 **어떻게 실행됐느냐**에 따라 달라진다. 실제로 확인한 결과는 이렇다.

```
① helper.py 를 직접 실행
   [helper.py] __name__ = '__main__'        ← 직접 실행하면 "__main__"

② runner.py 가 helper 를 import
   [runner.py] __name__ = '__main__'        ← 실행된 쪽이 "__main__"
   [helper.py] __name__ = 'helper'          ← 불려온 쪽은 파일 이름
```

**지금 실행 중인 파일 하나만 `"__main__"`이 되고 나머지는 자기 파일 이름을 받는다.** 파이썬이 지금 주인공이 누구인지 표시해두는 것이다.

### 가드가 없으면 벌어지는 일

②번 출력에서 `[helper.py] 실행됨`이 찍혔다. `runner.py`는 함수 하나만 쓰려고 `import` 했는데 `helper.py` 안의 `print`가 딸려 실행된 것이다.

**`import`는 그 파일을 처음부터 끝까지 한 번 실행하는 동작이다.** 함수만 빼오는 것이 아니다. 그래서 파일에 실행 코드가 그냥 놓여 있으면 import할 때마다 같이 돌아간다.

가드를 넣으면 이렇게 갈린다.

```
③ 가드가 있는 helper2.py 를 직접 실행
   [helper2] 나는 직접 실행됐다!
   [helper2] 1+2 = 3

④ runner2.py 가 helper2 를 import
   [runner2] helper2.add(10, 20) = 30
   ← helper2의 main() 은 실행되지 않았다
```

함수는 가져다 쓰고 실행 코드는 돌지 않는다. 이 두 줄이 하는 일은 그것뿐이다.

## 3. 자바와 비교하면 왜 필요한지 드러난다

자바는 진입점이 언어 차원에서 정해져 있다.

```java
public static void main(String[] args) { ... }
```

`java Main`을 실행하면 JVM이 이 시그니처를 찾아서 부른다. 다른 클래스 파일은 실행 대상이 아니다.

**파이썬은 아무 파일이나 실행할 수 있다.** `python 아무거나.py`를 하면 그 파일이 위에서 아래로 그냥 실행된다. 진입점이라는 개념이 언어에 없다.

그래서 하나의 파일이 실행 대상이 될 수도 있고 불려오는 대상이 될 수도 있으며, 두 경우를 구분하려고 관용구가 만들어졌다.

| | 자바 | 파이썬 |
| --- | --- | --- |
| 진입점 | `public static void main` (언어가 정함) | 없음 — 실행한 파일이 곧 진입점 |
| 이름 | `main` 고정 | 아무거나 가능 (`main`은 관례) |
| 구분 장치 | 불필요 | `if __name__ == "__main__":` |

`main()`이라는 함수 이름은 순수한 관례다. `run()`이든 다른 이름이든 상관없다.

## 4. 지금 우리 코드에 필요한가

지금은 없어도 동일하게 동작한다. `main.py`를 import하는 파일이 아직 없기 때문이다.

다만 곧 필요해진다.

- `store.py`를 만들면 `main.py`가 `import store`를 한다. `store.py` 맨 아래에 테스트용 실행 코드를 그냥 두었다면 `main.py`를 돌릴 때마다 함께 실행된다
- 나중에 테스트 코드가 `main.py`의 `now_utc()`만 빌려 쓸 때, 가드가 없으면 **불러오는 순간 `run-log.md`에 줄이 하나 써진다.** 테스트가 실제 데이터를 오염시킨다

지금은 쓰지 않지만 붙여두는 두 줄이다. 비용이 없고 나중에 사고를 막아주므로 파이썬 스크립트에는 거의 항상 붙인다.
