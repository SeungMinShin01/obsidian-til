# 수집기 05-2 - now_utc 함수 분석

> 상위: [[수집기 05 - main.py 코드 분석]]

```python
def now_utc() -> str:
    """현재 시각을 UTC 문자열로 돌려준다."""
    return datetime.now(timezone.utc).strftime("%Y-%m-%d %H:%M:%S")
```

## 1. 이 함수의 역할

지금 몇 시인지에 답하는 함수다. 그리고 `append_run_log`와 성격이 정반대다.

| | `append_run_log` | `now_utc` |
| --- | --- | --- |
| 하는 일 | 파일을 바꾼다 (부수 효과) | 값을 만들어 돌려준다 |
| 반환 | `None` | `str` |
| 여러 번 부르면 | 줄이 계속 쌓인다 | 아무 일도 일어나지 않는다 |

바깥 세상을 건드리지 않고 값만 만들어 내는 함수다. 부수 효과가 없으므로 몇 번을 불러도 파일 하나 바뀌지 않는다.

엄밀히는 부를 때마다 결과가 달라지므로 **순수 함수는 아니다.** 시계를 읽는 순간 이미 바깥에 의존한다.

## 2. 한 줄이 두 단계로 이어져 있다

```python
datetime.now(timezone.utc).strftime("%Y-%m-%d %H:%M:%S")
```

끊어 보면 이렇다.

```python
① datetime.now(timezone.utc)      # 지금 시각을 UTC로 가져온다 → datetime 객체
② .strftime("%Y-%m-%d %H:%M:%S")  # 그 객체를 문자열로 바꾼다 → "2026-08-12 08:58:53"
```

①이 돌려준 객체에 곧바로 ②를 붙인 형태이고, 변수를 만들지 않고 이어 쓰는 것을 **체이닝**이라고 한다. 풀어 쓰면 두 줄이 된다.

```python
now = datetime.now(timezone.utc)
return now.strftime("%Y-%m-%d %H:%M:%S")
```

## 3. `timezone.utc`가 핵심이다

```python
datetime.now()              # 이 컴퓨터의 시간대 기준
datetime.now(timezone.utc)  # UTC 기준
```

`datetime.now()`는 **실행하는 컴퓨터마다 다른 값을 준다.**

- 로컬 PC에서 → 한국 시간 (17:58)
- GitHub VM에서 → UTC (08:58)

같은 코드인데 결과가 9시간 차이 난다. 그러면 `run-log.md`에 이런 기록이 쌓인다.

```
실행: 2026-08-12 17:58:53 UTC   ← 로컬에서 테스트한 것 (사실은 KST인데 UTC라고 적힌다)
실행: 2026-08-12 08:58:53 UTC   ← VM에서 돈 것
```

시간이 거꾸로 가는 것처럼 보이고, 나중에 언제 실행됐는지 분석할 때 데이터가 뒤섞인다.

그래서 이 함수의 진짜 목적은 **기준 시간대를 하나로 고정하는 것**이다. 어디에서 돌리든 같은 기준의 값이 나오게 한다.

> 실무 원칙: **저장은 UTC로, 보여줄 때만 현지 시간으로.** 서버가 어느 나라에 있든 사용자가 어디에 있든 데이터는 하나의 기준으로 쌓인다. 공고 마감일을 다룰 때 이 원칙이 다시 나온다.

## 4. `strftime`과 포맷 문자열

```python
.strftime("%Y-%m-%d %H:%M:%S")   →   "2026-08-12 08:58:53"
```

`strftime`은 **string format time**의 줄임말이고 `%`로 시작하는 기호가 각 자리를 뜻한다.

| 기호 | 뜻 | 예 |
| --- | --- | --- |
| `%Y` | 연도 4자리 | `2026` |
| `%m` | 월 2자리 | `08` |
| `%d` | 일 2자리 | `12` |
| `%H` | 시 24시간제 | `08` |
| `%M` | 분 | `58` |
| `%S` | 초 | `53` |

`%m`(월)과 `%M`(분)이 대소문자로만 갈리므로 헷갈리기 쉽다. `%Y-%m-%d`는 통째로 외워두는 편이 낫다.

**이 형식을 고른 이유**는 큰 단위부터 쓰면 **글자순 정렬이 곧 시간순 정렬**이 되기 때문이다. `08/12/2026` 같은 형식은 정렬하면 순서가 뒤죽박죽이 된다. SQLite에 날짜를 `TEXT`로 저장해도 문제가 없는 이유가 이것이다.

## 5. 더 나아가 알면 좋은 것

- `datetime.now()`와 `datetime.utcnow()`의 차이 — 후자는 시간대 정보가 없는 값을 돌려주어 혼란을 일으킨다
- **naive datetime과 aware datetime** — 시간대 정보를 가진 시각과 갖지 않은 시각. 둘을 섞으면 비교가 실패한다
- `strptime` — `strftime`의 반대. 문자열을 시각 객체로 되돌린다
- ISO 8601 형식(`2026-08-12T08:58:53+00:00`)과 `isoformat()`
- 시각에 의존하는 함수를 어떻게 테스트할 것인가
