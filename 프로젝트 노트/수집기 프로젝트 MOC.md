# 수집기 프로젝트 MOC

GitHub Actions로 무인 구동하는 수집 파이프라인 프로젝트의 허브다. 채용공고 수집에서 시작해 통계 분석과 면접 준비 재료 생성까지 확장하는 것이 최종 목표이고, 진행하면서 나눈 대화 중 지식으로 남길 부분만 주제별로 정리한다.

## 프로젝트 개요

| 항목 | 내용 |
| --- | --- |
| 목표 | 채용공고를 무인으로 수집·저장하고, 쌓인 데이터로 학습 우선순위와 면접 준비 재료를 뽑는 시스템 |
| 저장소 | `collector` (Private) — `Desktop/수집기/collector` |
| 구성 | Python 수집기 + SQLite 저장 + 마크다운 뷰 + Node.js 노션 미러링 |
| 실행 | GitHub Actions cron (매일 09:00 KST) |
| 첫 소스 | 사람인 오픈 API |

| [[수집기 12 - 인증키를 코드 밖에 두기]] | 환경변수는 터미널에만 산다, 로컬과 Actions Secret이 같게 도착한다, `[]`와 `.get()` |
| [[수집기 13 - 소스를 쓸 수 있는지 확인하는 순서]] | 명세에 권한 조건은 없다, 포털의 직접제공형과 링크형, robots가 살아도 서비스는 죽을 수 있다 |
| [[수집기 14 - 크롤링의 실제 경계]] | Private이 방어하는 범위, 회원 여부가 갈림길, 개인정보 필드 배제, 원본과 집계의 공개 경계 |
| [[수집기 15 - 크롤링 대상 조사와 법적 판단]] | robots가 열려도 약관이 막는다, 조항은 「복사·복제」로 표현된다, 판례는 요건의 묶음이다 |
| [[수집기 16 - 수집 빈도와 깊이]] | Private은 분이 계량된다, 딜레이와 빈도는 다른 축, 조기 종료, 백필과 증분의 분리 |
| [[수집기 17 - SPA를 만났을 때]] | 응답이 200이어도 내용은 별개, 내부 API와 헤드리스, 비용이 판단을 갈랐다 |

번호 뒤에 `-1`, `-2`가 붙은 노트는 해당 주제의 세부 노트다. 상위 노트에서만 연결하고 이 표에는 올리지 않는다.
