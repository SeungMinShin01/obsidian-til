# 수집기 프로젝트 MOC

GitHub Actions로 무인 구동하는 수집 파이프라인 프로젝트의 허브다. 채용공고 수집에서 시작해 통계 분석과 면접 준비 재료 생성까지 확장하는 것이 최종 목표이고, 진행하면서 나눈 대화 중 지식으로 남길 부분만 주제별로 정리한다.

## 프로젝트 개요

| 항목 | 내용 |
| --- | --- |
| 목표 | 채용공고를 무인으로 수집·저장하고, 쌓인 데이터로 학습 우선순위와 면접 준비 재료를 뽑는 시스템 |
| 저장소 | `collector` (Private) — `Desktop/수집기/collector` |
| 구성 | Python 수집기 + SQLite 저장 + 마크다운 뷰 + Node.js 노션 미러링 |
| 실행 | GitHub Actions cron (매일 09:00 KST) |
| 소스 | moef(공공기관 채용정보) · jumpit(개발자, 크롤링) |

## 로드맵

「진행 기록」이 지나온 것이라면, 이건 앞으로 갈 곳이다. **큰 단계만** 적는다 — 자잘한 할 일은 아래 백로그로 뺀다. 최종 목표(북극성)는 하나: **수집한 데이터로 "뭘 먼저 공부할지"와 "면접 준비 재료"를 뽑는다.** 수집은 목적이 아니라 재료 확보다.

| 단계 | 상태 | 내용 |
| --- | --- | --- |
| 1 · 수집 배관 | 완료 | Actions cron 무인 실행, 실패 격리 |
| 2 · 저장·뷰 | 완료 | SQLite 원본 + 마크다운 뷰 |
| 3 · 기초 통계 | 완료 | 기술 빈도 · 동시출현 · 마감임박 |
| 4 · 시간 변화 관측 | 다음 | 월별/전체로 "지금 뭐가 뜨나" 비교 |
| 5 · 면접 준비 재료 | 예정 | 우대사항·자격요건을 RAG로 정리 |
| (옵션) 노션 미러링 | 보류 | 필요해지면 |

지금 위치: **토대(1~3) 완성, 4단계 문턱.**

이 표 너머의 확장 구상(범용 수집기 전환, 논문·뉴스 크롤링, 웹 반환, LLM 산출)은 별도로 → [[수집기 로드맵 - 장기 구상]].

**로드맵은 두 층이다.** 위 표가 **현재 진실**(확정한 것)이고, 장기 구상 노트는 아직 확정 아닌 방향이다. 구상이 확정되면 → ① 위 표에 단계 행 추가 → ② 아래 「로드맵 변경이력」에 무엇을/왜 한 줄 → ③ 구상 노트엔 `(승격됨)`으로 남긴다. 승격 전까지 구상은 이 표에 올리지 않고, 역방향(표 → 구상)은 없다. 절차 원문은 구상 노트의 「승격 규칙」.

### 백로그 (로드맵 아님 — 잔손질)

단계 목표가 아니라 언젠가 손볼 것들. 끝나면 지운다.

- jumpit 747건 채우기 (회차마다 known_ids로 이어받는 중) — **끝나는 순간 완료일을 기록**할 것. 시계열의 신뢰 구간 시작점이라 그때 안 남기면 복원 못 한다 (로드맵 3번 전제조건)
- collect.yml 하루 5회 반영 + job·이름 정리 — **2026-09-04에 2회(09:00·18:00 KST)까지 반영**, 5회까지 3회 남음. 위상 문제(실제 갱신 12~13시)는 18시 추가로 해소됐고 남은 것은 빈도뿐이다 (로드맵 1번 전제조건)
- 코드 리팩토링 (별도 분석 세션)
- 크롤링 소스 추가 (직접 해보기로 함)
- 파이썬 문법 학습 세션

### 로드맵 변경이력

계획 자체가 바뀐 순간을 남긴다. 「진행 기록」(무엇을 **했나**)과 다르다 — 여기는 무엇을 하기로/안 하기로 **정했나**다. 커지면 별도 노트로 뺀다.

| 날짜 | 바뀐 것 | 이유 |
| --- | --- | --- |
| 2026-08-13~18 | 첫 소스를 **공식 오픈 API 지향 → 전부 막혀 moef 채택, 개발자 공고는 jumpit 크롤링** | 크롤링 리스크(약관·robots·판례) 없이 배관을 먼저 검증하려 공식 오픈 API를 지향. 그러나 ① 사람인 API 신청 3주째 무응답 ② 잡코리아(기업용)에 개인회원으로 신청양식 제출 → 거절 메일 ③ 알리오 등이 고용24 OpenAPI로 통합돼 키는 발급되나 실제 호출 시 "개인회원은 사용할 수 없음". 개인이 쓸 수 있는 건 공공기관(moef)뿐이라 채택 → 개발자 공고가 적어 jumpit 내부 API 크롤링을 추가 |
| 2026-09-03 | 실행 시각 **09:00의 근거를 기록**(값은 유지) | 하루 단위 갱신이라 1일 1회로 충분하다 봤고, 9:30 등교 전 09시에 결과를 확인하려 09:00 지정 — 09시에 갱신되는 줄 알았음. **실제 사이트 갱신은 대략 12~13시**라 근거가 어긋남. 하루 5회/시각 조정(백로그) 때 이 실제 시각을 반영할 것 |
| 2026-09-03 | 우대사항 분석을 3단계 통계 → **5단계(RAG)로 미룸** | 단순 집계로는 부족, 생성 단계에서 다룰 재료로 판단 |
| 2026-09-03 | 크롤링 소스 추가를 **직접 하기로** | 어댑터 패턴을 스스로 적용해보는 연습 |
| 2026-09-03 | 로드맵을 이 MOC에 명시 | 「앞으로」를 한눈에 볼 자리가 없었음 |
| 2026-09-03 | **범용 수집기로의 확장 구상**을 장기 로드맵으로 편입 | 채용 밖(논문·뉴스)으로 넓히기로. 데이터는 일찍 수집 → [[수집기 로드맵 - 장기 구상]] |
| 2026-09-03 | 로드맵을 **두 층으로 분리하고 승격 규칙을 명시** | 확정(이 표)과 구상(장기 노트)이 섞이면 "하기로 정한 것"의 경계가 흐려짐. 구상 → 합의 → 이 표로 승격 → 변경이력 한 줄. 역방향 없음 |
| 2026-09-03 | 0단계(축적) 종료 조건을 **사람 판단으로** 정함 | 며칠·몇 건 같은 기계 기준을 두지 않는다. 쌓인 것을 보고 착수 시점을 직접 정한다 |
| 2026-09-03 | 잡코리아 추가의 전제조건에 **약관·robots 재조사 통과**를 추가 | 잡코리아는 API가 거절돼 크롤링 경로다. 법적 판단은 겪고 고칠 수 없는 결정이라 데이터 축적만으로는 착수 조건이 못 된다 |
| 2026-09-03 | 잡코리아 추가의 목적을 **채용 데이터 극대화**로 못박음 | 기존 서술이 "차단·429를 겪는 것"을 목적처럼 읽히게 했음. 예의 있는 크롤링은 그대로 지키고, 그래도 생기는 조용한 실패·TIMEOUT을 관측해 Action 세분화(사이트별 시간대 분리)의 근거로 삼는다 — 일부러 부하를 일으키는 것이 아니다 |
| 2026-09-03 | 백로그 두 건을 **로드맵 전제조건으로 승격** (실행 빈도·시각 정리 → 1번 / jumpit 백필 완료·시점 기록 → 3번) | 잔손질로 뒀지만 순서를 가르는 항목이었음. ① 실행 시각 어긋남은 대부분 1일 지연으로 흡수되나 크기를 모름 ② 하루 5회 반영이 시각 문제까지 같이 푼다 ③ 백필과 증분이 섞인 구간은 시계열 기준선을 오염시키고, **완료일을 그때 안 남기면 신뢰 구간 시작점을 복원할 수 없다.** 1번 앞에 두는 이유는 데이터 손실보다 관측 조건 — 실행 설정이 어긋난 채로 실패하면 TIMEOUT의 원인을 가를 수 없어 4번의 근거가 안 선다 |
| 2026-09-03 | 논문·뉴스 수집을 **범용 전환(2번) 뒤에 그대로 둠** | 원칙 1(수집은 일찍)에 어긋나는 것을 알고 감수한다. 현재 우선순위가 채용공고에 있고 논문·뉴스는 당장 급하지 않음. 우선순위가 바뀌면 이 판단도 바뀐다 |
