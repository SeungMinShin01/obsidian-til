# 수집기 13 - 소스를 쓸 수 있는지 확인하는 순서

> 허브: [[수집기 프로젝트 MOC]]

「수집기 10 - 수집 대상을 고르는 기준」이 "골라도 되는가"(법·약관)였다면 이 노트는 **"쓸 수 있는가"**다. 층이 다르고, 이쪽을 먼저 확인해야 한다는 것을 두 번 헛걸음하고 알았다.

## 1. 배운 내용

### 1-1. 고용24 — 명세는 훌륭했지만 개인은 호출이 안 된다

고용24 채용정보 API는 명세도 좋고 필드도 풍부했다. 직무내용·우대조건·자격면허·전형방법까지 구조화되어 있어서 4단계 LLM 레이어에 그대로 쓸 재료였다.

인증키를 받아 호출하니 이렇게 돌아왔다.

```xml
<GO24>
  <error>개인회원은 사용할 수 없는 OPEN-API입니다.</error>
</GO24>
```

**고용24 OPEN-API는 기업회원 전용이다.** 신청 시 사업자등록번호를 요구하고, 개인회원 계정으로 발급된 키는 접근 권한이 없다. 신청은 되는데 호출 단계에서 걸린다.

### 1-2. 이 에러는 좋은 에러였다

인증 실패도 아니고 파라미터 오류도 아니었다. **키를 읽고, 계정을 조회하고, 권한이 없다고 답한 것**이다.

거꾸로 읽으면 이렇게 확인된다.

- 엔드포인트 주소가 맞았다
- 파라미터 조합이 받아들여졌다
- 키 자체는 유효하다
- 우리 호출 코드는 정상이다

막힌 것은 코드가 아니라 계정이었다. **에러 메시지가 구체적이면 그 자체가 진단 결과다.** #빠른실패 → [[개념 - 빠르게 실패하기]]

### 1-3. 명세서에 권한 조건은 안 적혀 있다

명세서에는 요청 URL, 파라미터, 응답 필드, 출처 표기 의무까지 다 있었다. 없는 것은 **누가 쓸 수 있는가**였다.

> 명세와 필드를 보기 전에, 내 계정으로 호출되는지부터 확인한다.

한 번 호출해보는 것이 문서를 읽는 것보다 빠르다.

### 1-4. 공공데이터포털의 데이터셋에는 두 종류가 있다

워크넷 채용정보가 공공데이터포털에도 올라와 있어 우회가 되는 줄 알았는데, 신청 버튼을 누르니 고용24로 돌려보냈다.

| 종류 | 어디서 호출하나 | 버튼 | 신청 |
| --- | --- | --- | --- |
| **직접 제공형** | `apis.data.go.kr/...` | 「활용신청」 | 포털에서 처리, 개발계정은 자동승인 |
| **링크형** | 기관 자체 서버 | 「바로가기」 | 기관 사이트에서 처리 — **기관 규칙이 그대로 살아 있다** |

워크넷 채용정보는 링크형이다. 포털은 목록에 이름만 걸어두고 실제 API는 고용24가 제공한다. **포털을 거친다고 기업회원 조건이 우회되지 않는다.**

앞으로 포털에서 API를 고를 때는 **요청 주소가 `apis.data.go.kr`로 시작하는지**만 보면 된다.

### 1-5. `robots.txt`가 살아 있어도 서비스는 죽어 있을 수 있다

프로그래머스는 「수집기 10 - 수집 대상을 고르는 기준」의 조사에서 `robots.txt`가 열려 있어 크롤링 후보 3순위에 올려뒀다. 그런데 **채용 서비스 자체가 2025년 5월 19일부로 종료됐다.**

`robots.txt`는 여전히 응답한다. 문은 열려 있는데 안에 아무도 없는 상태였다.

### 1-6. 그래서 확인 순서가 바뀐다

| 순서 | 확인할 것 | 방법 |
| --- | --- | --- |
| 1 | **서비스가 운영 중인가** | 공고 목록 페이지를 실제로 연다 |
| 2 | **내 계정 등급으로 접근되는가** | 한 번 호출해본다. 명세서에는 대개 안 적혀 있다 |
| 3 | 자동 접근을 거절했는가 | `robots.txt` |
| 4 | 약관이 자동 수집을 막는가 | 사이트 하단 이용약관 |
| 5 | 필드가 쓸 만한가 | 명세서와 실제 응답 |

앞의 둘이 새로 붙었다. **둘 다 몇 분이면 끝나고, 통과 못 하면 뒤의 셋은 볼 필요가 없다.**

### 1-7. 어댑터 격리가 막아주는 것과 아닌 것

이번 일로 구분이 분명해졌다.

| | 어댑터 격리로 대응되나 |
| --- | --- |
| 돌던 소스가 어느 날 죽는다 (HTML 구조 변경, 서버 장애) | **된다.** `try`/`except continue`로 그 소스만 건너뛴다 |
| 애초에 쓸 수 없는 소스 (권한 없음, 서비스 종료) | **안 된다.** 시작 전 차단이라 런타임 처리 대상이 아니다 |

두 번째는 코드로 풀 문제가 아니라 조사로 거르는 문제다. 그래서 이 노트가 필요하다.

## 2. 추가로 알면 좋은 활용법

### 2-1. 갱신된 후보 목록 (2026-08-13)

| 소스             | 상태     | 비고                                                    |
| -------------- | ------ | ----------------------------------------------------- |
| **사람인 API**    | 승인 대기  | JSON, 1일 500회, 최대 110건/회. **응답에 `keyword` 필드가 따로 있다** |
| 점핏             | 운영 중   | 사람인 계열사(`kr.co.saramin.jumpit`). 사람인 API에 포함되는지 확인 필요 |

| 공공기관 채용정보(알리오) | 즉시 가능  | 개인 자동승인, 직접 제공형. IT 비중은 낮음                            |

| 원티드 · 사람인(크롤링) | 제외     | `robots.txt`로 명시적 거절                                  |

### 2-2. JSON 소스가 XML보다 유리한 이유

사람인은 JSON을 준다. 파이썬 `json` 모듈이 표준 라이브러리라 **딕셔너리로 바로 떨어진다.** `store.upsert_jobs`가 이미 `list[dict]`를 받으므로 변환 계층이 얇아진다.

XML은 `xml.etree.ElementTree`로 트리를 훑어야 하고, 중첩 구조를 평평하게 펴는 코드가 따로 필요하다.

### 2-3. 출처 표기 의무는 공개 시점에 발생한다

고용24 명세에 이런 조건이 붙어 있었다.

- 상세 페이지에 「채용정보 제공사이트로 이동」 버튼 노출
- 하단에 출처 이미지 명기
- 무단복제 및 배포 금지

지금은 Private 저장소에 개인 보관이라 해당하지 않는다. **5단계에서 React 대시보드를 공개하면 그때 실제로 발생한다.** 어느 소스를 쓰든 API 약관에 비슷한 조항이 있으므로, 공개 시점에 전 소스의 약관을 다시 훑어야 한다.
