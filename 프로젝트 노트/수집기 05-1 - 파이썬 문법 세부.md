# 수집기 05-1 - 파이썬 문법 세부

> 상위: [[수집기 05 - main.py 코드 분석]]

[[수집기 05 - main.py 코드 분석]]을 읽다 걸린 파이썬 문법을 따로 파고든 노트다. 상위 노트는 코드가 무엇을 하는지를 다루고, 이 노트는 문법 자체를 다룬다.

질문을 소제목으로 두고 결론만 남긴다. 대화 흐름은 남기지 않는다.

---

## 2026-08-12 · `-> str`은 람다식인가

아니다. 자바의 람다 화살표와 모양만 같고 의미가 다르다.

파이썬에서 `->`는 **반환 타입 힌트**다. 두 언어가 반환 타입을 적는 위치가 달라서 생긴 차이다.

| | 반환 타입 위치 | 예 |
| --- | --- | --- |
| Java | 함수 이름 앞 | `String nowUtc() { ... }` |
| Python | 함수 이름 뒤, `->` 다음 | `def now_utc() -> str:` |

파이썬은 타입 표기를 나중에 추가한 언어다. 이미 `def 이름(매개변수):` 문법이 굳어 있어 앞에 끼워 넣을 자리가 없었고, 그래서 뒤에 화살표로 붙였다.

**결정적인 차이는 강제성이다.** 파이썬의 타입 힌트는 실행할 때 무시된다.

```python
def now_utc() -> str:
    return 123        # 숫자를 돌려줘도 그냥 돌아간다
```

자바라면 컴파일되지 않는다. 파이썬에서는 사람이 읽기 좋으라고, 편집기가 이상한 부분을 알려주라고 붙이는 메모에 가깝다. 없어도 동일하게 동작한다.

## 2026-08-12 · 파이썬 람다는 JS의 익명 함수와 비슷한가

비슷하다. 이름 없이 함수를 만들어 값처럼 넘긴다는 개념이 같다.

```js
const twice = function(x) { return x * 2; };   // JS 익명 함수
const twice = (x) => x * 2;                    // JS 화살표 함수
```

```java
Function<Integer,Integer> twice = x -> x * 2;  // Java
```

```python
twice = lambda x: x * 2                        // Python
```

**다만 파이썬 람다는 훨씬 좁다. 식 하나만 들어가고 여러 줄을 쓸 수 없다.**

```python
f = lambda x:
    y = x * 2      # 문법 에러
    return y + 1
```

여러 줄이 필요하면 `def`를 써야 한다. 이것은 제약이 아니라 의도다. 복잡한 로직에 이름이 없으면 읽기 나빠진다는 입장이라 문법으로 막아두었다. JS는 익명 함수 안에 로직을 잔뜩 넣는 것이 흔하지만 파이썬은 권하지 않는다.

**쓰이는 빈도도 다르다.** JS는 이벤트 핸들러, `setTimeout`, `map`/`filter`, 비동기 처리까지 콜백이 많아 익명 함수를 안 쓸 수 없다. 파이썬은 정렬 기준 같은 자리에 주로 등장한다.

```python
jobs.sort(key=lambda job: job["deadline"])    # 마감일 순 정렬
```

JS에서 `map`/`filter`로 하던 일은 파이썬에서 다른 문법으로 처리하는 경우가 많다.

```js
const titles = jobs.map(j => j.title);        // JS
```
```python
titles = [j["title"] for j in jobs]           # Python 리스트 컴프리헨션
```

리스트 컴프리헨션이 파이썬에서 람다의 자리를 상당 부분 대신한다.

### 세 언어 대응 정리

| 개념 | Java | JS | Python |
| --- | --- | --- | --- |
| 익명 함수 | `x -> x*2` | `(x) => x*2` | `lambda x: x*2` |
| 반환 타입 | 이름 앞 (`String f()`) | 없음 | 이름 뒤 (`def f() -> str`) |
| 타입 강제 | 컴파일 시 검사 | 없음 | 표기해도 실행 시 무시 |

## 2026-08-12 · 파이썬에 진짜 상수는 없나

언어 차원의 상수 키워드는 없다. 자바의 `final`이나 JS의 `const`에 해당하는 문법이 없어서 대문자 이름으로 약속한다. 다만 "바꾸지 못하게" 만드는 수단은 몇 가지 있고, 성격이 서로 다르다.

### 이름과 값은 다른 문제다

```python
DATA_DIR = Path("data")
DATA_DIR = Path("다른곳")     # 이름을 다시 가리키는 것 — 막을 방법이 없다
```

```python
t = (1, 2, 3)
t[0] = 9                      # 값을 바꾸는 것 — TypeError로 막힌다
```

파이썬이 제공하는 수단은 대부분 두 번째(값의 불변)이고, 첫 번째(재할당 금지)는 관례에 맡긴다.

### 세 가지 수단

**`Final` — 의도를 선언만 한다**

```python
from typing import Final

DATA_DIR: Final = Path("data")
DATA_DIR = Path("다른곳")     # 실행은 된다. 편집기와 검사 도구만 경고한다
```

타입 힌트와 같은 성격이다. 실행할 때는 무시된다.

**`frozenset` / `tuple` — 값 자체가 바뀌지 않는다**

```python
KEYWORDS = frozenset({"Java", "Spring", "Python"})
KEYWORDS.add("Go")            # AttributeError
```

`set`은 내용을 바꿀 수 있지만 `frozenset`은 못 바꾼다. 다만 `KEYWORDS = ...`로 통째로 갈아끼우는 것은 여전히 막지 못한다.

**`Enum` — 유일하게 실행 중에도 막힌다**

```python
from enum import Enum

class Status(Enum):
    ACTIVE = "active"
    CLOSED = "closed"

Status.ACTIVE = "뭔가"        # AttributeError: cannot reassign member
```

파이썬에서 가장 상수에 가까운 것이고 자바의 `enum`과 거의 같다.

### 이 프로젝트에서 쓰게 될 자리

공고 상태처럼 값의 종류가 정해진 것은 `Enum`이 맞다. 문자열로 `"active"`를 여기저기 적으면 오타 하나에 조용히 망가지지만, `Enum`이면 없는 값을 쓰는 순간 에러가 난다.

```python
class JobStatus(Enum):
    ACTIVE = "active"
    CLOSED = "closed"
    REPOSTED = "reposted"

TECH_KEYWORDS = frozenset({"Java", "Spring", "Docker"})
```

### 다른 언어와의 대응

| | Java | JS | Python |
| --- | --- | --- | --- |
| 재할당 금지 | `final` | `const` | 없음 (대문자 관례 · `Final`은 검사 도구용) |
| 값 불변 | 불변 객체 | `Object.freeze` | `tuple`, `frozenset` |
| 열거형 | `enum` | 없음 (객체로 흉내) | `Enum` — 재할당이 실제로 막힌다 |

## 2026-08-12 · `__name__`은 파이썬의 생성자인가

아니다. 생성자에 해당하는 것은 `__init__`이고 `__name__`은 그냥 변수다.

### 던더가 공통점이라 헷갈린다

앞뒤로 `__`가 붙은 이름을 **던더**(double underscore)라고 부른다. 파이썬이 특별하게 다루는 이름이라는 표시일 뿐, 하는 일은 제각각이다.

| 던더 | 정체 |
| --- | --- |
| `__name__` | **변수.** 파이썬이 자동으로 채워주는 값 (직접 실행이면 `"__main__"`) |
| `__init__` | **메서드.** 객체가 만들어질 때 자동 호출된다 |
| `__str__` | 메서드. `print()`할 때 어떻게 보일지 정한다 |

`main.py`의 `__name__`은 이 파일이 어떻게 실행됐는지 알려주는 변수이고 클래스와는 무관하다.

### `__init__`이 자바 생성자에 대응한다

```java
public class Job {
    private String title;

    public Job(String title) {        // 생성자
        this.title = title;
    }
}

Job j = new Job("백엔드 개발자");
```

```python
class Job:
    def __init__(self, title):        # 초기화 메서드
        self.title = title

j = Job("백엔드 개발자")
```

| | Java | Python |
| --- | --- | --- |
| 이름 | 클래스 이름과 동일 | 항상 `__init__` |
| 자기 자신 | `this` (자동으로 있음) | `self` (첫 번째 매개변수로 직접 적는다) |
| 객체 생성 | `new` 키워드 | 클래스 이름을 함수처럼 호출 |
| 오버로딩 | 여러 개 가능 | 하나만. 기본값 인자로 대체한다 |

`self`는 메서드마다 첫 번째 자리에 직접 적어야 하지만 부를 때는 넘기지 않는다. 파이썬이 자동으로 채운다.

생성자 오버로딩이 없으므로 기본값으로 처리한다.

```python
class Job:
    def __init__(self, title, company=None):   # company는 생략할 수 있다
        self.title = title
        self.company = company
```

### 엄밀히는 생성자가 아니다

객체를 실제로 만드는 것은 `__new__`이고 `__init__`은 이미 만들어진 객체에 값을 채운다. 그래서 파이썬 문서는 `__init__`을 생성자가 아니라 **초기화 메서드**라고 부른다. `__new__`를 직접 다룰 일은 거의 없다.

### 이 프로젝트에서 만날 자리

공고 데이터를 다루기 시작하면 나온다.

```python
from dataclasses import dataclass

@dataclass
class Job:
    id: str
    title: str
    company: str
    deadline: str | None = None
```

`@dataclass`를 붙이면 `__init__`을 파이썬이 대신 만들어준다. 자바에서 롬복의 `@Data`가 하는 일과 같다. 필드만 선언하면 생성자와 문자열 표현, 비교 연산이 자동으로 생긴다.

## 2026-08-12 · `-> None`은 무슨 뜻인가

`None`은 파이썬에서 값이 없음을 나타내는 값이고 자바의 `null`, JS의 `null`에 해당한다. 그러므로 `-> None`은 이 함수가 돌려주는 값이 없다는 표시이고 자바의 `void`와 같은 자리다.

```python
def now_utc() -> str:                    # 문자열을 돌려준다
def append_run_log(...) -> None:         # 아무것도 돌려주지 않는다. 일만 한다
def connect() -> sqlite3.Connection:     # 연결 객체를 돌려준다
```

호출하는 쪽을 보면 차이가 드러난다.

```python
stamp = now_utc()          # 결과를 받아서 쓴다
append_run_log(message)    # 시키기만 한다 (받을 것이 없다)
```

### 자바의 void와 미묘하게 다르다

파이썬은 **모든 함수가 무언가를 돌려준다.** `return`을 쓰지 않으면 파이썬이 `None`을 돌려준다.

```python
def hello():
    print("안녕")
    # return이 없다

x = hello()
print(x)        # None
```

자바에서 `void` 메서드의 결과를 변수에 담으면 컴파일 에러가 나지만 파이썬은 담긴다. 안에 `None`이 들어있을 뿐이다.

| | 자바 | 파이썬 |
| --- | --- | --- |
| 표기 | `void` | `-> None` |
| 실제 반환 | 없음 | `None`이라는 값을 돌려준다 |
| 결과를 변수에 | 컴파일 에러 | 가능 (`None`이 들어간다) |

엄밀히는 `-> None`이 반환이 없다는 뜻이 아니라 `None`을 반환한다는 뜻이다.

### `None` 비교는 `is`로 한다

```python
if value is None:        # 관용구
if value == None:        # 동작은 하지만 쓰지 않는다
```

`None`은 프로그램 전체에 하나만 존재하는 값이라 같은 값인지(`==`)가 아니라 바로 그것인지(`is`)로 확인한다.

### 있을 수도 없을 수도 있는 값

```python
deadline: str | None = None
```

`str | None`은 문자열이거나 없거나라는 뜻이다. 마감일이 없는 공고도 있기 때문이다. 자바의 `Optional<String>`과 같은 개념이다.

타입 힌트이므로 이것 역시 강제되지 않는다. 어겨도 실행된다.
