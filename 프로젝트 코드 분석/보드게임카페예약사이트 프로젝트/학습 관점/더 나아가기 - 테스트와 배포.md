# 더 나아가기 - 테스트와 배포

"코드가 실행돼봤는가"와 "내 컴퓨터 밖에서 도는가" — 프로젝트를 완성으로 이끄는 마지막 두 축입니다.
허브: [[보드게임카페예약사이트 프로젝트에서 배울 것]]

## 1. 테스트 — 스모크에서 경계값까지

### 출발점이 된 사고

`adminController.js`에 `const db = require(...)`가 빠진 채 커밋돼 있었습니다( [[controllers와 models 분석]] ). 호출되는 순간 죽는 코드 — 즉 **한 번도 실행된 적 없는 코드가 저장소에 있었다**는 뜻입니다. 전 엔드포인트를 한 번씩 호출하는 스모크 테스트만 있어도 걸렸습니다.

### 1단계 — supertest 스모크

```javascript
const request = require("supertest");
const app = require("../app");   // listen 분리가 선행 조건 (아래)

describe("스모크", () => {
  test.each([
    "/api/games", "/api/notices", "/api/admin/users", "/api/admin/stats",
  ])("GET %s 가 5xx가 아니다", async (url) => {
    const res = await request(app).get(url);
    expect(res.status).toBeLessThan(500);
  });
});
```

여기서 첫 번째 리팩토링 필요가 나옵니다 — `server.js`가 `app` 생성과 `listen`을 한 파일에서 하고 있어서 테스트가 서버를 실제로 띄우게 됩니다. `app.js`(생성)와 `server.js`(listen)를 나누는 것이 관례이고, **"테스트하기 어렵다 = 분리가 덜 됐다"는 신호 읽기**의 첫 사례입니다.

### 2단계 — 테스트 DB 분리

`.env.test`에 별도 DB(`shirhal_test`)를 두고, 테스트 전후로 테이블을 초기화합니다. 환경변수 분리( [[더 나아가기 - 인증과 보안]] )가 여기서도 선행 조건이 됩니다 — 하드코딩된 `config/db.js`로는 테스트 DB 전환 자체가 불가능합니다. **좋은 구조는 테스트가 강요한다**는 것을 반복해서 확인하게 됩니다.

### 3단계 — 핵심 로직의 경계값

구간 겹침 판정( [[공부할 코드 - SQL과 데이터]] )이 최고의 대상입니다.

```
10:00~12:00 예약이 있을 때:
  12:00~14:00 → 성공해야 함 (경계 맞닿음은 겹침 아님)
  11:59~14:00 → 409
  09:00~13:00 → 409 (기존을 감싸는 경우 — 흔한 구현 누락)
  10:30~11:30 → 409 (기존에 포함되는 경우)
```

경계값(`>` vs `>=`)과 포함 관계가 정확히 검증됩니다. 이걸 DB 없이 테스트하려면 판정 로직을 순수 함수로 추출해야 하고 — 또 한 번 테스트가 구조를 개선시킵니다.

## 2. 스키마를 코드로 — schema.sql과 마이그레이션

저장소에 `.sql`이 없어서 테이블 구조를 쿼리에서 역추적해야 하고, `models/`와 실제 스키마가 어긋난 것도 원본이 없었기 때문입니다( [[controllers와 models 분석]] ).

1. **역생성**: 현재 DB에서 `SHOW CREATE TABLE` 8개 → `schema.sql`로 커밋. 이것만으로 "새 컴퓨터에서 프로젝트 재현"이 가능해진다
2. **제약 보강**: 이 기회에 `game_likes(user_id, game_id)` UNIQUE, FK 관계를 추가 — [[더 나아가기 - 동시성과 트랜잭션]] 의 최종 방어선 작업과 동일
3. **마이그레이션 도구**(knex 등): 스키마 변경을 번호 붙은 파일로 관리 — "스키마 변경도 커밋이 된다". `models/`가 스키마와 어긋나는 사고가 구조적으로 불가능해진다

연결: SQL day02 테이블과 제약조건 의 DDL이 "파일로 관리되는 순간" 실무가 됩니다.

## 3. 첫 배포 — 하드코딩이 전부 터지는 날

이 프로젝트를 그대로 배포하면 터지는 것들이 정확히 학습 목록입니다.

| 터지는 것 | 배우는 것 |
| --- | --- |
| `http://localhost:5000` 절대경로 4곳 | 상대경로 통일, API 베이스 URL 환경변수화 |
| CRA `proxy` (개발 전용) | nginx 리버스 프록시로 `/api` → 백엔드 연결 |
| `config/db.js` 하드코딩 | 환경변수 — 로컬/운영이 같은 코드, 다른 설정 |
| Toss 테스트 키·Syncfusion 키 | 시크릿 관리, 클라이언트 키/시크릿 키 구분 |
| `npm start` (개발 서버) | `npm run build` 정적 산출물 + 프로세스 매니저(pm2) |

**추천 순서는 "배포 먼저, 개념 나중"입니다.** 작은 구성(프론트 정적 호스팅 + 백엔드 1대 + DB)으로 일단 올려보면, 위 다섯 개가 왜 필요한지 하루 만에 몸으로 연결됩니다. 미리 개념부터 쌓는 것보다 빠릅니다.

배포 후 확인 목록이 곧 복습입니다: CORS가 실제로 어떻게 동작하는가(프록시가 사라진 세계), 환경변수는 어디서 주입되는가, DB는 누가 접속할 수 있는가( [[더 나아가기 - 인증과 보안]] 의 최소 권한).
