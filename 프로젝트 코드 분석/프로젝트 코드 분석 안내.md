# 프로젝트 코드 분석

이전에 진행한 **실제 프로젝트 코드**를 분석한 기록이 모이는 곳입니다.

상위: [[Vault 홈]]

## 이 폴더의 기록 방식

학습노트와 다릅니다. **개발자 일지 형식**으로 씁니다.

| | 학습노트 (언어 폴더) | 프로젝트 분석 (이 폴더) |
| --- | --- | --- |
| 목적 | 개념을 익히고 남기기 | 코드를 파악한 과정을 남기기 |
| 구성 | 배운 내용 → 활용법 → 심화 | 목표 → 살펴본 것 → 판단·근거 → 막힌 것 |
| 시점 | 주제 중심 | **날짜 중심, 시간순** |
| 남기는 것 | 정리된 결론 | **결론 + 그 판단에 이른 근거와 시행착오** |

템플릿: `_템플릿/프로젝트 분석 템플릿.md`

## 파일 이름

프로젝트마다 폴더 하나 + **상위 노드(MOC) 하나**를 만듭니다.

```
프로젝트 코드 분석/
└── <프로젝트명>/
    ├── <프로젝트명> MOC.md          ← 상위 노드. 이 프로젝트의 모든 노트가 여기 매달린다
    ├── 전문용어 정리.md              ← 분석에 나온 용어 사전
    ├── <코드 폴더별 분석 노트들>     ← back-end/ front-end/ 등 저장소 구조대로
    └── 학습 관점/                   ← 공부할 코드 + 더 나아가기
```

### 연결 규칙 (중요)

- 프로젝트 안의 노트는 **자기 프로젝트 MOC와 프로젝트 내부 노트**에만 링크한다
- **KDT 학습 노트(day 노트·언어 MOC)와 직접 링크하지 않는다** — 학습과의 연결은 `프로젝트 MOC ↔ [[KDT_2026 학습 지도]]` 한 줄이 전부이고, 세부 대응은 학습 지도의 **프로젝트 매핑표**에 둔다
- 프로젝트끼리도 서로 링크하지 않는다 (각자 독립 덩어리)
- 그래프뷰에서 프로젝트마다 MOC를 중심으로 한 덩어리씩 뭉치는 것이 목표 상태다

## 분석을 요청할 때

프로젝트 폴더를 연결해 주시면 다음 순서로 진행합니다.

1. 저장소 전체 훑기 — 구조·기술스택·진입점 파악
2. 핵심 파일부터 정독
3. 데이터 흐름 추적
4. 일지 작성 — 판단 근거와 막힌 지점 포함
