스킴이란?
URI 맨 앞에 붙는 이름표로, 뒤에 오는 주소를 어떤 규칙으로 해석하고 어떻게 접근할지를 정하는 부분이다.

https://www.example.com/search?q=cs
└┬┘
 스킴
왜 필요한가?
주소 문자열만 봐서는 그걸로 무엇을 해야 할지 알 수 없다는 문제가 있다.
example.com/a 를 웹 서버에 요청을 보내야하는지, 컴퓨터 디스크에서 파일을 찾아야 하는지, 메일 프로그램을 열어야 하는지 판단한 근거가 없다는 것이다.

스킴은 이 판단을 주소 자체가 들고 다니게 만든다. 

주소 문자열 받음 
→ 첫 번째 ':' 앞을 잘라 스킴 확인 ("https") 
→ 그 스킴을 처리할 담당자 선택 (HTTPS 처리 모듈) 
→ 나머지 부분을 그 스킴의 문법대로 해석 (호스트 / 경로 / 쿼리) 
→ 해당 방식으로 동작 실행

스킴이 달라지면 처리할 담당자와 문법의 해석이 달라진다.
|주소|스킴|실제로 하는 일|
|---|---|---|
|`https://example.com/a`|`https`|암호화된 연결로 웹 서버에 요청|
|`mailto:harry@example.com`|`mailto`|메일 작성 창을 염|
|`file:///C:/users/harry/note.md`|`file`|로컬 디스크에서 파일을 읽음|
|`jdbc:mysql://localhost:3306/db`|`jdbc`|JDBC 드라이버를 골라 DB에 접속|

스킴의 경계
첫번쨰 콜론(:) 앞 까지가 스킴. 콜론은 구분자일 뿐 스킴에 포함되지 않는다.
// 는 뒤에 호스트 이름(authority)이 이어진다는 표시다.

스킴 ≠ 프로토콜
`https` 스킴은 HTTPS 프로토콜을 쓰지만, 
- **프로토콜**: 네트워크에서 데이터를 주고받는 통신 규약
- **스킴**: 이 주소를 어떻게 해석할지 정하는 이름
mailto, data, urn은 스킴이지만 통신 프로토콜이 아니다. 즉, 스킴 = 프로토콜은 아니다.

// 가 붙는 이유
// 의 유무는 "호스트라는게 존재하는가"로 갈리는 게 아닌
주소 문법상 authority(접속 대상) 자리가 따로 있는가.이다
https://example.com/a
      └┬┘└────┬────┘
       │   authority 구획 → 여기로 접속해라
     "이제 authority 나온다"는 표시

mailto:harry@example.com
       └────────┬───────┘
          통째로 "메일함 이름"
        (접속 대상이 아니라 식별자)
htpps 에서 파서는 // 다음 조각을 잘라내 "연결할 대상"으로 넘긴다.
mailto 에서는 user@example.com 전체가 하나의 문자열로 메일 클라이언트에 전달될 뿐.

file:///C:/users/...

///가 세 개이며, // 다음에 아무것도 없이 바로 /C:/... 가 나온다.

- // 와 /C: 사이가 호스트 자리이다. 생략이 아닌 비어있다.
     file :// (빈칸) /C:/users/harry/note.md
      └┬┘  └┬┘  └──────────┬─────────┘
      선언  비었음          경로
호스트 자리를 채우면 다른 컴퓨터의 파일을 가리킬 수도 있다. 
예: `file://server1/share/note.md`

443 은 https 의 기본 포트
80 - http 포트

주소에 적혀있지 않아도 스킴마다 기본 포트가 정해져 있어서, 안 쓰면 그 값이 채워진다.

스킴 정리
스킴은 URI 문자열을 **누가**, **어떤 문법으로**, **무엇을 기본값으로 두고** 처리할지를 결정하는 부분이다. 통신 프로토콜을 고르는 건 그 결과 중 하나일 뿐이다.

① 담당자 — 이 문자열을 누가 처리하나 (HTTPS 모듈 / 메일 클라이언트 / 파일 시스템) 
② 문법 — 뒷부분을 어떻게 쪼개 읽나 (// 가 오나, 무엇이 authority인가) 
③ 기본값 — 안 적힌 칸을 무엇으로 채우나 (빈 호스트 = 이 컴퓨터, 포트 = 443)
