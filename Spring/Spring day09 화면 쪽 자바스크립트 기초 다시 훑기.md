# Spring day09 — 화면 쪽 자바스크립트 기초 다시 훑기

> 실습 파일: `static/day09/index.html`, `static/day09/index.js`
> 허브: [[Spring MOC]] · 이전: [[Spring day08 쿼리 메소드와 네이티브 쿼리]]

day08까지는 서버 쪽만 다뤘습니다. 리포지토리의 빈 몸통을 이름과 SQL로 채우는 자리에서 끝났고, 그 앞의 네 노트는 자바 문법(호출 표기·람다·스트림·메소드 레퍼런스)으로 나가 있었습니다.

이번 자리는 방향이 반대입니다. `resources/static` 아래에 day09 폴더를 새로 두고, 화면 쪽 코드를 서버가 내보내는 정적 파일로 붙여 자바스크립트 문법을 처음부터 다시 훑습니다. 다루는 것은 변수·상수, 배열을 도는 세 메소드, 함수를 적는 네 모양 — 앞으로 화면과 API를 잇는 코드에서 계속 쓰게 될 표기들입니다.

정리하면 **서버가 다 만들어 둔 JSON을 받아 그릴 쪽의 문법을, 실제로 쓰기 전에 한 번 훑어 두는 자리**입니다.

## 1. 배운 내용

### 1-1. HTML이 자바스크립트를 데려오는 한 줄

```html
<!doctype html>
<html lang="ko">
  <head>
    <meta charset="utf-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1" />
    <title>Page Title</title>
  </head>
  <body></body>
  <script src="index.js"></script>
</html>
```

`<script src="index.js"></script>` 한 줄이 별도 파일의 코드를 이 문서 안으로 끌어옵니다. 파일이 갈라져 있어도 **브라우저가 보기에는 HTML 문서 하나에 코드가 포함된 것과 같습니다.** 파일을 나누는 것은 사람이 읽기 위한 구분이지, 실행 단위가 나뉘는 것은 아닙니다.

`src` 값이 `index.js` 라는 상대 경로인 점이 중요합니다. 이 HTML이 `/day09/index.html` 로 열리면 스크립트는 `/day09/index.js` 를 찾습니다. `resources/static` 아래의 폴더 구조가 곧 주소가 되는 규칙이 여기서도 그대로 적용됩니다.

| 항목 | 정리 |
| --- | --- |
| `<script src="…">` | 외부 파일을 문서에 포함. 내용은 태그 사이에 적지 않는다 |
| 경로 | HTML이 열린 주소 기준의 상대 경로 |
| 두는 자리 | body 끝(또는 닫는 태그 뒤) — DOM이 만들어진 뒤 코드가 돌게 하기 위해 |
| `<meta charset="utf-8">` | 한글이 깨지지 않게 문서 인코딩을 먼저 정해 두는 자리 |

`<script>` 를 문서 위쪽(head)에 두면 아직 만들어지지 않은 요소를 찾게 되어 값이 비는 일이 생깁니다. 끝에 두는 관용은 그래서 붙었습니다.

### 1-2. `let` 과 `const` — 다시 대입할 수 있는가

```javascript
let count = 10;
count = 3;

const count2 = 20;
// count2 = 4;
```

`let` 은 값을 다시 대입할 수 있고, `const` 는 선언할 때 정한 값을 다시 대입할 수 없습니다. 주석으로 막아 둔 줄을 살리면 그 자리에서 오류가 납니다.

여기서 갈리는 것은 **"이름이 가리키는 대상을 바꿀 수 있는가"** 하나입니다. 값 자체가 얼어붙는 것은 아닙니다.

```javascript
const array = [10, 20, 30, 40, 50];
array.push(60);   // 된다 — 배열의 내용을 바꾼 것
// array = [1, 2]; // 안 된다 — 이름이 가리킬 대상을 바꾼 것
```

배열이나 객체를 `const` 로 두어도 안의 내용은 바뀝니다. `const` 가 막는 것은 재대입뿐이라, 실제 코드에서는 대부분을 `const` 로 두고 정말 다시 대입할 것만 `let` 으로 두는 편이 안전합니다.

| 키워드 | 재대입 | 재선언 | 유효 범위 |
| --- | --- | --- | --- |
| `let` | 가능 | 불가 | 블록(`{}`) |
| `const` | 불가 | 불가 | 블록(`{}`) |
| `var` | 가능 | 가능 | 함수 |

`var` 는 같은 이름을 두 번 선언해도 지나가고 범위가 함수 단위라 의도치 않게 값이 겹치는 자리가 생깁니다. 지금은 `let`·`const` 둘만 쓰는 편이 관용입니다.

### 1-3. 배열을 도는 세 메소드

```javascript
const array = [10, 20, 30, 40, 50];

array.forEach((value) => {
  console.log(value);
});

const newArray = array.map((value) => {
  return value;
});

const newArray2 = array.filter((value) => {
  return value >= 20;
});
```

셋 다 "배열을 처음부터 끝까지 돌면서 넘겨준 함수를 요소마다 부른다"는 점은 같습니다. 갈리는 것은 **무엇을 돌려주는가**입니다.

| 메소드 | 돌려주는 것 | 개수 | 타입 |
| --- | --- | --- | --- |
| `forEach` | 없음(`undefined`) | — | — |
| `map` | 새 배열 | 원본과 같음 | 콜백이 `return` 한 값의 타입 |
| `filter` | 새 배열 | 조건을 통과한 것만 | 원본과 같음 |

- `forEach` 는 결과를 안 돌려주므로, 값을 만들어 내는 것이 아니라 **요소마다 무언가를 하는** 자리에 씁니다(출력·화면에 붙이기 등)
- `map` 은 개수를 그대로 두고 **타입·모양을 바꿉니다.** 위 코드처럼 받은 값을 그대로 돌려주면 내용이 같은 새 배열이 나옵니다
- `filter` 는 타입을 그대로 두고 **개수를 줄입니다.** 콜백이 참을 돌려준 요소만 남습니다. `array.filter((value) => value >= 20)` 의 결과는 `[20, 30, 40, 50]` 입니다

셋 모두 **원본 배열을 바꾸지 않습니다.** `map`·`filter` 는 새 배열을 만들어 돌려주고, 원래 배열은 그대로 남습니다. 그래서 결과를 받을 변수를 따로 두는 표기가 붙습니다.

`return` 을 빠뜨리면 `map` 의 결과가 `undefined` 로 가득 찬 배열이 되고, `filter` 는 아무것도 통과하지 못해 빈 배열이 됩니다. 오류가 나지 않고 결과만 비므로, 값이 이상하면 콜백의 `return` 부터 보는 편이 빠릅니다.

### 1-4. 함수를 적는 네 모양

```javascript
// 선언적 함수
function func1(매개변수1, 매개변수2) {}

// 익명(이름 없는) 함수 — 변수에 담거나 인수로 넘겨 쓴다
const func2 = function (매개변수1, 매개변수2) {};

// 화살표 함수
const func4 = (매개변수1, 매개변수2) => {};

// 기본값을 가진 매개변수
const func5 = (매개변수1, 매개변수2, 매개변수3 = 'student') => {};
```

같은 일을 적는 네 표기이고, 아래로 갈수록 짧아집니다.

| 모양 | 이름 | 특징 |
| --- | --- | --- |
| `function 이름() {}` | 있음 | 선언 위치보다 먼저 불러도 동작(호이스팅) |
| `function () {}` | 없음 | 값이라 변수에 담거나 인수로 넘길 수 있다 |
| `() => {}` | 없음 | 익명 함수를 더 줄인 표기 |
| `(a, b = 'x') => {}` | 없음 | 인수를 안 보내면 기본값이 들어간다 |

**익명 함수가 필요한 이유**는 함수를 값처럼 다루기 위해서입니다. 이름을 붙일 자리가 필요 없는 곳 — 예를 들어 `forEach` 에 넘기는 콜백 — 에서는 이름이 오히려 군더더기가 됩니다. 앞의 배열 예제에서 `(value) => { … }` 로 적은 것이 전부 이 자리입니다.

화살표 함수의 축약 규칙도 함께 정리하면 이렇습니다.

```javascript
(value) => { return value >= 20; }  // 기본형
(value) => value >= 20              // 몸통이 식 하나면 중괄호와 return을 함께 생략
value => value >= 20                // 매개변수가 하나면 괄호도 생략 가능
() => 42                            // 매개변수가 없으면 빈 괄호는 남는다
```

중괄호와 `return` 은 한 묶음이라, 중괄호를 지우면 `return` 도 함께 지워야 합니다. 중괄호만 남기고 `return` 을 빠뜨리면 아무것도 돌려주지 않는 함수가 됩니다.

**기본값 매개변수**는 인수를 덜 보냈을 때 `undefined` 대신 정해 둔 값이 들어가게 합니다. 기본값이 있는 매개변수를 뒤쪽에 두는 것이 관용입니다 — 앞에 두면 그 자리를 건너뛰고 뒤에만 값을 보낼 방법이 없어 결국 `undefined` 를 직접 적어 넣게 됩니다.

### 1-5. 백틱 문자열 — 값을 끼워 넣는 표기

```javascript
console.log(`hello ${count}`);
let html = `<div> hello ${count2} </div>`;
```

작은따옴표·큰따옴표 대신 백틱(`` ` ``)으로 감싸면 안에 `${…}` 로 값을 끼워 넣을 수 있습니다. 따옴표로 적으면 `'hello ' + count` 처럼 이어 붙여야 하던 것이 한 줄로 줄어듭니다.

`${…}` 안에는 변수뿐 아니라 식도 들어갑니다(`${count + 1}`, `${dto.title}`). 또 백틱 문자열은 줄바꿈을 그대로 담을 수 있어서, 두 번째 줄처럼 **마크업 조각을 여러 줄로 적어 두는 자리**에 그대로 쓰입니다. 목록을 그릴 때 `map` 으로 백틱 조각을 만들고 `join('')` 으로 이어 붙이는 조합이 여기서 나옵니다.

| 표기 | 값 끼워 넣기 | 줄바꿈 |
| --- | --- | --- |
| `'…'` · `"…"` | `+` 로 이어 붙이기 | `\n` 을 적어야 한다 |
| `` `…` `` | `${…}` | 적은 그대로 들어간다 |

### 1-6. 조건을 적는 네 표기

```javascript
const point = 85;

if (point >= 90) { … } else if (point >= 80) { … } else { … }

point >= 90 ? 'A학점' : point >= 80 ? 'B학점' : 'C학점';

point >= 90 && 'A학점';   // 왼쪽이 참일 때만 오른쪽
point >= 90 || 'A학점';   // 왼쪽이 거짓일 때만 오른쪽

const nickName = null;
nickName ?? '익명사용자';  // 왼쪽이 null·undefined일 때만 오른쪽
```

넷 다 조건에 따라 갈라지는 코드이지만 **문(statement)인가 식(expression)인가**가 갈립니다. `if` 는 문이라 값이 되지 않고, 나머지 셋은 식이라 그 자체가 값이 되어 변수에 담거나 문자열 안에 끼워 넣을 수 있습니다. 화면 코드에서 삼항연산자가 자주 보이는 이유가 이것입니다 — 백틱 안에는 `if` 를 못 넣습니다.

| 표기 | 값이 되는가 | 돌려주는 것 |
| --- | --- | --- |
| `if / else if / else` | 안 됨 | — |
| `조건 ? A : B` | 됨 | 조건에 따라 `A` 또는 `B` |
| `조건 && A` | 됨 | 조건이 참이면 `A`, 아니면 조건값(`false`) |
| `조건 \|\| A` | 됨 | 조건이 참이면 조건값(`true`), 아니면 `A` |
| `값 ?? A` | 됨 | 값이 `null`·`undefined` 면 `A`, 아니면 값 |

**단축평가**(`&&`·`||`)는 왼쪽만 보고 결과가 정해지면 오른쪽을 아예 실행하지 않습니다. 그래서 `조건 && 그릴것` 이 "조건이 참일 때만 그린다"로 읽히고, 마크업을 만드는 자리에서 `if` 대신 쓰입니다.

`||` 와 `??` 의 갈림은 **무엇을 "없음"으로 보는가**입니다. `||` 는 `0`·빈 문자열·`false` 까지 거짓으로 보아 오른쪽으로 넘어가지만, `??` 는 `null`·`undefined` 일 때만 넘어갑니다. 개수 `0` 이나 빈 제목이 값으로 의미가 있는 자리에서는 `??` 를 써야 합니다.

삼항연산자를 이어 붙인 두 번째 줄은 `if / else if / else` 를 그대로 옮긴 모양입니다. 오른쪽부터 묶여서 읽히므로 조건이 셋을 넘어가면 `if` 로 돌아가는 편이 읽기 좋습니다.

### 1-7. 배열을 도는 세 가지 반복문

```javascript
const array = [10, 20, 30, 40, 50];

for (let index = 0; index < array.length; index++) { console.log(array[index]); }

for (let index in array) { console.log(array[index]); }  // in  — 인덱스가 나온다

for (let value of array) { console.log(value); }         // of  — 값이 나온다
```

`in` 과 `of` 는 한 글자 차이인데 반복변수에 들어오는 것이 다릅니다. `in` 은 **키(인덱스)** 를, `of` 는 **값**을 꺼내 줍니다. 배열에서 값만 필요하면 `of` 가 짧고, 몇 번째인지 알아야 하면 `in` 이나 일반 `for` 를 씁니다.

| 표기 | 반복변수에 들어오는 것 | 쓰는 자리 |
| --- | --- | --- |
| `for (let i = 0; …; i++)` | 직접 만든 숫자 | 인덱스를 다루거나 거꾸로·건너뛰며 돌 때 |
| `for (… in …)` | 키(배열이면 인덱스, **문자열**) | 객체의 키를 훑을 때 |
| `for (… of …)` | 값 | 배열의 값만 필요할 때 |

`in` 이 꺼내 주는 인덱스는 숫자가 아니라 **문자열**입니다. 그대로 더하면 `'0' + 1` 이 `'01'` 이 되므로, 인덱스로 계산할 일이 있으면 일반 `for` 를 쓰는 편이 안전합니다. `in` 은 원래 객체의 키를 도는 표기라, 배열에 쓰면 이런 어긋남이 따라옵니다.

앞의 1-3에서 본 `forEach`·`map`·`filter` 와 견주면 **`break` 로 중간에 멈출 수 있는가**가 갈립니다. `for` 계열은 멈출 수 있고, 배열 메소드는 도는 일을 배열에 맡기는 표기라 멈추지 못합니다(찾는 즉시 멈추고 싶으면 `find`·`some` 을 씁니다). 자바 쪽에서 `forEach` 에 `break` 가 성립하지 않던 것과 같은 사정입니다.

### 1-8. 객체 — 값 여러 개를 한 값으로

```javascript
const obj1 = { name: '유재석', age: 40, func1: (param) => {} };
obj1.func1();      // 속성 이름으로 꺼내 쓰기

const obj2 = ['유재석', 40, (param) => {}];
obj2[2]();         // 인덱스로 꺼내 쓰기
```

중괄호는 **이름으로 꺼내는 묶음**, 대괄호는 **순서로 꺼내는 묶음**입니다. 담을 수 있는 것에는 제한이 없어서 숫자·문자열뿐 아니라 객체·배열·함수까지 값으로 들어갑니다. 위에서 `func1` 자리에 화살표 함수가 그대로 들어간 것이 1-4에서 정리한 "함수가 값"이라는 성질이 눈에 보이는 자리입니다.

| 표기 | 꺼내는 방법 | 자바 쪽에서 가까운 것 |
| --- | --- | --- |
| `{ key: value }` | `obj.key` · `obj['key']` | 필드를 가진 객체 / `Map` |
| `[값, 값, 값]` | `obj[0]` | 배열 / `List` |

`obj.key` 와 `obj['key']` 는 같은 일을 합니다. 점 표기가 짧아 기본이고, 꺼낼 키 이름이 변수에 담겨 있을 때만 대괄호 표기를 씁니다(`obj[keyName]`).

서버가 내려주는 JSON이 정확히 이 두 모양입니다. `{ … }` 는 DTO 한 벌, `[ … ]` 는 DTO 목록이라, 응답을 받아 쓰는 코드는 결국 이 두 표기를 오가는 일이 됩니다.

없는 키를 꺼내도 오류가 아니라 `undefined` 가 나옵니다. 오타가 조용히 지나가는 자리라, 값이 비면 키 이름부터 맞춰 보는 편이 빠릅니다.

### 1-9. 펼침 연산자와 구조 분해 — 담는 표기와 꺼내는 표기

```javascript
// 펼침(spread) — 기존 것을 펼쳐 새 것을 만든다
const obj3 = { ...obj1, phone: '010' };   // 객체
const obj4 = ['010', ...obj2];            // 배열

// 구조 분해 — 안의 값을 각각의 변수로 꺼낸다
const { name, age } = obj1;               // 객체는 이름으로
const [name2, ...array2] = obj2;          // 배열은 순서로
```

둘은 방향이 반대입니다. `...` 이 **왼쪽(담는 자리)** 에 있으면 펼쳐 넣는 것이고, **오른쪽(꺼내는 자리)** 에 있으면 남은 것을 모으는 것입니다.

| 표기 | 하는 일 |
| --- | --- |
| `{ ...obj, key: 값 }` | 기존 속성을 그대로 복사하고 일부만 덧쓰기(뒤에 적은 쪽이 이긴다) |
| `[...arr, 값]` | 기존 값을 그대로 두고 뒤에 붙이기 |
| `const { a, b } = obj` | 객체에서 **이름이 같은** 속성을 꺼내 변수로 |
| `const [a, ...rest] = arr` | 배열에서 **순서대로** 꺼내고 나머지는 묶어서 |

객체 구조 분해는 이름이 짝이므로 순서를 바꿔 적어도 됩니다. 배열 구조 분해는 순서가 짝이라 건너뛰려면 자리를 비워 둡니다(`const [, second] = arr`).

펼침이 만드는 것은 **새 객체·새 배열**입니다. 원본은 그대로 남고 주소값이 갈리므로, 값을 바꿀 때 원본을 고치지 않고 새것을 만들어 갈아 끼우는 방식이 됩니다. 리액트의 state처럼 "바뀌었는지"를 주소값으로 판정하는 자리에서 이 표기가 관용이 된 이유입니다.

다만 복사되는 것은 한 겹뿐입니다. 안에 또 객체가 들어 있으면 그 안쪽은 같은 것을 가리키므로, 중첩된 값을 고치면 원본도 함께 바뀝니다.

### 1-10. 콜백 함수 — 함수를 넘겨 두고 나중에 부르기

```javascript
function printSuccess(message) {
  console.log('성공', message);
}

function printScore(score, onSuccess, onError) {
  if (score >= 80) onSuccess('합격');
  else onError('불합격');
}

printScore(50, printSuccess);
```

인수 자리에 **함수 이름만** 적는 것이 요점입니다. `printSuccess` 는 함수 자체를 넘기는 것이고, `printSuccess()` 는 지금 실행해서 그 결과를 넘기는 것이라 뜻이 완전히 갈립니다.

| 적은 것 | 넘어가는 것 |
| --- | --- |
| `f(plus)` | `plus` 함수 |
| `f(plus(3, 3))` | `plus` 를 실행한 결과 `6` |
| `f(3 + 3)` | `6` |

넘겨받은 쪽은 그 함수를 **자기가 정한 시점에** 부릅니다. 위 코드에서 `printScore` 는 점수를 보고 성공 쪽인지 실패 쪽인지 갈라 부르고, 넘긴 쪽은 "무엇을 할지"만 정해 둡니다. 판단은 받는 쪽이, 할 일은 넘기는 쪽이 갖는 구조입니다.

1-3의 `forEach`·`map`·`filter` 에 넘긴 화살표 함수가 전부 이 자리였습니다. 자바 쪽에서 람다를 인수로 넘기던 것과 같은 구조이고, 다른 점은 자바는 넘길 모양을 인터페이스로 정해 두는 반면 자바스크립트는 함수가 처음부터 값이라 그런 단계가 없다는 것입니다.

그래서 개수가 어긋나도 실행 시점까지 안 걸립니다. 위 호출은 인수를 둘만 보냈으므로 `onError` 는 `undefined` 이고, 점수가 80 미만이라 그 자리에서 "함수가 아니다"라는 오류가 납니다. 콜백을 여러 개 받는 함수는 기본값을 두거나 부르기 전에 있는지 확인해 두는 편이 안전합니다.

### 1-11. 동기와 비동기 — `async` · `await`

```javascript
const backLoad = async () => {
  const response = await axios( … );
};
```

**동기**는 부른 쪽이 결과가 올 때까지 기다리는 것이고, **비동기**는 기다리지 않고 다음 줄로 넘어가는 것입니다. 서버를 부르는 통신은 응답이 언제 올지 모르므로 비동기입니다 — 기다렸다면 그동안 화면 전체가 멈춥니다.

문제는 그다음입니다. 기다리지 않고 넘어가므로 **결과를 받아 쓰는 줄이 응답보다 먼저 실행됩니다.** 그래서 순서대로 적었는데 값이 비는 자리가 생깁니다.

`async` 와 `await` 은 그 순서를 되돌리는 짝입니다.

| 키워드 | 붙이는 자리 | 하는 일 |
| --- | --- | --- |
| `async` | 함수 선언 앞 | 이 함수 안에서 기다릴 수 있게 표시 |
| `await` | 기다릴 호출 앞 | 결과가 올 때까지 이 줄에서 멈춘다 |

둘은 반드시 짝입니다. `async` 없는 함수 안에서 `await` 을 적으면 문법 오류가 나고, `await` 없이 `async` 만 붙이면 아무것도 기다리지 않습니다.

`await` 이 멈추는 것은 **그 함수 안쪽뿐**입니다. 바깥 코드는 계속 흘러가므로 화면이 멈추지 않습니다. 비동기인 채로 두고 안쪽 순서만 맞춰 주는 표기라, "비동기를 동기로 바꾼다"기보다 **비동기 코드를 순서대로 읽히게 적는 표기**에 가깝습니다.

받는 값은 응답 객체 전체라, 실제 데이터는 그 안의 `data` 에 들어 있습니다.

```javascript
const backLoad = async () => {
  const response = await axios.get('/api/board');
  const list = response.data;   // 서버가 내려준 JSON은 여기
};
backLoad();
```

마지막 줄처럼 괄호를 붙여야 실제로 실행됩니다. 이름만 적으면 1-10에서 본 대로 함수를 가리키기만 할 뿐 아무 일도 일어나지 않습니다.

## 2. 추가로 알면 좋은 활용법

### 2-1. 자주 함께 쓰는 배열 메소드

`map`·`filter` 외에 화면을 그릴 때 자주 붙는 것들입니다.

| 메소드 | 하는 일 |
| --- | --- |
| `find` | 조건을 만족하는 **첫 요소 하나**를 돌려준다(없으면 `undefined`) |
| `some` / `every` | 하나라도 참인가 / 전부 참인가를 `true`·`false` 로 |
| `reduce` | 요소를 하나의 값으로 줄인다(합계·그룹화 등) |
| `join` | 배열을 문자열 하나로 이어 붙인다 |
| `sort` | 정렬 — **원본을 바꾸므로** 필요하면 복사한 뒤 정렬한다 |
| `includes` | 값이 들어 있는지 |

`map` 으로 마크업 조각을 만든 다음 `join('')` 으로 이어 붙이는 조합이 목록을 그릴 때의 관용입니다. `join()` 을 빼면 쉼표가 사이사이 끼어 들어갑니다.

### 2-2. 체이닝 — 이어 붙여 적기

`filter` 와 `map` 이 둘 다 배열을 돌려주므로 그대로 이을 수 있습니다.

```javascript
const result = array
  .filter((value) => value >= 20)
  .map((value) => value * 2);
```

이어 붙일 수 있는 조건은 **앞의 호출이 배열을 돌려줄 것** 하나입니다. `forEach` 는 아무것도 안 돌려주므로 그 뒤로는 이어지지 않습니다.

순서가 곧 의미라 `filter` 를 앞에 두는 편이 낫습니다. 걸러 낼 것을 먼저 빼면 뒤의 `map` 이 도는 횟수가 줄어듭니다.

### 2-3. 화살표 함수와 `function` 이 갈리는 자리

두 표기가 언제나 바꿔 쓸 수 있는 것은 아닙니다. 갈리는 것은 `this` 입니다.

- `function` 으로 만든 함수는 **부르는 방식**에 따라 `this` 가 달라진다
- 화살표 함수는 자기 `this` 를 갖지 않고 **바깥 범위의 `this`** 를 그대로 쓴다

콜백 안에서 바깥의 `this` 를 그대로 쓰고 싶을 때 화살표 함수가 편합니다. 반대로 객체의 메소드로 둘 때는 `function` 표기가 맞습니다.

또 화살표 함수에는 `arguments` 가 없고, 생성자로 쓸 수 없습니다. 대부분의 자리에서는 화살표 함수로 두고, `this` 가 걸리는 자리에서만 갈라 생각하면 됩니다.

### 2-4. 값을 꺼내 쓰는 짧은 표기들

앞으로 응답 JSON을 다룰 때 계속 붙는 표기입니다.

```javascript
const { title, content } = dto;        // 구조 분해 — 필요한 키만 꺼내기
const [first, second] = array;         // 배열도 같은 방식으로
const merged = { ...dto, done: true }; // 펼침 연산자로 복사하며 일부만 바꾸기
const name = dto.writer ?? '익명';      // null·undefined일 때만 오른쪽 값
const len = dto.list?.length;          // 중간이 비어 있으면 오류 대신 undefined
```

`??` 와 `||` 는 다릅니다. `||` 는 `0`·빈 문자열도 거짓으로 보아 오른쪽 값을 쓰지만, `??` 는 `null`·`undefined` 일 때만 넘어갑니다. 숫자 `0` 이 값으로 의미가 있는 자리라면 `??` 를 써야 합니다.

## 3. 더 나아가 알면 좋은 것

### 3-1. 같은 구조가 언어를 건너 반복되는 자리

day08에서 자바 쪽으로 정리한 것과 모양이 겹칩니다. 익명 구현체를 람다로 줄이던 축약이 자바스크립트에서는 익명 함수를 화살표 함수로 줄이는 축약이고, 컬렉션을 도는 메소드에 동작을 넘기던 구조가 배열 메소드에 콜백을 넘기는 구조와 같습니다.

| 하는 일 | 자바 쪽 표기 | 자바스크립트 쪽 표기 |
| --- | --- | --- |
| 요소마다 무언가 하기 | `forEach` + `Consumer` | `forEach` + 콜백 |
| 타입 바꾸기 | `map` + `Function` | `map` + 콜백 |
| 개수 줄이기 | `filter` + `Predicate` | `filter` + 콜백 |
| 동작을 값으로 넘기기 | 람다 | 익명 함수·화살표 함수 |

다른 점은 자바 쪽은 넘길 동작의 모양을 인터페이스로 미리 정해 두고 컴파일러가 맞춰 보는 반면, 자바스크립트는 함수가 처음부터 값이라 그런 단계가 없다는 것입니다. 그래서 짧게 적히는 대신 매개변수 개수나 반환 유무가 어긋나도 실행할 때까지 걸리지 않습니다.

### 3-2. 실행 시점에만 드러나는 어긋남

타입 검사가 없어 조용히 넘어가는 자리가 몇 군데 있습니다.

- `map` 콜백에서 `return` 을 빠뜨리면 `undefined` 배열이 나온다
- 없는 키를 꺼내면 오류가 아니라 `undefined` 가 나온다
- 문자열과 숫자를 `+` 로 더하면 이어 붙기가 된다(`'3' + 1` 은 `'31'`)
- `==` 는 타입을 맞춰 보고 비교하므로 `'1' == 1` 이 참이 된다 — `===` 를 쓰는 편이 안전하다

값이 이상하면 오류 메시지를 기다리지 말고 중간 단계를 출력해 어디서 모양이 갈렸는지 보는 편이 빠릅니다.

### 3-3. 다음에 볼 키워드

- `document.querySelector` · `innerHTML` · `textContent` — 화면에서 자리를 잡고 값을 넣기
- 템플릿 리터럴(백틱) — 문자열 안에 값을 끼워 마크업 조각 만들기
- `fetch` · `axios` — 서버 API 부르기(`get`·`post`·`put`·`delete` 와 인수 자리의 갈림)
- `Promise` · `try`/`catch`/`finally` — `await` 이 실패했을 때의 갈래와 `Promise.all` 로 여럿을 한꺼번에 기다리기
- 이벤트 리스너와 이벤트 위임 — `onclick` 속성 대신 코드에서 붙이기
- `JSON.parse` / `JSON.stringify` — 문자열과 객체 사이 변환
- 모듈(`type="module"`·`import`) — 파일이 갈리면 이름도 갈리게 하기

- `2026B_Spring/springweb/src/main/resources/static/day09/index.js` (**문법을 훑는 본체** — `let` 과 `const` 가 재대입 가능 여부로만 갈리고 배열·객체의 내용은 `const` 여도 바뀌므로 대부분을 `const` 로 두는 관용, `forEach`·`map`·`filter` 셋이 도는 방식은 같고 돌려주는 것으로 갈리는 표와 `map` 은 개수를 두고 타입을 바꾸며 `filter` 는 타입을 두고 개수를 줄이는 대비·셋 모두 원본을 바꾸지 않아 결과를 받을 변수를 따로 두는 표기·`return` 을 빠뜨리면 오류 없이 결과만 비는 자리, 함수를 적는 네 모양(선언적·익명·화살표·기본값 매개변수)이 아래로 갈수록 짧아지는 축약이고 익명 함수가 필요한 이유가 함수를 값처럼 넘기기 위해서라는 점·중괄호와 `return` 이 한 묶음이라 함께 지워야 하는 생략 규칙·기본값 매개변수를 뒤쪽에 두는 관용, 백틱 문자열이 `${…}` 로 값을 끼워 넣고 줄바꿈을 그대로 담아 마크업 조각을 만드는 자리, 조건을 적는 네 표기가 문인가 식인가로 갈려 백틱 안에는 삼항연산자만 들어가는 점과 단축평가가 오른쪽을 아예 실행하지 않는 성질·`||` 와 `??` 가 `0`·빈 문자열을 없음으로 보는가에서 갈리는 자리, `for … in` 과 `for … of` 가 키와 값으로 갈리고 `in` 의 인덱스가 문자열이라 계산에 쓰면 어긋나는 점·`for` 계열은 `break` 가 되고 배열 메소드는 안 되는 대비, 중괄호는 이름으로 대괄호는 순서로 꺼내는 묶음이고 함수까지 값으로 담기는 점과 그 두 모양이 그대로 응답 JSON의 모양인 자리, 펼침과 구조 분해가 담는 방향·꺼내는 방향으로 반대인 대비와 펼침이 새 객체를 만들어 주소값이 갈리는 성질·한 겹만 복사되는 한계, 콜백에서 함수 이름만 적는 것과 괄호를 붙이는 것의 뜻 차이와 판단은 받는 쪽이 할 일은 넘기는 쪽이 갖는 구조·인수 개수가 어긋나도 실행 시점에야 걸리는 자리, 비동기가 결과를 안 기다려 받아 쓰는 줄이 먼저 도는 문제와 `async`·`await` 이 짝으로 그 순서만 되돌리는 표기인 점·`await` 이 멈추는 범위가 함수 안쪽뿐이라 화면은 안 멈추는 자리·응답 객체의 `data` 에 실제 값이 들어 있는 점)
